# 5.3 常用标准库练习题

## 一、模块选择题

为下列需求选择最合适的标准库模块，并说明理由：

1. 递归查找目录中所有 `.md` 文件；
2. 读取环境变量中的端口号；
3. 生成密码重置令牌；
4. 解析命令行选项 `--output`；
5. 计算一段代码执行耗时；
6. 处理上海和纽约之间的时间转换；
7. 统计文本中出现频率最高的十个单词；
8. 启动外部命令并检查退出状态；
9. 读取已安装发行包的版本；
10. 读取安装包内附带的 JSON 模板。

## 二、基础编程题

### 1. 文件统计器

使用 `pathlib` 编写程序，输入一个目录后输出：

- 文件总数和子目录总数；
- 不同扩展名的文件数量；
- 最大的五个文件；
- 所有 Python 文件的总行数；
- 无法读取的文件及错误原因。

### 2. 配置加载器

从环境变量读取：

- `APP_HOST`，默认 `127.0.0.1`；
- `APP_PORT`，默认 `8000`，必须转换为整数；
- `APP_DEBUG`，支持 `true/false/1/0/yes/no`；
- `APP_ALLOWED_HOSTS`，按逗号分割。

对非法配置给出明确错误，不允许默默使用错误值。

### 3. JSON 通讯录

实现命令行通讯录：

- 数据保存到 JSON 文件；
- 支持添加、删除、查询和列出联系人；
- 保存中文时保持可读；
- 文件不存在时创建空数据；
- JSON 损坏时不能覆盖原文件；
- 写入时考虑先写临时文件再替换。

### 4. CSV 成绩分析

读取包含姓名、班级、科目、成绩的 CSV：

- 校验必需字段；
- 把成绩转换为数值；
- 统计每班平均分；
- 统计每科最高分；
- 输出不合法行及原因；
- 把汇总结果写入新的 CSV。

### 5. 日志实践

为一个批量文件处理程序配置日志：

- 控制台输出 `INFO` 及以上；
- 文件保存 `DEBUG` 及以上；
- 日志包含时间、级别、模块名和消息；
- 单个文件失败时使用 `logger.exception()`；
- 批处理结束后输出成功与失败数量。

## 三、专题练习

### 1. 日期时间

编写会议安排工具：

- 用户输入上海时间；
- 输出伦敦、纽约、东京对应时间；
- 使用 `zoneinfo`；
- 明确处理输入格式错误；
- 分析夏令时可能造成的影响；
- 禁止仅用固定小时数相加减。

### 2. 正则表达式

分别为以下任务选择 `fullmatch`、`search`、`finditer` 或 `sub`：

- 验证用户名整体格式；
- 从日志中提取全部 IPv4 候选文本；
- 查找文本是否包含订单编号；
- 隐藏手机号中间四位；
- 把连续空白替换为一个空格。

说明为什么某些任务还需要正则之外的业务校验。

### 3. 随机与安全

实现两个函数：

- `draw_lottery()`：模拟普通抽奖，允许通过种子复现实验；
- `generate_reset_token()`：生成安全令牌，不允许使用 `random`。

解释两者的随机性要求为什么不同。

### 4. 子进程

实现一个命令执行函数：

```python
def run_command(arguments, timeout=10):
    ...
```

要求：

- 参数必须是字符串列表；
- 捕获标准输出和标准错误；
- 使用文本模式；
- 超时给出明确结果；
- 非零退出码不能被当作成功；
- 不使用 `shell=True`；
- 记录执行耗时。

### 5. 精确金额

使用 `Decimal` 实现购物车金额计算：

- 商品单价从字符串构造；
- 支持数量、折扣和税率；
- 最终金额保留两位小数；
- 明确舍入规则；
- 对比直接使用 `float` 的结果。

## 四、综合实践：日志分析 CLI

使用标准库完成一个日志分析工具：

```bash
python -m log_analyzer access.log --level ERROR --top 10 --json report.json
```

要求：

1. 使用 `argparse` 解析位置参数和选项；
2. 使用 `pathlib` 检查输入输出路径；
3. 使用 `re` 解析日志行；
4. 使用 `datetime` 解析时间；
5. 使用 `Counter` 统计级别、模块和错误消息；
6. 使用 `json` 输出结构化报告；
7. 使用 `logging` 记录工具自己的运行信息；
8. 使用 `perf_counter()` 输出处理耗时；
9. 对格式错误的行计数并保留少量样例；
10. 设计合理退出码：成功、参数错误、文件错误、部分数据错误。

## 五、思考题

1. 为什么 Base64 不能用于加密敏感数据？
2. 为什么密码不能简单保存为一次 SHA-256 哈希？
3. 为什么性能计时推荐 `perf_counter()` 而不是 `datetime.now()`？
4. 为什么库模块通常不应调用 `logging.basicConfig()`？
5. 为什么包内资源不能假定当前工作目录？
6. `Counter`、`defaultdict`、`deque` 分别解决了普通容器的哪些痛点？
7. 缓存函数结果时，哪些函数不适合使用 `lru_cache`？
