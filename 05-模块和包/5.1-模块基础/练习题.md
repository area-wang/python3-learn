# 5.1 模块基础练习题

## 一、概念题

1. 什么是 Python 模块？模块与普通 `.py` 文件有什么关系？
2. `import math` 与 `from math import sqrt` 对当前命名空间的影响有什么区别？
3. 为什么不推荐在项目代码中使用 `from module import *`？
4. 模块第一次导入时，为什么会执行文件中的顶层语句？
5. `sys.modules` 的作用是什么？重复导入同一模块时通常会发生什么？
6. 模块被直接运行和被其他模块导入时，`__name__` 分别是什么？
7. `__all__` 能否阻止调用者访问模块中的内部名称？为什么？
8. 什么是模块遮蔽？为什么把文件命名为 `json.py` 可能引发问题？
9. 什么是循环导入？“部分初始化的模块”是怎样产生的？
10. 为什么不建议在业务代码中随意使用 `sys.path.append()`？

## 二、判断代码输出

### 1. 导入缓存

```python
# logger.py
print("loading logger")
```

```python
# main.py
import logger
import logger
print("done")
```

写出通常情况下的输出，并解释原因。

### 2. 名称绑定

```python
# config.py
mode = "development"
```

```python
from config import mode
import config

config.mode = "production"
print(mode)
print(config.mode)
```

写出输出，并解释 `mode` 为什么没有自动同步。

### 3. 入口保护

```python
# report.py
def build_report():
    return "report ready"


print("module loaded")

if __name__ == "__main__":
    print(build_report())
```

分别说明执行 `python report.py` 与在其他文件中执行 `import report` 时的输出。

## 三、编程题

### 1. 数学工具模块

创建 `math_tools.py`，要求：

- 定义常量 `PI`；
- 实现 `circle_area(radius)`；
- 实现 `rectangle_area(width, height)`；
- 对不合法的负数参数抛出 `ValueError`；
- 在模块直接运行时展示几个示例；
- 模块被导入时不能自动打印示例。

再创建 `main.py`，导入并调用其中的函数。

### 2. 文本处理模块

创建 `text_tools.py`，实现：

- `normalize_space(text)`：把连续空白转换为单个空格；
- `word_count(text)`：统计单词数量；
- `slugify(text)`：把英文文本转换为小写连字符形式；
- 使用 `__all__` 只声明希望公开的接口；
- 至少为每个函数编写三个调用示例。

### 3. 排查名称遮蔽

创建一个名为 `random.py` 的文件和一个导入 `random` 标准库的 `main.py`：

1. 观察 `random.__file__`；
2. 记录出现的问题；
3. 重命名本地文件并清理缓存；
4. 再次验证实际导入来源；
5. 总结避免模块名称冲突的规则。

### 4. 动态导入

编写函数：

```python
def call_function(module_name, function_name, *args, **kwargs):
    ...
```

要求使用 `importlib.import_module()` 动态导入模块，通过 `getattr()` 获取函数并调用。补充以下异常处理：

- 模块不存在；
- 属性不存在；
- 属性存在但不可调用。

### 5. 消除循环导入

设计两个模块 `order.py` 和 `payment.py`：

- `order.py` 需要创建订单并调用支付功能；
- `payment.py` 需要记录订单编号；
- 先故意构造循环导入并观察错误；
- 再通过提取公共数据结构或调整依赖方向解决问题；
- 画出重构前后的依赖方向。

## 四、综合实践：命令行单位转换器

创建以下结构：

```text
converter_project/
├── main.py
├── length.py
├── temperature.py
└── weight.py
```

要求：

1. 每个模块只负责一类单位转换；
2. 每个模块至少提供两个方向的转换函数；
3. `main.py` 负责获取输入、选择功能和展示结果；
4. 模块导入时不执行交互行为；
5. 为函数设计清晰的命名和文档字符串；
6. 对非法数值和未知单位给出明确错误；
7. 使用 `module.function` 形式体现函数来源；
8. 思考当转换类型增加到二十种时，当前设计是否仍然合理。

## 五、参考检查点

- 是否能说明“导入模块”不只是读取名称，还会执行模块顶层代码；

- 是否能通过 `module.__file__` 判断导入来源；
- 是否避免星号导入和随意修改 `sys.path`；
- 是否能识别名称绑定与对象修改之间的区别；
- 是否能通过调整职责和依赖方向消除循环导入。
