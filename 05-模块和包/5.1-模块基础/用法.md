# 5.1 模块基础

模块是 Python 组织和复用代码的基本单位。通常一个 `.py` 文件就是一个模块，文件中的变量、函数、类和其他对象都属于该模块的命名空间。

## 1. 为什么需要模块

当程序越来越大时，把所有代码写在一个文件中会带来以下问题：

- 名称容易冲突，难以确认变量和函数来自哪里；
- 文件过长，阅读、定位和修改困难；
- 相同功能无法方便地在多个程序中复用；
- 测试边界不清晰，多个功能相互影响；
- 多人协作时容易频繁修改同一个文件。

模块可以把相关功能放在同一个命名空间中：

```python
# calculator.py
PI = 3.1415926


def add(left, right):
    return left + right


class Calculator:
    def multiply(self, left, right):
        return left * right
```

其他文件可以导入并使用它：

```python
import calculator

print(calculator.PI)
print(calculator.add(10, 20))
machine = calculator.Calculator()
print(machine.multiply(3, 4))
```

## 2. 模块的常见来源

| 类型 | 说明 | 示例 |
|---|---|---|
| 自定义模块 | 自己编写的 `.py` 文件 | `calculator.py` |
| 标准库模块 | Python 安装时自带 | `math`、`json`、`pathlib` |
| 第三方模块 | 通过包管理工具安装 | `requests`、`pytest` |
| 内置模块 | 编译进解释器，通常没有普通 `.py` 文件 | `sys`、`builtins` |
| 扩展模块 | 使用 C、C++、Rust 等编译生成 | `_ssl`、部分科学计算库 |

模块名应尽量使用小写字母和下划线，例如 `user_service.py`，不要使用空格、连字符或与标准库同名的名称。

## 3. `import` 的基本形式

### 3.1 导入整个模块

```python
import math

print(math.sqrt(16))
print(math.pi)
```

特点：

- 当前命名空间只新增模块名 `math`；
- 使用成员时写成 `math.sqrt`，来源清晰；
- 不容易与当前文件中的名称冲突；
- 通常是最推荐的导入方式。

### 3.2 使用别名

```python
import datetime as dt

today = dt.date.today()
```

别名适用于模块名较长或存在行业惯例的情况。别名应简洁但仍然容易理解，不要为了少写几个字符使用含义不明的名称。

### 3.3 从模块导入指定成员

```python
from math import pi, sqrt

print(pi)
print(sqrt(25))
```

特点：

- 可以直接使用 `pi` 和 `sqrt`；
- 代码更短，但来源不如 `math.sqrt` 明确；
- 若本地已有同名对象，后绑定的名称会覆盖前一个绑定。

可以给成员设置别名：

```python
from datetime import datetime as DateTime

now = DateTime.now()
```

### 3.4 星号导入

```python
from math import *
```

除交互式探索等少数场景外，不建议这样写，原因包括：

- 阅读代码时无法直接判断名称来源；
- 容易覆盖当前命名空间中的同名对象；
- 静态分析、自动补全和重构更困难；
- 模块新增公开名称后，调用方行为可能意外改变。

星号导入会优先参考模块定义的 `__all__`；没有 `__all__` 时，通常导入不以下划线开头的名称。

```python
# tools.py
__all__ = ["format_name"]


def format_name(name):
    return name.strip().title()


def _normalize_space(text):
    return " ".join(text.split())
```

`__all__` 表达的是模块希望公开的接口，但它不是安全或权限机制，调用者仍然可以显式访问其他名称。

## 4. 导入模块时发生了什么

以 `import example` 为例，解释器大致会完成以下工作：

1. 检查 `sys.modules` 中是否已经缓存 `example`；
2. 根据导入系统和搜索路径寻找模块；
3. 创建模块对象，并设置 `__name__`、`__spec__`、`__package__` 等属性；
4. 将模块对象提前放入 `sys.modules`；
5. 执行模块顶层代码，把创建的名称放入模块命名空间；
6. 在当前作用域中绑定模块名 `example`。

因此，模块第一次成功导入时通常会执行一次顶层代码，之后再次导入通常直接复用缓存对象：

```python
# counter.py
print("counter 模块正在初始化")

value = 0
```

```python
import sys

import counter  # 打印初始化信息
import counter  # 通常不再执行顶层代码

print(counter is sys.modules["counter"])  # True
```

不要依赖“重复执行 `import`”来重新运行模块。学习或调试时可以了解 `importlib.reload()`，但生产代码中通常应把需要重复执行的逻辑封装成函数。

```python
import importlib
import counter

importlib.reload(counter)
```

重新加载存在旧对象引用、类实例仍属于旧类等复杂情况，不适合作为常规业务流程。

## 5. 模块顶层代码与导入副作用

模块顶层代码是文件中不在函数或类定义内部的语句：

```python
print("导入时立即执行")
config = load_config()       # 导入时读取配置
connection = connect_db()    # 导入时连接数据库
```

如果顶层代码执行耗时操作、网络请求、数据库连接、修改全局状态或输出内容，就会产生导入副作用。良好的模块通常只在顶层执行以下操作：

- 定义常量；
- 定义函数和类；
- 完成轻量、确定且必要的初始化；
- 声明公开接口和元数据。

耗时或依赖外部环境的工作应放到函数中，由调用者明确触发。

## 6. `__name__` 与程序入口

每个模块都有 `__name__` 属性：

- 文件被直接运行时，`__name__ == "__main__"`；
- 文件被导入时，`__name__` 通常是它的完整模块名。

```python
# temperature.py
def celsius_to_fahrenheit(celsius):
    return celsius * 9 / 5 + 32


def main():
    value = float(input("请输入摄氏温度："))
    print(celsius_to_fahrenheit(value))


if __name__ == "__main__":
    main()
```

这样设计后：

```bash
python temperature.py
```

会执行 `main()`，而：

```python
from temperature import celsius_to_fahrenheit

print(celsius_to_fahrenheit(20))
```

只导入函数，不会请求用户输入。

入口保护的主要价值是把“可复用功能”和“直接运行行为”分开。它不是为了阻止代码被访问。

## 7. 模块命名空间

模块对象拥有自己的全局命名空间：

```python
# settings.py
DEBUG = True
PORT = 8000
```

```python
import settings

print(settings.__dict__["DEBUG"])
print(settings.PORT)
```

两个模块中可以有同名变量而互不冲突：

```python
import development_settings
import production_settings

print(development_settings.DEBUG)
print(production_settings.DEBUG)
```

注意，`from settings import DEBUG` 是把当时的对象绑定到当前名称，并不会建立自动同步关系：

```python
from settings import DEBUG
import settings

settings.DEBUG = False
print(DEBUG)           # 仍是原来绑定的对象
print(settings.DEBUG)  # False
```

需要持续读取模块中的最新绑定时，保留模块引用并使用 `settings.DEBUG`。

## 8. 模块搜索路径

导入普通模块时，解释器会使用导入系统查找目标。常见搜索位置体现在 `sys.path` 中：

```python
import sys

for path in sys.path:
    print(path)
```

其中通常包括：

- 启动脚本所在目录或当前工作目录相关入口；
- `PYTHONPATH` 环境变量提供的目录；
- Python 标准库目录；
- 当前环境中的 `site-packages`；
- `.pth` 文件等机制补充的路径。

常见 `ModuleNotFoundError` 排查顺序：

1. 检查模块名是否拼写正确；
2. 检查当前使用的是哪个 Python 解释器；
3. 检查模块是否安装在该解释器对应的环境中；
4. 检查运行入口和项目根目录是否正确；
5. 检查本地文件是否与目标模块重名；
6. 打印 `sys.path`、`module.__file__` 辅助定位。

不要在业务代码中随意执行 `sys.path.append(...)` 修补项目结构。更合理的方式是使用正确的包结构、从项目根目录以模块方式运行，或把项目安装到虚拟环境。

## 9. 模块遮蔽问题

如果当前目录存在 `json.py`、`random.py`、`typing.py` 等文件，它们可能遮蔽标准库或第三方模块：

```text
project/
├── random.py
└── main.py
```

`main.py` 中的 `import random` 可能导入本地 `random.py`，导致预期 API 不存在，甚至产生循环导入。

可以检查实际来源：

```python
import random

print(random.__file__)
```

解决方法是重命名冲突文件，并清理对应的 `__pycache__` 后重新运行。

## 10. 字节码缓存 `__pycache__`

Python 可能把模块编译后的字节码保存到 `__pycache__` 目录，以加快后续启动：

```text
__pycache__/
└── calculator.cpython-3xx.pyc
```

要点：

- `.pyc` 是字节码缓存，不是源代码的替代品；
- Python 会根据缓存标记判断能否复用；
- 删除缓存通常不会破坏程序，下次运行可重新生成；
- 一般不应把本地生成的 `__pycache__` 提交到版本库。

## 11. 动态导入

模块名在运行时才确定时，可以使用 `importlib.import_module()`：

```python
from importlib import import_module

module_name = "json"
json_module = import_module(module_name)
print(json_module.dumps({"name": "Python"}))
```

动态导入常用于插件系统、可配置后端和框架扩展点。模块名来自外部输入时，应使用白名单或可信配置，避免任意模块被加载。

## 12. 循环导入

如果 `a.py` 导入 `b.py`，而 `b.py` 又在顶层导入 `a.py`，就形成循环导入：

```python
# a.py
from b import function_b


def function_a():
    return "A"
```

```python
# b.py
from a import function_a


def function_b():
    return "B"
```

导入执行过程中，模块会先进入 `sys.modules`，再执行顶层代码。因此另一方可能看到一个“只初始化了一部分”的模块，出现无法导入名称等错误。

优先采用以下方式解决：

1. 把双方共同依赖的对象提取到第三个模块；
2. 重新划分职责，让依赖保持单向；
3. 仅在确有必要时，把导入延迟到函数内部；
4. 对仅供类型检查的导入使用 `TYPE_CHECKING` 和前向引用。

```python
from typing import TYPE_CHECKING

if TYPE_CHECKING:
    from user import User


def send_message(user: "User", message: str) -> None:
    print(user, message)
```

函数内导入可以缓解初始化顺序问题，但如果架构本身职责纠缠，它只是临时手段。

## 13. 模块自省

调试和学习时，可以查看模块的重要属性：

```python
import json

print(json.__name__)      # 模块名
print(json.__file__)      # 来源文件；部分内置模块可能没有
print(json.__package__)   # 所属包
print(json.__spec__)      # 导入规范
print(dir(json))          # 可访问名称列表
help(json.dumps)          # 查看帮助
```

`dir()` 适合交互式探索，但不应把它当成稳定的公开 API 清单；正式使用应阅读文档并遵循模块公开接口。

## 14. 模块设计建议

- 模块名使用清晰的小写名称，避免与标准库重名；
- 一个模块围绕一组高度相关的职责组织；
- 公开接口保持少而稳定，内部实现可使用前导下划线；
- 避免导入时执行昂贵或不可预测的操作；
- 导入通常放在文件顶部，并按标准库、第三方库、本地模块分组；
- 优先使用明确导入，避免星号导入；
- 可执行逻辑放入 `main()`，使用入口保护；
- 从根本上消除循环依赖，而不是大量使用局部导入掩盖问题；
- 不要通过修改 `sys.path` 弥补不合理的目录结构。

## 15. 本节小结

1. 一个 `.py` 文件通常就是一个模块，模块拥有独立的全局命名空间。
2. `import module` 来源清晰、冲突少，通常优于把大量成员直接导入当前命名空间。
3. 模块第一次导入时会执行顶层代码，并通常缓存到 `sys.modules`。
4. `if __name__ == "__main__":` 用于分离直接运行行为与可复用接口。
5. 导入失败要从解释器、安装环境、搜索路径、运行入口和名称遮蔽等方面排查。
6. 循环导入通常反映模块职责或依赖方向存在问题，应优先重构设计。
