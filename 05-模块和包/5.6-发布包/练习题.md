# 5.6 发布包练习题

## 一、概念题

1. 发行项目名与导入包名有什么区别？为什么 `awesome-tools` 不能直接作为 Python 导入语句？
2. 构建前端、构建后端、安装前端和包索引分别负责什么？
3. `pyproject.toml` 中 `[build-system]` 和 `[project]` 的职责是什么？
4. 静态版本和动态版本各有什么优缺点？
5. 为什么项目声明支持的 Python 版本必须在 CI 中验证？
6. Wheel 与 sdist 分别是什么？为什么通常应同时发布？
7. 为什么不能只在源码仓库中运行测试就断言发行包正确？
8. 包数据为什么可能在构建后丢失？
9. 为什么同一版本号不应对应不同构建内容？
10. 发布凭据泄露后，为什么仅从最新提交删除令牌并不够？

## 二、配置练习

为一个名为 `text-cleaner`、导入名为 `text_cleaner` 的项目编写 `pyproject.toml`，要求包含：

- 一个构建后端；
- 版本 `0.1.0`；
- 一行描述和 `README.md`；
- 最低 Python 版本；
- 作者和许可证；
- 一个运行依赖；
- `test` 可选依赖组；
- 项目主页、源码和问题追踪链接；
- 命令 `text-clean` 指向 `text_cleaner.cli:main`。

说明每个字段的作用，以及哪些字段属于标准项目元数据、哪些配置属于特定构建后端。

## 三、项目搭建题

创建项目：

```text
text-cleaner/
├── pyproject.toml
├── README.md
├── LICENSE
├── src/
│   └── text_cleaner/
│       ├── __init__.py
│       ├── cleaner.py
│       ├── cli.py
│       ├── data/
│       │   └── stop_words.txt
│       └── py.typed
└── tests/
    └── test_cleaner.py
```

要求：

1. 实现文本空白标准化和停用词删除；
2. 使用 `importlib.resources` 读取包内数据；
3. 提供带退出码的 CLI；
4. 配置源码发现、资源文件和类型标记；
5. 可编辑安装后运行测试；
6. 构建 wheel 和 sdist；
7. 检查产物中是否包含资源；
8. 在全新环境安装 wheel；
9. 从源码目录外测试导入和 CLI；
10. 删除源码目录后再次确认安装产物可工作。

## 四、产物验证题

写一份自动化冒烟测试脚本，接受 wheel 路径并执行：

1. 创建临时虚拟环境；
2. 安装指定 wheel；
3. 导入顶层包；
4. 调用一个公开函数；
5. 读取一个包资源；
6. 执行 CLI 的 `--help`；
7. 验证非法输入返回非零退出码；
8. 输出已安装发行版本；
9. 确认测试不从仓库源码导入；
10. 清理临时环境。

## 五、版本判断题

假设当前版本是 `1.4.2`，为以下变化选择下一个版本并说明理由：

1. 修复文档拼写；
2. 修复不改变公开接口的计算错误；
3. 新增向后兼容函数；
4. 删除已弃用的公开函数；
5. 修改 CLI 参数名称且旧名称不再支持；
6. 发布 `2.0.0` 前的第一个候选版本；
7. 已发布的 `1.4.2` 缺少一个文件，需要重新发布修复产物。

说明项目采用的版本策略，并讨论 `0.x` 项目是否采用相同承诺。

## 六、发布故障排查

### 1. wheel 中缺少子包

源码运行正常，但安装 wheel 后 `import package.subpackage` 失败。列出需要检查的构建配置和产物证据。

### 2. 资源读取失败

仓库中存在 `templates/default.txt`，但用户安装后文件不存在。修复构建配置，并使用已安装 wheel 验证。

### 3. CLI 不可用

包成功安装但命令不存在。检查脚本入口声明、函数位置、环境脚本目录和 `PATH`。

### 4. 依赖遗漏

开发机运行成功，干净环境导入时报第三方模块不存在。解释为什么本地环境掩盖了元数据错误。

### 5. 版本已存在

上传工具提示文件或版本已存在。说明为什么不应覆盖，并制定修复版本流程。

## 七、设计 CI 发布流程

设计一条从提交到正式发布的流水线，包括：

- 多 Python 版本测试；
- 多平台测试或明确的平台范围；
- 代码质量检查；
- 构建一次 wheel 和 sdist；
- 元数据与 README 检查；
- wheel 安装冒烟测试；
- sdist 重建测试；
- 受保护标签触发；
- 安全认证或可信发布；
- 发布后从索引重新安装验证；
- 发布说明生成；
- 失败后的回滚或撤回策略。

画出阶段依赖，并指出哪些步骤失败后必须禁止上传。

## 八、发布前审计

选择一个自己编写的包，逐项提供证据：

- 目录结构符合构建配置；
- 版本只有一个权威来源；
- 所有直接依赖已声明；
- README 示例可以运行；
- 许可证与代码来源清楚；
- wheel 和 sdist 都能构建；
- 产物不包含秘密和无关大文件；
- 干净环境安装成功；
- 公开导入和 CLI 成功；
- 包内资源成功读取；
- 最低支持 Python 版本测试成功；
- 发布账号和令牌安全；
- 版本号未被目标索引使用；
- 发布失败时有明确处理方案。
