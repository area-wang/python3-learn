# 05-模块和包

模块和包是 Python 组织代码、复用功能和管理依赖的核心机制。本章从单个模块出发，逐步扩展到包结构、标准库与第三方依赖，再进入模块化设计和发行包发布，帮助你建立从“拆分代码”到“交付可安装项目”的完整知识体系。

## 🎯 学习目标

完成本章后，你应该能够：

- 理解模块对象、模块命名空间、导入缓存和模块搜索路径；
- 正确使用普通包、绝对导入、相对导入与 `python -m`；
- 根据任务选择合适的 Python 标准库，避免重复造轮子；
- 使用 `pip`、虚拟环境和依赖声明管理第三方库；
- 按职责、边界和依赖方向设计可维护的模块结构；
- 使用 `pyproject.toml` 构建、检查和发布 wheel 与源码发行包。

## 🧭 建议学习顺序

1. 先完成 **5.1**，弄清楚导入行为，尤其是缓存、搜索路径和入口保护；
2. 再学习 **5.2**，把多个模块组织成边界清晰的包；
3. 通过 **5.3** 建立常用工具箱，并完成至少一个综合 CLI 练习；
4. 学习 **5.4**，为每个练习项目建立独立虚拟环境并记录依赖；
5. 使用 **5.5** 的原则重构前面完成的项目；
6. 最后完成 **5.6**，将重构后的项目构建为 wheel，并在干净环境中安装验证。

## 🧪 推荐实践路线

可以将六节练习串联成一个逐步演进的项目：

1. 创建若干独立工具模块；
2. 将模块整理成带子包的命令行应用；
3. 使用标准库实现配置、日志、数据存储和参数解析；
4. 引入一个第三方库，并完善环境与依赖声明；
5. 按接口、业务、基础设施拆分模块并补充测试替身；
6. 增加项目元数据和命令入口，构建 wheel，在新虚拟环境中验证安装。

## ✅ 章节完成标准

如果你能独立完成以下任务，说明已经掌握本章核心内容：

- 解释一个模块首次导入与再次导入时的行为差异；
- 为多模块程序设计合理包结构，并修复常见导入错误；
- 为文件、时间、数据交换、日志和子进程任务选择合适标准库；
- 创建隔离环境，声明直接依赖，并排查解释器或版本冲突；
- 将混杂的单文件程序重构为职责清晰、依赖可替换的模块；
- 构建 wheel 和 sdist，并在干净环境中验证导入、CLI 与资源文件。
