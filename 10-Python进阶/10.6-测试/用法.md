# 10.6 测试

测试用于验证代码行为是否符合预期。进阶阶段要养成写可测试代码和自动化测试的习惯，避免每次修改都靠手动运行。

## 1. 一个可测试函数

```python
def add(a: int, b: int) -> int:
    return a + b
```

对应测试可以写成：

```python
def test_add() -> None:
    assert add(1, 2) == 3
```

测试函数应尽量短，只验证一个明确行为。

## 2. `unittest`

`unittest` 是 Python 标准库自带测试框架：

```python
import unittest

class TestMath(unittest.TestCase):
    def test_add(self) -> None:
        self.assertEqual(add(1, 2), 3)

if __name__ == "__main__":
    unittest.main()
```

常用断言：

| 断言 | 说明 |
|---|---|
| `assertEqual(a, b)` | 判断相等 |
| `assertTrue(x)` | 判断为真 |
| `assertIsNone(x)` | 判断是 `None` |
| `assertRaises(Error)` | 判断会抛出异常 |

## 3. pytest 思路

`pytest` 不是标准库，但在实际项目中很常用。它支持直接使用 `assert`：

```python
def test_divide() -> None:
    assert divide(6, 2) == 3
```

测试异常：

```python
import pytest

def test_divide_zero() -> None:
    with pytest.raises(ZeroDivisionError):
        divide(1, 0)
```

如果项目没有安装 `pytest`，也可以先用标准库 `unittest`。

## 4. 测试组织

常见目录结构：

```text
project/
├── app/
│   └── calculator.py
└── tests/
    └── test_calculator.py
```

测试文件通常以 `test_` 开头，测试函数也以 `test_` 开头。

## 5. 可测试代码建议

- 函数输入输出要明确，减少依赖全局变量。
- 把纯逻辑和文件、网络、数据库操作分开。
- 边界条件要单独测试。
- Bug 修复后补一个能复现问题的测试。
- 测试名称要表达行为，例如 `test_divide_by_zero_raises`。

## 6. 常见测试类型

| 类型 | 关注点 |
|---|---|
| 单元测试 | 一个函数或类的行为 |
| 集成测试 | 多个模块协作是否正确 |
| 回归测试 | 已修复问题不会再次出现 |
| 边界测试 | 空值、极值、异常输入 |
