# 10.8 性能分析

性能优化的第一步是测量。不要凭感觉修改代码，应先定位瓶颈，再选择合适的优化方法。

## 1. 先看复杂度

很多性能问题来自不合适的算法或数据结构：

```python
items = list(range(100000))

# 慢：列表 membership 是 O(n)
print(99999 in items)

# 快：集合 membership 平均是 O(1)
item_set = set(items)
print(99999 in item_set)
```

优先检查是否存在重复循环、无意义排序、频繁线性查找等问题。

## 2. `timeit`

`timeit` 适合测量小段代码：

```python
from timeit import timeit

data = list(range(10000))

list_time = timeit("9999 in data", globals=globals(), number=10000)
set_data = set(data)
set_time = timeit("9999 in set_data", globals=globals(), number=10000)

print(list_time)
print(set_time)
```

同一段代码要多次执行，避免单次测量被系统波动影响。

## 3. `cProfile`

`cProfile` 用于分析整个程序的函数调用耗时：

```python
import cProfile

def main() -> None:
    result = sum(i * i for i in range(1_000_000))
    print(result)

cProfile.run("main()")
```

重点关注：

- 调用次数特别多的函数
- 总耗时高的函数
- 单次耗时高的函数

## 4. 缓存

对相同输入会重复计算的纯函数，可以考虑 `functools.lru_cache`：

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n: int) -> int:
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)
```

缓存适合输入有限、结果稳定、重复调用多的场景。不适合结果依赖时间、随机数、外部状态的函数。

## 5. 减少不必要工作

常见优化方向：

- 把循环内不变的计算移到循环外。
- 用生成器避免一次性创建大列表。
- 用集合或字典替代频繁列表查找。
- 批量处理文件或网络操作，减少重复打开连接。
- 使用标准库或成熟第三方库，不重复造低效实现。

## 6. 优化顺序

建议按这个顺序处理性能问题：

1. 明确性能目标，例如 10 秒内完成。
2. 用真实数据复现慢的问题。
3. 用 `timeit` 或 `cProfile` 定位瓶颈。
4. 优先改算法和数据结构。
5. 再考虑缓存、并发或底层优化。
6. 优化后重新测量，确认确实变快。

没有测量结果的优化，很容易让代码更复杂但收益很小。
