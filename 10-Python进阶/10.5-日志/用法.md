# 10.5 日志

日志用于记录程序运行过程中的关键信息。相比 `print()`，`logging` 可以控制级别、格式、输出位置和模块来源，更适合真实项目。

## 1. 基本用法

```python
import logging

logging.basicConfig(level=logging.INFO)

logging.debug("调试信息")
logging.info("程序开始")
logging.warning("配置缺失，使用默认值")
logging.error("操作失败")
```

常见日志级别从低到高：

| 级别 | 适用场景 |
|---|---|
| `DEBUG` | 调试细节 |
| `INFO` | 正常流程信息 |
| `WARNING` | 可恢复的异常情况 |
| `ERROR` | 某个操作失败 |
| `CRITICAL` | 程序可能无法继续运行 |

## 2. 日志格式

```python
logging.basicConfig(
    level=logging.INFO,
    format="%(asctime)s %(levelname)s %(name)s: %(message)s",
)
```

常用字段：

- `%(asctime)s`：时间
- `%(levelname)s`：日志级别
- `%(name)s`：日志器名称
- `%(message)s`：日志内容

## 3. 模块化日志

在模块中推荐使用 `getLogger(__name__)`：

```python
import logging

logger = logging.getLogger(__name__)

def load_config(path: str) -> dict[str, str]:
    logger.info("加载配置文件: %s", path)
    return {}
```

这样日志能显示来自哪个模块，便于定位问题。

## 4. 记录异常堆栈

捕获异常时使用 `logger.exception()`，它会自动记录堆栈信息：

```python
try:
    int("abc")
except ValueError:
    logger.exception("转换数字失败")
```

不要只记录 `"失败了"`，应带上能帮助定位问题的上下文。

## 5. 参数化日志

推荐使用 logging 自带的参数化格式：

```python
logger.info("用户 %s 登录成功", username)
```

不要为了日志提前拼接复杂字符串：

```python
logger.info(f"用户 {username} 登录成功")
```

参数化日志在日志级别被过滤时可以减少不必要的字符串格式化开销。

## 6. 常见建议

- 库代码不要随意调用 `basicConfig()`，应交给应用入口配置。
- 日志里避免记录密码、token、身份证等敏感信息。
- `DEBUG` 写细节，`INFO` 写关键流程，`ERROR` 写失败原因。
- 异常日志优先用 `exception()` 保留堆栈。
