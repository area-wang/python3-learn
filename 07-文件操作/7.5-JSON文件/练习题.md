## 二、判断代码输出

### 1. tuple 与字典 key

```python
import json

data = {"point": (1, 2), 3: "three"}
text = json.dumps(data)
print(text)
result = json.loads(text)
print(result)
print(type(result["point"]))
```

写出输出，并解释 `(1, 2)` 和 `3` 各自发生了什么变化。

### 2. ensure_ascii 对比

```python
import json

info = {"city": "上海"}
print(json.dumps(info))
print(json.dumps(info, ensure_ascii=False))
print(json.loads(json.dumps(info)) == info)
```

写出三行输出，并说明为什么第一行和第二行文本不同，但第三行的结果依然是 `True`。

### 3. default 与 TypeError

```python
import json
import datetime

def handler(obj):
    if isinstance(obj, datetime.date):
        return obj.isoformat()
    raise TypeError(f"不能序列化 {type(obj)}")

data = {"day": datetime.date(2026, 7, 24), "tag": {1, 2}}
print(json.dumps(data, default=handler))
```

预言运行结果（是正常输出还是抛异常），并说明原因；如果抛异常，指出触发点。

### 4. JSONDecodeError 定位

```python
import json

text = '{\n  "a": 1,\n  "b": 2,\n}'
try:
    json.loads(text)
except json.JSONDecodeError as e:
    print(e.lineno, e.colno)
```

写出大致输出（数值即可，不要求精确到具体实现版本），并说明这段 JSON 违反了什么规则。

## 三、编程题

### 1. 配置文件读写工具

实现 `load_config(path)` 与 `save_config(path, config)`：

- `save_config` 用 `indent=2`、`ensure_ascii=False`、`sort_keys=True` 写出美观且中文可读的配置文件；
- `load_config` 读取时若文件不存在，返回一个默认配置字典而不抛异常；
- 若文件存在但内容不是合法 JSON，捕获 `JSONDecodeError` 并打印出错的行列号后重新抛出。

### 2. 自定义对象的编解码

给定一个简单类：

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y
```

- 实现一个 `PointEncoder`（继承 `json.JSONEncoder`），把 `Point` 编码为 `{"__point__": true, "x": ..., "y": ...}`；
- 实现配套的 `point_object_hook`，把带有 `"__point__"` 标记的字典还原为 `Point` 实例；
- 验证 `json.loads(json.dumps(p, cls=PointEncoder), object_hook=point_object_hook)` 能得到值相等的新对象。

### 3. 安全解析器

实现 `safe_parse(text)`：

- 尝试 `json.loads(text)`，成功则直接返回结果；
- 捕获 `JSONDecodeError`，返回一个包含 `lineno`、`colno`、`pos`、`msg` 的字典而不是抛出异常；
- 额外处理一种常见错误：如果文本使用了单引号（形如 `{'a': 1}`），给出更友好的提示「请使用双引号」。

### 4. 去重与顺序检测

实现 `parse_strict(text)`：

- 使用 `object_pairs_hook` 检测 JSON 对象中是否存在重复的 key；
- 若存在重复 key，抛出 `ValueError` 并指明重复的 key 名称；
- 若不存在重复，正常返回一个普通 `dict`（保持原有顺序）。

## 四、综合实践：多语言应用配置中心

某应用需要把散落在代码里的配置统一收敛到 JSON 文件中，要求实现一个小型「配置中心」模块：

1. 定义配置的默认值（`dict`），包含嵌套结构（如 `{"db": {"host": ..., "port": ...}, "features": {"dark_mode": True}}`）；
2. 实现 `load_or_init(path)`：文件不存在时用默认配置写入一份，并返回默认配置；文件存在则读取并与默认配置做深度合并（避免旧配置缺字段时报错）；
3. 支持配置中包含 `datetime` 类型的 `updated_at` 字段，需要自定义 `default`/`JSONEncoder` 处理写入，以及 `object_hook` 处理读取还原；
4. 写入时保证中文字段（如描述性文本）不被转义成 `\uXXXX`，并保持稳定的 key 顺序方便版本控制查看 diff；
5. 提供 `update_config(path, **kwargs)`：更新指定的顶层字段后立即回写文件，同时自动刷新 `updated_at`；
6. 对读取阶段的 `JSONDecodeError` 做兜底：记录出错的行列号到日志，并回退为默认配置而不是让程序崩溃；
7. 思考：如果两个进程同时调用 `update_config` 写同一个文件，可能出现什么问题？结合 7.2 学过的上下文管理器，你会如何加锁或做原子写入（先写临时文件再 `os.replace`）？
