# 7.5 JSON文件

JSON（JavaScript Object Notation）是目前最通用的数据交换格式：结构简单、可读性好、几乎所有语言都有原生支持，广泛用于配置文件、Web 接口、日志记录等场景。Python 内置 `json` 模块，无需安装第三方包即可完成 Python 对象与 JSON 文本之间的相互转换（这一过程称为**序列化**与**反序列化**）。

## 1. `json` 模块总览

`json` 模块提供四个核心函数：

| 函数 | 作用 | 输入/输出 |
|---|---|---|
| `json.dumps(obj)` | 序列化为字符串 | Python 对象 → `str` |
| `json.loads(s)` | 从字符串反序列化 | `str`/`bytes` → Python 对象 |
| `json.dump(obj, fp)` | 序列化并写入文件 | Python 对象 → 文件 |
| `json.load(fp)` | 从文件反序列化 | 文件 → Python 对象 |

记忆技巧：带 `s` 的（`dumps`/`loads`）操作字符串（string），不带 `s` 的操作文件（file pointer）。

## 2. `json.dumps()` 与 `json.loads()`

```python
import json

data = {"name": "张三", "age": 25, "active": True}
text = json.dumps(data)
print(text)            # {"name": "张三", "age": 25, "active": true}

obj = json.loads(text)
print(obj)              # {'name': '张三', 'age': 25, 'active': True}
print(type(obj))         # <class 'dict'>
```

类型映射表：

| Python 类型 | JSON 类型 | 反序列化回 Python |
|---|---|---|
| `dict` | object | `dict` |
| `list`、`tuple` | array | `list` |
| `str` | string | `str` |
| `int` | number（整数） | `int` |
| `float` | number（实数） | `float` |
| `True`/`False` | `true`/`false` | `bool` |
| `None` | `null` | `None` |

`tuple` 序列化后变成 JSON array，反序列化回来是 `list`，**元组信息丢失**且不报错，容易被忽略：

```python
t = (1, 2, 3)
s = json.dumps(t)
print(s, type(json.loads(s)))   # [1, 2, 3] <class 'list'>
```

`dict` 的 key 在 JSON 中必须是字符串；如果 Python 字典的 key 是 `int`，会被强制转成字符串：

```python
print(json.dumps({1: "a", 2: "b"}))   # {"1": "a", "2": "b"}
```

## 3. `json.dump()` 与 `json.load()`：直接读写文件

`dump`/`load` 接收一个文件对象（`fp`），省去手工拼接字符串再读写的步骤：

```python
data = {"users": ["alice", "bob"], "count": 2}

with open("data.json", "w", encoding="utf-8") as f:
    json.dump(data, f)

with open("data.json", encoding="utf-8") as f:
    loaded = json.load(f)
print(loaded)   # {'users': ['alice', 'bob'], 'count': 2}
```

打开文件时务必用文本模式并显式指定 `encoding="utf-8"`；`loads`/`load` 允许传入 `bytes`，但 `dump`/`dumps` 始终写出 `str`，不支持直接写二进制文件对象（`'wb'`）。

## 4. 格式化参数

| 参数 | 作用 | 默认值 |
|---|---|---|
| `indent` | 缩进空格数，美化输出；`None` 为紧凑单行 | `None` |
| `separators` | `(item_sep, key_sep)`，控制逗号/冒号后是否带空格 | 紧凑 `(', ', ': ')`，指定 `indent` 后自动变为 `(',', ': ')` |
| `sort_keys` | 按 key 字母序排序输出，便于 diff 和测试 | `False` |
| `ensure_ascii` | 是否把非 ASCII 字符转义成 `\uXXXX` | `True` |
| `default` | 遇到无法序列化的对象时的回调函数（见第 6 节） | `None` |

```python
data = {"b": 2, "name": "Alice", "scores": [90, 85, 78]}

# indent 美化 + sort_keys 稳定顺序
print(json.dumps(data, indent=2, sort_keys=True))

# separators 生成最紧凑输出，减小体积
print(json.dumps(data, separators=(",", ":")))
# {"b":2,"name":"Alice","scores":[90,85,78]}
```

`ensure_ascii`（默认 `True`）会把非 ASCII 字符转义为 `\uXXXX`，对中文很不友好：

```python
data = {"城市": "北京"}
print(json.dumps(data))                    # {"城市": "北京"}
print(json.dumps(data, ensure_ascii=False))  # {"城市": "北京"}
```

两种输出在语义上等价（都是合法 JSON，标准解析器都能还原出正确的中文），只是可读性不同。写中文配置文件、日志文件时通常设置 `ensure_ascii=False`；生成的 JSON 若要给非 UTF-8 环境的老系统使用，才保留默认转义。

## 5. `json` 无法原生序列化的类型

`json.dumps()` 只认识第 2 节表格里的基本类型，遇到其他类型抛 `TypeError`：

```python
import datetime

json.dumps({"time": datetime.datetime.now()})
# TypeError: Object of type datetime is not JSON serializable
```

常见的「不能直接序列化」的类型：

| 类型 | 现象 |
|---|---|
| `tuple` | 能序列化，但会**静默**变成 `list`（不报错，容易被忽略） |
| `set` | 直接抛 `TypeError` |
| `datetime`/`date`/`time` | 直接抛 `TypeError` |
| 自定义类实例 | 直接抛 `TypeError` |
| `bytes`、`complex`、`Decimal` | 直接抛 `TypeError` |

要序列化这些类型，需要通过 `default` 参数或自定义编码器告诉 `json` 如何把它们转换成基本类型。

## 6. 自定义编码：`default` 参数与 `JSONEncoder`

`default` 接收一个函数，遇到无法识别的对象时调用它，返回一个可被 JSON 表示的值：

```python
def custom_default(obj):
    if isinstance(obj, datetime.datetime):
        return obj.isoformat()      # 转成字符串
    if isinstance(obj, set):
        return list(obj)            # 转成列表
    raise TypeError(f"Object of type {type(obj).__name__} is not JSON serializable")

data = {"time": datetime.datetime(2026, 7, 24, 10, 0), "tags": {"a", "b"}}
print(json.dumps(data, default=custom_default, ensure_ascii=False))
# {"time": "2026-07-24T10:00:00", "tags": ["a", "b"]}
```

`default` 只对**顶层无法识别的单个对象**调用，不会递归改变已支持的类型。

对于需要复用的编码逻辑，更规范的写法是继承 `json.JSONEncoder` 并重写 `default()`：

```python
class CustomEncoder(json.JSONEncoder):
    def default(self, obj):
        if isinstance(obj, datetime.datetime):
            return {"__datetime__": obj.isoformat()}
        if isinstance(obj, Point):
            return {"__point__": True, "x": obj.x, "y": obj.y}
        return super().default(obj)   # 交给父类抛出标准 TypeError

class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

text = json.dumps({"created": datetime.datetime.now(), "pos": Point(1, 2)},
                   cls=CustomEncoder, ensure_ascii=False)
```

通过 `cls=CustomEncoder` 传入自定义编码器；在自定义类型上加类型标记（如 `"__point__": True`）是为了反序列化时能区分「普通字典」还是「需要还原的对象」。

## 7. 自定义解码：`object_hook` 与 `object_pairs_hook`

`object_hook` 在 `loads()`/`load()` 中生效，每当解析出一个 JSON object（对应 Python 字典）就调用一次：

```python
def custom_object_hook(d):
    if d.get("__point__"):
        return Point(d["x"], d["y"])
    if "__datetime__" in d:
        return datetime.datetime.fromisoformat(d["__datetime__"])
    return d   # 不是特殊标记的字典，原样返回

restored = json.loads(text, object_hook=custom_object_hook)
print(restored["pos"].x, restored["pos"].y)   # 1 2
```

`object_hook` 自底向上调用：嵌套结构中最内层的字典先被处理，再逐层向外，内层还原出的对象可直接作为外层字典的值。

`object_pairs_hook` 接收键值对列表（`[(key, value), ...]`）而非字典，适合需要拿到原始键值对序列的场景，如检测重复 key：

```python
def detect_duplicate_keys(pairs):
    keys = [k for k, v in pairs]
    if len(keys) != len(set(keys)):
        raise ValueError("发现重复的 key")
    return dict(pairs)

json.loads('{"a": 1, "a": 2}', object_pairs_hook=detect_duplicate_keys)
# ValueError: 发现重复的 key
```

若同时传入 `object_hook` 与 `object_pairs_hook`，后者优先生效。

## 8. 错误处理：`JSONDecodeError`

解析格式非法的 JSON 文本会抛出 `json.JSONDecodeError`（`ValueError` 的子类），携带三个定位属性：`lineno`（行号，从 1 起）、`colno`（列号，从 1 起）、`pos`（字符偏移，从 0 起）。

```python
bad = '{\n  "a": 1,\n  "b": 2,\n}'
try:
    json.loads(bad)
except json.JSONDecodeError as e:
    print(f"第 {e.lineno} 行第 {e.colno} 列出错：{e.msg}")
```

常见触发原因：

| 错误写法 | 说明 |
|---|---|
| `{'a': 1}` | 用单引号代替双引号，JSON 规范只认双引号字符串 |
| `{"a": 1,}` | 末尾多余的逗号（trailing comma），JSON 不允许 |
| `{"a": 1} // 注释` | JSON 不支持注释，标准解析器直接报错 |
| `{"a": 1` | 括号不匹配，缺少收尾的 `}` |
| `{"a": NaN}` | 严格 JSON 不支持 `NaN`（见第 9 节，Python 默认放宽了限制） |
| `''`（空字符串） | 抛 `Expecting value`，`pos` 指向 0 |

## 9. 数字精度与特殊值

JSON 规范本身只有一种 `number` 类型，不区分整数和浮点数；Python 根据文本形式（有无小数点/指数）决定还原成 `int` 还是 `float`：

```python
print(json.loads("10"))     # 10，int
print(json.loads("10.0"))   # 10.0，float
print(json.loads("1e3"))    # 1000.0，float（科学计数法一律是 float）
```

Python 的 `int` 是任意精度的，超大整数可无损往返；但浮点数存在标准的二进制精度问题，与 JSON 本身无关：

```python
big = 12345678901234567890
print(json.loads(json.dumps(big)) == big)   # True
print(json.dumps(0.1 + 0.2))                 # 0.30000000000000004
```

`parse_float`/`parse_int` 可自定义数字解析方式，例如把小数统一解析为 `Decimal` 避免精度丢失：

```python
from decimal import Decimal

data = json.loads('{"price": 19.99}', parse_float=Decimal)
print(data["price"], type(data["price"]))   # 19.99 <class 'decimal.Decimal'>
```

标准 JSON 不允许 `NaN`、`Infinity`、`-Infinity`，但 Python 的 `json` 默认**放宽**了这一限制（非标准行为，与其他语言的解析器交互时可能不兼容）：

```python
print(json.dumps(float("nan")))   # NaN
print(json.dumps(float("inf")))   # Infinity
print(json.loads("NaN"))           # nan
```

需要严格模式时可传 `allow_nan=False`：

```python
json.dumps(float("nan"), allow_nan=False)
# ValueError: Out of range float values are not JSON compliant
```

## 10. 嵌套结构与美化输出

复杂配置常是多层嵌套的字典和列表，`indent` 配合 `sort_keys` 能生成结构清晰、便于人工检查的文本：

```python
config = {
    "database": {"host": "localhost", "port": 5432, "options": {"ssl": True}},
    "servers": [{"name": "web1", "ip": "10.0.0.1"}, {"name": "web2", "ip": "10.0.0.2"}],
}
print(json.dumps(config, indent=2, sort_keys=True, ensure_ascii=False))
```

`pprint.pprint()` 也能打印嵌套结构，但输出的是 Python 字面量语法（单引号字符串、`True`/`None`），不是合法 JSON：`json.dumps(indent=2)` 用于生成/展示可交换的数据格式，`pprint` 只用于调试时在终端查看 Python 对象。

## 11. 安全性：为什么 `json` 比 `pickle`/`eval` 更安全

`json.loads()` 解析的是纯数据格式，过程**不会执行任何代码**，即使输入来自不可信来源，最坏情况也只是解析失败或得到非预期的数据结构。相比之下，`eval()` 会把字符串当 Python 表达式执行；`pickle.loads()` 反序列化时可以触发对象的 `__reduce__` 方法，恶意构造的数据可以在反序列化阶段执行任意代码。

| 方式 | 能否执行任意代码 | 适用场景 |
|---|---|---|
| `json.loads()` | 否 | 跨语言数据交换、不可信输入 |
| `eval()` | 是 | 几乎不应用于反序列化 |
| `pickle.loads()` | 是 | 仅限完全信任的内部数据（如自己写的缓存文件） |

处理外部输入（HTTP 请求体、用户上传的配置文件等）时应优先选择 `json`，只在数据完全可信、且需要保存 Python 特有对象时才考虑 `pickle`。

## 12. 本节小结

1. `dumps`/`loads` 处理字符串，`dump`/`load` 直接读写文件对象，二者接口用法一致；
2. Python 与 JSON 的类型有明确映射，但 `tuple` 会静默变成 `list`，`dict` 的 key 会被强制转成字符串；
3. 写中文数据时用 `ensure_ascii=False` 保持可读，格式化输出用 `indent`，需要稳定顺序用 `sort_keys=True`；
4. `set`、`datetime`、自定义对象无法直接序列化，需要 `default` 参数或子类化 `JSONEncoder`；反序列化对应用 `object_hook`/`object_pairs_hook` 还原；
5. 排查 `JSONDecodeError` 时利用 `e.lineno`/`e.colno`/`e.pos` 快速定位问题（常见于单引号、末尾逗号、注释、括号不匹配）；
6. `json.loads()` 不会执行任意代码，处理不可信输入应优先于 `eval()`/`pickle`。
