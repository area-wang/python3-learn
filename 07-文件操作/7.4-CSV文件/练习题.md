## 一、概念题

3. `csv.reader` 读出的每一行是什么类型？其中的元素又是什么类型？和直觉上「数字列应该是数字」有什么冲突？
4. `quoting` 参数的四种取值（`QUOTE_MINIMAL`/`QUOTE_ALL`/`QUOTE_NONNUMERIC`/`QUOTE_NONE`）分别在什么场景下使用？

9. 字段内容中如果本身包含引号字符（`"`），CSV 是如何转义的？`csv` 模块读写时是怎么处理这种转义的？

## 二、判断代码输出

### 1. 忘记 `newline=""` 会怎样

```python
import csv

with open("demo.csv", "w", encoding="utf-8") as f:   # 注意：没有 newline=""
    writer = csv.writer(f)
    writer.writerow(["a", "b"])
    writer.writerow(["c", "d"])

with open("demo.csv", encoding="utf-8", newline="") as f:
    print(f.read())
```

在 Windows 上和在 macOS/Linux 上运行，输出的换行情况是否一致？解释原因。

### 2. `DictReader` 的 `restkey`/`restval`

```python
import csv
import io

data = "a,b,c\n1,2,3,4,5\n6,7\n"
reader = csv.DictReader(io.StringIO(data), restkey="extra", restval="?")
for row in reader:
    print(row)
```

写出两行的输出结果，说明多出的字段和缺失的字段分别被如何处理。

### 3. 类型不转换的陷阱

```python
import csv
import io

data = "price,qty\n3,2\n"
reader = csv.DictReader(io.StringIO(data))
for row in reader:
    print(row["price"] * row["qty"])
```

预言这段代码的实际行为（是报错还是产生某种「看起来合理但错误」的结果），并解释原因。

### 4. `QUOTE_NONNUMERIC` 的效果

```python
import csv
import io

buf = io.StringIO()
writer = csv.writer(buf, quoting=csv.QUOTE_NONNUMERIC)
writer.writerow(["name", 18, 92.5])
print(buf.getvalue())

buf.seek(0)
reader = csv.reader(buf, quoting=csv.QUOTE_NONNUMERIC)
print(next(reader))
```

写出输出，并说明哪些字段被加了引号、读回时各个值分别是什么类型。

## 三、编程题

### 1. 安全的 CSV 读取器

编写 `read_csv_safe(path)`：

- 尝试用 `utf-8-sig` 读取，兼容有无 BOM 的情况；
- 用 `DictReader` 解析，返回 `list[dict]`；
- 若某一行列数与表头不一致，用 `restkey`/`restval` 兜底，不能让程序崩溃；
- 文件不存在时给出清晰的错误提示。

### 2. 类型化加载器

编写 `load_typed_rows(path, schema)`，其中 `schema` 是形如 `{"price": float, "qty": int, "order_date": "date"}` 的字典：

- 用 `DictReader` 读取原始行（全部是字符串）；
- 按 `schema` 对指定列做类型转换（`"date"` 用 `datetime.strptime(value, "%Y-%m-%d")`）；
- 转换失败时记录这一行的原始内容与错误信息，跳过该行继续处理其余行；
- 返回 `(成功转换的行列表, 失败记录列表)`。

### 3. 字典写出器

编写 `write_dict_rows(path, rows, fieldnames)`：

- 用 `DictWriter` 写出，`writeheader()` 只调用一次；
- 对 `rows` 中出现的、不在 `fieldnames` 内的多余键采取忽略而不是报错的策略；
- 对缺少某些 `fieldnames` 键的行，先补齐默认值（如 `""`）再写入，避免 `ValueError`；
- 写出时正确处理 `newline=""`。

### 4. 方言探测与统一转换

编写 `normalize_csv(src_path, dst_path)`：

- 用 `csv.Sniffer` 探测 `src_path` 的分隔符与是否有表头；
- 无论原分隔符是逗号、分号还是制表符，统一转换成标准逗号分隔、`QUOTE_MINIMAL`、UTF-8（无 BOM）格式写入 `dst_path`；
- 若探测失败（样本太短或格式混乱），退回默认假设「逗号分隔、有表头」，并打印一条警告。

## 四、综合实践：多来源销售数据合并

某公司从三个不同渠道导出销售记录 CSV，格式并不统一：

- `store_a.csv`：UTF-8 编码，逗号分隔，列名为 `姓名,商品,单价,数量,日期`；
- `store_b.csv`：Excel 导出，带 UTF-8 BOM，分号分隔，列名为 `name;item;price;qty;date`；
- `store_c.csv`：没有表头，纯逗号分隔，列顺序固定为「姓名、商品、单价、数量、日期」。

要求实现一个合并脚本，完成以下步骤：

1. 对每个文件先做编码与方言探测（结合 BOM 判断与 `csv.Sniffer`），确定正确的 `encoding`、`delimiter`、是否有表头；
2. 分别用合适的方式（`DictReader` 或手动指定 `fieldnames`）读取三个文件，统一映射成同一套内部字段名（如 `name`/`item`/`price`/`qty`/`date`）；
3. 对 `price` 转 `float`、`qty` 转 `int`、`date` 转 `datetime.date`，转换失败的行单独收集，不能让整个流程中断；
4. 合并三份数据，按 `date` 升序排序；
5. 计算每个商品的销售总额（`price * qty` 求和），按总额降序输出前 5 名；
6. 用 `DictWriter` 把合并后的完整数据写出到 `merged.csv`，统一使用逗号分隔、UTF-8（无 BOM）、标准表头顺序；
7. 单独把转换失败的记录写到 `errors.csv`，附带来源文件名与失败原因，便于人工核查。
