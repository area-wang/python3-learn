# 7.4 CSV文件

CSV（Comma-Separated Values，逗号分隔值）是最常见的表格类文本格式，Excel、数据库、日志系统都能导入导出它。它看起来只是「逗号分隔的文本行」，但字段里出现逗号、换行、引号时，情况远比想象复杂。Python 标准库 `csv` 模块专门处理这些细节，本节介绍它的读写、方言（dialect）、`DictReader`/`DictWriter`、编码与嗅探等实用技巧。

## 1. 为什么不能用 `split(",")` 解析 CSV

直觉的做法是逐行 `line.split(",")`，但这在真实数据面前很快失效：

```python
line = '张三,"北京市, 朝阳区",28'
print(line.split(","))
# ['张三', '"北京市', ' 朝阳区"', '28']   —— 字段被错误拆成 4 份
```

CSV 规范（RFC 4180，Python 的 `csv` 模块是其超集实现）用引号包裹含有分隔符、换行符的字段，并用「双写引号」转义字段内部的引号：

```text
张三,"北京市, 朝阳区",28
李四,"他说：""你好""",30
"多行\n地址",...
```

`split(",")` 完全不理解引号语义，遇到下面这些情况都会出错：

- 字段内部包含分隔符（逗号）；
- 字段内部包含换行符（导致一条记录跨多行文本）；
- 字段内部包含引号本身（需要双写转义 `""`）；
- 不同系统/软件导出的分隔符不一致（逗号、分号、制表符）。

`csv` 模块内置了一个小型状态机来正确处理引号、转义与跨行字段，这是坚持使用它而不是手写字符串处理的根本原因。

## 2. `csv.reader`：基础读取

```python
import csv

with open("users.csv", encoding="utf-8", newline="") as f:
    reader = csv.reader(f)
    header = next(reader)          # 手动取出表头，csv 不会自动识别表头
    for row in reader:
        print(row)                 # 每行是一个 list[str]
        name, age = row[0], row[1]
        print(name, int(age))      # 需要手动转换类型
```

关键点：

- `reader` 是一个惰性迭代器，每次迭代产生一个 `list`，元素全部是 `str`，**没有任何类型转换**，哪怕看起来是数字；
- 必须显式 `header = next(reader)` 跳过表头（如果有），`csv` 不会自动识别表头；
- 空行会被解析成空列表 `[]`，遍历时要留意。

### 2.1 为什么必须 `newline=""`

`csv` 模块文档明确要求：打开文件用于 `csv.reader`/`csv.writer` 时，`open()` 必须传 `newline=""`。原因是 CSV 字段内部可能嵌入换行符（引号包裹的多行字段），如果文本模式按默认 `newline=None` 做「通用换行归一化」，`\r\n` 会被提前转换成 `\n`，`csv` 模块自己内部又要按规范处理行结束符，两边各转换一次会导致换行符被重复处理或丢失（尤其在 Windows 上生成的 `\r\n` 文件）。

```python
# 错误：容易在 Windows 生成的 CSV 上出现多余空行或换行错乱
with open("data.csv", encoding="utf-8") as f:
    reader = csv.reader(f)

# 正确：交给 csv 模块自己处理换行
with open("data.csv", encoding="utf-8", newline="") as f:
    reader = csv.reader(f)
```

## 3. `csv.writer`：基础写入

```python
import csv

with open("out.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["姓名", "城市", "年龄"])           # 写一行
    writer.writerows([                                  # 写多行
        ["张三", "北京市, 朝阳区", 28],
        ["李四", '他说："你好"', 30],
    ])
```

生成的文件内容：

```text
姓名,城市,年龄
张三,"北京市, 朝阳区",28
李四,"他说：""你好""",30
```

- `writerow(row)` 写一行，`row` 是任意可迭代对象（`list`/`tuple`），非字符串元素会自动 `str()` 化；
- `writerows(rows)` 写多行，本质是循环调用 `writerow`；
- 字段中包含分隔符、引号、换行符时，`writer` 会自动加引号并转义，无需手工处理；
- 写入同样要求 `open(..., "w", newline="")`：这次是为了避免 `csv` 模块写出的 `\r\n`（`csv` 默认方言的行结束符）再被文本模式的换行转换叠加一次，导致 Windows 上出现每行之间多一个空行。这是新手最常踩的坑。

```python
# 常见错误现场：Windows 上每两行之间多一个空白行
with open("out.csv", "w", encoding="utf-8") as f:   # 漏了 newline=""
    writer = csv.writer(f)
    writer.writerow(["a", "b"])
    writer.writerow(["c", "d"])
```

## 4. 方言（Dialect）与格式化参数

`reader`/`writer` 可以传入一组格式化参数，控制如何切分/拼接字段：

```python
csv.reader(csvfile, dialect='excel', **fmtparams)
csv.writer(csvfile, dialect='excel', **fmtparams)
```

| 参数 | 说明 | 默认值 |
|---|---|---|
| `delimiter` | 字段分隔符 | `,` |
| `quotechar` | 引号字符，用于包裹含特殊字符的字段 | `"` |
| `quoting` | 加引号策略，见下表 | `QUOTE_MINIMAL` |
| `escapechar` | 转义字符，`quoting=QUOTE_NONE` 时用它转义分隔符 | `None` |
| `lineterminator` | **写入**时使用的行结束符（读取时 `csv` 自动识别多种换行，此参数不影响读取） | `\r\n` |
| `skipinitialspace` | 分隔符后的空白是否忽略 | `False` |
| `doublequote` | 字段内引号是否用双写 `""` 转义（`False` 则需配合 `escapechar`） | `True` |

`quoting` 的四种取值：

| 取值 | 含义 |
|---|---|
| `csv.QUOTE_MINIMAL` | 只对包含分隔符、引号、换行符的字段加引号（默认，最常用） |
| `csv.QUOTE_ALL` | 无条件给所有字段加引号 |
| `csv.QUOTE_NONNUMERIC` | 非数字字段加引号；配合 reader 使用时会把未加引号的字段自动转换成 `float` |
| `csv.QUOTE_NONE` | 从不加引号，遇到特殊字符要用 `escapechar` 转义，否则写入时抛 `csv.Error` |

```python
# 使用分号分隔（欧洲常见导出习惯），并对所有字段加引号
with open("euro.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.writer(f, delimiter=";", quoting=csv.QUOTE_ALL)
    writer.writerow(["name", "city"])
    writer.writerow(["张三", "北京"])
```

```text
"name";"city"
"张三";"北京"
```

`QUOTE_NONNUMERIC` 配合 reader 使用可以省去手工 `float()` 转换：未加引号的字段会自动转换成 `float`，加了引号的字段仍保持 `str`。

## 5. 内置方言与自定义方言

`csv` 内置两种方言：

| 方言 | 说明 |
|---|---|
| `csv.excel` | 默认方言，逗号分隔，`\r\n` 行结束符，兼容 Excel 导出的 CSV |
| `csv.excel_tab` | 与 `excel` 相同，但分隔符是制表符 `\t` |

可以通过 `csv.register_dialect` 注册一个可复用的自定义方言：

```python
csv.register_dialect(
    "pipe",
    delimiter="|",
    quotechar="'",
    quoting=csv.QUOTE_MINIMAL,
    lineterminator="\n",
)

with open("data.psv", encoding="utf-8", newline="") as f:
    reader = csv.reader(f, dialect="pipe")
    for row in reader:
        print(row)

csv.unregister_dialect("pipe")     # 用完可注销
```

`csv.get_dialect(name)` 获取已注册方言对象；`csv.list_dialects()` 列出所有已注册方言名。方言本质是把一组格式化参数打包成可复用的名字，避免每次都重复传递一长串关键字参数。

## 6. `csv.DictReader`：按列名读取

`DictReader` 把每一行解析为字典（`dict`，Python 3.8+ 保留插入顺序），键来自表头行：

```python
import csv

with open("users.csv", encoding="utf-8", newline="") as f:
    reader = csv.DictReader(f)
    for row in reader:
        print(row["姓名"], row["年龄"])   # row 是 {'姓名': '张三', '年龄': '28', ...}
```

关键参数：

| 参数 | 说明 |
|---|---|
| `fieldnames` | 指定列名列表；不传则**用文件第一行**作为表头。若原文件本身没有表头，需要显式传入 `fieldnames`，否则第一条数据会被误当成表头丢失 |
| `restkey` | 当某行的列数**多于**表头列数时，多出的值会被收集成一个 `list`，存到这个键下（默认 `None` 表示丢弃） |
| `restval` | 当某行的列数**少于**表头列数时，缺失的列用这个值填充（默认 `None`） |

```python
# 原始文件没有表头，手动指定列名
with open("no_header.csv", encoding="utf-8", newline="") as f:
    reader = csv.DictReader(f, fieldnames=["name", "city", "age"])
    for row in reader:
        print(row)

# 处理列数不齐的「参差」数据
with open("ragged.csv", encoding="utf-8", newline="") as f:
    reader = csv.DictReader(f, restkey="extra", restval="")
    for row in reader:
        print(row)   # 多出的字段收进 row["extra"]，缺失的字段补 ""
```

## 7. `csv.DictWriter`：按字典写入

```python
import csv

rows = [
    {"姓名": "张三", "城市": "北京", "年龄": 28},
    {"姓名": "李四", "城市": "上海", "年龄": 30},
]

with open("out.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.DictWriter(f, fieldnames=["姓名", "城市", "年龄"])
    writer.writeheader()       # 写表头，必须显式调用，不会自动写
    writer.writerows(rows)
```

- `fieldnames` 是必传参数，决定写出列的顺序；
- `writeheader()` 需要手动调用一次，`DictWriter` 不会替你自动写表头；
- `extrasaction` 控制传入字典包含 `fieldnames` 之外多余键时的行为：

```python
# extrasaction="raise"（默认）：多余键直接报 ValueError
writer = csv.DictWriter(f, fieldnames=["姓名", "年龄"], extrasaction="raise")
writer.writerow({"姓名": "王五", "年龄": 22, "备注": "VIP"})  # 抛 ValueError

# extrasaction="ignore"：静默丢弃多余键
writer = csv.DictWriter(f, fieldnames=["姓名", "年龄"], extrasaction="ignore")
writer.writerow({"姓名": "王五", "年龄": 22, "备注": "VIP"})  # "备注" 被丢弃
```

如果字典缺少某个 `fieldnames` 中的键，`writerow` 会直接抛 `ValueError`（没有 `restval` 那样的默认值机制，这与 `DictReader` 不对称，容易混淆）。

## 8. 编码问题：BOM 与分隔符差异

### 8.1 Excel 导出的 BOM

Windows 版 Excel「另存为 CSV UTF-8」时，会在文件开头写入 UTF-8 BOM（字节 `EF BB BF`）。用普通 `utf-8` 打开会导致第一个字段名前面多出一个不可见字符：

```python
with open("excel_export.csv", encoding="utf-8", newline="") as f:
    reader = csv.DictReader(f)
    row = next(reader)
    print(list(row.keys())[0])   # '﻿姓名'，前面带了看不见的 BOM

# 正确做法：用 utf-8-sig，会自动识别并剥离 BOM
with open("excel_export.csv", encoding="utf-8-sig", newline="") as f:
    reader = csv.DictReader(f)
    row = next(reader)
    print(list(row.keys())[0])   # '姓名'，正常
```

`utf-8-sig` 兼容两种情况：文件有 BOM 会自动剥离，没有 BOM 也能正常按 UTF-8 解码，因此对「不确定来源是否带 BOM」的 CSV 文件是更安全的默认选择。

### 8.2 分隔符差异

一些欧洲语言环境（法语、德语等）的 Excel 默认导出分隔符是分号 `;`，因为逗号在这些地区被用作小数点。拿到这类文件如果直接用默认 `delimiter=","` 解析，会把整行当成一个字段；此时需要显式传入 `delimiter=";"`。不确定分隔符时可以先读一小段样本人工判断，或使用第 9 节的 `Sniffer` 自动检测。

## 9. `csv.Sniffer`：自动嗅探格式

`Sniffer` 通过分析一段样本文本，猜测分隔符、引号字符等方言参数，也能判断首行是否为表头：

```python
import csv

with open("unknown.csv", encoding="utf-8-sig", newline="") as f:
    sample = f.read(2048)          # 取一段样本
    f.seek(0)

    sniffer = csv.Sniffer()
    dialect = sniffer.sniff(sample)              # 猜测方言
    has_header = sniffer.has_header(sample)      # 猜测是否有表头

    reader = csv.reader(f, dialect=dialect)
    if has_header:
        next(reader)              # 跳过表头
    for row in reader:
        print(row)
```

`sniff()` 依赖统计规律，样本太短、字段值高度相似、或分隔符本身混杂在字段内容中时可能误判，因此：

- 样本尽量覆盖多行（含表头和若干数据行），而不是只取一行；
- 猜测结果建议做一次合理性检查（比如列数是否稳定）后再大规模应用；
- 生产环境更可靠的做法是让上游明确约定格式，把嗅探仅作为兜底或一次性探索手段。

## 10. 类型转换：一切都是字符串

无论 `reader` 还是 `DictReader`（`QUOTE_NONNUMERIC` 除外），读出来的值全部是 `str`，这是最容易踩的坑，需要手工转换：

```python
from datetime import datetime

with open("orders.csv", encoding="utf-8", newline="") as f:
    reader = csv.DictReader(f)
    for row in reader:
        # row["单价"] * row["数量"] 是字符串运算，不是乘法，必须先转换：
        price = float(row["单价"])
        qty = int(row["数量"])
        total = price * qty
        order_date = datetime.strptime(row["下单日期"], "%Y-%m-%d")
```

常见的错误示范是 `"3" * "2"`——两个字符串相乘会直接抛 `TypeError: can't multiply sequence by non-int of type 'str'`；如果不小心写成 `int(row["数量"]) * row["单价"]`（只转换了一个），则会得到字符串被重复若干次的意外结果，而不是报错，排查起来更隐蔽。

## 11. 大文件与性能

`csv.reader`/`DictReader` 本身是惰性迭代器，逐行产出，不会一次性把整个文件读入内存，适合处理体积较大的 CSV：

```python
total = 0
with open("big.csv", encoding="utf-8", newline="") as f:
    reader = csv.reader(f)
    next(reader)               # 跳过表头
    for row in reader:
        total += float(row[2])
print(total)
```

要避免的反模式是先 `list(csv.reader(f))` 或先 `f.readlines()` 再解析，这会把全部数据一次性驻留内存。如果需要做统计分析、分组聚合、多表关联等较重的数据处理，通常改用 `pandas.read_csv()`：它底层用 C 实现解析、支持分块读取（`chunksize`）、类型推断和向量化运算，比手写 `csv` 循环快得多，但引入了额外依赖，简单的逐行处理场景仍优先用标准库 `csv` 模块。

## 12. 常见异常与坑

| 异常/现象 | 触发场景 |
|---|---|
| `csv.Error` | `csv` 模块内部错误的基类，如 `QUOTE_NONE` 模式下字段包含分隔符又没提供 `escapechar` |
| `csv.Error: field larger than field limit` | 单个字段超过 `csv.field_size_limit()` 默认值（131072），需要用 `csv.field_size_limit(new_limit)` 调大 |
| `ValueError`（`DictWriter`） | `extrasaction="raise"` 时字典包含 `fieldnames` 之外的键 |
| 每行之间多一空行（Windows） | 写入时忘记 `newline=""` |
| 字段前带 `﻿` | Excel 导出的 UTF-8 BOM，未用 `utf-8-sig` 解码 |
| 行被错误拆分/合并 | 用 `split(",")` 手写解析而非 `csv` 模块 |
| 列数不一致 | 每行字段数不同（「参差」数据），`reader` 直接返回不等长的 `list`，`DictReader` 需要 `restkey`/`restval` 处理 |

字段本身包含引号字符时，`csv` 默认用「双写引号」转义（`doublequote=True`）：

```python
with open("quote_demo.csv", "w", encoding="utf-8", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(['他说："你好"'])
# 写出：  "他说：""你好"""

with open("quote_demo.csv", encoding="utf-8", newline="") as f:
    reader = csv.reader(f)
    print(next(reader))   # ['他说："你好"']  —— 读回时自动还原
```

## 13. 本节小结

1. CSV 看似简单，实际涉及引号、转义、跨行字段等规则，不要用 `split(",")` 手写解析，优先用 `csv` 模块；
2. 无论读还是写 CSV，都要给 `open()` 传 `newline=""`，把换行处理完全交给 `csv` 模块，避免 Windows 下的空行/换行错乱；
3. `reader`/`writer` 处理 `list`，`DictReader`/`DictWriter` 处理 `dict`，后者需要显式管理 `fieldnames`、`writeheader()`、`restkey`/`restval`、`extrasaction`；
4. `csv` 读出的所有字段都是 `str`（`QUOTE_NONNUMERIC` 除外），数值、日期都需要手工转换，这是最常见的隐蔽 bug 来源；
5. 拿到来源不明的 CSV 时，优先考虑 BOM（用 `utf-8-sig`）和分隔符差异（用 `csv.Sniffer` 辅助判断），不要假设一定是逗号分隔的纯 UTF-8；
6. 大文件坚持逐行迭代而非整体读入；数据分析场景更适合上升到 `pandas.read_csv`。
