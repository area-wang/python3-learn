# 7.2 上下文管理器

`with` 语句是 Python 管理资源的标准方式。它把「申请资源—使用—释放资源」三步打包，让清理代码一定会执行，即使中间抛异常也不会漏掉关闭文件。本节聚焦文件场景，并扩展到自实现上下文管理器。

## 1. 为什么需要 `with`

不用 `with` 的写法：

```python
f = open("data.txt", encoding="utf-8")
try:
    text = f.read()
finally:
    f.close()
```

`finally` 必须手写，而且一旦忘了，资源就泄漏。`with` 把这套结构自动化：

```python
with open("data.txt", encoding="utf-8") as f:
    text = f.read()
# 离开 with 块时自动调用 f.close()
```

`with` 的价值：

- 资源释放由语法保证，不依赖开发者自觉；
- 异常路径也会执行清理；
- 缩进明确标示资源存活区间，可读性更好；
- 同时管理多个资源时不易写错顺序。

## 2. `with` 的执行协议

`with` 语句结构：

```python
with expression as var:
    body
```

执行流程：

1. 求值 `expression`，得到上下文管理器对象 `mgr`；
2. 调用 `mgr.__enter__()`，把返回值绑定到 `var`；
3. 执行 `body`；
4. 不论是否抛异常，都调用 `mgr.__exit__(exc_type, exc_val, exc_tb)`；
5. 如果 `__exit__` 返回真值，则吞掉 `body` 抛出的异常；返回假值时异常继续向外传播。

`as var` 可以省略：当 `__enter__()` 的返回值不需要使用时（如只用作资源保护）。

## 3. 文件对象的 `with` 行为

文件对象实现了上下文管理协议：`__enter__` 返回文件对象自身，`__exit__` 调用 `close()`。

```python
with open("x.txt", encoding="utf-8") as f:
    print(f.read())     # 在块内使用
print(f.closed)         # True，离开块后已关闭
```

`with` 块结束后的文件对象仍然存在，但它处于 `closed` 状态。尝试继续读写会抛 `ValueError: I/O operation on closed file`。

## 4. 同时管理多个资源

```python
with open("in.txt", encoding="utf-8") as src, open("out.txt", "w", encoding="utf-8") as dst:
    dst.write(src.read())
```

多个 `with` 写在一行可读性差，超过两个时推荐嵌套或多用 `contextlib.ExitStack`（第 8 节）：

```python
# 嵌套写法
with open("in.txt", encoding="utf-8") as src:
    with open("out.txt", "w", encoding="utf-8") as dst:
        for line in src:
            dst.write(line)
```

资源关闭顺序与打开顺序相反（先进后出），这对依赖关系很重要——例如先关数据文件再关日志文件可能造成信息残留。

## 5. 自实现上下文管理器

### 5.1 实现协议

```python
class ManagedFile:
    def __init__(self, path, mode="r", encoding="utf-8"):
        self.path = path
        self.mode = mode
        self.encoding = encoding
        self.file = None

    def __enter__(self):
        self.file = open(self.path, self.mode, encoding=self.encoding)
        return self.file

    def __exit__(self, exc_type, exc_val, exc_tb):
        if self.file is not None:
            self.file.close()
        # 返回 None/False，异常正常传播
        return False
```

使用：

```python
with ManagedFile("data.txt") as f:
    f.read()
```

### 5.2 决定是否吞掉异常

`__exit__` 返回真值时会吞掉 `body` 抛出的异常。绝大多数资源管理器不应吞异常，应返回 `False` 或 `None`，让真实问题暴露出来。

```python
def __exit__(self, exc_type, exc_val, exc_tb):
    self.file.close()
    if exc_type is not None:
        print(f"捕获到异常：{exc_val}")  # 仅记录，不吞
    return False
```

只在确有理由抑制特定异常时才返回 `True`（如使用 `contextlib.suppress`）。

## 6. `contextlib.contextmanager` 装饰器

把一个生成器函数转成上下文管理器，是更简洁的写法：

```python
from contextlib import contextmanager

@contextmanager
def open_managed(path, mode="r", encoding="utf-8"):
    f = open(path, mode, encoding=encoding)
    try:
        yield f          # with 块内的 as 变量得到 f
    finally:
        f.close()
```

使用方式与类版完全一致：

```python
with open_managed("data.txt") as f:
    f.read()
```

关键点：

- `yield` 之前的代码对应 `__enter__`；
- `yield` 的值绑定到 `as` 变量；
- `yield` 之后的代码对应 `__exit__`，写进 `finally` 保证一定执行；
- 若 `with` 块内抛异常，会在 `yield` 处被重新抛出，可被 `try/except` 捕获决定是否吞掉。

```python
@contextmanager
def safe_open(path, encoding="utf-8"):
    try:
        f = open(path, encoding=encoding)
    except FileNotFoundError:
        print(f"{path} 不存在")
        raise
    try:
        yield f
    finally:
        f.close()
```

## 7. `contextlib` 常用工具

### 7.1 `closing`

为只有 `close()` 方法、未实现协议的对象提供上下文管理：

```python
from contextlib import closing
import urllib.request

with closing(urllib.request.urlopen("http://example.com")) as resp:
    data = resp.read()
```

### 7.2 `suppress`

吞掉指定异常，等价于「什么都不做」的 `try/except`：

```python
from contextlib import suppress

with suppress(FileNotFoundError):
    os.remove("maybe.txt")   # 不存在也不报错
```

### 7.3 `redirect_stdout` / `redirect_stderr` / `redirect_stdin`

临时重定向标准流，常用于测试与日志捕获：

```python
from contextlib import redirect_stdout
import io

buf = io.StringIO()
with redirect_stdout(buf):
    print("被重定向")
print(buf.getvalue())      # 被重定向\n
```

### 7.4 `nullcontext`

什么都不做的占位上下文管理器。常用于「条件化开启上下文」：

```python
from contextlib import nullcontext

cm = open("log.txt", "a") if debug else nullcontext()
with cm as f:
    if f is not None:
        f.write("...")
```

### 7.5 `redirect_log` 与 `AbstractContextManager`

`contextlib.AbstractContextManager` 可作为基类，只需实现 `__enter__` 或 `__exit__` 之一即可使用 `with`，另一个默认返回 `self`/`None`。

## 8. `ExitStack`：动态组合资源

`ExitStack` 用于在运行时才知道需要开几个资源的场景，并按入栈相反顺序清理。

```python
from contextlib import ExitStack

files = ["a.txt", "b.txt", "c.txt"]
with ExitStack() as stack:
    handles = [stack.enter_context(open(f, encoding="utf-8")) for f in files]
    for h in handles:
        process(h)
# 三个文件按 c → b → a 顺序关闭
```

`stack.callback(fn, *args)` 注册普通清理函数；`stack.push(cm)` 压入上下文管理器或 `(exit_func)`；`stack.close()` 立即触发全部清理。也可用于「条件化 with」：

```python
with ExitStack() as stack:
    src = stack.enter_context(open("in.txt", encoding="utf-8"))
    if needs_output:
        dst = stack.enter_context(open("out.txt", "w", encoding="utf-8"))
    else:
        dst = nullcontext()
```

## 9. 异步上下文管理器

异步代码使用 `async with`，对应实现 `__aenter__` 与 `__aexit__`：

```python
class AsyncFile:
    async def __aenter__(self):
        # 异步打开
        return self

    async def __aexit__(self, exc_type, exc_val, exc_tb):
        await self.close()
        return False
```

`contextlib.asynccontextmanager` 是异步版本，用法与同步版对称。文件对象本身不支持 `async with`，异步 I/O 通常使用 `aiofiles` 等库。

## 10. 常见陷阱

- `with open(...) as f` 之后仍保留 `f`，但已是关闭状态；
- 把 `__exit__` 的异常参数当成普通的 `except` 处理对象，混淆了「进入 `__exit__`」与「捕获异常」；
- 在生成器式上下文管理器中忘记 `try/finally`，导致 `with` 块异常时 `yield` 之后的清理不执行；
- `as var` 省略后想用文件对象——此时拿不到引用；
- 嵌套 `with` 时资源打开与关闭顺序相反，依赖关系反了可能造成数据丢失。

## 11. 文件场景最佳实践

- 任何 `open()` 都包在 `with` 中，禁止裸 `open` 后手工 `close`；
- 多个文件先开时，依赖者后打开（先开的先关，避免半成品依赖）；
- 资源对象如果只是借出来用，且不归你管理，避免在 `__exit__` 中关闭它；
- 需要原子写时，在 `with` 中写临时文件，退出时再 `os.replace()`（详见 7.10）；
- 把文件相关的「打开—处理—关闭」整体放进一个上下文管理器函数，封装业务而非裸 `open`。

## 12. 本节小结

1. `with` 把资源清理语法化，离开块时一定会执行 `__exit__`，异常路径也覆盖；
2. 自定义上下文管理器有两条路：实现协议（`__enter__`/`__exit__`）或用 `@contextmanager` 装饰生成器；
3. `__exit__` 默认不吞异常，绝大多数资源管理器应当让它传播；
4. 多个资源用嵌套 `with` 或 `ExitStack`，关闭顺序与打开相反；
5. `contextlib` 提供了 `closing`/`suppress`/`redirect_*`/`nullcontext` 等常用工具；
6. 异步场景使用 `async with` 与 `@asynccontextmanager`，文件 I/O 用 `aiofiles`。
