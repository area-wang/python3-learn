# 7.3 文件路径

文件路径是文件读写的第一步——在真正 `open()` 一个文件之前，程序往往先要拼接、拆解、规范化路径字符串。Python 提供了两套路径处理方案：历史悠久的 `os.path`（面向字符串）和更现代的 `pathlib`（面向对象）。本节讲清楚二者的能力边界、常用 API，以及跨平台写路径代码时的坑。

## 1. `os.path` 与 `pathlib`：两种思路

`os.path` 把路径当作普通字符串处理，所有函数接收字符串、返回字符串，历史上一直是标准做法：

```python
import os.path

full = os.path.join("data", "2026", "report.csv")
print(full)          # data/2026/report.csv（POSIX）或 data\2026\report.csv（Windows）
```

`pathlib`（3.4+）把路径包装成 `Path` 对象，路径操作变成对象的属性和方法，代码更直观：

```python
from pathlib import Path

full = Path("data") / "2026" / "report.csv"
print(full)           # data/2026/report.csv
```

如何选择：

| 场景 | 推荐 |
|---|---|
| 新代码、需要频繁做路径运算（取父目录、拼子路径、改后缀） | `pathlib` |
| 需要与只接受字符串路径的老 API/第三方库对接 | `os.path`，或 `str(path_obj)` 转换 |
| 只是简单判断文件是否存在等一次性操作 | 两者皆可，`os.path.exists()` 更短 |
| 需要遍历目录树、按通配符查找文件 | `pathlib` 的 `glob`/`rglob` 更简洁 |

两者并不互斥：`Path` 对象可以直接传给 `open()`、`os.path.exists()` 等接受路径的函数；`os.fspath(path)` 可以把 `Path` 转成字符串。混用没有问题，但同一个模块内部风格应保持一致，避免忽而字符串拼接、忽而 `Path` 运算。

## 2. `os.path` 常用函数

```python
import os.path

p = "/home/user/data/report.2026.csv"
```

| 函数 | 作用 | 示例结果 |
|---|---|---|
| `os.path.join(*parts)` | 按平台分隔符拼接路径 | `join("a", "b")` → `"a/b"` |
| `os.path.split(p)` | 拆成 `(目录, 文件名)` | `("/home/user/data", "report.2026.csv")` |
| `os.path.splitext(p)` | 拆成 `(不含扩展名部分, 扩展名)` | `(".../report.2026", ".csv")` |
| `os.path.basename(p)` | 取文件名部分 | `"report.2026.csv"` |
| `os.path.dirname(p)` | 取目录部分 | `"/home/user/data"` |
| `os.path.abspath(p)` | 转成绝对路径（基于当前工作目录） | `"/home/user/data/..."` |
| `os.path.relpath(p, start)` | 计算相对路径 | `relpath(p, "/home")` → `"user/data/report.2026.csv"` |
| `os.path.normpath(p)` | 规范化路径，折叠 `..`、`.`、多余分隔符 | `normpath("a//b/../c")` → `"a/c"` |
| `os.path.exists(p)` | 路径是否存在（文件或目录） | `True`/`False` |
| `os.path.isfile(p)` | 是否为普通文件 | `True`/`False` |
| `os.path.isdir(p)` | 是否为目录 | `True`/`False` |
| `os.path.isabs(p)` | 是否为绝对路径 | `True`/`False` |
| `os.path.getsize(p)` | 文件大小（字节） | `1024` |
| `os.path.getmtime(p)` | 最后修改时间（时间戳） | `1753267200.0` |
| `os.path.expanduser(p)` | 展开 `~` 为家目录 | `expanduser("~/x")` → `"/home/user/x"` |
| `os.path.expandvars(p)` | 展开环境变量 | `expandvars("$HOME/x")` → `"/home/user/x"` |

```python
import os.path

path = os.path.join("logs", "2026", "app.log")
if os.path.exists(path):
    size = os.path.getsize(path)
    print(f"{path} 大小 {size} 字节")

name, ext = os.path.splitext("archive.tar.gz")
print(name, ext)      # archive.tar .gz（注意只拆最后一段，.tar 仍在 name 里）
```

`getsize`/`getmtime` 在路径不存在时抛 `FileNotFoundError`，调用前应先 `exists()` 判断，或用 `try/except` 兜底。

## 3. 跨平台分隔符与拼接陷阱

不同系统的路径分隔符不同：POSIX（Linux/macOS）用 `/`，Windows 用 `\`。`os.sep` 保存当前平台的分隔符：

```python
import os
print(os.sep)       # Linux/macOS: '/'；Windows: '\\'
```

**永远不要手写字符串拼接路径**：

```python
# 错误示范：硬编码分隔符，Windows 下会得到混合路径
bad = "data" + "/" + "2026" + "/" + "report.csv"

# 正确：交给 os.path.join 或 pathlib 处理平台差异
good = os.path.join("data", "2026", "report.csv")
```

`os.path.join` 还有一个容易踩的坑：只要某一段是绝对路径，前面的部分会被丢弃：

```python
os.path.join("a", "/b", "c")   # 结果是 '/b/c'，'a' 被丢弃
```

这在拼接用户输入的路径片段时尤其危险——如果用户传入以 `/` 开头的字符串，会意外替换掉预期的根目录。

## 4. `pathlib.Path` 基础

`Path` 用 `/` 运算符重载来拼接路径，可读性远高于字符串拼接：

```python
from pathlib import Path

p = Path("data") / "2026" / "report.csv"
print(p)                      # data/2026/report.csv
print(type(p))                # <class 'pathlib.PosixPath'>（Windows 上是 WindowsPath）
```

`pathlib` 区分「纯路径」和「具体路径」两个层级：

| 类型 | 说明 |
|---|---|
| `PurePath` / `PurePosixPath` / `PureWindowsPath` | 只做字符串层面的路径运算，不触碰文件系统，可在任意平台构造任意风格的路径 |
| `Path` | 继承自 `PurePath`，额外提供 `exists()`、`open()`、`mkdir()` 等触碰真实文件系统的方法；实例化时自动根据当前平台选择 `PosixPath` 或 `WindowsPath` |

```python
from pathlib import PureWindowsPath

# 在 Linux 上也能解析 Windows 风格路径（不需要访问真实文件）
w = PureWindowsPath("C:\\Users\\alice\\data.txt")
print(w.drive, w.name)         # C: data.txt
```

常用起点：

```python
Path.cwd()     # 当前工作目录（绝对路径）
Path.home()    # 当前用户家目录
Path(__file__) # 当前脚本文件路径（需在模块顶层获取 __file__）
```

## 5. `Path` 的属性

```python
from pathlib import Path

p = Path("/home/user/data/report.2026.tar.gz")
```

| 属性 | 含义 | 结果 |
|---|---|---|
| `p.name` | 完整文件名（含扩展名） | `"report.2026.tar.gz"` |
| `p.stem` | 去掉**最后一个**扩展名的文件名 | `"report.2026.tar"` |
| `p.suffix` | 最后一个扩展名 | `".gz"` |
| `p.suffixes` | 全部扩展名组成的列表 | `[".2026", ".tar", ".gz"]` |
| `p.parent` | 上一级目录（`Path` 对象） | `Path("/home/user/data")` |
| `p.parents` | 所有祖先目录组成的序列，索引 0 是直接父目录 | `parents[0]` → `.../data`，`parents[1]` → `.../user` |
| `p.parts` | 按分隔符拆分成的元组 | `('/', 'home', 'user', 'data', 'report.2026.tar.gz')` |
| `p.anchor` | 根/盘符部分 | `"/"`（Windows 下可能是 `"C:\\"`） |
| `p.as_posix()` | 无论平台如何都用 `/` 表示的字符串 | `"/home/user/data/report.2026.tar.gz"` |
| `p.as_uri()` | 转成 `file://` URI（要求是绝对路径） | `"file:///home/user/data/report.2026.tar.gz"` |

`stem`/`suffix` 只处理最后一段扩展名，多重扩展名（如 `.tar.gz`）需要多调用一次：

```python
p = Path("archive.tar.gz")
print(p.stem, p.suffix)          # archive.tar .gz
print(Path(p.stem).suffix)        # .tar，拿到第二层扩展名
```

## 6. `Path` 与文件系统交互

### 6.1 状态判断

```python
p = Path("data/report.csv")
p.exists()       # 路径是否存在
p.is_file()      # 是否为普通文件
p.is_dir()       # 是否为目录
p.is_symlink()   # 是否为符号链接（不会自动解析目标）
p.stat()         # 返回 os.stat_result：st_size、st_mtime、st_mode 等
```

```python
info = p.stat()
print(info.st_size, info.st_mtime)
```

### 6.2 路径规范化

```python
p = Path("./data/../data/report.csv")
print(p.resolve())    # 绝对路径，折叠 . 和 ..，并解析符号链接
print(p.absolute())   # 转绝对路径，但不解析 .. 和符号链接
```

`resolve()` 默认在路径不存在时也不报错（会尽量拼出绝对路径）；传 `strict=True` 时若路径不存在会抛 `FileNotFoundError`。

### 6.3 遍历目录

```python
p = Path("data")

for child in p.iterdir():       # 仅遍历直接子项，不递归
    print(child)

for csv_file in p.glob("*.csv"):        # 当前目录下匹配的文件
    print(csv_file)

for csv_file in p.rglob("*.csv"):       # 递归遍历所有子目录
    print(csv_file)
```

`glob`/`rglob` 支持 `*`、`**`、`?`、`[abc]` 等通配符；`p.glob("**/*.csv")` 与 `p.rglob("*.csv")` 效果等价。

### 6.4 创建、修改与删除

```python
p = Path("output/2026/07")
p.mkdir(parents=True, exist_ok=True)   # 递归创建，已存在则不报错

f = Path("output/2026/07/note.txt")
f.touch(exist_ok=True)                 # 创建空文件（或更新修改时间）

f.rename("output/2026/07/note_old.txt")    # 重命名/移动
f.replace("output/2026/07/final.txt")      # 类似 rename，但目标存在时会覆盖（原子替换）

f.unlink(missing_ok=True)              # 删除文件，不存在也不报错（3.8+）
Path("output/2026/07").rmdir()         # 删除空目录，非空会抛 OSError
```

`mkdir()` 不传 `parents=True` 时，若父目录不存在会抛 `FileNotFoundError`；不传 `exist_ok=True` 时，目录已存在会抛 `FileExistsError`。

### 6.5 读写快捷方法

`Path` 内置了文件读写的语法糖，等价于 `open()` 后读写再关闭：

```python
p = Path("note.txt")
p.write_text("你好\n", encoding="utf-8")
text = p.read_text(encoding="utf-8")

p2 = Path("data.bin")
p2.write_bytes(b"\x00\x01")
data = p2.read_bytes()

# 需要更复杂的模式（如追加、缓冲控制）时仍用 open()
with p.open("a", encoding="utf-8") as f:
    f.write("追加一行\n")
```

这些快捷方法每次调用都会完整打开再关闭文件，适合小文件的一次性读写；大文件或需要精细控制（追加、`newline`、`buffering`）仍应使用 `Path.open()` 或内置 `open()`。

## 7. 路径比较、哈希与排序

`Path` 重载了 `==`、`<` 等比较运算符，也实现了 `__hash__`，可以直接放进 `set` 或作为字典键：

```python
paths = {Path("a/b"), Path("a") / "b"}
print(len(paths))    # 1，两个 Path 表示同一路径，视为相等

cache = {}
cache[Path("config.json")] = "已加载"
```

注意：路径比较是**字符串层面**的比较，不会自动解析 `..`、符号链接或大小写：

```python
Path("a/./b") == Path("a/b")     # False，未经过规范化
Path("a/b").resolve() == Path("./a/b").resolve()   # 更可靠的比较方式
```

排序默认按 `parts` 逐段比较（类似字符串排序）：

```python
sorted(Path(p) for p in ["b.txt", "a.txt", "c.txt"])
# [Path('a.txt'), Path('b.txt'), Path('c.txt')]
```

## 8. 相对路径与绝对路径

```python
base = Path("/home/user/project")
target = Path("/home/user/project/src/main.py")

rel = target.relative_to(base)
print(rel)                     # src/main.py

target.is_relative_to(base)    # True（3.9+），判断 target 是否在 base 之下
```

`relative_to()` 要求 `target` 确实以 `base` 为前缀，否则抛 `ValueError`；`is_relative_to()` 则返回布尔值，适合在不确定前提下做安全判断。

解析符号链接时，`resolve(strict=False)`（默认）遇到不存在的路径不会报错，只是尽力拼出绝对形式；`resolve(strict=True)` 会在任意中间环节不存在时抛出 `FileNotFoundError`，适合需要确认路径真实存在的场景。

## 9. 常见陷阱

- **混用风格不一致**：同一模块里一会儿 `os.path.join`，一会儿 `Path` 运算，容易在类型上出错（字符串与 `Path` 混传给同一个函数）。建议一个函数/模块内统一风格。
- **忘记规范化**：直接拼接含 `..`、`.` 的路径参与比较或作为字典键，会因为字符串不同而判断出错，应先 `resolve()` 或 `normpath()`。
- **路径穿越（path traversal）风险**：如果把用户输入直接拼进基础目录，攻击者可能通过 `../../etc/passwd` 之类的输入跳出预期目录。安全做法是拼接后用 `resolve()` 得到绝对路径，再用 `is_relative_to()`（或手工 `relative_to()` + `try/except`）确认结果仍在基础目录之下：

  ```python
  base = Path("/srv/uploads").resolve()
  target = (base / user_supplied_name).resolve()
  if not target.is_relative_to(base):
      raise ValueError("非法路径，疑似路径穿越")
  ```

- **大小写与分隔符的平台差异**：Windows 文件系统默认大小写不敏感，POSIX 默认大小写敏感；同一段代码在两个平台上判断路径是否相同可能得到不同结果。跨平台代码不应依赖大小写来区分路径。
- **`Path` 直接传给期望字符串的老接口**：多数标准库和第三方库已支持 `os.PathLike`，可以直接接受 `Path`，但极少数老代码只做 `isinstance(x, str)` 检查，此时需要 `str(p)` 显式转换。

## 10. `os.path` 与 `pathlib` 对照表

| 需求 | `os.path` | `pathlib` |
|---|---|---|
| 拼接路径 | `os.path.join(a, b)` | `Path(a) / b` |
| 取文件名 | `os.path.basename(p)` | `Path(p).name` |
| 取目录 | `os.path.dirname(p)` | `Path(p).parent` |
| 拆扩展名 | `os.path.splitext(p)` | `Path(p).stem` / `.suffix` |
| 转绝对路径 | `os.path.abspath(p)` | `Path(p).resolve()` / `.absolute()` |
| 转相对路径 | `os.path.relpath(p, start)` | `Path(p).relative_to(start)` |
| 判断存在 | `os.path.exists(p)` | `Path(p).exists()` |
| 判断文件/目录 | `os.path.isfile(p)` / `isdir(p)` | `Path(p).is_file()` / `.is_dir()` |
| 文件大小 | `os.path.getsize(p)` | `Path(p).stat().st_size` |
| 展开家目录 | `os.path.expanduser(p)` | `Path(p).expanduser()` |
| 规范化 | `os.path.normpath(p)` | `Path(p).resolve()`（连带解析符号链接） |
| 遍历目录 | `os.listdir(p)` + 手工过滤 | `Path(p).iterdir()` / `.glob()` / `.rglob()` |

## 11. 本节小结

1. `os.path` 面向字符串、`pathlib` 面向对象，新代码优先用 `pathlib`，与老接口对接时可用 `str(path)` 互转；
2. 拼接路径永远使用 `os.path.join` 或 `Path` 的 `/` 运算符，禁止手写分隔符字符串拼接；
3. `PurePath` 只做字符串运算不碰文件系统，`Path` 才提供 `exists()`/`open()`/`mkdir()` 等真实 I/O 能力；
4. `stem`/`suffix` 只处理最后一段扩展名，多重扩展名（`.tar.gz`）需要额外处理；
5. `resolve()` 能规范化路径并解析符号链接，是做路径比较、防止路径穿越攻击的关键手段；
6. 涉及用户输入拼接路径时，务必用 `resolve()` + `is_relative_to()` 校验结果仍在预期目录内，避免路径穿越安全问题。
