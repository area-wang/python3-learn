# 7.6 文件系统

文件读写（7.1）关注单个文件的内容，路径操作（7.3）关注路径字符串本身的拼接与解析。本节要解决的是更「宏观」的问题：如何列出目录、创建/删除目录树、复制/移动文件、查看文件元数据、安全地生成临时文件——这些都是操作系统文件系统层面的管理动作，主要由 `os`、`shutil`、`pathlib`、`tempfile` 几个标准库模块协作完成。

## 1. 模块分工总览

| 模块 | 定位 |
|---|---|
| `os` | 对操作系统调用的薄封装，提供最底层的目录遍历、创建/删除、重命名、stat 元数据接口 |
| `os.path` | 路径字符串处理与存在性/类型判断（详见 7.3） |
| `shutil` | 建立在 `os` 之上的「高级」文件操作：递归复制、删除整棵目录树、移动、磁盘用量 |
| `pathlib` | 面向对象的路径 API，`Path` 对象直接暴露 `mkdir()`、`rmdir()`、`iterdir()` 等方法（路径本身的用法见 7.3，本节只讲目录/文件系统相关方法） |
| `tempfile` | 生成安全、唯一、自动清理的临时文件与目录 |

一般原则：能用 `pathlib` 就优先用 `pathlib`（接口更统一、跨平台性更好）；批量/递归的目录操作找 `shutil`；需要最原始的控制（如自定义 `onerror`、`os.walk` 的剪枝）时用 `os`。

## 2. 列出目录内容

三种方式，能力递增：

```python
import os
from pathlib import Path

# 方式一：os.listdir，只返回文件名字符串列表，无类型信息
names = os.listdir(".")

# 方式二：os.scandir，返回 DirEntry 对象，自带缓存的 stat 信息
with os.scandir(".") as it:
    for entry in it:
        print(entry.name, entry.is_file(), entry.is_dir())

# 方式三：pathlib，返回 Path 对象，可直接链式操作
for p in Path(".").iterdir():
    print(p.name, p.is_file())
```

`os.scandir()` 比 `os.listdir()` 快的原因：在多数操作系统上，目录遍历系统调用本身就会返回文件类型和部分 stat 信息，`scandir` 把这些信息缓存进 `DirEntry`，调用 `entry.is_file()`/`entry.stat()` 不必再发起一次 `stat` 系统调用；而对 `os.listdir()` 返回的名字调用 `os.path.isfile()` 则每次都要重新 `stat`。

| 方式 | 返回类型 | 是否含类型/stat 信息 | 推荐场景 |
|---|---|---|---|
| `os.listdir(path)` | `list[str]` | 无 | 只需要名字 |
| `os.scandir(path)` | 迭代器，元素为 `DirEntry` | 有缓存（`is_file`/`is_dir`/`stat`） | 需要判断类型或统计信息，追求性能 |
| `Path(path).iterdir()` | 迭代器，元素为 `Path` | 无（`is_file()`/`stat()` 仍会发起系统调用，除非用 `entry` 版本） | 需要面向对象后续操作（拼路径、改后缀等） |

`os.scandir()` 是上下文管理器（`with` 用法），退出时会关闭底层目录句柄；`os.listdir()`/`iterdir()` 不需要显式关闭。三者都**不保证顺序**，也不递归，只列出当前层级，且都不包含 `.`/`..`。

## 3. 遍历目录树

### 3.1 `os.walk()`

```python
for dirpath, dirnames, filenames in os.walk("project", topdown=True):
    print(dirpath, "->", dirnames, filenames)
```

每次迭代返回一个三元组：

| 元素 | 含义 |
|---|---|
| `dirpath` | 当前目录路径（字符串） |
| `dirnames` | 当前目录下的子目录名列表 |
| `filenames` | 当前目录下的文件名列表 |

`topdown=True`（默认）时先访问父目录再访问子目录，此时**可以就地修改 `dirnames`** 来跳过某些子树（比如排除 `.git`、`node_modules`）：

```python
for dirpath, dirnames, filenames in os.walk("project"):
    dirnames[:] = [d for d in dirnames if d not in {".git", "__pycache__", "node_modules"}]
    for name in filenames:
        print(os.path.join(dirpath, name))
```

必须用切片赋值 `dirnames[:] = ...` 而不是 `dirnames = ...`，后者只是重新绑定局部变量，`os.walk` 内部持有的仍是原列表，剪枝不会生效。

`topdown=False` 时先访问子目录再返回父目录（自底向上），常用于「先处理完子目录内容再删除父目录」的场景，但此时**无法通过修改 `dirnames` 剪枝**（子目录已经先被遍历了）。

`os.walk()` 默认忽略遍历中的 `OSError`（比如权限不足），可通过 `onerror=callback` 参数接收错误回调；`followlinks=False`（默认）不会跟随符号链接进入，避免死循环。

### 3.2 `pathlib` 的替代写法

```python
for p in Path("project").rglob("*"):
    if p.is_file():
        print(p)
```

`rglob(pattern)` 等价于 `glob("**/" + pattern)`，一次性返回整棵子树中匹配的所有条目（文件和目录都会出现，需要自行用 `is_file()`/`is_dir()` 过滤）。它更简洁，但**不支持在遍历中途剪枝**——如果目录树很大且需要跳过某些子树（如虚拟环境目录），`os.walk()` 的剪枝能力更高效，因为它可以避免进入不需要的子目录，而 `rglob` 会先枚举再过滤。

## 4. 创建目录

| 方式 | 能否递归创建父目录 | 目录已存在时 |
|---|---|---|
| `os.mkdir(path)` | 不能，父目录不存在会抛 `FileNotFoundError` | 抛 `FileExistsError` |
| `os.makedirs(path, exist_ok=False)` | 能 | `exist_ok=False`（默认）抛 `FileExistsError`；`exist_ok=True` 静默跳过 |
| `Path(path).mkdir(parents=False, exist_ok=False)` | `parents=True` 时能 | `exist_ok=True` 静默跳过 |

```python
import os
from pathlib import Path

# 只能创建单层，父目录 data 必须已存在
os.mkdir("data/cache")

# 递归创建，中间目录自动补全，已存在也不报错
os.makedirs("data/2026/07/24", exist_ok=True)

# pathlib 等价写法，推荐
Path("data/2026/07/24").mkdir(parents=True, exist_ok=True)
```

`exist_ok=True` 只忽略「目录已存在」，如果同名路径存在但是一个**文件**，仍然会抛 `FileExistsError`（不会把文件误删后建目录）。

## 5. 删除文件与目录

| 函数 | 作用对象 | 能否递归 | 遇到非空目录 |
|---|---|---|---|
| `os.remove(path)` / `os.unlink(path)` | 单个文件 | — | 传目录会抛 `IsADirectoryError` |
| `os.rmdir(path)` | 单个空目录 | 否 | 目录非空抛 `OSError: Directory not empty` |
| `shutil.rmtree(path)` | 整棵目录树 | 是 | 会连同其中所有文件、子目录一起删除 |

`os.remove` 与 `os.unlink` 是完全相同的函数（`unlink` 是类 Unix 术语的别名），任选其一即可。

```python
import shutil

os.remove("temp.log")          # 删单个文件
os.rmdir("empty_dir")          # 删单个空目录

# 递归删除整棵目录树，危险操作！
shutil.rmtree("build")

# 忽略删除过程中的所有错误（比如部分文件不存在）
shutil.rmtree("build", ignore_errors=True)

# 自定义错误处理，比如清除只读属性后重试
def remove_readonly(func, path, exc_info):
    os.chmod(path, 0o777)
    func(path)

shutil.rmtree("build", onerror=remove_readonly)   # Python 3.12+ 推荐用 onexc
```

Python 3.12 起 `onerror` 已废弃，改用签名为 `onexc(func, path, exc)` 的 `onexc` 参数（直接接收异常对象而不是 `exc_info` 三元组）。

**安全警告**：`shutil.rmtree()` 没有回收站，删除立刻生效且不可逆，一旦传错路径（尤其是拼出来的动态路径）后果严重。实践建议：

- 删除前先用 `os.path.exists()`/日志打印确认目标路径；
- 对用户输入拼接出的路径，先做规范化（`os.path.abspath`）并校验是否落在预期的根目录之内；
- 批量删除前可以先 `dry_run`（只打印将要删除的路径，不真正执行）。

## 6. 复制文件与目录

```python
import shutil

shutil.copyfile("src.txt", "dst.txt")   # 只复制内容，不复制权限/时间戳，且目标必须是文件路径
shutil.copy("src.txt", "dst_dir/")      # 复制内容+权限位，目标可以是目录（自动补文件名）
shutil.copy2("src.txt", "dst_dir/")     # 复制内容+权限位+时间戳等全部元数据，"copy + metadata"

shutil.copytree("src_dir", "dst_dir", dirs_exist_ok=True)  # 递归复制整个目录树
```

| 函数 | 复制内容 | 复制元数据 | 支持目录 | 目标可以是目录路径 |
|---|---|---|---|---|
| `shutil.copyfile(src, dst)` | 是 | 否 | 否 | 否，必须是完整文件路径 |
| `shutil.copy(src, dst)` | 是 | 部分（权限位） | 否 | 是 |
| `shutil.copy2(src, dst)` | 是 | 完整（含 `st_mtime`/`st_atime`） | 否 | 是 |
| `shutil.copytree(src, dst)` | 是（递归） | 完整（内部用 `copy2`） | 是，专用于目录 | 目标即新目录名 |

`copytree` 默认要求目标目录不存在，否则抛 `FileExistsError`；Python 3.8+ 提供 `dirs_exist_ok=True` 允许合并写入已存在的目录（同名文件会被覆盖）。还可以传 `ignore=shutil.ignore_patterns("*.pyc", "__pycache__")` 排除不需要复制的文件。

## 7. 移动与重命名

```python
import shutil

shutil.move("a.txt", "archive/a.txt")   # 跨文件系统也能工作，本质是"复制+删除"或系统级 rename
os.rename("old.txt", "new.txt")         # 同一文件系统内的原子重命名，跨文件系统会抛 OSError
os.replace("tmp.txt", "final.txt")      # 与 rename 类似，但目标已存在时会静默覆盖（原子操作）
```

| 函数 | 目标已存在时 | 跨文件系统 | 是否原子 |
|---|---|---|---|
| `os.rename(src, dst)` | Unix 上直接覆盖；Windows 上抛 `FileExistsError` | 不支持，跨设备抛 `OSError` | 同文件系统内是原子的 |
| `os.replace(src, dst)` | 无条件覆盖（跨平台行为一致） | 不支持 | 是，专为「覆盖」设计的原子操作 |
| `shutil.move(src, dst)` | 目标是目录则移入目录；是文件则覆盖 | 支持（回退为拷贝+删除源） | 视情况，跨文件系统不再原子 |

`os.rename` 在不同平台上对「目标已存在」的行为不一致（这是历史遗留的 POSIX vs Windows 差异），因此**需要覆盖语义时应始终使用 `os.replace()`**，它在所有平台上都保证覆盖且原子——这正是「先写临时文件，再替换正式文件」这种安全写入模式的关键（见第 10 节）。`shutil.move()` 更适合「不确定是否跨设备」的通用移动场景，代价是失去原子性保证。

## 8. 文件元数据

`os.stat(path)` 返回一个 `os.stat_result` 对象：

```python
st = os.stat("data.txt")
print(st.st_size)    # 字节数
print(st.st_mtime)   # 最近修改时间（Unix 时间戳，float）
print(st.st_ctime)   # 创建时间（Windows）或元数据变更时间（Unix，注意不是"创建时间"）
print(st.st_atime)   # 最近访问时间
print(st.st_mode)    # 文件类型 + 权限位（整数）
```

| 字段 | 含义 |
|---|---|
| `st_size` | 文件大小（字节） |
| `st_mtime` | 内容最后修改时间戳 |
| `st_atime` | 最后访问时间戳（部分文件系统挂载时禁用更新以提升性能） |
| `st_ctime` | Unix 上是 inode 元数据变更时间，**不等于**文件创建时间；Windows 上才是真正的创建时间 |
| `st_mode` | 文件类型与权限，需配合 `stat` 模块解析 |

判断类型要用 `stat` 模块常量，而不是直接比较 `st_mode`：

```python
import stat

st = os.stat("data.txt")
print(stat.S_ISDIR(st.st_mode))   # 是否目录
print(stat.S_ISREG(st.st_mode))   # 是否普通文件
print(stat.S_ISLNK(st.st_mode))   # 是否符号链接（需用 os.lstat 才不会自动跟随链接）
print(oct(stat.S_IMODE(st.st_mode)))  # 提取权限部分，如 '0o644'
```

只需要大小或修改时间时，`os.path` 提供了更直接的快捷函数（内部也是调用 `stat`）：

```python
os.path.getsize("data.txt")    # 等价于 os.stat(path).st_size
os.path.getmtime("data.txt")   # 等价于 os.stat(path).st_mtime
os.path.getctime("data.txt")
```

修改权限用 `os.chmod(path, mode)`，`mode` 通常写成八进制字面量：

```python
os.chmod("script.sh", 0o755)   # rwxr-xr-x
os.chmod("secret.txt", 0o600)  # 仅所有者可读写
```

Windows 上 `os.chmod` 只能有效切换只读位，无法精细控制 POSIX 的三组权限（详见第 12 节）。

## 9. 检查存在性与类型

```python
os.path.exists("a.txt")   # 路径存在（文件、目录、符号链接指向的目标都算）
os.path.isfile("a.txt")   # 是普通文件
os.path.isdir("a.txt")    # 是目录
os.path.islink("a.txt")   # 是符号链接（哪怕指向的目标不存在）
```

**竞态条件（TOCTOU, Time-Of-Check-To-Time-Of-Use）警告**：「先检查再使用」不是原子操作。在检查与使用之间的极短时间窗口内，文件完全可能被其他进程创建、删除或替换：

```python
# 反例：检查和打开之间可能被别的进程删除文件
if os.path.exists("data.txt"):
    with open("data.txt") as f:   # 仍可能抛 FileNotFoundError
        ...

# 更稳妥：直接尝试操作，用异常处理结果（EAFP：Easier to Ask Forgiveness than Permission）
try:
    with open("data.txt") as f:
        ...
except FileNotFoundError:
    ...
```

多进程/多线程环境、共享目录、临时目录等场景尤其容易触发这类竞态，优先选择「尝试并捕获异常」而不是「先判断再操作」。

## 10. 临时文件与目录

`tempfile` 模块生成的文件名唯一且默认只有当前用户可访问，避免了手写「随机文件名」时的猜测攻击和命名冲突风险。

```python
import tempfile

# 命名临时文件，跨平台在关闭后行为不同（见下）
with tempfile.NamedTemporaryFile(mode="w", suffix=".txt", delete=True) as f:
    f.write("临时数据")
    f.flush()
    print(f.name)   # 磁盘上的实际路径
# 退出 with 块后文件被自动删除（delete=True 是默认值）

# 临时目录，退出 with 块后自动递归删除
with tempfile.TemporaryDirectory() as tmpdir:
    path = os.path.join(tmpdir, "cache.bin")
    with open(path, "wb") as f:
        f.write(b"...")
# tmpdir 及其中所有内容已被清理

# 更底层的接口：只负责创建，不负责自动清理，需要手工管理
fd, path = tempfile.mkstemp(suffix=".tmp")
os.close(fd)          # mkstemp 返回的是已打开的文件描述符，用完要么用 os.fdopen 包装要么直接 close
os.remove(path)        # 自己负责删除

tmp_dir = tempfile.mkdtemp()
shutil.rmtree(tmp_dir)  # 自己负责删除
```

`NamedTemporaryFile` 在 Windows 上如果 `delete=True`（默认），文件在**打开状态下不能被同一进程之外的程序再次打开**（POSIX 允许，Windows 不允许），这是常见的跨平台差异；Python 3.12 起提供 `delete_on_close=False` 可以更精细地控制。

**原子写入模式**：这是 `tempfile` + `os.replace()` 的经典组合，避免程序中途崩溃导致目标文件只写了一半：

```python
def atomic_write(path, data):
    dir_ = os.path.dirname(os.path.abspath(path)) or "."
    fd, tmp_path = tempfile.mkstemp(dir=dir_)   # 临时文件建在同一目录，确保 replace 时同一文件系统
    try:
        with os.fdopen(fd, "w", encoding="utf-8") as f:
            f.write(data)
        os.replace(tmp_path, path)  # 原子替换，读者永远只能看到"全旧"或"全新"，不会看到半截内容
    except Exception:
        os.remove(tmp_path)
        raise
```

临时文件必须建在与目标文件**相同的文件系统**（通常即同一目录）下，否则 `os.replace()` 会因跨设备而失败，退化为非原子的复制。

## 11. 磁盘用量与查找可执行文件

```python
total, used, free = shutil.disk_usage("/")
print(f"总计 {total/2**30:.1f} GB, 已用 {used/2**30:.1f} GB, 剩余 {free/2**30:.1f} GB")

python_path = shutil.which("python3")   # 在 PATH 环境变量中查找可执行文件，找不到返回 None
```

`shutil.disk_usage(path)` 返回一个具名元组 `(total, used, free)`，单位字节，`path` 可以是该磁盘/分区上的任意路径。`shutil.which()` 常用于在跨平台脚本中检测某个命令行工具是否可用，行为等价于 shell 里的 `which`/`where`。

## 12. 跨平台注意事项

| 差异点 | 说明 |
|---|---|
| 大小写敏感性 | Linux 文件系统默认区分大小写（`A.txt` 与 `a.txt` 是两个文件）；macOS（默认 APFS）与 Windows 默认**不区分**大小写但会保留原始大小写；跨平台代码不要依赖大小写来区分文件 |
| 路径长度限制 | Windows 传统 API 限制路径总长 260 字符（可通过注册表启用长路径支持或用 `\\?\` 前缀绕过）；Linux/macOS 单个文件名一般限制 255 字节，总路径长度限制远大于 Windows |
| 权限模型 | POSIX（Linux/macOS）使用「所有者/组/其他」三组读写执行位，`os.chmod` 完整生效；Windows 使用 ACL（访问控制列表），`os.chmod` 只能模拟极有限的只读/读写切换，精细权限需要 `pywin32` 等专用库 |
| 换行符与文本文件 | 与目录操作关系不大，但复制/移动文本文件不会改变其内容字节，换行符差异只在按文本模式读写时体现（见 7.1） |
| 符号链接 | Windows 创建符号链接默认需要管理员权限（或开启开发者模式），行为与 POSIX 不完全对等，跨平台代码若依赖符号链接需要额外测试 |
| 大小写不敏感带来的覆盖 | 在 macOS/Windows 上创建 `Report.txt` 后再创建 `report.txt` 实际是覆盖同一文件，Linux 上则是两个独立文件——这类代码在不同平台上表现不同，需要显式规避 |

## 13. 本节小结

1. 目录级操作按「谁负责」分工：`os` 提供原始系统调用（`listdir`/`scandir`/`walk`/`mkdir`/`remove`），`shutil` 提供高级批量操作（`copytree`/`rmtree`/`move`/`disk_usage`），`pathlib` 提供面向对象的统一封装；
2. 列目录优先用 `os.scandir()` 或 `Path.iterdir()`，避免对每个文件名再单独 `stat`；遍历整棵树用 `os.walk()`（可剪枝）或 `rglob("*")`（更简洁但不能中途剪枝）；
3. 创建目录首选 `os.makedirs(exist_ok=True)` 或 `Path.mkdir(parents=True, exist_ok=True)`，一步到位处理「父目录不存在」和「目录已存在」两种情况；
4. `shutil.rmtree()` 递归删除且不可逆，务必做路径校验，必要时先 dry-run 确认；
5. 需要覆盖语义（写入覆盖已有文件）时用 `os.replace()` 而不是 `os.rename()`，它跨平台原子且行为一致，是安全写入模式的基础；
6. 检查文件是否存在再操作存在竞态风险（TOCTOU），优先用 try/except 直接尝试并处理异常，而不是先 `exists()` 判断。
