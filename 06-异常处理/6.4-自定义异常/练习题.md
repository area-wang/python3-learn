# 6.4 自定义异常练习题

## 一、概念题

1. 为什么 `raise Exception("余额不足")` 不如自定义异常方便？自定义异常解决了哪两类问题？
2. 自定义异常时，选择父类有什么讲究？举出至少 3 种常见选择及其理由。
3. 在自定义异常构造器中为什么要调用 `super().__init__(...)`？不调用会有什么影响？
4. 异常对象的 `args` 与实例属性有什么区别？访问结构化信息时应该优先使用哪种？为什么？
5. 异常继承层级过深有什么缺点？通常多少层比较合适？
6. 在分层架构里，为什么要在层边界“翻译”异常？翻译时为什么要用 `raise ... from e`？
7. `except Parent:` 能否捕获 `Parent` 的子类异常？基于这个规律，多个 `except` 分支应如何排序？
8. 错误码模式（如 `ApiError(40401, ...)`）相比用多个异常类有什么优缺点？
9. 命名自定义异常时应遵循什么惯例？`BalanceException` 与 `InsufficientBalanceError` 哪个更好？为什么？
10. 把异常类集中放在 `exceptions.py`、分散在各子领域、或定义在使用它们的模块里，各有什么场景？

## 二、判断代码输出

### 1. 继承可捕获性

```python
class AppError(Exception):
    pass

class TaskError(AppError):
    pass

try:
    raise TaskError("boom")
except AppError as e:
    print("父类捕获:", type(e).__name__)
```

写出输出，并说明为什么 `except AppError` 能捕获 `TaskError`。

### 2. 结构化属性

```python
class InvalidAge(ValueError):
    def __init__(self, age, reason):
        super().__init__(f"年龄非法: {age}, {reason}")
        self.age = age
        self.reason = reason

try:
    raise InvalidAge(-1, "不能为负")
except InvalidAge as e:
    print(e.age, e.reason, str(e), e.args)
```

写出输出，说明 `str(e)` 与 `e.args` 分别来自哪里。

### 3. 分组捕获

```python
class PaymentError(Exception): pass
class PaymentTimeout(PaymentError): pass
class PaymentRejected(PaymentError): pass

def pay(kind):
    if kind == "timeout":
        raise PaymentTimeout()
    elif kind == "rejected":
        raise PaymentRejected()
    else:
        raise PaymentError()

for kind in ("timeout", "rejected", "other"):
    try:
        pay(kind)
        print("ok")
    except PaymentTimeout:
        print(kind, "-> timeout")
    except PaymentError:
        print(kind, "-> other")
```

写出输出，并说明为什么“rejected”会落入 `other` 分支。

### 4. 翻译保留原因

```python
class NotFound(LookupError): pass

def find(id_):
    try:
        return {"a": 1}.pop(id_)
    except KeyError as e:
        raise NotFound(f"未找到 {id_}") from e

try:
    find("b")
except NotFound as e:
    print("cause:", type(e.__cause__).__name__)
    print("msg:", e)
```

写出输出。

### 5. 携带 args

```python
class ApiError(Exception):
    def __init__(self, code, message):
        super().__init__(code, message)
        self.code = code
        self.message = message

try:
    raise ApiError(40001, "缺少字段")
except ApiError as e:
    print(e.code, e.message)
    print(e.args)
```

写出输出，说明 `e.args` 与具名属性 `e.code` 各自的用途。

### 6. 未给父类传消息

```python
class Weird(Exception):
    def __init__(self, code):
        self.code = code

try:
    raise Weird(9000)
except Weird as e:
    print(repr(e))
    print(e.code)
```

写出输出，说明由于没有调用 `super().__init__`，`str(e)` 表现如何。

## 四、编程题

### 1. 校验异常族

为一组校验失败定义一个根异常 `ValidationError(ValueError)`，并派生：

- `EmptyNameError`
- `OutOfRangeError`（携带 `actual`、`low`、`high`）

### 2. 错误码异常

### 3. 翻译并保留原因

实现 `class ConnectionFailed(RuntimeError)` 和 `class NotFound(LookupError)`。编写 `class FakeDB`，带有 `query(id_)` 在 `id_ == "x"` 时抛 `KeyError`、在 `id_ == "y"` 时抛内置 `ConnectionError`。编写 `get_record(db, id_)`：

- `KeyError → NotFound(id_) from e`
- `ConnectionError → ConnectionFailed("数据库不可用") from e`

外层分别用两个调用测试，并打印最终异常与其 `__cause__` 类型。

### 4. 分层模型

模拟三层架构：

- `repository.get_user(user_id)`：内部抛 `repository.UserNotFound`（内部异常）；
- `service.login(user_id, password)`：捕获内部异常，翻译为 `service.UserNotFoundError(user_id) from e`；密码不对时抛 `service.AuthenticationError(user_id)`；
- `api.handle(...)`：分别捕获两种 service 异常输出不同 JSON 响应，第三类 catch 根异常 `AppError` 兜底。

### 5. 读属性即可
