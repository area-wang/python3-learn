# 6.1 异常基础练习题

## 一、概念题

1. 语法错误（SyntaxError）和异常（Exception）有什么本质区别？它们分别在什么阶段被发现？
2. 所有 Python 异常的根类是什么？为什么用户代码通常只捕获 `Exception` 而不是 `BaseException`？
3. `KeyboardInterrupt` 和 `SystemExit` 属于哪个异常的子类？为什么不应被普通业务代码捕获？
4. 异常是对象意味着什么？异常对象通常携带哪些信息？
5. `ValueError` 和 `TypeError` 有什么区别？分别给出一个能触发它们的例子并说明为何是那一类。
6. 阅读一段 traceback 时，“most recent call last” 表示什么？应该从哪一端开始读？
7. 异常传播的机制是怎样的？函数未捕获异常时会怎样影响它的返回值？
8. 用返回值表达错误和用异常表达错误各有什么优缺点？为什么 Python 社区推荐“异常用于异常情况”？
9. 为什么不建议把 `try-except` 当作 `if` 来做正常控制流？
10. 写出至少 5 个常见内置异常及其典型触发场景。

## 二、判断代码输出

### 1. 识别异常类型

```python
data = {"a": 1}
print(data["b"])
```

写出抛出的异常类型，并说明为什么不是 `IndexError`。

### 2. 子类被父类捕获

```python
try:
    {}["missing"]
except LookupError as e:
    print("A:", type(e).__name__)
except KeyError as e:
    print("B:", type(e).__name__)
```

写出输出，并解释为什么只会进入其中一个分支。

### 3. 异常传播

```python
def f():
    g()

def g():
    h()

def h():
    print(1 / 0)

f()
```

写出终止时打印的异常类型，并描述异常是从哪个函数开始、经过哪些函数传播到顶层的。

### 4. 捕获顺序

```python
try:
    raise ValueError("v")
except Exception as e:
    print("Exception:", e)
except ValueError as e:
    print("ValueError:", e)
```

写出输出，并说明 `except` 分支的匹配规则。

### 5. 异常对象属性

```python
try:
    int("abc")
except ValueError as e:
    print(e.args)
    print(e.__class__.__name__)
    print(len(e.args))
```

写出输出。

### 6. 未绑定名称

```python
def check():
    total = 0
    if total > 0:
        result = "positive"
    return result

print(check())
```

写出抛出的异常类型，并解释为什么不是 `NameError` 而可能是另一种本地变量相关异常。

## 三、改错题

### 1. 过宽的 try

```python
def process(data):
    try:
        value = int(data)
        result = 100 / value
        names = ["a", "b"]
        print(names[value])
        return result
    except Exception:
        return 0
```

指出这段代码存在的问题，并改写成更合理的捕获方式：对不同可能的异常分别给出有意义的返回值或错误信息。

### 2. 吞掉异常

```python
def load_config(path):
    try:
        with open(path) as f:
            return f.read()
    except:
        pass
```

说明为什么不应这样写，并改写成在文件不存在时返回 `None`、其他异常正常抛出的版本。

### 3. 类型选择错误

```python
def to_int(text):
    if isinstance(text, int):
        return text
    raise TypeError("传入必须是字符串或整数")  # 这里该用 TypeError 吗？
```

分析注释中的取舍：传入非法类型时用 `TypeError` 还是 `ValueError` 更合适？为什么？

## 四、编程题

### 1. 异常类型识别

不运行代码，判断以下每条语句会触发哪种异常（写出异常名）；然后用 `try-except` 包裹并在 `except` 中打印类型名进行验证。

### 2. 传播路径观察

编写一个三层调用函数 `a -> b -> c`，在 `c` 中抛出 `RuntimeError`。要求：

1. 不在 `b` 中捕获，让异常传播到 `a`；
2. 在 `a` 中捕获并打印异常类型和消息；
3. 再修改 `b`，让它捕获后打印“b 已捕获”，然后重新抛出，观察 `a` 是否还能捕获。

### 3. 异常信息提取

编写函数 `safe_eval(func, *args)`，调用 `func(*args)`。若发生异常，返回一个字典 `{"ok": False, "type": 异常类名, "message": str(异常), "args": 异常.args}`；若成功，返回 `{"ok": True, "value": 结果}`。并对以下调用展示返回值：

```python
safe_eval(int, "abc")
safe_eval(int, "42")
safe_eval(lambda: 1 / 0)
```

### 4. 类型判断题改造

下面的代码用异常做条件分支，改写为不用异常的实现：

```python
def get_value(mapping, key, default):
    try:
        return mapping[key]
    except KeyError:
        return default
```

要求用两种方式实现：使用 `dict.get`；使用 `in` 判断。并简述何时用异常版本也合理。

### 5. 异常对象观察

编写代码，主动抛出一个带多个参数的异常，例如 `raise ValueError("拓扑不支持", 401, "请重试")`，然后在 `except` 中分别打印：

1. 异常类型名；
2. `str(e)`；
3. `e.args` 的长度和每个元素；
4. `e.__cause__` 和 `e.__context__`。

说明 `str(e)` 和 `args` 之间的关系。

### 6. 错误表达方式对比

实现一个解析整数的函数 `parse_positive_int(text)`，分别用两种风格编写：

- 风格 A：解析失败时返回 `None`；
- 风格 B：解析失败时抛出 `ValueError`。

再编写调用方代码，演示风格 A 下“忘记检查返回值导致后续报错”的情形，以及风格 B 下“异常被正确处理”的情形，并比较两种风格带来的差异。

## 五、综合实践：错误诊断器

编写一个函数 `diagnose(statement)`，接收一个无参可调用对象 `statement`，调用它，并返回一份诊断报告，包含：

1. 是否成功；
2. 成功时返回结果；
3. 失败时记录异常类型名、异常消息、`args` 内容；
4. 失败时打印一个简化的“调用位置”：使用 `traceback` 标准库提取最近一帧的文件名、行号、函数名（提示：`traceback.extract_tb(e.__traceback__)` 或 `traceback.format_tb`）。

要求：

- 不要捕获 `KeyboardInterrupt` 和 `SystemExit`；
- 至少对“整数解析失败”“除零”“键不存在”三种情况各测试一次；
- 输出格式清晰，便于阅读。

最后回答：为什么这类诊断函数适合用异常实现，而不适合用返回特殊值实现？
