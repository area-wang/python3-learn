# 6.1 异常基础

异常（exception）是程序运行过程中出现的错误或意外情况。Python 用异常对象来表示这些问题，并在异常发生时中断正常的执行流程。理解异常的发生机制、常见类型和传播方式，是编写健壮程序的前提。

## 1. 错误与异常的关系

Python 中有两类需要区分的问题：

| 类型 | 出现时机 | 是否能被捕获 | 示例 |
|---|---|---|---|
| 语法错误（SyntaxError） | 编译/解析阶段 | 一般不能，代码无法执行 | `print("hi"` |
| 异常（Exception） | 运行阶段 | 可以被 `try` 捕获 | `1 / 0`、`int("abc")` |

语法错误意味着代码本身写法不正确，必须先修正再运行；异常则是在代码语法正确的前提下，运行时遇到了无法处理的情况。

```python
# 语法错误：解析失败，无法执行
# print("hello"

# 异常：语法正确，运行时出错
print(1 / 0)  # ZeroDivisionError
```

## 2. 异常是一个对象

Python 中一切皆对象，异常也不例外。每个异常都是某个异常类的实例，携带错误信息：

```python
try:
    1 / 0
except ZeroDivisionError as e:
    print(type(e))   # <class 'ZeroDivisionError'>
    print(isinstance(e, BaseException))  # True
    print(e)         # division by zero
    print(repr(e))   # ZeroDivisionError('division by zero')
```

异常对象通常包含：

- 类型：说明发生了什么类别的错误，如 `ZeroDivisionError`；
- 消息：人类可读的描述，通过 `str(e)` 或 `args` 获取；
- 回溯（traceback）：调用栈信息，辅助定位出错位置；
- `cause` 与 `context`：异常链信息（见 6.3 节）。

## 3. 异常类层级

所有异常都继承自 `BaseException`。绝大多数用户代码应只捕获 `Exception` 及其子类，而不是 `BaseException`，因为后者还包含 `KeyboardInterrupt`、`SystemExit` 等系统级退出异常，捕获它们可能干扰解释器正常退出。

```text
BaseException
├── SystemExit              # sys.exit() 触发
├── KeyboardInterrupt       # Ctrl+C 中断
├── GeneratorExit           # 生成器被关闭
└── Exception               # 绝大多数普通异常的父类
    ├── StopIteration
    ├── ArithmeticError
    │   └── ZeroDivisionError
    ├── LookupError
    │   ├── IndexError
    │   └── KeyError
    ├── ValueError
    ├── TypeError
    ├── AttributeError
    ├── OSError
    │   ├── FileNotFoundError
    │   ├── PermissionError
    │   └── ...
    └── ...
```

抓住层级关系很重要：捕获父类异常会同时捕获其所有子类异常。

```python
try:
    {}["missing"]
except LookupError as e:   # KeyError 是 LookupError 的子类，能被捕获
    print("LookupError 捕获到:", type(e).__name__)
```

## 4. 常见内置异常

| 异常 | 触发场景 | 示例 |
|---|---|---|
| `TypeError` | 对类型不支持的操作 | `len(5)`、`"a" + 1` |
| `ValueError` | 类型正确但值非法 | `int("abc")`、`float("nan")` |
| `ZeroDivisionError` | 除以零或取模零 | `5 / 0`、`7 % 0` |
| `IndexError` | 索引超出序列范围 | `[1, 2][10]` |
| `KeyError` | 字典键不存在 | `{}["x"]` |
| `AttributeError` | 访问不存在的属性 | `object().no_such_attr` |
| `NameError` | 使用未绑定的名称 | `print(undefined_var)` |
| `UnboundLocalError` | 局部变量未赋值就使用 | 函数内先引用后赋值 |
| `FileNotFoundError` | 打开不存在的文件 | `open("no.txt")` |
| `PermissionError` | 权限不足 | 写入只读目录 |
| `StopIteration` | 迭代器耗尽 | `next(iter([]))` |
| `KeyBoardInterrupt` | 用户中断 | Ctrl+C |
| `AssertionError` | `assert` 条件为假 | `assert 1 > 2` |
| `ImportError` / `ModuleNotFoundError` | 导入失败 | `import not_a_module` |
| `RuntimeError` | 其他不适合归类的运行期错误 | 递归过深等 |

理解每个异常“为什么发生”，比死记名字更重要。例如下面每条语句触发的异常不同：

```python
len(5)            # TypeError
int("abc")        # ValueError
[1, 2][10]        # IndexError
{}["x"]           # KeyError
open("no.txt")    # FileNotFoundError
import no_module  # ModuleNotFoundError
```

`ValueError` 与 `TypeError` 容易混淆，区分要点是：类型本身是否错误。传入 `int("abc")`，字符串是 `int` 能接受的类型，只是内容无法解析，所以是 `ValueError`；而 `int([1, 2])`，列表根本不是 `int` 能处理的类型，所以是 `TypeError`。

## 5. 异常未被处理时的表现

异常发生且未捕获时，Python 会沿调用栈向上传播，最终到达顶层，程序终止并打印 traceback：

```python
def first():
    second()

def second():
    third()

def third():
    1 / 0   # ZeroDivisionError 在此抛出

first()
```

运行后会看到类似输出：

```text
Traceback (most recent call last):
  File "demo.py", line 10, in <module>
    first()
  File "demo.py", line 2, in first
    second()
  File "demo.py", line 5, in second
    third()
  File "demo.py", line 8, in third
    1 / 0
ZeroDivisionError: division by zero
```

阅读 traceback 的要点：

- 从下往上看：最底行是异常类型和消息，往上是调用栈；
- “most recent call last”表示最近调用的在最下方；
- 每一段标注文件名、行号和所在函数或位置，点击行号可定位源码。

## 6. 异常传播的机制

异常抛出后，当前函数立即停止执行，异常沿调用链逐层向上传播，直到被某个 `try-except` 捕获或到达顶层导致程序终止。这意味着：

- 越靠近异常源的 `try` 越先有机会处理；
- 调用者可以选择处理，也可以选择不处理让异常继续上抛；
- 未被处理的异常沿原路返回，函数中尚未返回的值会被丢弃。

```python
def divide(a, b):
    return a / b          # 这里抛出 ZeroDivisionError

def average(numbers):
    total = sum(numbers)
    return divide(total, 0)   # 异常从此处传播

average([10, 20])        # 最终在调用 average 处暴露异常
```

`average` 没有处理异常，它直接把 `divide` 抛出的异常透传给调用者。函数是否处理异常是一种设计选择：

- 知道如何恢复或翻译异常的层次负责处理；
- 无法处理的层次让异常上抛，由更上层的调用者决定。

## 7. 主动观察异常

`try-except` 将在 6.2 节详细讲解，本节先用最简单形式观察异常信息：

```python
try:
    value = int(input("请输入数字："))
    print(10 / value)
except ValueError as e:
    print("不是合法数字：", e)
except ZeroDivisionError as e:
    print("不能除以零：", e)
```

要点：

- 不同 `except` 分支对应不同异常类型；
- `as` 把异常对象绑定到一个名字，便于读取信息；
- 匹配按照从上到下的顺序，命中一个后不再匹配后续分支。

## 8. 获取异常的更多信息

除消息外，异常对象还提供：

```python
try:
    1 / 0
except ZeroDivisionError as e:
    print(e.args)            # ('division by zero',)
    print(e.__class__.__name__)  # ZeroDivisionError
    print(e.__cause__)       # None，除非主动 raise from
    print(e.__context__)    # None，此处没有上下文异常
```

`args` 保存异常构造时传入的参数，通常是错误描述。自定义异常可以扩展更多属性（见 6.4 节）。

## 9. 异常与返回值的区别

初学者容易用返回值表达错误，例如返回 `None` 或 `-1`。但在 Python 中，异常通常是更自然的错误表达方式：

| 方面 | 返回值表达错误 | 异常表达错误 |
|---|---|---|
| 易忽略 | 调用者可能忘记检查 | 不处理就会传播，难以忽略 |
| 错误信息 | 仅靠约定，可能歧义 | 由异常类型携带，语义清晰 |
| 正常路径 | 每步都要判断返回值 | 正常路径清爽 |
| 控制流 | 用 `if` 控制 | 用 `try-except` 跳转 |

```python
# 风格 A：返回值表达错误，容易漏判
def parse_int(text):
    if text.isdigit():
        return int(text)
    return None

result = parse_int("abc")
print(result + 1)   # TypeError: None + 1，错误被无声放大

# 风格 B：异常表达错误，不会被忽略
def parse_int(text):
    if text.lstrip("-").isdigit():
        return int(text)
    raise ValueError(f"无法解析为整数: {text!r}")

try:
    print(parse_int("abc") + 1)
except ValueError as e:
    print("处理失败：", e)
```

Python 社区普遍遵循“异常用于异常情况”的原则：正常控制流不要用异常代替条件判断（不要把 `try-except` 当 `if` 用），但真实错误应当用异常表达。

## 10. 常见误区

- **滥用裸 `except`**：`except:` 会捕获包括 `KeyboardInterrupt` 在内的所有异常，应改用 `except Exception:` 或具体类型。
- **捕获过宽**：`try` 包住大量无关代码会让真正的错误来源难以定位，应只包住可能出错的少量代码。
- **吞掉异常**：`except: pass` 把异常悄悄丢弃，排查问题时会非常痛苦；至少要记录日志。
- **捕获后不处理**：捕获了异常却什么都不做，等于掩盖问题。
- **用异常做控制流**：例如用 `try: x = d[k] except KeyError` 替代 `d.get(k)`，性能与可读性都更差。

## 11. 异常的性能提示

异常处理在“正常路径”开销很小，只有真正抛出异常时才有较明显开销。因此应避免在热路径上频繁抛出并捕获异常来替代条件判断：

```python
# 不推荐：用异常探测边界
def find_first_negative(numbers):
    for i, n in enumerate(numbers):
        try:
            if n < 0:
                return i
        except TypeError:
            continue

# 更好：先检查类型或使用可选逻辑，避免异常作为常规分支
```

查询字典是否有键应优先 `get` 或 `in`，而不是 `try-except KeyError` 来探测缺失。

## 12. 本节小结

1. 异常是运行期错误，与编译期的语法错误不同，可以被 `try` 捕获。
2. 所有异常继承自 `BaseException`，但用户代码通常只处理 `Exception` 及其子类。
3. 异常是对象，携带类型、消息、回溯、上下文等信息。
4. 未捕获的异常沿调用栈向上传播，最终导致程序终止并打印 traceback。
5. 常见异常如 `ValueError`、`TypeError`、`KeyError`、`FileNotFoundError` 等各自对应特定场景，理解成因比记忆名字重要。
6. 异常是 Python 表达错误的主流方式，但不应替代正常条件判断。
