# 6.2 捕获异常

捕获异常是异常处理的核心。Python 通过 `try` 语句块把“可能出错的代码”与“出错后的处理逻辑”分开，并配合 `except`、`else`、`finally` 三个子句分别表达不同语义。掌握它们的组合方式和执行顺序，是编写健壮代码的关键。

## 1. 最基本的 try-except

```python
try:
    number = int(input("请输入数字："))
    print(10 / number)
except ZeroDivisionError:
    print("不能除以零")
```

执行流程：

1. 先执行 `try` 中的代码；
2. 若正常结束，跳过 `except`；
3. 若发生 `ZeroDivisionError`，跳到对应 `except` 执行；
4. 发生其他类型异常且没有匹配分支时，异常继续向上传播。

## 2. 捕获多种异常

### 2.1 多个 except 分支

```python
try:
    number = int(input("请输入数字："))
    print(10 / number)
except ValueError:
    print("输入不是合法数字")
except ZeroDivisionError:
    print("不能除以零")
```

要点：

- 按**从上到下**顺序匹配，命中一个后执行该分支，不再匹配后续分支；
- 父类异常应写在子类**之后**，否则子类分支永远无法命中。

错误的写法（`Exception` 在前会吞掉具体异常）：

```python
try:
    1 / 0
except Exception:
    print("命中 Exception")
except ZeroDivisionError:     # 永远到不了这里
    print("命中 ZeroDivisionError")
```

### 2.2 一个 except 捕获多种类型

把多个异常类型放进元组：

```python
try:
    number = int(input("请输入数字："))
    print(10 / number)
except (ValueError, ZeroDivisionError) as e:
    print("输入有误：", type(e).__name__, e)
```

当多种异常的处理方式相同时，用元组合并更简洁。

### 2.3 获取异常对象

用 `as` 把异常对象绑定到一个名字：

```python
try:
    {}["x"]
except KeyError as e:
    print("缺少键：", e.args[0])
```

`e` 只在该 `except` 块内有效，块结束后会被删除（这是为避免循环引用）。

## 3. else 子句

`else` 在 `try` 块**没有发生任何异常**时执行。它常用于把“依赖 try 块成功执行”的后续逻辑分离出来：

```python
try:
    number = int(input("请输入数字："))
except ValueError:
    print("不是合法数字")
else:
    print("解析成功，结果为：", number)
    print("它的两倍是：", number * 2)
```

把后续逻辑放进 `else` 而不是直接写在 `try` 末尾的好处：

- 后续逻辑若抛出异常，**不会被同名的 except 误捕获**；
- 意图清晰：`try` 只包含真正可能出错的代码，`else` 承接成功后的操作。

对比：

```python
# 容易误捕获：如果 processing(number) 抛出 ValueError，也会被下面捕获
try:
    number = int(text)
    processing(number)
except ValueError:
    print("出错了")

# 更合理：只捕获解析，后续异常不会被误吞
try:
    number = int(text)
except ValueError:
    print("解析失败")
else:
    processing(number)
```

## 4. finally 子句

`finally` 无论是否发生异常、是否被捕获，都会执行。它最常见的用途是**释放资源**：

```python
f = open("data.txt")
try:
    content = f.read()
finally:
    f.close()   # 无论是否读到，都确保关闭
```

`finally` 的执行时机：

- `try` 正常结束 → 执行 `finally`；
- `try` 抛异常并被 `except` 捕获 → 先执行 `except`，再执行 `finally`；
- `try` 抛异常但未被捕获 → 异常暂停，先执行 `finally`，再继续传播；
- `try` 或 `except` 中 `return` → 仍会在返回前执行 `finally`。

```python
def load():
    try:
        return "ok"
    finally:
        print("finally 仍然执行")
```

调用 `load()` 会先打印 `finally 仍然执行`，再返回 `"ok"`。

### 4.1 finally 中再抛异常的注意点

如果 `finally` 中又抛出新异常，会**替换**之前正在传播的异常，原异常可能丢失：

```python
try:
    1 / 0
finally:
    raise ValueError("清理时出错")   # 原本的 ZeroDivisionError 被替换
```

因此 `finally` 中的代码应尽量保持简单稳定，不要引入新的复杂逻辑。

## 5. 完整结构

四个子句同时出现时，**固定的顺序**是：`try → except → else → finally`。

```python
try:
    number = int(input("请输入数字："))
    result = 10 / number
except ValueError:
    print("不是合法数字")
except ZeroDivisionError:
    print("不能除以零")
else:
    print("结果是", result)
finally:
    print("处理完成")
```

执行顺序与含义：

| 子句 | 何时执行 | 用途 |
|---|---|---|
| `try` | 最先 | 放置可能出错的代码 |
| `except` | `try` 抛出匹配异常时 | 处理异常 |
| `else` | `try` 未抛出任何异常时 | 承接成功后的后续逻辑 |
| `finally` | 无论如何都会执行 | 资源清理 |

`else` 和 `finally` 都可省略；`except` 和 `finally` 至少要有一个，`try` 不能单独存在。

## 6. 异常匹配规则

`except` 判断是否匹配用的是 `isinstance` 语义：

```python
class MyError(ValueError):
    pass

try:
    raise MyError("自定义")
except ValueError as e:
    print("ValueError 捕获到子类:", type(e).__name__)
```

因为 `MyError` 是 `ValueError` 的子类，所以会被 `except ValueError` 捕获。这意味着：

- 捕获父类会连带捕获所有子类；
- 想分别处理子类和父类时，子类必须写在前面。

## 7. 裸 except 与 Exception

### 7.1 裸 except

```python
try:
    ...
except:    # 等价于 except BaseException
    ...
```

`except:` 会捕获**所有**异常，包括 `KeyboardInterrupt`、`SystemExit`，这会干扰程序的中断与退出。一般禁止使用。

### 7.2 Exception

```python
try:
    ...
except Exception as e:
    ...
```

捕获 `Exception` 涵盖了绝大多数普通错误，但**不会**捕获 `KeyboardInterrupt`、`SystemExit`，是“捕获所有普通异常”的推荐写法。

### 7.3 最佳实践

优先**精确捕获**你预期会发生的异常，让意料之外的异常继续上抛暴露出来：

```python
# 推荐：精确捕获
except FileNotFoundError:
    ...

# 次选：需要笼统兜底时
except Exception as e:
    log(e)
    raise
```

## 8. 捕获后重新抛出

在 `except` 中可以使用 `raise`（不带参数）把当前捕获的异常原样上抛：

```python
def process(data):
    try:
        return int(data)
    except ValueError as e:
        log(e)
        raise    # 重新抛出，保留原始 traceback
```

对比直接 `raise e`：

```python
# 不推荐：会改变 traceback 起点
raise e

# 推荐：保留原始异常上下文
raise
```

`raise` 不带参数会保持完整的原始异常栈，便于上层诊断。

## 9. 打印与记录异常

调试时常需要打印异常完整信息，标准库 `traceback` 提供了便利方法：

```python
import traceback

try:
    1 / 0
except Exception:
    traceback.print_exc()      # 直接打印到标准错误
    # 或者
    message = traceback.format_exc()   # 作为字符串返回
    # log.error(message)
```

生产代码中，把 `format_exc()` 写入日志比 `print` 更合适，因为日志通常带有时间、级别、上下文。

## 10. 实用模式

### 10.1 默认值回退

```python
def parse_int(text, default=0):
    try:
        return int(text)
    except ValueError:
        return default
```

### 10.2 多次尝试

```python
for attempt in range(3):
    try:
        result = network_request()
        break
    except ConnectionError:
        if attempt == 2:
            raise
        time.sleep(1)
```

### 10.3 转换异常

```python
def load_user(user_id):
    try:
        return db.get(user_id)
    except db.NotFoundError as e:
        raise ValueError(f"用户不存在: {user_id}") from e
```

把底层异常转换为更高层语义的异常（`from` 与异常链见 6.3 节）。

### 10.4 清理与回滚

```python
conn = db.connect()
try:
    conn.execute("INSERT ...")
    conn.execute("UPDATE ...")
    conn.commit()
except Exception:
    conn.rollback()
    raise
finally:
    conn.close()
```

成功时提交，失败时回滚，无论成功失败都关闭连接。

## 11. 常见误区

- **捕获过宽**：`except Exception` 包住一大段无明显出错点的代码，真正问题被遮蔽。应只包住可能出错的最小范围。
- **裸 `except:`**：会吞掉 `KeyboardInterrupt`，导致 Ctrl+C 无响应。
- **`except: pass`**：吞掉异常且无任何记录，最难排查。
- **`except` 顺序错误**：父类写在子类前，使子类分支不可达。
- **`finally` 中抛异常**：会覆盖原始异常，丢失诊断信息。
- **`return` 与异常的混用**：在 `try` 里 `return` 后还要依赖 `finally` 的执行，应清晰理解执行顺序。

## 12. 执行顺序速查

```python
def demo(value):
    try:
        print("A: try 开始")
        result = 10 / value
        print("B: try 结束")
    except ZeroDivisionError:
        print("C: except")
        result = None
    else:
        print("D: else")
    finally:
        print("E: finally")
    print("F: 函数返回前")
    return result
```

- `demo(2)` 输出：`A → B → D → E → F`，返回 `5`；
- `demo(0)` 输出：`A → C → E → F`，返回 `None`；
- 若抛出非 `ZeroDivisionError`（如把 `value` 改成会触发 `TypeError` 的输入）：`A → E`，然后异常继续传播，`F` 不会执行。

记住口诀：**成功走 else，失败走 except，finally 必经，return 之前先 finally**。

## 13. 本节小结

1. `try-except` 把可能出错的代码与处理逻辑分离，按从上到下顺序匹配异常类型。
2. `except` 用元组可一次捕获多种异常，用 `as` 可获取异常对象。
3. `else` 仅在 `try` 无异常时执行，适合放“成功后继续”的逻辑，避免被误捕获。
4. `finally` 无论如何都会执行，适合资源清理；其中抛异常会替换原异常。
5. 优先精确捕获；避免裸 `except`、`except Exception` 大包大揽、`except: pass`。
6. 不带参数的 `raise` 可重新抛出并保留原始 traceback。
7. 完整结构固定顺序为 `try → except → else → finally`。
