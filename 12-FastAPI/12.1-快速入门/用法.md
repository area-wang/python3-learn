# 12.1 快速入门

前面的章节里，我们已经学过类型提示（10.1）、数据类（10.2）、异步编程（8.8）和网络请求（10.9）。FastAPI 恰好把这几样东西拼在了一起：**用类型提示声明接口，用 Pydantic 校验数据，用 asyncio 处理并发，最后对外提供 HTTP 服务**。本节的目标是把 FastAPI 跑起来，弄清楚「一个请求进来以后发生了什么」，并学会在 `async def` 和 `def` 之间做出正确选择——这是后面所有小节的地基。

> 本章示例在 Python 3.14 / FastAPI 0.143 / Pydantic 2.14 / Starlette 1.8 下实际运行验证。Python 3.10 及以上都可以学习本章（需要支持 `str | None` 写法）。

## 1. FastAPI 是什么

FastAPI 是一个用于构建 **Web API** 的现代 Python 框架，核心卖点有三个：

1. **基于类型提示**：参数写成 `item_id: int`，框架就自动完成「取值 → 类型转换 → 校验 → 报错」；
2. **自动生成接口文档**：根据代码自动生成 OpenAPI 规范，自带 Swagger UI 和 ReDoc 两套交互式文档；
3. **高性能 + 原生异步**：基于 ASGI 标准，支持 `async/await`，性能与 Node.js、Go 的常见框架处于同一量级。

### 1.1 架构：FastAPI = Starlette + Pydantic

FastAPI 本身代码量并不大，它站在两个库的肩膀上：

```text
            ┌───────────────────────────────────────────┐
            │                 FastAPI                    │
            │  路由声明 · 依赖注入 · OpenAPI 文档生成     │
            ├─────────────────────┬─────────────────────┤
            │      Starlette      │      Pydantic       │
            │  ASGI Web 工具箱：   │  数据校验/序列化：   │
            │  路由、请求/响应、   │  类型转换、字段约束、│
            │  中间件、WebSocket   │  JSON Schema 生成   │
            └─────────────────────┴─────────────────────┘
                          ▲
                          │ ASGI 协议
            ┌─────────────┴─────────────┐
            │  ASGI 服务器（Uvicorn 等）  │  负责监听端口、解析 HTTP
            └───────────────────────────┘
```

| 组件 | 负责什么 | 你会直接接触到的东西 |
|---|---|---|
| **Uvicorn** | ASGI 服务器，监听端口、解析 HTTP 协议、把请求交给应用 | `uvicorn main:app`、`fastapi dev` |
| **Starlette** | Web 层的基础设施 | `Request`、`Response`、中间件、`StaticFiles`、`WebSocket` |
| **Pydantic** | 数据层 | `BaseModel`、`Field`、校验错误 |
| **FastAPI** | 胶水 + 增强 | `FastAPI()`、`@app.get`、`Depends`、`Query`、`Path`、`Body` |

> 💡 **ASGI vs WSGI**：Flask、Django（传统模式）使用 WSGI——一个请求占用一个线程直到返回，天生是同步的。ASGI 是它的异步继任者，允许单个进程在等待 I/O 时切换去处理别的请求，并原生支持 WebSocket、长连接等场景。`FastAPI()` 实例本身就是一个 ASGI 应用（一个可调用对象），所以它能被任何 ASGI 服务器运行。

### 1.2 与 Flask / Django 对比

| 维度 | FastAPI | Flask | Django（+ DRF） |
|---|---|---|---|
| 定位 | API 优先的轻量框架 | 通用微框架 | 全家桶 Web 框架 |
| 协议 | ASGI（原生异步） | WSGI（同步为主，2.0 起有限支持 async） | WSGI / ASGI（异步支持在逐步完善） |
| 参数解析与校验 | 类型提示 + Pydantic 自动完成 | 手动 `request.args.get()` 或扩展 | DRF Serializer |
| 接口文档 | 内置自动生成 | 需要扩展（flasgger 等） | 需要扩展（drf-spectacular 等） |
| ORM / 后台管理 | 不内置，自由选择（SQLAlchemy、SQLModel…） | 不内置 | 内置 ORM、Admin、Auth |
| 依赖注入 | 内置 `Depends` | 无 | 无 |
| 学习曲线 | 低（会类型提示即可） | 很低 | 较高 |
| 适合场景 | 前后端分离 API、微服务、AI/模型服务 | 小型站点、原型 | 内容型网站、需要后台管理的业务系统 |

**一句话选型**：要写 JSON API、关心性能和类型安全 → FastAPI；要一个带后台管理、用户系统的完整网站 → Django；只想快速写几个页面 → Flask。

## 3. 第一个应用

新建 `main.py`：

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/")
async def root():
    return {"message": "Hello FastAPI"}


@app.get("/items/{item_id}")
async def read_item(item_id: int, q: str | None = None):
    return {"item_id": item_id, "q": q}
```

逐行拆解：

| 代码 | 含义 |
|---|---|
| `app = FastAPI()` | 创建应用实例，它就是一个 ASGI 应用；变量名 `app` 是约定，运行命令会找它 |
| `@app.get("/")` | **路径操作装饰器**：当收到 `GET /` 请求时，调用下面的函数 |
| `async def root()` | **路径操作函数**（也叫端点、视图函数） |
| `return {...}` | 返回 dict、list、Pydantic 模型等，FastAPI 自动转成 JSON 响应 |
| `{item_id}` | 路径参数，值会按函数签名中的 `item_id: int` 转换成整数 |
| `q: str \| None = None` | 不在路径里的参数 → **查询参数**，有默认值所以是可选的 |

## 4. 运行方式

### 4.1 `fastapi dev`：开发模式

```bash
fastapi dev main.py
```

输出（节选）：

```text
 ⚡️ Starting FastAPI in development mode

 🐍 Using import string: main:app

 🌐 Server started at http://127.0.0.1:8000
    Documentation at http://127.0.0.1:8000/docs

INFO:     Will watch for changes in these directories: ['/path/to/fastapi-demo']
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
INFO:     Started reloader process [35962] using WatchFiles
INFO:     Application startup complete.
```

开发模式的特点：

- **自动重载**：保存代码后服务自动重启；
- 默认只监听 `127.0.0.1`（仅本机可访问）；
- 不传路径时，会依次尝试 `main.py`、`app.py`、`api.py`、`app/main.py` 等，并在其中查找名为 `app` 或 `api` 的 FastAPI 实例。

也可以在 `pyproject.toml` 中固定入口，之后直接 `fastapi dev` 即可：

```toml
[tool.fastapi]
entrypoint = "main:app"
```

### 4.2 `fastapi run`：生产模式

```bash
fastapi run main.py
```

与 `dev` 的区别：**关闭自动重载**，默认监听 `0.0.0.0`（所有网卡，容器里必须这样），默认端口同样是 8000。可以通过 `--workers 4` 启动多个进程（部署细节见 12.15）。

### 4.3 直接用 `uvicorn`

`fastapi` 命令底层就是 Uvicorn，也可以直接调用它：

```bash
uvicorn main:app --reload                       # 开发：自动重载
uvicorn main:app --host 0.0.0.0 --port 8080     # 指定监听地址和端口
```

`main:app` 的含义是「`main` 模块里的 `app` 对象」。如果应用在 `app/main.py` 中，就写成 `app.main:app`。

### 4.4 在脚本内启动（调试用）

```python
import uvicorn
from fastapi import FastAPI

app = FastAPI()


@app.get("/")
async def root():
    return {"message": "Hello FastAPI"}


if __name__ == "__main__":
    uvicorn.run("main:app", host="127.0.0.1", port=8000, reload=True)
```

这样可以直接 `python main.py` 运行，也方便在 IDE 里打断点调试。注意开启 `reload=True` 时必须传**导入字符串** `"main:app"`，而不是 `app` 对象本身。

| 方式 | 适合 | 特点 |
|---|---|---|
| `fastapi dev` | 日常开发 | 自动发现应用、自动重载、输出友好 |
| `fastapi run` | 生产 / 容器 | 无重载、监听 0.0.0.0、可多进程 |
| `uvicorn main:app` | 需要精细控制参数 | 选项最全，生产环境也常用 |
| `uvicorn.run(...)` | IDE 调试 | 可以 `python main.py` 启动 |

### 4.5 发送请求验证

服务跑起来后，另开一个终端：

```bash
curl http://127.0.0.1:8000/
# {"message":"Hello FastAPI"}

curl "http://127.0.0.1:8000/items/5?q=hello"
# {"item_id":5,"q":"hello"}

curl http://127.0.0.1:8000/items/5
# {"item_id":5,"q":null}

curl http://127.0.0.1:8000/items/foo
# {"detail":[{"type":"int_parsing","loc":["path","item_id"],"msg":"Input should be a valid integer, unable to parse string as an integer","input":"foo"}]}
```

注意最后一个请求：我们**一行校验代码都没写**，FastAPI 根据 `item_id: int` 自动返回了状态码 **422** 和详细的错误说明。错误体的结构会在 12.2 详细解读。

## 5. 自动生成的交互式文档

FastAPI 启动后自动提供三个地址：

| 地址 | 内容 |
|---|---|
| `http://127.0.0.1:8000/docs` | **Swagger UI**：可以直接在页面上填参数、点 “Try it out” 发请求 |
| `http://127.0.0.1:8000/redoc` | **ReDoc**：排版更适合阅读的文档 |
| `http://127.0.0.1:8000/openapi.json` | 原始的 **OpenAPI 3.1** 规范（JSON） |

`openapi.json` 的开头大致如下：

```json
{
  "openapi": "3.1.0",
  "info": {"title": "FastAPI", "version": "0.1.0"},
  "paths": {
    "/items/{item_id}": {
      "get": {
        "summary": "Read Item",
        "operationId": "read_item_items__item_id__get",
        "parameters": [
          {"name": "item_id", "in": "path", "required": true, "schema": {"type": "integer", "title": "Item Id"}},
          ...
```

这份 JSON 是**机器可读的接口契约**，用途远不止看文档：前端可以用它生成 TypeScript 客户端，测试工具（Postman、Apifox）可以直接导入，网关可以用它做校验。

### 5.1 定制文档信息

```python
from fastapi import FastAPI

app = FastAPI(
    title="商品服务",
    description="一个用于学习 FastAPI 的示例服务",
    version="1.0.0",
    docs_url="/docs",          # 设为 None 可关闭 Swagger UI
    redoc_url=None,            # 关闭 ReDoc
    openapi_url="/openapi.json",
)


@app.post(
    "/items",
    status_code=201,
    tags=["items"],
    summary="创建商品",
)
async def create_item():
    """创建一个商品。

    - **name**: 商品名称
    - **price**: 价格，必须大于 0
    """
    return {"ok": True}
```

- `title`、`description`、`version` 会显示在文档顶部；
- `tags` 用于在文档中对接口分组；
- `summary` 是接口的标题，不写时默认用函数名转换（`create_item` → `Create Item`）；
- 函数的 **docstring** 会作为接口描述，支持 Markdown；
- `status_code=201` 指定成功时的状态码（创建资源通常用 201）。

> ⚠️ 生产环境如果不希望公开接口文档，把 `docs_url`、`redoc_url`、`openapi_url` 都设为 `None` 即可，或者通过配置按环境开关。

## 6. 路径操作装饰器与 HTTP 方法

FastAPI 为每种 HTTP 方法都提供了对应装饰器：

| 装饰器 | HTTP 方法 | 典型语义 | 是否幂等 |
|---|---|---|---|
| `@app.get()` | GET | 查询资源 | ✅ |
| `@app.post()` | POST | 创建资源 / 触发动作 | ❌ |
| `@app.put()` | PUT | 整体替换资源 | ✅ |
| `@app.patch()` | PATCH | 部分更新资源 | ❌（通常） |
| `@app.delete()` | DELETE | 删除资源 | ✅ |
| `@app.head()` / `@app.options()` / `@app.trace()` | 其余方法 | 较少手写 | — |

一个典型的 RESTful 资源接口：

```python
from fastapi import FastAPI

app = FastAPI()

fake_db: dict[int, dict] = {1: {"name": "键盘"}, 2: {"name": "鼠标"}}


@app.get("/items")
async def list_items():
    return list(fake_db.values())


@app.get("/items/{item_id}")
async def get_item(item_id: int):
    return fake_db.get(item_id)


@app.post("/items", status_code=201)
async def create_item(name: str):
    new_id = max(fake_db) + 1
    fake_db[new_id] = {"name": name}
    return {"id": new_id, "name": name}


@app.delete("/items/{item_id}", status_code=204)
async def delete_item(item_id: int):
    fake_db.pop(item_id, None)
```

```bash
curl -X POST "http://127.0.0.1:8000/items?name=monitor"
# {"id":3,"name":"monitor"}

curl -X DELETE http://127.0.0.1:8000/items/3 -i
# HTTP/1.1 204 No Content
```

> ⚠️ curl 不会自动对 URL 中的中文做百分号编码，直接写 `?name=显示器` 会被 Uvicorn 拒绝（`Invalid HTTP request received`）。中文参数要手动编码成 `?name=%E6%98%BE%E7%A4%BA%E5%99%A8`，或者用 `/docs` 页面、httpx 等会自动编码的工具发请求。

> 💡 这里 `create_item(name: str)` 的 `name` 是查询参数，仅用于演示。真实项目中创建资源的数据应放在**请求体**里，这正是 12.3 的内容。

同一路径注册多个方法时，用 `api_route`：

```python
from fastapi import FastAPI

app = FastAPI()


@app.api_route("/ping", methods=["GET", "POST"])
async def ping():
    return {"pong": True}
```

用未注册的方法访问已存在的路径，会得到 `405 Method Not Allowed`：

```bash
curl -X PUT http://127.0.0.1:8000/ping
# {"detail":"Method Not Allowed"}

curl http://127.0.0.1:8000/not-exist
# {"detail":"Not Found"}        ← 404
```

### 6.1 返回值会被怎样处理

路径操作函数可以返回多种类型，FastAPI 会用 `jsonable_encoder` 把它转换成 JSON：

| 返回值 | 结果 |
|---|---|
| `dict` / `list` / `str` / `int` / `None` | 直接序列化成 JSON |
| Pydantic 模型 | 序列化成 JSON 对象 |
| `datetime`、`UUID`、`Decimal`、`Enum` 等 | 自动转换成 JSON 可表示的值 |
| `Response` 及其子类 | **原样返回**，不再做任何处理（12.5 详解） |

## 7. `async def` 还是 `def`？

这是初学 FastAPI 最容易出错、也最重要的一个问题。FastAPI 两种写法都支持，但执行方式完全不同：

| 写法 | 在哪里执行 | 适合 |
|---|---|---|
| `async def` | 直接在**事件循环**（主线程）中执行 | 函数里调用的都是 `await` 异步库（`httpx.AsyncClient`、异步数据库驱动、`asyncio.sleep`） |
| `def` | 被丢到**线程池**中执行，不阻塞事件循环 | 函数里调用的是同步阻塞库（`requests`、同步数据库驱动、文件 I/O、`time.sleep`） |

验证一下：

```python
import threading

from fastapi import FastAPI

app = FastAPI()


@app.get("/sync")
def sync_endpoint():
    return {"thread": threading.current_thread().name}


@app.get("/async")
async def async_endpoint():
    return {"thread": threading.current_thread().name}
```

```bash
curl http://127.0.0.1:8000/sync
# {"thread":"AnyIO worker thread"}       ← 线程池中的工作线程

curl http://127.0.0.1:8000/async
# {"thread":"MainThread"}                ← 事件循环所在的主线程
```

### 7.1 错误示范：在 `async def` 里阻塞

```python
import asyncio
import time

from fastapi import FastAPI

app = FastAPI()


@app.get("/bad")
async def bad():
    time.sleep(1)  # ❌ 在 async def 里调用同步阻塞函数
    return {"ok": "bad"}


@app.get("/good-async")
async def good_async():
    await asyncio.sleep(1)  # ✅ 异步等待，不阻塞事件循环
    return {"ok": "good-async"}


@app.get("/good-sync")
def good_sync():
    time.sleep(1)  # ✅ 普通 def，会被放到线程池执行
    return {"ok": "good-sync"}
```

用 `uvicorn block:app` 启动后，对每个接口**同时**发 5 个请求，实测总耗时：

| 接口 | 5 个并发请求总耗时 | 原因 |
|---|---|---|
| `/bad` | **约 5 秒** | `time.sleep` 卡住了事件循环，5 个请求只能排队一个个处理 |
| `/good-async` | 约 1 秒 | `await` 时事件循环切去处理其他请求 |
| `/good-sync` | 约 1 秒 | 5 个请求分别在线程池的 5 个线程中执行 |

`/bad` 的危害不只是自己慢：**在它阻塞期间，整个进程里的所有其他接口都无法响应**。这和 8.8 中「在协程里调用 `time.sleep()` 会让所有任务一起变慢」是同一个道理。

### 7.2 选择规则

```text
函数里需要 await 吗？
├── 是 → 用 async def（且内部所有 I/O 都必须是异步的）
└── 否 → 函数里有阻塞 I/O 吗（requests、同步 DB、读大文件）？
         ├── 是 → 用 def（交给线程池）
         └── 否（纯计算、直接返回数据）→ 两者皆可，async def 略省一次线程切换
```

> 💡 拿不准时**用 `def`**：最坏情况只是多一次线程切换的开销；而在 `async def` 里误用阻塞调用，最坏情况是整个服务卡死。
>
> ⚠️ 线程池默认大小是 40 个线程。`def` 接口并不是无限并发的，大量慢速同步请求同样会排队。CPU 密集型任务（图像处理、大量计算）更适合交给进程池或任务队列，见 12.11、12.15。

## 8. 一个请求的完整旅程

把本节内容串起来，一次 `GET /items/5?q=hello` 请求经历了：

```text
客户端
  │ HTTP 请求
  ▼
Uvicorn ── 解析 HTTP，构造 ASGI scope，调用 app(scope, receive, send)
  ▼
中间件（12.10）── 例如 CORS、日志、计时
  ▼
路由匹配 ── 按声明顺序匹配路径 + 方法；匹配不到 → 404/405
  ▼
参数解析与校验 ── 依据函数签名从路径/查询/请求体/Header 取值，用 Pydantic 校验
  │                 校验失败 → 直接返回 422，函数不会被调用
  ▼
依赖注入（12.7）── 执行 Depends 声明的依赖
  ▼
执行路径操作函数 ── async def 在事件循环中，def 在线程池中
  ▼
返回值处理 ── response_model 过滤（12.5）→ jsonable_encoder → JSONResponse
  ▼
Uvicorn ── 写回 HTTP 响应
```

记住这张图，后面每一节其实都是在其中某一环上展开。

```text
└── body.py            # 12.3 示例
```

项目变大后如何拆分为 `routers/`、`models/`、`services/` 等模块，见 12.12。

## 常见坑

1. **zsh 安装报 `no matches found`**：`pip install "fastapi[standard]"` 要加引号。
2. **文件名叫 `fastapi.py`**：会遮蔽真正的 `fastapi` 包，导致 `ImportError: cannot import name 'FastAPI'`。示例文件不要和库同名。
3. **`uvicorn main:app` 找不到模块**：必须在 `main.py` 所在目录执行，或写成完整的包路径 `app.main:app`。
4. **`uvicorn.run(app, reload=True)` 报错或不重载**：开启重载时要传导入字符串 `"main:app"`。
5. **在 `async def` 里调用 `requests.get()`、`time.sleep()`、同步数据库驱动**：会阻塞整个服务。要么换成异步库，要么把函数改成 `def`。
6. **`fastapi dev` 在容器里外部访问不到**：dev 默认只监听 `127.0.0.1`，需要 `--host 0.0.0.0`，生产用 `fastapi run`。
7. **修改代码后接口没变化**：确认是否用了 `--reload` / `fastapi dev`；`fastapi run` 不会自动重载。
8. **以为返回 `None` 会得到空响应体**：返回 `None` 时响应体是 JSON 的 `null`；要真正的「无内容」，用 `status_code=204`。

## 小结

- FastAPI = **Starlette**（Web 层）+ **Pydantic**（数据层）+ 类型提示驱动的路由和文档生成，运行在 **Uvicorn** 等 ASGI 服务器上。
- 安装用 `"fastapi[standard]"`，开发用 `fastapi dev`，生产用 `fastapi run` 或 `uvicorn`。
- 每个应用自带 `/docs`、`/redoc`、`/openapi.json`，类型提示即文档。
- 路径操作 = HTTP 方法装饰器 + 路径 + 函数；返回值自动转为 JSON。
- 参数类型不对时自动返回 422，函数根本不会执行。
- `async def` 在事件循环中运行，**里面绝不能有阻塞调用**；`def` 在线程池中运行，适合同步库。拿不准就用 `def`。
