### 3. 找错：JWT 校验

```python

from fastapi import Depends, FastAPI, HTTPException
```

### 4. scopes 累加

### 5. 认证还是授权

```python
from typing import Annotated

from fastapi import APIRouter, Depends, FastAPI, HTTPException
from fastapi.security import OAuth2PasswordBearer
from fastapi.testclient import TestClient

app = FastAPI()
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")
ROLES = {"t1": "admin", "t2": "user"}


def current_role(token: Annotated[str, Depends(oauth2_scheme)]) -> str:
    if token not in ROLES:
        raise HTTPException(401, "bad token")
    return ROLES[token]


def admin_only(role: Annotated[str, Depends(current_role)]):
    if role != "admin":
        raise HTTPException(403, "forbidden")


router = APIRouter(prefix="/admin", dependencies=[Depends(admin_only)])


@router.get("/ping")
def ping():
    return "pong"


app.include_router(router)
client = TestClient(app)
for headers in [{}, {"Authorization": "Bearer t9"}, {"Authorization": "Bearer t2"}, {"Authorization": "Bearer t1"}]:
    r = client.get("/admin/ping", headers=headers)
    print(r.status_code, r.json())
```

## 三、编程题

### 1. 多 Key API 认证

实现一个 API Key 认证依赖：

- Key 可以来自请求头 `X-API-Key` 或查询参数 `api_key`；
- 服务端只保存 Key 的 **SHA-256 摘要**（API Key 本身是高熵随机串，快速哈希即可），校验时用 `secrets.compare_digest` 比较摘要；
- 每个 Key 关联一个客户端名称和一个"每日配额"，超出配额返回 429；
- 用 `TestClient` 覆盖：缺少 Key、Key 错误、两种位置都能用、超出配额。

### 2. 注册与登录

在本节第 7 节完整示例的基础上增加：

- `POST /register`：接收 JSON `{username, password, email}`，用户名已存在返回 409，密码长度少于 8 位返回 422（用 Pydantic 校验）；
- 密码用 pwdlib 哈希后存储；
- 注册成功返回用户信息（不能包含任何密码相关字段）；
- 编写测试：注册 → 登录 → 访问 `/users/me` 的完整流程。

### 3. 角色与资源归属

实现一个文章 API：

- 用户有 `admin`、`author`、`reader` 三种角色；
- `GET /posts`：任何已登录用户；
- `POST /posts`：`author` 或 `admin`；
- `PUT /posts/{id}`：作者本人或 `admin`；
- `DELETE /posts/{id}`：仅 `admin`；
- 角色检查用 `RoleChecker` 类实现，归属检查用"加载资源 + 检查归属"依赖实现；
- 测试中用 `app.dependency_overrides` 替换 `get_current_user`，快速切换不同身份。

### 4. 双 token 与注销

在第 10 节示例的基础上：

- 登录时把 refresh token 写入 `HttpOnly` Cookie，access token 放在响应体中；
- `POST /refresh` 从 Cookie 读取 refresh token（用 `APIKeyCookie`），轮换后写入新 Cookie；
- 实现 `POST /logout`：撤销当前 refresh token 并删除 Cookie；
- 检测"已撤销的 refresh token 被再次使用"时，撤销该用户的**所有** refresh token（提示：按用户维护 jti 集合）；
- 用 `TestClient` 验证完整流程。

### 5. scopes 授权

为一个"日历"服务设计 scopes：`calendar:read`、`calendar:write`、`profile`：

- `/token` 根据用户可用权限与申请的 scope 求交集后签发；
- `GET /events` 需要 `calendar:read`，`POST /events` 需要 `calendar:read` 和 `calendar:write`，`GET /me` 需要 `profile`；
- 缺少 scope 时返回 403，并在 `WWW-Authenticate` 头中写明所需的 scope；
- 在 `/docs` 中验证：登录时只勾选部分 scope，观察哪些接口可以调用。

## 四、综合实践：带完整认证体系的待办事项 API

实现一个单文件（或按模块拆分）的待办事项服务：

1. **用户体系**：注册、登录（`OAuth2PasswordRequestForm`）、获取当前用户、修改密码（需要验证旧密码，修改后旧 token 失效——提示：在 payload 中加入"密码版本号"或在用户表记录 `password_changed_at`，校验 `iat`）。
2. **密码安全**：pwdlib + Argon2；登录失败统一提示；用户不存在时也执行哈希校验；同一用户名 5 分钟内失败 5 次后锁定 15 分钟。
3. **Token**：access token 15 分钟，refresh token 7 天并轮换；`SECRET_KEY` 从环境变量读取，缺失时启动失败（而不是悄悄使用默认值）。
4. **授权**：普通用户只能访问自己的待办事项；`admin` 角色可以查看所有用户和所有待办事项；`/admin` 路由器整体由路由器级依赖保护。
5. **响应安全**：所有返回用户的接口使用 `response_model`，确保不泄露哈希；错误响应不暴露内部异常信息。
6. **测试**：至少 10 个测试用例，覆盖登录成功/失败、token 过期（提示：签发一个 `exp` 在过去的 token）、token 被篡改、错误的 token 类型、越权访问、锁定逻辑。
