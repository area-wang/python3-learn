## 三、编程题

### 1. 基础接口测试

为下面的应用编写测试，要求覆盖：正常创建、重复创建（409）、缺少字段（422）、`price` 为负数（422）、查询不存在的商品（404）。使用 `@pytest.mark.parametrize` 合并所有 422 场景。

```python
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field

app = FastAPI()
items: dict[str, float] = {}


class Item(BaseModel):
    name: str
    price: float = Field(gt=0)


@app.post("/items/", status_code=201)
def create_item(item: Item):
    if item.name in items:
        raise HTTPException(status_code=409, detail="已存在")
    items[item.name] = item.price
    return item


@app.get("/items/{name}")
def get_item(name: str):
    if name not in items:
        raise HTTPException(status_code=404, detail="不存在")
    return {"name": name, "price": items[name]}
```

注意：`items` 是模块级字典，测试之间会互相污染。请用 fixture（如 `autouse=True`）保证每个测试开始时它是空的。

## 四、综合实践：为博客 API 建立完整测试体系

为一个包含用户注册登录（JWT）、文章增删改查、评论、文章封面上传的博客 API 建立测试体系：

1. 目录结构：`tests/conftest.py`、`tests/unit/`（service 层单元测试，不经过 HTTP）、`tests/api/`（接口测试）；
2. `conftest.py` 提供：测试数据库（事务回滚）、`client`、`user_factory`、`post_factory`、`auth_client(user)`（返回已带 token 的客户端）等 fixture；

5. 文章发布后会调用外部"内容审核服务"，用 `respx` 模拟审核通过、拒绝、服务不可用三种情况；
