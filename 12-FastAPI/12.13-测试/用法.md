# 12.13 测试

上一节把项目拆成了 router / service / repository 等多个层次，并且通过依赖注入把它们串起来。这样做的一大回报就是**好测**。本节讲如何给 FastAPI 应用写自动化测试：用 `TestClient` 在不启动服务器的情况下发请求，用 pytest 的 fixture 组织测试，用 `app.dependency_overrides` 替换数据库、当前用户、外部服务等依赖，用「内存 SQLite + 事务回滚」让每个测试拥有干净的数据库，以及如何测试 lifespan、异步代码、WebSocket 和统计覆盖率。

> 本节以 10.6 中的 pytest 基础为前提。代码在 FastAPI 0.143 / Starlette 1.8 / SQLAlchemy 2.1 / pytest 9 / Python 3.14 下实际跑通。

## 1. 准备工作

```bash
pip install "fastapi[standard]" pytest pytest-cov httpx2 respx
```

| 包 | 用途 |

### 1.1 版本差异：`httpx` 与 `httpx2`

`fastapi.testclient.TestClient` 就是 `starlette.testclient.TestClient`，它基于 httpx 风格的客户端实现。查看 Starlette 1.8 的 `starlette/testclient.py` 源码，导入时的逻辑是：

1. 优先 `import httpx2 as httpx`（httpx2 是 httpx 作者维护的下一代版本，API 与 httpx 保持一致）；
2. 没有 `httpx2` 时退回到 `httpx`，**测试照常能跑**，但会发出警告；
3. 两者都没有则报 `RuntimeError`，提示 `pip install httpx2`。

而 `fastapi[standard]` 目前只自带 `httpx`，所以新建项目直接跑测试会看到：

```text
=============================== warnings summary ===============================
.../fastapi/testclient.py:1: StarletteDeprecationWarning: Using `httpx` with `starlette.testclient` is deprecated; install `httpx2` instead.
    from starlette.testclient import TestClient as TestClient  # noqa

23 passed, 1 warning in 0.10s
```

消除方法二选一：

```bash
pip install httpx2         # 推荐：TestClient 自动改用 httpx2，测试代码一行都不用改
```

或者暂时在 pytest 配置里忽略这条警告（注意它的类别是 `StarletteDeprecationWarning`，它继承自 `UserWarning` 而**不是** `DeprecationWarning`，写成 `DeprecationWarning` 是过滤不掉的）：

```toml
# pyproject.toml
[tool.pytest.ini_options]
filterwarnings = [
    "ignore:Using `httpx` with `starlette.testclient`:starlette.exceptions.StarletteDeprecationWarning",
]
```

> 💡 这条警告只与 `TestClient` 有关。第 9 节异步测试用的 `httpx.AsyncClient` + `ASGITransport` 是直接使用 `httpx`，本身不触发警告；不过只要测试中（包括 `conftest.py`）导入了 `TestClient`，整个测试会话里就会出现一次。装了 `httpx2` 后，`TestClient` 的用法、`response` 对象的属性与本节示例完全一致。老版本 FastAPI/Starlette（Starlette 1.0 之前）只需要 `httpx`，不会有这条警告。

## 2. `TestClient` 基础

`TestClient` 直接在进程内调用 ASGI 应用，**不需要启动 uvicorn、不占用端口**，速度非常快。它的用法和 `requests`/`httpx` 几乎一样。

```python
# main.py
from fastapi import FastAPI, HTTPException

app = FastAPI()

fake_items = {"foo": {"name": "Foo", "price": 10.5}}


@app.get("/")
def root():
    return {"message": "Hello World"}


@app.get("/items/{item_id}")
def read_item(item_id: str):
    if item_id not in fake_items:
        raise HTTPException(status_code=404, detail="Item not found")
    return fake_items[item_id]
```

```python
# test_main.py
from fastapi.testclient import TestClient

from main import app

client = TestClient(app)


def test_root():
    response = client.get("/")
    assert response.status_code == 200
    assert response.json() == {"message": "Hello World"}


def test_read_item():
    response = client.get("/items/foo")
    assert response.status_code == 200
    assert response.json() == {"name": "Foo", "price": 10.5}


def test_read_missing_item():
    response = client.get("/items/bar")
    assert response.status_code == 404
    assert response.json() == {"detail": "Item not found"}
```

```bash
$ pytest -v
test_main.py::test_root PASSED                                           [ 33%]
test_main.py::test_read_item PASSED                                      [ 66%]
test_main.py::test_read_missing_item PASSED                              [100%]

============================== 3 passed in 0.19s ===============================
```

注意测试函数是普通的 `def`，不是 `async def`——即使被测接口是 `async def`，`TestClient` 也会在内部帮你跑事件循环。

`response` 对象常用属性：

| 属性/方法 | 说明 |
|---|---|
| `status_code` | 状态码 |
| `json()` | 解析 JSON 响应体 |
| `text` / `content` | 文本 / 字节形式的响应体 |
| `headers` | 响应头（大小写不敏感） |
| `cookies` | 响应设置的 cookie |

> ⚠️ `TestClient` 默认 `raise_server_exceptions=True`：服务器端未处理的异常会**直接在测试中抛出**（而不是返回 500），方便看到真实的错误栈。如果就是想测试 500 响应（比如验证 12.6 中的全局异常处理器），用 `TestClient(app, raise_server_exceptions=False)`：
>
> ```python
> client = TestClient(app, raise_server_exceptions=False)
> assert client.get("/boom").status_code == 500
> ```

from collections.abc import Iterator

from sqlalchemy import create_engine
from sqlalchemy.orm import DeclarativeBase, Session, sessionmaker

DATABASE_URL = "sqlite:///./todo.db"

engine = create_engine(DATABASE_URL, connect_args={"check_same_thread": False})
SessionLocal = sessionmaker(bind=engine, autoflush=False)


class Base(DeclarativeBase):
    pass


def get_db() -> Iterator[Session]:
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()

from typing import Annotated

    Depends,
    FastAPI,
    Form,
    Header,
    HTTPException,
    UploadFile,

from app.database import Base, engine, get_db
from app.models import Todo
from app.weather import WeatherClient, fetch_temperature, get_weather_client

## 4. 用 `conftest.py` 和 fixture 组织测试

`conftest.py` 中定义的 fixture 会被同目录及子目录下的所有测试文件自动发现，不需要 import。测试里的「公共准备工作」——创建测试数据库、创建客户端、准备登录凭证——都放在这里。

```python
# tests/conftest.py
from collections.abc import Iterator

import pytest
from fastapi.testclient import TestClient
from sqlalchemy import create_engine
from sqlalchemy.orm import Session
from sqlalchemy.pool import StaticPool

from app.auth import get_current_user
from app.database import Base, get_db
from app.main import app

# 内存 SQLite：StaticPool 保证所有连接共用同一个底层连接，否则每个连接都是一个全新的空库
engine = create_engine(
    "sqlite://",
    # autocommit=False（Python 3.12+）让 sqlite3 驱动正确处理 BEGIN/SAVEPOINT，回滚才能生效
    connect_args={"check_same_thread": False, "autocommit": False},
    poolclass=StaticPool,
)
Base.metadata.create_all(bind=engine)


@pytest.fixture
def db_session() -> Iterator[Session]:
    """每个测试一个外层事务，测试结束后整体回滚，测试之间互不污染。"""
    connection = engine.connect()
    transaction = connection.begin()
    session = Session(bind=connection, join_transaction_mode="create_savepoint")
    yield session
    session.close()
    transaction.rollback()
    connection.close()


@pytest.fixture
def client(db_session: Session) -> Iterator[TestClient]:
    def override_get_db():
        yield db_session

    app.dependency_overrides[get_db] = override_get_db
    yield TestClient(app)
    app.dependency_overrides.clear()


@pytest.fixture
def auth_headers() -> dict[str, str]:
    return {"Authorization": "Bearer token-alice"}


@pytest.fixture
def as_user(client: TestClient):
    """跳过真实鉴权，直接指定当前用户。用法：as_user("bob")。"""

    def _login_as(username: str) -> TestClient:
        app.dependency_overrides[get_current_user] = lambda: username
        return client

    return _login_as
```

fixture 之间的依赖关系：`as_user` → `client` → `db_session`。测试函数只要在参数里写 `client`，pytest 就会按顺序创建 `db_session` 和 `client`；测试结束后按相反顺序执行 `yield` 之后的清理代码。

这里用到了三个关键技术，下面逐一展开。

## 5. `app.dependency_overrides`：替换依赖

`app.dependency_overrides` 是一个字典：**键是原依赖函数，值是替代函数**。FastAPI 解析依赖时，如果发现某个依赖在这个字典里，就改用替代函数。

```python
app.dependency_overrides[get_db] = override_get_db            # 换数据库
app.dependency_overrides[get_current_user] = lambda: "bob"     # 跳过鉴权
app.dependency_overrides[get_weather_client] = FakeWeatherClient  # 换外部服务
```

要点：

| 要点 | 说明 |
|---|---|
| 键必须是**同一个函数对象** | 必须是 `Depends(...)` 里写的那个函数，从定义它的模块 import 进来 |
| 替代函数也可以有参数 | 替代函数的参数同样会被当作依赖解析（可以声明 `Query`、`Header`、其他 `Depends`） |
| 替代函数可以是 `yield` 依赖 | 如上面的 `override_get_db` |
| 对子依赖同样有效 | 覆盖 `get_current_user` 后，它内部依赖的 `oauth2_scheme` 也不会再执行，所以不需要 token |
| 全局生效 | 它是挂在 `app` 上的普通字典，**不清理就会泄漏到后续测试** |

> ⚠️ 一定要在 fixture 的 `yield` 之后调用 `app.dependency_overrides.clear()`（或 `pop` 掉自己设置的键）。把覆盖写在测试函数体里而不清理，会导致后面的测试莫名其妙地"通过"或"失败"，而且结果依赖于测试执行顺序，极难排查。

## 6. 测试数据库：内存 SQLite + 事务回滚

测试数据库要满足两点：**和开发/生产库隔离**、**每个测试开始时都是干净的**。

### 6.1 为什么需要 `StaticPool`

`sqlite://`（不带文件名）表示内存数据库。内存数据库的特点是：**每一个新连接都是一个全新的空库**。SQLAlchemy 对内存 SQLite 默认使用 `SingletonThreadPool`——**每个线程一个连接**。而 FastAPI 会把同步（`def`）接口放到线程池里执行，`TestClient` 本身也在另一个线程里运行应用，于是在主线程 `create_all` 建的表，请求处理线程里却"不存在"，接口直接 500（`no such table`）。`StaticPool` 让整个引擎不论哪个线程都只用同一个底层连接，问题就解决了。`check_same_thread=False` 则允许这个连接被多个线程使用。

### 6.2 每个测试一个事务，结束时回滚

`db_session` fixture 的思路：

1. 从引擎拿一个连接，**开启外层事务**；
2. 把 Session 绑定到这个连接上，`join_transaction_mode="create_savepoint"` 表示：业务代码里的 `db.commit()` 只会提交一个 SAVEPOINT（保存点），不会真正提交外层事务；
3. 测试结束后回滚外层事务，测试期间写入的所有数据都消失。

这样业务代码完全不用改（照常 `commit`），而测试之间互不影响：

```python
# tests/test_todos.py
from fastapi.testclient import TestClient
from sqlalchemy import select
from sqlalchemy.orm import Session

from app.models import Todo


def test_create_todo(client: TestClient, auth_headers):
    response = client.post("/todos/", json={"title": "写测试"}, headers=auth_headers)
    assert response.status_code == 201
    data = response.json()
    assert data["title"] == "写测试"
    assert data["done"] is False
    assert data["owner"] == "alice"


def test_create_todo_validation(client: TestClient, auth_headers):
    response = client.post("/todos/", json={"title": ""}, headers=auth_headers)
    assert response.status_code == 422


def test_db_is_isolated(client: TestClient, auth_headers):
    # 上一个测试插入的数据已被回滚，这里看到的是空表
    assert client.get("/todos/", headers=auth_headers).json() == []


def test_todo_written_to_db(client: TestClient, db_session: Session, auth_headers):
    client.post("/todos/", json={"title": "检查数据库"}, headers=auth_headers)
    todo = db_session.scalars(select(Todo)).one()
    assert todo.title == "检查数据库"


def test_prepare_data_directly(as_user, db_session: Session):
    # 直接往数据库里准备数据，比调接口更快、更可控
    db_session.add_all([Todo(title="A", owner="alice"), Todo(title="B", owner="bob")])
    db_session.commit()

    client = as_user("bob")  # 覆盖 get_current_user，不需要 token
    titles = [t["title"] for t in client.get("/todos/").json()]
    assert titles == ["B"]


def test_cannot_read_others_todo(as_user, db_session: Session):
    todo = Todo(title="alice 的秘密", owner="alice")
    db_session.add(todo)
    db_session.commit()

    client = as_user("bob")
    assert client.get(f"/todos/{todo.id}").status_code == 404
```

`test_todo_written_to_db` 演示了同时从 HTTP 和数据库两个角度断言：测试拿到的 `db_session` 和接口里用的是同一个 Session，所以能直接查到接口写入的数据。

> ⚠️ **SQLite 驱动的事务陷阱**：Python 标准库 `sqlite3` 默认的事务处理方式与 SQLAlchemy 的 SAVEPOINT 机制不兼容。如果去掉 `"autocommit": False`，上面 `test_db_is_isolated` 等测试会失败——前一个测试的数据没有被回滚。实测结果：
>
> ```text
> FAILED tests/test_todos.py::test_db_is_isolated - AssertionError: assert [{'i...
> FAILED tests/test_todos.py::test_todo_written_to_db - sqlalchemy.exc.Multiple...
> FAILED tests/test_todos.py::test_prepare_data_directly - AssertionError: asse...
> ```
>
> Python 3.12+ 用 `connect_args={"autocommit": False}` 即可；更老的 Python 需要用 SQLAlchemy 文档中的事件监听写法：
>
> ```python
> from sqlalchemy import event
>
>
> @event.listens_for(engine, "connect")
> def _do_connect(dbapi_connection, connection_record):
>     dbapi_connection.isolation_level = None   # 关闭驱动自带的事务管理
>
>
> @event.listens_for(engine, "begin")
> def _do_begin(conn):
>     conn.exec_driver_sql("BEGIN")             # 由 SQLAlchemy 显式开启事务
> ```

### 6.3 几种测试数据库方案对比

| 方案 | 速度 | 隔离性 | 与生产一致性 | 说明 |
|---|---|---|---|---|
| 内存 SQLite + 事务回滚（本节） | 最快 | 好 | 低 | 学习和中小项目首选 |
| 每个测试 `drop_all` + `create_all` | 慢（表多时明显） | 好 | 低 | 实现最简单，不依赖事务 |
| 独立的测试 PostgreSQL + 事务回滚 | 中 | 好 | 高 | 用到数据库特有功能（JSONB、数组等）时必须 |
| Docker / testcontainers 临时起库 | 慢 | 最好 | 最高 | CI 中常用 |

> 💡 SQLite 和 PostgreSQL/MySQL 在类型、约束、大小写、并发上都有差异。核心逻辑在 SQLite 上测通后，CI 里最好再用与生产相同的数据库跑一遍。

## 7. 测试各种类型的请求

`TestClient` 的请求方法参数与 httpx 一致：

| 参数 | 用途 | Content-Type |
|---|---|---|
| `params={...}` | 查询参数 | — |
| `json={...}` | JSON 请求体 | `application/json` |
| `data={...}` | 表单 | `application/x-www-form-urlencoded` |
| `files={...}` | 文件上传（可与 `data` 同时使用） | `multipart/form-data` |
| `headers={...}` | 请求头 | — |
| `client.cookies.set(k, v)` | 设置 cookie（作用于后续所有请求） | — |

```python
# tests/test_requests.py
import pytest
from fastapi.testclient import TestClient


@pytest.mark.parametrize(
    ("username", "password", "status_code"),
    [
        ("alice", "secret", 200),
        ("alice", "wrong", 400),
        ("nobody", "secret", 400),
    ],
)
def test_login(client: TestClient, username, password, status_code):
    # data= 发送表单（application/x-www-form-urlencoded）
    response = client.post("/login", data={"username": username, "password": password})
    assert response.status_code == status_code


def test_login_missing_field(client: TestClient):
    response = client.post("/login", data={"username": "alice"})
    assert response.status_code == 422
    assert response.json()["detail"][0]["loc"] == ["body", "password"]


def test_upload(client: TestClient):
    # files= 发送 multipart/form-data，元组为 (文件名, 内容, MIME 类型)
    files = {"file": ("hello.txt", b"hello world", "text/plain")}
    response = client.post("/upload", files=files)
    assert response.json() == {"filename": "hello.txt", "size": 11, "type": "text/plain"}


def test_headers_and_cookies(client: TestClient):
    client.cookies.set("session_id", "abc123")
    response = client.get("/whoami", headers={"User-Agent": "pytest"})
    assert response.json() == {"user_agent": "pytest", "session_id": "abc123"}


def test_login_then_use_token(client: TestClient):
    token = client.post("/login", data={"username": "bob", "password": "123456"}).json()[
        "access_token"
    ]
    response = client.post(
        "/todos/", json={"title": "买牛奶"}, headers={"Authorization": f"Bearer {token}"}
    )
    assert response.status_code == 201
    assert response.json()["owner"] == "bob"


def test_no_token(client: TestClient):
    response = client.get("/todos/")
    assert response.status_code == 401
    assert response.headers["www-authenticate"] == "Bearer"
```

`@pytest.mark.parametrize` 把一个测试函数展开成多个用例，pytest 输出中会显示参数：

```text
tests/test_requests.py::test_login[alice-secret-200] PASSED
tests/test_requests.py::test_login[alice-wrong-400] PASSED
tests/test_requests.py::test_login[nobody-secret-400] PASSED
```

**鉴权接口的两种测试思路**：

| 思路 | 示例 | 适合 |
|---|---|---|
| 走完整流程：先登录拿 token，再带 token 请求 | `test_login_then_use_token` | 测试鉴权本身是否正确 |
| 覆盖 `get_current_user` 直接指定用户 | `as_user("bob")` | 测试业务逻辑，鉴权不是重点 |

> ⚠️ 不要在每个请求里传 `cookies=...` 参数——新版 httpx 已弃用"单次请求级别"的 cookie，会产生警告 `Setting per-request cookies=<...> is being deprecated ... Set cookies directly on the client instance instead.`，应设置在客户端上：`client.cookies.set(...)`。由于 `client` fixture 每个测试都新建，cookie 不会泄漏到其他测试。

## 8. 测试 lifespan

12.11 讲过，`lifespan` 中的启动/关闭逻辑（建表、连接池、加载模型等）在应用启动和关闭时执行。`TestClient` **只有在 `with` 语句中使用时才会触发 lifespan**：

```python
# tests/test_lifespan.py
from fastapi.testclient import TestClient

from app.main import app


def test_without_context_manager():
    client = TestClient(app)              # 不触发 lifespan
    assert client.get("/health").json() == {"ready": False}


def test_with_context_manager():
    with TestClient(app) as client:       # 进入时执行 yield 之前的代码
        assert client.get("/health").json() == {"ready": True}
    assert app.state.ready is False       # 退出时执行 yield 之后的代码
```

如果应用依赖 lifespan 中初始化的资源（比如 `app.state.redis`），那么 `client` fixture 就要写成：

```python
@pytest.fixture
def client():
    with TestClient(app) as c:
        yield c
```

> ⚠️ 本例的 lifespan 会对 `app/database.py` 中的**真实引擎**执行 `create_all`，所以运行 `test_with_context_manager` 后项目目录下会多出一个 `todo.db`。真实项目中应当让数据库地址来自配置（12.12 的 `Settings`），测试时通过环境变量指向测试库，避免 lifespan 动到开发数据库。

## 9. 异步测试

`TestClient` 适用于绝大多数场景。但如果**测试函数本身**需要 `await`（例如测试中还要调用异步的数据库驱动、异步的 service），就需要异步测试。

FastAPI 依赖的 `anyio` 自带 pytest 插件，用 `@pytest.mark.anyio` 标记测试，配合 `httpx.AsyncClient` + `ASGITransport` 发请求：

```python
# tests/test_async.py
import httpx
import pytest

from app.main import app


@pytest.fixture
def anyio_backend():
    return "asyncio"


@pytest.mark.anyio
async def test_root_async():
    transport = httpx.ASGITransport(app=app)
    async with httpx.AsyncClient(transport=transport, base_url="http://test") as ac:
        response = await ac.get("/health")
    assert response.status_code == 200
    # ASGITransport 不会触发 lifespan
    assert response.json() == {"ready": False}


@pytest.mark.anyio
async def test_with_lifespan():
    # 手动进入 lifespan 上下文
    async with app.router.lifespan_context(app):
        transport = httpx.ASGITransport(app=app)
        async with httpx.AsyncClient(transport=transport, base_url="http://test") as ac:
            response = await ac.get("/health")
    assert response.json() == {"ready": True}
```

| | `TestClient` | `AsyncClient` + `ASGITransport` |
|---|---|---|
| 测试函数 | 普通 `def` | `async def` + `@pytest.mark.anyio` |
| 触发 lifespan | `with TestClient(app)` 时触发 | **不触发**，需手动 `async with app.router.lifespan_context(app)` 或用第三方库 `asgi-lifespan` |
| 测试中能否 `await` | 不能 | 能 |
| WebSocket | 支持 | 不支持 |
| 典型场景 | 绝大多数接口测试 | 测试中需要调用其他异步代码 |

> 💡 `anyio_backend` fixture 用来指定事件循环实现，默认就是 `"asyncio"`，显式写出来更清楚。如果项目里所有异步测试都用 asyncio，可以把它放到 `conftest.py` 中。另一个常见选择是 `pytest-asyncio` 插件（`@pytest.mark.asyncio`），两者择一即可，不要混用。
>
> ⚠️ 异步测试中尽量不要用 `TestClient`：它会在另一个线程里**另起一个事件循环**运行应用，调用本身是同步阻塞的。简单接口看起来也能跑通，但一旦应用和测试共享异步资源（比如同一个异步数据库连接池），这些资源就会跨事件循环使用而报错。异步测试统一用 `AsyncClient` + `ASGITransport`，应用和测试运行在同一个事件循环里。

## 10. 测试 WebSocket

`TestClient.websocket_connect()` 返回一个上下文管理器，可以收发消息：

```python
# tests/test_ws.py
import pytest
from fastapi.testclient import TestClient
from starlette.websockets import WebSocketDisconnect

from app.main import app


def test_ws_echo():
    client = TestClient(app)
    with client.websocket_connect("/ws/echo") as ws:
        ws.send_text("hello")
        assert ws.receive_json() == {"echo": "hello", "length": 5}
        ws.send_text("你好")
        assert ws.receive_json() == {"echo": "你好", "length": 2}


def test_ws_server_close():
    client = TestClient(app)
    with client.websocket_connect("/ws/echo") as ws:
        ws.send_text("bye")
        with pytest.raises(WebSocketDisconnect) as exc_info:
            ws.receive_text()
        assert exc_info.value.code == 1000
```

| 方法 | 说明 |
|---|---|
| `send_text` / `send_json` / `send_bytes` | 发送消息 |
| `receive_text` / `receive_json` / `receive_bytes` | 接收消息（服务端已关闭时抛 `WebSocketDisconnect`） |
| `close(code=...)` | 客户端主动关闭 |

WebSocket 连接 URL 中可以带查询参数和请求头：`client.websocket_connect("/ws?token=xxx", headers={...})`，用于测试 WebSocket 鉴权。

## 11. 模拟外部服务

接口里调用了第三方 HTTP 服务（天气、支付、短信……）时，测试**绝不能真的发请求**：慢、不稳定、可能产生费用、CI 环境可能没网。常用三种办法：

```python
# tests/test_weather.py
import httpx
import respx
from fastapi.testclient import TestClient

from app import main
from app.main import app
from app.weather import WEATHER_API, get_weather_client


# 方式一：monkeypatch 替换模块里的函数
def test_weather_monkeypatch(client: TestClient, monkeypatch):
    monkeypatch.setattr(main, "fetch_temperature", lambda city: 25.0)
    response = client.get("/weather/beijing")
    assert response.json() == {"city": "beijing", "temperature": 25.0}


# 方式二：dependency_overrides 替换依赖（接口设计成依赖注入时最干净）
class FakeWeatherClient:
    def get_temperature(self, city: str) -> float:
        return {"beijing": 25.0, "harbin": -20.0}[city]


def test_weather_dependency_override(client: TestClient):
    app.dependency_overrides[get_weather_client] = FakeWeatherClient
    assert client.get("/v2/weather/harbin").json()["temperature"] == -20.0


# 方式三：respx 拦截 httpx 发出的 HTTP 请求，被测代码完全不改
@respx.mock
def test_weather_respx(client: TestClient):
    route = respx.get(WEATHER_API, params={"city": "shanghai"}).mock(
        return_value=httpx.Response(200, json={"temperature": 30.5})
    )
    response = client.get("/weather/shanghai")
    assert response.json() == {"city": "shanghai", "temperature": 30.5}
    assert route.called
```

| 方式 | 替换的层级 | 优点 | 注意 |
|---|---|---|---|
| `monkeypatch.setattr` | Python 函数/属性 | 通用，pytest 自带，测试结束自动还原 | 要 patch **使用处**的名字：`main.py` 中 `from app.weather import fetch_temperature` 后，要 patch `app.main.fetch_temperature`，patch `app.weather.fetch_temperature` 无效 |
| `dependency_overrides` | FastAPI 依赖 | 最干净，不依赖模块内部实现 | 需要代码本身用依赖注入；记得清理（本例由 `client` fixture 清理） |
| `respx` | HTTP 传输层 | 连 URL、参数、请求体、超时、错误状态码都能测到 | 只能拦截 `httpx`；`requests` 库需要用 `responses` 等对应工具 |

> 💡 这再次体现了 12.12 中分层和依赖注入的价值：外部调用封装成可注入的 client 后，测试只需一行 `dependency_overrides` 就能替换。

## 14. 测试分层与组织建议

| 测试类型 | 测什么 | 工具 | 数量 |
|---|---|---|---|
| 单元测试 | service、工具函数、Pydantic 校验规则 | 直接调用 + 假的 repository | 多 |
| 接口测试 | 路由、参数校验、状态码、鉴权、序列化 | `TestClient` + 测试数据库 + `dependency_overrides` | 中 |
| 端到端测试 | 真实数据库、真实部署环境下的完整流程 | 真实服务 + HTTP 客户端 | 少 |

每个接口至少覆盖：

1. **正常路径**：正确输入返回正确结果和状态码；
2. **校验失败**：缺字段、类型错误、越界 → 422；
3. **鉴权**：未登录 → 401，无权限（访问别人的数据）→ 403/404；
4. **资源不存在** → 404；
5. **业务冲突**（如重复创建）→ 409 等。

## 常见坑

1. **`dependency_overrides` 没清理**：覆盖泄漏到后续测试，结果依赖执行顺序。始终在 fixture 的 `yield` 之后 `clear()`。
2. **覆盖了错误的函数对象**：键必须是 `Depends(...)` 中实际使用的那个函数。例如路由里用的是 `Depends(get_db)`，你却覆盖了某个同名但不同模块的 `get_db`，覆盖不会生效，测试会悄悄连上真实数据库。
3. **内存 SQLite 报 `no such table`**：忘了 `poolclass=StaticPool`，建表（主线程）和查询（请求处理线程）用的不是同一个连接，也就不是同一个库。
4. **数据没有回滚**：使用 `sqlite3` 驱动时没有设置 `autocommit=False`（或事件监听），SAVEPOINT 不生效。
5. **lifespan 没执行**：用了 `TestClient(app)` 而不是 `with TestClient(app) as client`；或者使用了 `ASGITransport`（它从不触发 lifespan）。
6. **monkeypatch 了定义处而不是使用处**：`from x import f` 之后，使用方模块持有的是自己的引用，要 patch `使用方模块.f`。
7. **在 `async def` 测试中使用 `TestClient`**：应用会跑在另一个事件循环里，共享异步资源时出错，应改用 `httpx.AsyncClient` + `ASGITransport`。
8. **测试里真的访问外网**：慢且不稳定。可以利用 respx 的默认行为发现漏网之鱼：在 `@respx.mock` 下，未被 mock 的请求会直接抛 `AllMockedAssertionError: RESPX: <Request('GET', ...)> not mocked!`。
9. **模块级 `client = TestClient(app)` 与覆盖混用**：在模块顶层创建的客户端无法与每个测试的 fixture 配合，cookie 也会在测试之间共享。项目变大后统一用 fixture 创建客户端。
10. **`get_settings` 被 `@lru_cache` 缓存**：测试中修改环境变量不生效，需要 `get_settings.cache_clear()` 或用 `dependency_overrides[get_settings]`。

## 小结

- `TestClient` 在进程内调用应用，不需要启动服务器；测试函数是普通 `def`，请求参数（`params`/`json`/`data`/`files`/`headers`）与 httpx 一致。
- 用 `conftest.py` 集中定义 fixture（测试数据库、客户端、登录凭证），用 `@pytest.mark.parametrize` 批量覆盖多组输入。
- `app.dependency_overrides` 是 FastAPI 测试的核心武器，可以替换数据库、当前用户、配置、外部服务；记得在 fixture 中清理。
- 测试数据库推荐「内存 SQLite + `StaticPool` + 每测试外层事务回滚」，注意 `sqlite3` 驱动需要 `autocommit=False` 才能正确回滚。
- `with TestClient(app)` 才会触发 lifespan；异步测试用 `@pytest.mark.anyio` + `httpx.AsyncClient(transport=ASGITransport(app))`，它不触发 lifespan。
- WebSocket 用 `client.websocket_connect()` 测试；外部 HTTP 服务用 `monkeypatch`、`dependency_overrides` 或 `respx` 模拟。
- 用 `pytest --cov=app --cov-report=term-missing` 找出没测到的代码，重点看 `Missing` 列。
