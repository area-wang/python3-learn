# 12.5 响应处理练习题

## 一、概念题

1. 声明响应模型（返回类型注解或 `response_model`）会带来哪三方面的作用？其中哪一项对安全最重要，为什么说它是一种"白名单"机制？
2. 返回类型注解 `-> UserOut` 和装饰器参数 `response_model=UserOut` 同时存在时，FastAPI 以哪个为准？什么场景下应该用 `response_model=...` 搭配 `-> Any`？
3. 为什么推荐把用户相关模型拆成 `UserCreate`、`UserOut`、`UserInDB` 三个？如何用继承减少重复字段？
4. `response_model_exclude_unset`、`response_model_exclude_defaults`、`response_model_exclude_none` 的判断依据分别是什么？如果数据中显式写了 `"description": None`，三者分别会不会去掉它？
5. 为什么不推荐长期使用 `response_model_include` / `response_model_exclude` 来裁剪字段？
6. 如何根据业务逻辑动态返回 201 或 200？如何在不放弃响应模型过滤的前提下设置响应头和 Cookie？
7. 直接 `return JSONResponse(...)` 与 `return dict` 在校验、过滤、序列化上有什么区别？这会带来什么风险？
8. `jsonable_encoder` 解决了什么问题？为什么直接 `JSONResponse(content={"t": datetime.now()})` 会报错？
9. `FileResponse` 与 `StreamingResponse` 分别适合什么场景？`FileResponse` 相比"读出文件内容再返回"有哪些优势？
10. 返回值不符合响应模型时，客户端收到的状态码是 422 还是 500？为什么这样设计？

## 二、判断代码输出 / 找错

### 1. 过滤还是不过滤

```python
from fastapi import FastAPI
from fastapi.responses import JSONResponse
from pydantic import BaseModel

app = FastAPI()


class UserOut(BaseModel):
    username: str


user = {"username": "tom", "password": "123"}


@app.get("/a")
async def a() -> UserOut:
    return user


@app.get("/b")
async def b() -> UserOut:
    return JSONResponse(user)


@app.get("/c", response_model=UserOut)
async def c() -> dict:
    return user
```

分别写出 `/a`、`/b`、`/c` 的响应体。

### 2. exclude_unset 的结果

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    price: float = 0
    tags: list[str] = []
    note: str | None = None


@app.get("/x", response_model=Item, response_model_exclude_unset=True)
async def x():
    return {"name": "pen", "price": 0, "note": None}


@app.get("/y", response_model=Item, response_model_exclude_none=True)
async def y():
    return {"name": "pen", "price": 0, "note": None}
```

写出 `/x` 和 `/y` 的响应体，并解释差异。

### 3. 启动失败

```python
from fastapi import FastAPI, Response
from fastapi.responses import RedirectResponse

app = FastAPI()


@app.get("/go")
async def go(redirect: bool) -> Response | dict:
    if redirect:
        return RedirectResponse("/docs")
    return {"ok": True}
```

这段代码在什么时候报错？报什么错？给出最小修改。

### 4. 消失的响应头

```python
from fastapi import FastAPI, Response
from fastapi.responses import JSONResponse

app = FastAPI()


@app.get("/data")
async def data(response: Response):
    response.headers["X-Total-Count"] = "100"
    return JSONResponse({"items": []})
```

客户端能收到 `X-Total-Count` 头吗？为什么？给出两种正确写法。

### 5. 状态码与响应体

```python
from fastapi import FastAPI, status

app = FastAPI()


@app.delete("/items/{item_id}", status_code=status.HTTP_204_NO_CONTENT)
async def delete_item(item_id: int):
    return {"deleted": item_id}
```

这个接口的设计有什么问题？应该如何修改？如果确实想返回被删除的对象，应使用哪个状态码？

## 三、编程题

### 1. 文章模型分离（基础）

为"文章"资源设计 `ArticleCreate`（标题、正文、标签）、`ArticleOut`（多出 `id`、`author`、`created_at`）、`ArticleInDB`（多出 `is_deleted`、`view_count`），要求：

- 用继承减少重复；
- 实现 `POST /articles`（201）和 `GET /articles/{id}`，返回值中不能出现 `is_deleted`、`view_count`；
- 写测试或 curl 验证这两个字段确实被过滤。

### 2. 多格式输出（基础）

实现 `GET /report`，根据查询参数 `format`：

- `json`（默认）：返回 `{"total": 3, "items": [...]}`；
- `csv`：返回 `text/csv`，并带 `Content-Disposition: attachment; filename=report.csv`；
- `html`：返回一个包含表格的 HTML 页面；
- 思考这个接口的返回类型注解应该怎么写才能通过启动。

### 3. 条件创建（进阶）

实现 `PUT /configs/{key}`：

- 不存在时创建，返回 201，并设置 `Location` 响应头；
- 已存在时更新，返回 200；
- 两种情况都要经过响应模型 `ConfigOut` 的过滤（模型中不包含内部字段 `updated_by`）；
- 不允许直接返回 `JSONResponse`。

### 4. 登录与登出（进阶）

实现：

- `POST /login`：接收用户名密码（JSON），校验通过后设置 `HttpOnly`、`SameSite=lax`、有效期 1 小时的 Cookie `session_id`，返回用户基本信息；
- `GET /me`：读取 `session_id` Cookie，返回当前用户；未登录返回 401；
- `POST /logout`：删除 Cookie；
- 用 `curl -c cookies.txt` / `-b cookies.txt` 演示完整流程。

### 5. 大数据导出（进阶）

实现 `GET /export/orders`，模拟导出 100 万条订单：

- 使用生成器 + `StreamingResponse` 逐行输出 CSV；
- 比较"先拼成完整字符串再返回"和"流式输出"两种实现的内存占用（提示：`tracemalloc` 或观察进程内存）；
- 用 `curl -N` 观察数据是逐步到达的。

### 6. 规范化文档（挑战）

为一个商品服务的 4 个接口（增删改查）补全 OpenAPI 文档：

- 定义 `ErrorMessage` 模型，统一声明 404、409 的响应结构；
- 用一个公共字典复用错误响应，并在个别接口上追加特有的错误码；
- `GET /products/{id}/image` 声明 `image/png` 响应类型；
- 打开 `/docs` 和 `/openapi.json` 检查结果，截图或记录每个接口的 Responses 列表。

## 四、综合实践：通讯录 API 的响应设计

实现一个通讯录服务（数据存在内存中），重点在于响应设计：

1. 联系人模型拆分：创建（含 `phone`、`email`、`remark`）、列表项（只有 `id`、`name`、`phone` 的脱敏形式，如 `138****1234`）、详情（完整字段，但不含内部字段 `owner_id`）；
2. `GET /contacts` 返回 `list[ContactListItem]`，并通过响应头 `X-Total-Count` 返回总数；
3. `GET /contacts/{id}` 返回详情，支持 `?fields=name,phone` 只返回指定字段（思考：用 `response_model_include` 还是手动构造？两者对文档有什么影响？）；
4. `PATCH /contacts/{id}` 只更新传入的字段，响应使用 `exclude_none`；
5. `DELETE /contacts/{id}` 返回 204；
6. `GET /contacts/export` 以 `FileResponse` 或 `StreamingResponse` 导出 vCard / CSV 文件，文件名含中文（如 `通讯录.csv`），验证浏览器下载时文件名正确；
7. 所有接口在文档中都要有准确的成功和错误响应说明。

## 五、参考检查点

- 能否为每个对外接口声明响应模型，并说清它在校验、过滤、文档上的作用；
- 能否设计合理的输入/输出/存储模型，确保敏感字段不会出现在响应中；
- 能否正确区分 `exclude_unset`、`exclude_defaults`、`exclude_none` 的差异；
- 能否使用 `fastapi.status` 常量和注入的 `Response` 对象控制状态码、响应头、Cookie；
- 能否根据场景选用 `HTMLResponse`、`PlainTextResponse`、`RedirectResponse`、`FileResponse`、`StreamingResponse`，并知道 `response_class` 的用法；
- 是否清楚直接返回 `Response` 实例会绕过响应模型，并在手动构造 JSON 响应时使用 `jsonable_encoder`；
- 能否使用 `responses=` 让 OpenAPI 文档完整描述成功和错误响应。
