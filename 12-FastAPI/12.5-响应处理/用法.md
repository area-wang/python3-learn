# 12.5 响应处理

前面几节都在讨论"如何接收请求"：参数从哪来、怎么校验。本节转向另一半——**如何返回响应**。一个合格的 API 响应不只是"把数据 return 出去"，还要考虑：返回的字段是否经过过滤（不能把密码哈希泄露出去）、文档里的响应结构是否准确、状态码是否符合语义、需要返回 HTML/文件/流时怎么办、如何设置响应头和 Cookie。FastAPI 用 `response_model`（或返回类型注解）+ 各种 `Response` 类解决这些问题。

> 本节示例基于 FastAPI 0.143 / Pydantic 2.14 / Starlette 1.8 / Python 3.14 实际运行验证。

## 1. 默认行为：return 了什么，返回什么

不做任何声明时，FastAPI 会把路由函数的返回值用 `jsonable_encoder` 转成可 JSON 序列化的结构，再包装成 `JSONResponse`：

```python
from datetime import datetime

from fastapi import FastAPI

app = FastAPI()


@app.get("/now")
async def now():
    return {"time": datetime(2024, 1, 1, 12, 0), "tags": ["a", "b"]}
# {"time":"2024-01-01T12:00:00","tags":["a","b"]}
```

`dict`、`list`、Pydantic 模型、`datetime`、`UUID`、`Decimal` 等都能被正确转换。但这种写法有两个问题：

1. **没有任何过滤**：return 了什么字段，客户端就能看到什么字段。
2. **文档不准确**：`/docs` 中这个接口的响应结构只显示为"任意 JSON"。

## 2. 声明响应模型

### 2.1 两种写法：返回类型注解 vs `response_model`

```python
from typing import Any

from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()


class UserIn(BaseModel):
    username: str
    password: str
    email: EmailStr
    full_name: str | None = None


class UserOut(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None


# 写法一：返回类型注解（推荐）
@app.post("/users")
async def create_user(user: UserIn) -> UserOut:
    return user


# 写法二：response_model 参数
@app.post("/users-v2", response_model=UserOut)
async def create_user_v2(user: UserIn) -> Any:
    return user
```

```bash
curl -X POST http://127.0.0.1:8000/users -H "Content-Type: application/json" \
  -d '{"username": "tom", "password": "secret", "email": "tom@example.com"}'
# {"username":"tom","email":"tom@example.com","full_name":null}
```

`EmailStr` 需要 `email-validator`，`fastapi[standard]` 已包含。

两种写法都会让 FastAPI 做三件事：

| 作用 | 说明 |
|---|---|
| **校验** | 返回值必须符合模型，不符合时服务端报错（500），而不是把错误数据发给客户端 |
| **过滤** | 只保留模型中声明的字段，`password` 被自动去掉 |
| **文档** | `/docs` 中准确显示响应结构 |

> 💡 注意第一种写法：函数签名写的是 `-> UserOut`，实际返回的却是 `UserIn` 对象。这在类型检查器看来"不太对"，但 FastAPI 会按 `UserOut` 过滤后返回，能正常工作。

### 2.2 两者同时出现时谁优先？

**`response_model` 优先**。当你需要返回一个类型和响应模型"对不上"的对象（例如数据库 ORM 对象、普通 dict），又不想让类型检查器报错时，就用 `response_model=...` 配合 `-> Any`：

```python
from typing import Any

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class UserOut(BaseModel):
    username: str


@app.get("/me", response_model=UserOut)
async def me() -> Any:
    # 返回 dict，类型检查器不报错，FastAPI 仍按 UserOut 过滤
    return {"username": "tom", "password_hash": "xxx"}
# {"username":"tom"}
```

| 场景 | 推荐写法 |
|---|---|
| 返回值本身就是响应模型的实例 | `-> UserOut` |
| 返回 dict / ORM 对象 / 子类实例，希望类型检查也通过 | `response_model=UserOut` + `-> Any` |
| 返回值是 `Response` 子类，或不想要任何校验和过滤 | `response_model=None`（见 6.3） |

### 2.3 过滤字段的安全意义

响应模型最重要的价值是**安全**。设想一个返回数据库用户记录的接口：

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

fake_db = {"tom": {"username": "tom", "hashed_password": "$argon2id$...", "is_admin": True}}


class UserPublic(BaseModel):
    username: str


@app.get("/unsafe/{name}")
async def unsafe(name: str):
    return fake_db[name]   # 💥 哈希和权限标记全部泄露


@app.get("/safe/{name}")
async def safe(name: str) -> UserPublic:
    return fake_db[name]   # ✅ 只返回 username
```

```bash
curl http://127.0.0.1:8000/unsafe/tom
# {"username":"tom","hashed_password":"$argon2id$...","is_admin":true}
curl http://127.0.0.1:8000/safe/tom
# {"username":"tom"}
```

> ⚠️ 即使今天数据库里没有敏感字段，明天某人加一列 `phone` 或 `id_card`，没有响应模型的接口就会**悄无声息地**把它暴露出去。**对外接口一律声明响应模型**，这是"白名单"思维。

## 3. 输入、输出、存储模型分离

### 3.1 三种模型

同一个"用户"概念，在不同阶段需要的字段不一样：

| 模型 | 用途 | 包含 |
|---|---|---|
| `UserCreate`（输入） | 注册时客户端提交 | 明文 `password` |
| `UserOut`（输出） | 返回给客户端 | 不含任何密码 |
| `UserInDB`（存储） | 写入数据库 | `hashed_password` |

### 3.2 用继承消除重复

```python
from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()


class UserBase(BaseModel):
    username: str
    email: EmailStr
    full_name: str | None = None


class UserCreate(UserBase):
    password: str


class UserOut(UserBase):
    pass


class UserInDB(UserBase):
    hashed_password: str


def fake_hash(password: str) -> str:
    return "hashed_" + password


fake_db: dict[str, UserInDB] = {}


@app.post("/users", status_code=201)
async def create_user(user_in: UserCreate) -> UserOut:
    user_db = UserInDB(
        **user_in.model_dump(exclude={"password"}),
        hashed_password=fake_hash(user_in.password),
    )
    fake_db[user_db.username] = user_db
    return user_db   # UserInDB 实例，按 UserOut 过滤后返回
```

```bash
curl -X POST http://127.0.0.1:8000/users -H "Content-Type: application/json" \
  -d '{"username": "tom", "password": "secret", "email": "tom@example.com"}'
# {"username":"tom","email":"tom@example.com","full_name":null}
```

`model_dump()` 把模型转成 dict，`exclude={"password"}` 排除明文密码，再用 `**` 解包和 `hashed_password` 一起构造存储模型。这是 Pydantic v2 的标准写法（v1 中叫 `.dict()`，已废弃）。

> 💡 当返回类型是 `UserBase` 这样的父类，而实际返回的是子类 `UserCreate` 实例时，FastAPI 同样会按父类过滤，额外字段不会泄露。

## 4. 控制输出哪些字段

### 4.1 `response_model_exclude_unset`：只返回"实际设置过"的字段

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Product(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float = 10.5
    tags: list[str] = []


products = {
    "foo": {"name": "Foo", "price": 50.2},
    "bar": {"name": "Bar", "description": None, "price": 62, "tax": 20.2},
}


@app.get("/full/{pid}")
async def full(pid: str) -> Product:
    return products[pid]


@app.get("/unset/{pid}", response_model=Product, response_model_exclude_unset=True)
async def unset(pid: str):
    return products[pid]


@app.get("/none/{pid}", response_model=Product, response_model_exclude_none=True)
async def none(pid: str):
    return products[pid]


@app.get("/include/{pid}", response_model=Product, response_model_include={"name", "price"})
async def include(pid: str):
    return products[pid]
```

| 请求 | 响应 |
|---|---|
| `GET /full/foo` | `{"name":"Foo","description":null,"price":50.2,"tax":10.5,"tags":[]}` |
| `GET /unset/foo` | `{"name":"Foo","price":50.2}` |
| `GET /unset/bar` | `{"name":"Bar","description":null,"price":62.0,"tax":20.2}` |
| `GET /none/bar` | `{"name":"Bar","price":62.0,"tax":20.2,"tags":[]}` |
| `GET /include/bar` | `{"name":"Bar","price":62.0}` |

注意 `/unset/bar` 中的 `"description": null` 被保留了——因为数据中**显式**设置了 `None`，它算"已设置"。`exclude_unset` 关注的是"有没有设置"，`exclude_none` 关注的是"值是不是 None"。

| 参数 | 去掉哪些字段 | 典型用途 |
|---|---|---|
| `response_model_exclude_unset=True` | 没有被显式赋值的字段（即使用默认值的） | PATCH 局部更新的回显、减小响应体 |
| `response_model_exclude_defaults=True` | 值等于默认值的字段 | 同上，判断依据不同 |
| `response_model_exclude_none=True` | 值为 `None` 的字段 | 客户端不希望看到 null |
| `response_model_include={...}` / `response_model_exclude={...}` | 白名单 / 黑名单 | 临时裁剪 |

> ⚠️ `include` / `exclude` 不会改变 `/docs` 中的响应结构（文档仍显示完整模型），长期使用容易让文档与实际不符。更推荐**定义一个新的模型**。

## 5. 多种响应结构：`list` 与 Union

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Cat(BaseModel):
    kind: str = "cat"
    name: str
    indoor: bool


class Dog(BaseModel):
    kind: str = "dog"
    name: str
    breed: str


@app.get("/cats")
async def list_cats() -> list[Cat]:
    return [Cat(name="Tom", indoor=True), Cat(name="Kitty", indoor=False)]


@app.get("/pets/{name}")
async def get_pet(name: str) -> Cat | Dog:
    if name == "tom":
        return Cat(name="Tom", indoor=True)
    return Dog(name=name, breed="husky")


@app.get("/stats")
async def stats() -> dict[str, int]:
    return {"cats": 2, "dogs": 5}
```

```bash
curl http://127.0.0.1:8000/cats
# [{"kind":"cat","name":"Tom","indoor":true},{"kind":"cat","name":"Kitty","indoor":false}]
curl http://127.0.0.1:8000/pets/tom
# {"kind":"cat","name":"Tom","indoor":true}
curl http://127.0.0.1:8000/pets/max
# {"kind":"dog","name":"max","breed":"husky"}
```

> 💡 Union 中把**更具体**（字段更多）的类型放前面。文档中 Union 会显示为 `anyOf`，前端可以根据 `kind` 区分类型；更严谨的做法是使用 Pydantic 的判别联合（discriminated union）。

## 6. 状态码

### 6.1 在装饰器中声明

```python
from fastapi import FastAPI, status

app = FastAPI()


@app.post("/items", status_code=status.HTTP_201_CREATED)
async def create_item(name: str):
    return {"name": name}


@app.delete("/items/{item_id}", status_code=status.HTTP_204_NO_CONTENT)
async def delete_item(item_id: int):
    return None   # 204 不应有响应体
```

`fastapi.status` 提供了所有状态码常量，比写魔法数字 `201` 更可读，还有 IDE 补全。常用状态码：

| 状态码 | 常量 | 语义 |
|---|---|---|
| 200 | `HTTP_200_OK` | 成功（GET 默认） |
| 201 | `HTTP_201_CREATED` | 创建成功（POST 新建资源） |
| 204 | `HTTP_204_NO_CONTENT` | 成功但无响应体（DELETE） |
| 400 | `HTTP_400_BAD_REQUEST` | 业务上的请求错误 |
| 401 | `HTTP_401_UNAUTHORIZED` | 未认证（没登录） |
| 403 | `HTTP_403_FORBIDDEN` | 无权限（登录了但不允许） |
| 404 | `HTTP_404_NOT_FOUND` | 资源不存在 |
| 409 | `HTTP_409_CONFLICT` | 冲突（如用户名已存在） |
| 422 | `HTTP_422_UNPROCESSABLE_CONTENT` | 参数校验失败（FastAPI 自动返回） |
| 500 | `HTTP_500_INTERNAL_SERVER_ERROR` | 服务端异常 |

> ⚠️ 新版本 Starlette 按 RFC 9110 重命名了部分常量：`HTTP_422_UNPROCESSABLE_ENTITY` → `HTTP_422_UNPROCESSABLE_CONTENT`，`HTTP_413_REQUEST_ENTITY_TOO_LARGE` → `HTTP_413_CONTENT_TOO_LARGE`。旧名字仍可用但会发出弃用警告，很多旧教程里还是旧名字。

### 6.2 动态修改状态码

装饰器中的状态码是固定的。如果要根据逻辑返回不同状态码（例如"存在则 200 更新，不存在则 201 创建"），可以注入 `Response` 参数：

```python
from fastapi import FastAPI, Response, status

app = FastAPI()
items = {"foo": "Foo"}


@app.put("/items/{item_id}")
async def upsert(item_id: str, name: str, response: Response):
    if item_id not in items:
        response.status_code = status.HTTP_201_CREATED
    items[item_id] = name
    return {"item_id": item_id, "name": name}
```

```bash
curl -i -X PUT "http://127.0.0.1:8000/items/bar?name=Bar"   # HTTP/1.1 201 Created
curl -i -X PUT "http://127.0.0.1:8000/items/bar?name=Bar2"  # HTTP/1.1 200 OK
```

## 7. 设置响应头与 Cookie

同样通过注入 `Response` 参数实现，返回值依然走响应模型的校验和过滤：

```python
from fastapi import FastAPI, Response

app = FastAPI()


@app.post("/login")
async def login(response: Response):
    response.headers["X-Request-ID"] = "abc-123"
    response.set_cookie(
        key="session_id",
        value="s3cr3t",
        httponly=True,      # JS 无法读取，防 XSS 窃取
        secure=False,       # 生产环境应为 True，仅 HTTPS 发送
        samesite="lax",     # 防 CSRF
        max_age=3600,       # 有效期（秒）
    )
    return {"message": "登录成功"}


@app.post("/logout")
async def logout(response: Response):
    response.delete_cookie("session_id")
    return {"message": "已退出"}
```

```bash
curl -i -X POST http://127.0.0.1:8000/login
# HTTP/1.1 200 OK
# x-request-id: abc-123
# set-cookie: session_id=s3cr3t; HttpOnly; Max-Age=3600; Path=/; SameSite=lax
# ...
# {"message":"登录成功"}
```

`set_cookie` 的常用参数：

| 参数 | 说明 |
|---|---|
| `key` / `value` | Cookie 名和值 |
| `max_age` / `expires` | 有效期（秒）/ 过期时间点；都不设则为会话 Cookie |
| `path` / `domain` | 生效路径 / 域名 |
| `httponly` | 禁止 JavaScript 访问 |
| `secure` | 只在 HTTPS 下发送 |
| `samesite` | `"lax"`（默认）/ `"strict"` / `"none"`（需配合 `secure=True`） |

## 8. 各种 Response 类

### 8.1 一览

所有响应类都可以从 `fastapi.responses` 导入（它们大多是 Starlette 类的再导出）：

| 类 | Content-Type | 用途 |
|---|---|---|
| `JSONResponse` | `application/json` | 默认响应；自定义状态码/头时手动使用 |
| `HTMLResponse` | `text/html` | 返回 HTML 页面 |
| `PlainTextResponse` | `text/plain` | 纯文本 |
| `RedirectResponse` | — | 重定向，默认 307 |
| `FileResponse` | 根据文件后缀推断 | 文件下载 |
| `StreamingResponse` | 自定义 | 流式输出：大文件、实时生成内容 |
| `Response` | 自定义 | 所有响应的基类，返回任意内容 |

### 8.2 直接返回 Response 对象

```python
from fastapi import FastAPI, Response
from fastapi.responses import HTMLResponse, JSONResponse, PlainTextResponse, RedirectResponse

app = FastAPI()


@app.get("/json")
async def json_resp():
    return JSONResponse(content={"msg": "accepted"}, status_code=202, headers={"X-Job": "1"})


@app.get("/html")
async def html():
    return HTMLResponse("<h1>你好，FastAPI</h1>")


@app.get("/text")
async def text():
    return PlainTextResponse("pong")


@app.get("/old-page")
async def old_page():
    return RedirectResponse("/html", status_code=301)   # 永久重定向


@app.get("/xml")
async def xml():
    data = '<?xml version="1.0"?><note><to>Tom</to></note>'
    return Response(content=data, media_type="application/xml")
```

```bash
curl -i http://127.0.0.1:8000/old-page
# HTTP/1.1 301 Moved Permanently
# location: /html
```

### 8.3 用 `response_class` 声明（推荐用于固定类型）

如果某个接口总是返回 HTML/文本，把类放到装饰器的 `response_class` 上，函数只需要 return 内容本身。好处是 `/docs` 中会显示正确的 Content-Type：

```python
from fastapi import FastAPI
from fastapi.responses import HTMLResponse, PlainTextResponse, RedirectResponse

app = FastAPI()


@app.get("/page", response_class=HTMLResponse)
async def page():
    return "<h1>hi</h1>"


@app.get("/ping", response_class=PlainTextResponse)
async def ping():
    return "pong"


@app.get("/go", response_class=RedirectResponse, status_code=302)
async def go():
    return "/page"   # 直接返回 URL 字符串
```

### 8.4 文件下载：`FileResponse`

```python
from pathlib import Path

from fastapi import FastAPI, HTTPException
from fastapi.responses import FileResponse

app = FastAPI()
FILES_DIR = Path("files")
FILES_DIR.mkdir(exist_ok=True)
(FILES_DIR / "report.csv").write_text("name,score\ntom,90\n", encoding="utf-8")


@app.get("/download/{name}")
async def download(name: str):
    path = FILES_DIR / Path(name).name
    if not path.is_file():
        raise HTTPException(404, "文件不存在")
    # 传 filename 会设置 Content-Disposition: attachment，浏览器弹出下载
    return FileResponse(path, filename=f"导出-{path.name}")
```

```bash
curl -i http://127.0.0.1:8000/download/report.csv
# content-type: text/csv; charset=utf-8
# content-disposition: attachment; filename*=utf-8''%E5%AF%BC%E5%87%BA-report.csv
```

`FileResponse` 会以流的方式异步读取文件，并自动设置 `Content-Length`、`Last-Modified`、`ETag`，还支持 `Range` 请求（断点续传）。含中文的文件名会自动按 RFC 5987 编码。

### 8.5 流式响应：`StreamingResponse`

当响应内容是"边生成边发送"的——例如导出百万行 CSV、AI 模型逐字输出——不应该先拼好整个字符串再返回。`StreamingResponse` 接收一个**生成器**（同步或异步均可）：

```python
import asyncio

from fastapi import FastAPI
from fastapi.responses import StreamingResponse

app = FastAPI()


def csv_rows():
    yield "id,name\n"
    for i in range(1, 4):
        yield f"{i},user{i}\n"


@app.get("/export")
async def export():
    return StreamingResponse(
        csv_rows(),
        media_type="text/csv",
        headers={"Content-Disposition": "attachment; filename=users.csv"},
    )


async def slow_words():
    for word in ["FastAPI", "流式", "输出"]:
        yield word + "\n"
        await asyncio.sleep(0.5)   # 模拟逐步生成


@app.get("/stream")
async def stream():
    return StreamingResponse(slow_words(), media_type="text/plain")
```

```bash
curl -N http://127.0.0.1:8000/stream    # -N 关闭缓冲，可以看到每 0.5 秒出现一行
```

> 💡 SSE（Server-Sent Events）和 WebSocket 等更完整的实时推送方案会在 12.14 详细讲解。

### 8.6 直接返回 Response 会绕过校验和过滤

这是一个非常容易踩的坑：

```python
from fastapi import FastAPI
from fastapi.responses import JSONResponse
from pydantic import BaseModel

app = FastAPI()


class UserOut(BaseModel):
    username: str


@app.get("/bypass")
async def bypass() -> UserOut:
    return JSONResponse({"username": "tom", "password": "leak"})
# {"username":"tom","password":"leak"}   💥 密码泄露
```

**只要返回的是 `Response` 实例，FastAPI 就原样发送**，不再做任何校验、过滤、序列化——响应模型此时只对文档有效。需要自定义状态码或头时，优先使用 6.2 / 第 7 节注入 `Response` 参数的方式，这样返回值依然会经过响应模型。

### 8.7 返回类型是 Response 时的注解

```python
from fastapi import FastAPI, Response
from fastapi.responses import JSONResponse, RedirectResponse

app = FastAPI()


@app.get("/portal")
async def portal() -> RedirectResponse:   # ✅ 单一 Response 子类，可以直接注解
    return RedirectResponse("/docs")


@app.get("/teleport", response_model=None)   # ✅ 混合类型时必须禁用响应模型
async def teleport(go: bool = True) -> Response | dict:
    if go:
        return RedirectResponse("/docs")
    return {"message": "stay"}
```

如果去掉 `response_model=None`，`Response | dict` 不是合法的 Pydantic 字段类型，应用**启动时**就会抛出 `FastAPIError: Invalid args for response field!`。

## 9. `jsonable_encoder`：转成可 JSON 序列化的数据

当你需要**手动**构造 `JSONResponse`，或者要把模型存入只接受 JSON 兼容数据的地方（如 Redis、NoSQL 数据库）时，`jsonable_encoder` 能把 Pydantic 模型、`datetime`、`UUID`、`set` 等递归转成 `dict`/`list`/`str`/`int`/... 的组合：

```python
from datetime import datetime

from fastapi import FastAPI
from fastapi.encoders import jsonable_encoder
from fastapi.responses import JSONResponse
from pydantic import BaseModel

app = FastAPI()


class Event(BaseModel):
    title: str
    at: datetime


@app.get("/event")
async def event():
    data = {"event": Event(title="发布会", at=datetime(2024, 1, 1, 12, 0)), "ts": datetime(2024, 1, 2)}
    encoded = jsonable_encoder(data)
    print(type(encoded["event"]), type(encoded["ts"]))   # <class 'dict'> <class 'str'>
    return JSONResponse(content=encoded, status_code=202)
# {"event":{"title":"发布会","at":"2024-01-01T12:00:00"},"ts":"2024-01-02T00:00:00"}
```

> ⚠️ `JSONResponse(content=...)` 内部只用标准库 `json.dumps`，直接把 `datetime` 或 Pydantic 对象放进去会报 `TypeError: Object of type datetime is not JSON serializable`。手动构造 `JSONResponse` 前务必先 `jsonable_encoder`。

## 10. 用 `responses=` 声明额外响应（文档）

一个接口除了成功响应，还可能返回 404、409 等。用 `responses` 参数可以把这些都写进 OpenAPI 文档，前端同学一看就知道要处理哪些情况：

```python
from fastapi import FastAPI
from fastapi.responses import JSONResponse
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    id: str
    name: str


class Message(BaseModel):
    message: str


items = {"foo": Item(id="foo", name="Foo")}


@app.get(
    "/items/{item_id}",
    responses={
        404: {"model": Message, "description": "商品不存在"},
        200: {
            "description": "返回商品 JSON，也可以返回商品图片",
            "content": {"image/png": {}},
        },
    },
)
async def read_item(item_id: str) -> Item:
    if item_id not in items:
        return JSONResponse(status_code=404, content={"message": "商品不存在"})
    return items[item_id]
```

打开 `/docs`，这个接口的 Responses 区域会显示 200（同时有 `application/json` 和 `image/png` 两种内容类型）、404（结构为 `Message`）以及 FastAPI 自动添加的 422。

> 💡 多个接口共享同样的额外响应时，可以定义一个字典 `common_responses = {404: {...}, 401: {...}}`，再用 `responses={**common_responses, 409: {...}}` 组合。12.12 中还会看到在 `APIRouter` 层统一声明。

## 11. 综合示例：用户资源的完整响应设计

```python
# main.py
from typing import Any

from fastapi import FastAPI, HTTPException, Response, status
from pydantic import BaseModel, EmailStr

app = FastAPI()


class UserBase(BaseModel):
    username: str
    email: EmailStr


class UserCreate(UserBase):
    password: str


class UserUpdate(BaseModel):
    email: EmailStr | None = None
    nickname: str | None = None


class UserOut(UserBase):
    id: int
    nickname: str | None = None


class UserInDB(UserOut):
    hashed_password: str


db: dict[int, UserInDB] = {}
not_found = {404: {"description": "用户不存在"}}


@app.post("/users", status_code=status.HTTP_201_CREATED)
async def create_user(user_in: UserCreate, response: Response) -> UserOut:
    user = UserInDB(
        id=len(db) + 1,
        **user_in.model_dump(exclude={"password"}),
        hashed_password="hashed_" + user_in.password,
    )
    db[user.id] = user
    response.headers["Location"] = f"/users/{user.id}"
    return user


@app.get("/users")
async def list_users() -> list[UserOut]:
    return list(db.values())


@app.get("/users/{user_id}", responses=not_found)
async def get_user(user_id: int) -> UserOut:
    if user_id not in db:
        raise HTTPException(status.HTTP_404_NOT_FOUND, "用户不存在")
    return db[user_id]


@app.patch(
    "/users/{user_id}",
    response_model=UserOut,
    response_model_exclude_none=True,
    responses=not_found,
)
async def update_user(user_id: int, patch: UserUpdate) -> Any:
    if user_id not in db:
        raise HTTPException(status.HTTP_404_NOT_FOUND, "用户不存在")
    updated = db[user_id].model_copy(update=patch.model_dump(exclude_unset=True))
    db[user_id] = updated
    return updated


@app.delete("/users/{user_id}", status_code=status.HTTP_204_NO_CONTENT, responses=not_found)
async def delete_user(user_id: int) -> None:
    if db.pop(user_id, None) is None:
        raise HTTPException(status.HTTP_404_NOT_FOUND, "用户不存在")
```

```bash
curl -i -X POST http://127.0.0.1:8000/users -H "Content-Type: application/json" \
  -d '{"username": "tom", "email": "tom@example.com", "password": "secret"}'
# HTTP/1.1 201 Created
# location: /users/1
# {"username":"tom","email":"tom@example.com","id":1,"nickname":null}

curl -X PATCH http://127.0.0.1:8000/users/1 -H "Content-Type: application/json" -d '{"nickname": "汤姆"}'
# {"username":"tom","email":"tom@example.com","id":1,"nickname":"汤姆"}

curl -i -X DELETE http://127.0.0.1:8000/users/1
# HTTP/1.1 204 No Content
```

这个例子覆盖了：输入/输出/存储模型分离（`hashed_password` 永远不会出现在响应中）、201 + `Location` 头、`list[UserOut]` 列表响应、PATCH 时 `exclude_unset` 只更新客户端传了的字段、204 无响应体、`responses` 统一声明 404。

## 常见坑

1. **对外接口不写响应模型**：数据库加个敏感字段就直接泄露，响应模型是"白名单"，一定要有。
2. **以为返回 `JSONResponse` 也会被过滤**：返回 `Response` 实例会绕过一切校验和过滤，需要定制状态码/头时优先注入 `Response` 参数。
3. **`JSONResponse` 里直接放 `datetime` / 模型对象**：会 `TypeError`，先 `jsonable_encoder`。
4. **混淆 `exclude_unset` 和 `exclude_none`**：前者看"是否被显式赋值"，后者看"值是否为 None"。
5. **注解写成 `-> Response | dict` 却不加 `response_model=None`**：启动即报错。
6. **返回值不符合响应模型**：不是返回 422，而是服务端抛出 `ResponseValidationError`，客户端收到 500——这是服务端 bug，不是客户端的错。
7. **204 却返回了内容**：204 语义上不允许有响应体，路由应返回 `None`。
8. **用 `include`/`exclude` 长期裁剪字段**：文档与实际不一致，应该定义专门的模型。
9. **照抄旧教程的状态码常量**：`HTTP_422_UNPROCESSABLE_ENTITY` 等旧名已弃用。

## 小结

- 用返回类型注解（`-> UserOut`）或 `response_model` 声明响应模型，获得**校验、过滤、文档**三重收益；两者并存时 `response_model` 优先。
- 输入、输出、存储模型分离，用继承消除重复字段，敏感字段只存在于存储模型中。
- `response_model_exclude_unset` / `exclude_none` / `include` / `exclude` 控制输出字段，长期需求优先定义新模型。
- 状态码用 `fastapi.status` 常量；需要动态状态码、响应头或 Cookie 时注入 `Response` 参数。
- `HTMLResponse`、`PlainTextResponse`、`RedirectResponse`、`FileResponse`、`StreamingResponse` 覆盖非 JSON 场景；固定类型用 `response_class` 声明。
- 直接返回 `Response` 实例会绕过响应模型；手动构造 JSON 响应前先 `jsonable_encoder`。
- 用 `responses=` 把错误响应写进文档，让 API 的使用者一目了然。
