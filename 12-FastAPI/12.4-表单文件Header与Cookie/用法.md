# 12.4 表单、文件、Header 与 Cookie

12.2 和 12.3 讲的参数都来自 **URL**（路径参数、查询参数）和 **JSON 请求体**。但真实的 HTTP 请求里还有很多数据并不走这两条路：浏览器 `<form>` 提交的表单、上传的图片和附件、放在请求头里的 Token 和客户端信息、浏览器自动携带的 Cookie。本节把这些"其他来源"的参数一次讲清楚，并说明什么时候应该绕过参数声明、直接操作底层的 `Request` 对象。

> 本节示例基于 FastAPI 0.143 / Pydantic 2.14 / Starlette 1.8 / Python 3.14 实际运行验证。

## 1. 参数来源总览

FastAPI 的核心思想是：**用函数参数声明"从哪里取数据、取成什么类型"**。到目前为止，你已经见过前三种，本节补全剩下的：

| 声明方式 | 数据来源 | 典型 Content-Type | 本节 |
|---|---|---|---|
| `item_id: int`（出现在路径里） | URL 路径 `/items/{item_id}` | — | 12.2 |
| `q: str \| None = None` | 查询字符串 `?q=xxx` | — | 12.2 |
| `item: Item`（Pydantic 模型） | JSON 请求体 | `application/json` | 12.3 |
| `Annotated[str, Form()]` | 表单字段 | `application/x-www-form-urlencoded` 或 `multipart/form-data` | ✅ |
| `Annotated[bytes, File()]` / `UploadFile` | 上传的文件 | `multipart/form-data` | ✅ |
| `Annotated[str, Header()]` | 请求头 | — | ✅ |
| `Annotated[str, Cookie()]` | Cookie | — | ✅ |
| `request: Request` | 整个原始请求 | 任意 | ✅ |

`Form`、`File`、`Header`、`Cookie` 和 12.2 中的 `Query`、`Path` 是"兄弟"——它们都继承自同一套参数类，所以 `default`、`alias`、`description`、`min_length`、`pattern`、`deprecated` 等校验/文档参数用法完全一样。

## 2. 表单数据：`Form`

### 2.1 安装依赖

FastAPI 解析表单依赖 `python-multipart`。如果用 `pip install "fastapi[standard]"` 安装，它已经包含在内；否则需要单独安装：

```bash
pip install python-multipart
```

没装的话，应用**启动时**就会报错，提示需要安装 `python-multipart`。

### 2.2 基本用法

```python
# main.py
from typing import Annotated

from fastapi import FastAPI, Form

app = FastAPI()


@app.post("/login")
async def login(
    username: Annotated[str, Form()],
    password: Annotated[str, Form(min_length=6)],
):
    return {"username": username}
```

运行与请求：

```bash
fastapi dev main.py

# -d 发送的是 application/x-www-form-urlencoded
curl -X POST http://127.0.0.1:8000/login -d "username=tom&password=123456"
# {"username":"tom"}
```

> ⚠️ **为什么必须显式写 `Form()`？** 如果只写 `username: str`，FastAPI 会把它当成**查询参数**。`Form()` 是在告诉框架"这个值从请求体的表单字段里取"。

如果客户端用 JSON 调用这个接口，会得到 422，因为表单字段在 JSON 里找不到：

```bash
curl -X POST http://127.0.0.1:8000/login \
  -H "Content-Type: application/json" \
  -d '{"username": "tom", "password": "123456"}'
```

```json
{
  "detail": [
    {"type": "missing", "loc": ["body", "username"], "msg": "Field required", "input": null},
    {"type": "missing", "loc": ["body", "password"], "msg": "Field required", "input": null}
  ]
}
```

### 2.3 表单的两种编码

| 编码 | 何时出现 | 能否带文件 |
|---|---|---|
| `application/x-www-form-urlencoded` | HTML `<form>` 默认、`curl -d` | ❌ |
| `multipart/form-data` | `<form enctype="multipart/form-data">`、`curl -F` | ✅ |

对于 `Form()` 参数，FastAPI 两种编码都能解析，开发者无需关心。只有带文件时客户端必须用 `multipart/form-data`。

### 2.4 表单模型：用 Pydantic 模型声明一组表单字段

当表单字段很多时，可以像 JSON 请求体一样用 Pydantic 模型来声明，只需要在 `Annotated` 里加上 `Form()`：

```python
from typing import Annotated

from fastapi import FastAPI, Form
from pydantic import BaseModel, Field

app = FastAPI()


class LoginForm(BaseModel):
    model_config = {"extra": "forbid"}  # 禁止出现模型之外的字段

    username: str
    password: str = Field(min_length=6)
    remember_me: bool = False


@app.post("/login")
async def login(data: Annotated[LoginForm, Form()]):
    return data
```

```bash
curl -X POST http://127.0.0.1:8000/login -d "username=tom&password=123456&remember_me=true"
# {"username":"tom","password":"123456","remember_me":true}

curl -X POST http://127.0.0.1:8000/login -d "username=tom&password=123456&extra=1"
# {"detail":[{"type":"extra_forbidden","loc":["body","extra"],"msg":"Extra inputs are not permitted","input":"1"}]}
```

> 💡 `model_config = {"extra": "forbid"}` 适合"严格表单"：客户端多传了任何字段都会被拒绝，能更早发现前后端字段名不一致的问题。

## 3. 文件上传：`File` 与 `UploadFile`

文件上传必须使用 `multipart/form-data`，同样依赖 `python-multipart`。FastAPI 提供两种接收方式。

### 3.1 `bytes`：整个文件读进内存

```python
from typing import Annotated

from fastapi import FastAPI, File

app = FastAPI()


@app.post("/files")
async def create_file(file: Annotated[bytes, File()]):
    return {"file_size": len(file)}
```

```bash
echo -n "hello" > a.txt
curl -X POST http://127.0.0.1:8000/files -F "file=@a.txt"
# {"file_size":5}
```

简单，但**整个文件会被读进内存**，并且拿不到文件名和类型。只适合很小的文件。

### 3.2 `UploadFile`：推荐方式

```python
from fastapi import FastAPI, UploadFile

app = FastAPI()


@app.post("/upload")
async def upload(file: UploadFile):
    content = await file.read()
    return {
        "filename": file.filename,
        "content_type": file.content_type,
        "size": file.size,
        "read_bytes": len(content),
    }
```

```bash
curl -X POST http://127.0.0.1:8000/upload -F "file=@a.txt;type=text/plain"
# {"filename":"a.txt","content_type":"text/plain","size":5,"read_bytes":5}
```

注意 `UploadFile` 类型的参数**不需要**写 `File()`，FastAPI 能从类型推断出来；当你想加 `description` 等元信息时再写成 `Annotated[UploadFile, File(description="...")]`。

### 3.3 `bytes` vs `UploadFile`

| 对比项 | `bytes` + `File()` | `UploadFile` |
|---|---|---|
| 存储方式 | 全部放内存 | `SpooledTemporaryFile`：小文件在内存，超过阈值自动落到临时磁盘文件 |
| 大文件 | 可能耗尽内存 | ✅ 安全 |
| 文件名 / 类型 | ❌ 拿不到 | ✅ `filename` / `content_type` |
| 读取方式 | 直接是 `bytes` | `await file.read()` 等异步方法 |
| 适用 | 几 KB 的小文件、快速原型 | **绝大多数场景** |

### 3.4 `UploadFile` 的属性与方法

| 属性 | 说明 |
|---|---|
| `filename` | 客户端上传时的原始文件名（**不可信**，可能包含路径） |
| `content_type` | 客户端声明的 MIME 类型，如 `image/png`（**不可信**，可伪造） |
| `size` | 文件大小（字节） |
| `headers` | 该文件分段的头信息 |
| `file` | 底层的 `SpooledTemporaryFile`，是一个普通的同步文件对象 |

| 异步方法 | 说明 |
|---|---|
| `await file.read(size=-1)` | 读取 `size` 字节，默认读全部 |
| `await file.write(data)` | 写入 |
| `await file.seek(offset)` | 移动文件指针，例如 `seek(0)` 回到开头 |
| `await file.close()` | 关闭文件 |

指针的行为和普通文件一致——读过一次后，再读需要先 `seek(0)`：

```python
from fastapi import FastAPI, UploadFile

app = FastAPI()


@app.post("/peek")
async def peek(file: UploadFile):
    head = await file.read(3)   # 读前 3 字节，例如检查文件魔数
    await file.seek(0)          # 回到开头
    full = await file.read()
    await file.close()
    return {"head": head.decode(), "full": full.decode()}
```

```bash
echo -n "abcdef" > s.txt
curl -X POST http://127.0.0.1:8000/peek -F "file=@s.txt"
# {"head":"abc","full":"abcdef"}
```

### 3.5 保存到磁盘：分块读取 + 大小限制

把整个文件 `read()` 进内存再写盘，对大文件来说一样危险。正确做法是**分块**读写，并在过程中检查大小：

```python
from pathlib import Path

from fastapi import FastAPI, HTTPException, UploadFile, status

app = FastAPI()

UPLOAD_DIR = Path("uploads")
UPLOAD_DIR.mkdir(exist_ok=True)
CHUNK_SIZE = 1024 * 1024        # 每次读 1 MB
MAX_SIZE = 5 * 1024 * 1024      # 最大 5 MB


@app.post("/upload")
async def upload(file: UploadFile):
    # 只取文件名部分，防止 "../../etc/passwd" 这类路径穿越
    dest = UPLOAD_DIR / Path(file.filename).name
    size = 0
    with dest.open("wb") as f:
        while chunk := await file.read(CHUNK_SIZE):
            size += len(chunk)
            if size > MAX_SIZE:
                f.close()
                dest.unlink()   # 删除写了一半的文件
                raise HTTPException(status.HTTP_413_CONTENT_TOO_LARGE, "文件过大")
            f.write(chunk)
    return {"filename": file.filename, "saved_to": str(dest), "size": size}
```

```bash
curl -X POST http://127.0.0.1:8000/upload -F "file=@a.txt;filename=../../evil.txt"
# {"filename":"../../evil.txt","saved_to":"uploads/evil.txt","size":5}
```

可以看到恶意文件名中的 `../../` 被 `Path(...).name` 去掉了。

> ⚠️ 生产环境中，更稳妥的做法是**完全不使用客户端文件名**，而是用 `uuid4().hex + 后缀` 生成服务端文件名，原始文件名只存进数据库用于展示。

> ⚠️ `with dest.open("wb")` 中的 `f.write()` 是同步磁盘 IO，在 `async def` 里会短暂阻塞事件循环。文件不大时可以接受；高并发大文件场景可以用 `aiofiles`，或者改用下面的同步写法。

### 3.6 同步写法：`def` 路由 + `shutil.copyfileobj`

`UploadFile.file` 是普通的同步文件对象。如果路由函数用 `def`（而非 `async def`）定义，FastAPI 会把它放进线程池执行，这时可以放心使用同步 IO：

```python
import shutil
from pathlib import Path

from fastapi import FastAPI, UploadFile

app = FastAPI()
UPLOAD_DIR = Path("uploads")
UPLOAD_DIR.mkdir(exist_ok=True)


@app.post("/upload-sync")
def upload_sync(file: UploadFile):
    dest = UPLOAD_DIR / Path(file.filename).name
    with dest.open("wb") as f:
        shutil.copyfileobj(file.file, f)   # 内部就是分块复制
    return {"saved_to": str(dest), "file_type": type(file.file).__name__}
# {"saved_to":"uploads/s.txt","file_type":"SpooledTemporaryFile"}
```

### 3.7 可选文件与多文件上传

```python
from typing import Annotated

from fastapi import FastAPI, File, UploadFile

app = FastAPI()


@app.post("/avatar")
async def avatar(file: UploadFile | None = None):
    if file is None:
        return {"message": "未上传文件，使用默认头像"}
    return {"filename": file.filename}


@app.post("/multi")
async def multi(files: Annotated[list[UploadFile], File(description="可一次上传多个文件")]):
    return {"filenames": [f.filename for f in files], "count": len(files)}
```

多文件上传时，客户端用**同一个字段名**重复多次：

```bash
curl -X POST http://127.0.0.1:8000/multi -F "files=@a.txt" -F "files=@s.txt"
# {"filenames":["a.txt","s.txt"],"count":2}
```

### 3.8 文件 + 表单字段混合

一个请求里同时上传文件和普通字段（例如"发帖 = 标题 + 正文 + 配图"）是非常常见的需求：

```python
from typing import Annotated

from fastapi import FastAPI, File, Form, UploadFile

app = FastAPI()


@app.post("/profile")
async def update_profile(
    name: Annotated[str, Form()],
    avatar: Annotated[UploadFile, File(description="头像图片")],
    tags: Annotated[list[str], Form()] = [],
):
    return {"name": name, "avatar": avatar.filename, "tags": tags}
```

```bash
curl -X POST http://127.0.0.1:8000/profile \
  -F "name=tom" -F "tags=a" -F "tags=b" -F "avatar=@me.png;type=image/png"
# {"name":"tom","avatar":"me.png","tags":["a","b"]}
```

### 3.9 为什么不能同时接收 Form 和 JSON Body

下面的写法**看起来**合理，实际上永远无法正常工作：

```python
from typing import Annotated

from fastapi import FastAPI, Form
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str


@app.post("/mix")
async def mix(title: Annotated[str, Form()], item: Item):
    return {"title": title, "item": item}
```

原因在 HTTP 协议层面：**一个请求只有一个请求体，也只有一个 `Content-Type`**。它要么是表单编码，要么是 JSON，不可能同时是两者。只要路由声明了任何 `Form`/`File` 参数，FastAPI 就会按表单解析整个请求体，此时 `item` 也被当作表单字段去找，结果找不到：

```json
{"detail":[{"type":"missing","loc":["body","item"],"msg":"Field required","input":null}]}
```

解决方案：

| 方案 | 做法 |
|---|---|
| 全部改用表单 | 把 `Item` 的字段拆成多个 `Form()`，或用 `Annotated[Item, Form()]` 表单模型 |
| JSON 字符串塞进表单字段 | `meta: Annotated[str, Form()]`，在函数里 `Item.model_validate_json(meta)` |
| 拆成两个接口 | 先 `POST /files` 上传得到文件 ID，再用 JSON 接口提交业务数据（大型项目常用） |

## 4. 请求头：`Header`

### 4.1 基本用法与下划线自动转换

```python
from typing import Annotated

from fastapi import FastAPI, Header

app = FastAPI()


@app.get("/headers")
async def read_headers(
    user_agent: Annotated[str | None, Header()] = None,
    x_request_id: Annotated[str | None, Header()] = None,
):
    return {"user_agent": user_agent, "x_request_id": x_request_id}
```

```bash
curl http://127.0.0.1:8000/headers -H "X-Request-ID: abc-123"
# {"user_agent":"curl/8.7.1","x_request_id":"abc-123"}
```

这里有两个"自动"：

1. **下划线 → 连字符**：HTTP 头习惯写成 `User-Agent`，但 Python 变量名不能有 `-`，所以 FastAPI 自动把参数名 `user_agent` 转换成 `user-agent` 去匹配。
2. **大小写不敏感**：HTTP 头名本来就不区分大小写，`X-Request-ID`、`x-request-id` 都能匹配到 `x_request_id`。

### 4.2 关闭转换：`convert_underscores=False`

极少数情况下，某些客户端或代理会发送**真的带下划线**的头（如 `strange_header`）。这时要关闭转换：

```python
from typing import Annotated

from fastapi import FastAPI, Header

app = FastAPI()


@app.get("/strange")
async def strange(
    strange_header: Annotated[str | None, Header(convert_underscores=False)] = None,
):
    return {"strange_header": strange_header}
```

> ⚠️ 很多代理服务器（如 Nginx 默认配置）会**直接丢弃**名字含下划线的请求头。自定义请求头请一律使用连字符。

### 4.3 重复的请求头：用 `list` 接收

同一个头可以出现多次。声明为 `list[str]` 即可拿到全部值：

```python
from typing import Annotated

from fastapi import FastAPI, Header

app = FastAPI()


@app.get("/tokens")
async def tokens(x_token: Annotated[list[str] | None, Header()] = None):
    return {"x_token": x_token}
```

```bash
curl http://127.0.0.1:8000/tokens -H "X-Token: foo" -H "X-Token: bar"
# {"x_token":["foo","bar"]}
```

### 4.4 必填请求头

不给默认值就是必填。缺失时返回 422，`loc` 中的位置是 `header`：

```python
from typing import Annotated

from fastapi import FastAPI, Header

app = FastAPI()


@app.get("/secure")
async def secure(x_api_key: Annotated[str, Header()]):
    return {"key_prefix": x_api_key[:4]}
```

```bash
curl http://127.0.0.1:8000/secure
# {"detail":[{"type":"missing","loc":["header","x-api-key"],"msg":"Field required","input":null}]}
```

> 💡 注意 `loc` 里显示的是转换后的名字 `x-api-key`。像 API Key 这类"每个接口都要校验"的头，后面 12.7 会教你用**依赖注入**统一处理，而不是在每个路由里都写一遍。

### 4.5 Header 参数模型

一组相关的头可以用 Pydantic 模型声明：

```python
from typing import Annotated

from fastapi import FastAPI, Header
from pydantic import BaseModel

app = FastAPI()


class CommonHeaders(BaseModel):
    host: str
    x_tag: list[str] = []
    x_client_version: str | None = None


@app.get("/common")
async def common(headers: Annotated[CommonHeaders, Header()]):
    return headers
```

```bash
curl http://127.0.0.1:8000/common -H "X-Tag: a" -H "X-Tag: b" -H "X-Client-Version: 1.2.0"
# {"host":"127.0.0.1:8000","x_tag":["a","b"],"x_client_version":"1.2.0"}
```

模型字段同样会做下划线到连字符的转换。

## 5. Cookie：`Cookie`

### 5.1 读取 Cookie

```python
from typing import Annotated

from fastapi import FastAPI, Cookie

app = FastAPI()


@app.get("/me")
async def me(session_id: Annotated[str | None, Cookie()] = None):
    if session_id is None:
        return {"message": "未登录"}
    return {"session_id": session_id}
```

```bash
curl http://127.0.0.1:8000/me
# {"message":"未登录"}

curl http://127.0.0.1:8000/me -b "session_id=abc123"
# {"session_id":"abc123"}
```

> 💡 Cookie 参数名**不会**做下划线转换，`session_id` 就匹配名为 `session_id` 的 Cookie。

> 💡 本节只讲"读取" Cookie。"设置" Cookie 属于响应的一部分，放在 12.5 的 `response.set_cookie()` 中讲解。

### 5.2 Cookie 参数模型

```python
from typing import Annotated

from fastapi import FastAPI, Cookie
from pydantic import BaseModel

app = FastAPI()


class Cookies(BaseModel):
    model_config = {"extra": "forbid"}

    session_id: str
    theme: str = "light"
    tracker: str | None = None


@app.get("/prefs")
async def prefs(cookies: Annotated[Cookies, Cookie()]):
    return cookies
```

```bash
curl http://127.0.0.1:8000/prefs -b "session_id=abc"
# {"session_id":"abc","theme":"light","tracker":null}

curl http://127.0.0.1:8000/prefs -b "session_id=abc; foo=x"
# {"detail":[{"type":"extra_forbidden","loc":["cookie","foo"],"msg":"Extra inputs are not permitted","input":"x"}]}
```

> ⚠️ 对 Cookie 使用 `extra="forbid"` 要谨慎：浏览器会携带同域下的**所有** Cookie（包括第三方统计脚本写入的），开启后很容易误伤正常用户。它更适合内部 API。

## 6. 直接使用 `Request` 对象

### 6.1 什么时候需要 `Request`

FastAPI 底层基于 Starlette。在路由函数中声明一个类型为 `Request` 的参数，就能拿到 Starlette 的原始请求对象：

```python
from fastapi import FastAPI, Request

app = FastAPI()


@app.post("/raw")
async def raw(request: Request):
    body = await request.body()
    return {
        "client_host": request.client.host if request.client else None,
        "method": request.method,
        "url": str(request.url),
        "path": request.url.path,
        "query": dict(request.query_params),
        "content_type": request.headers.get("content-type"),
        "cookies": request.cookies,
        "body": body.decode(),
    }
```

```bash
curl -X POST "http://127.0.0.1:8000/raw?a=1" -b "sid=1" \
  -H "Content-Type: text/plain" -d "hi"
```

```json
{
  "client_host": "127.0.0.1",
  "method": "POST",
  "url": "http://127.0.0.1:8000/raw?a=1",
  "path": "/raw",
  "query": {"a": "1"},
  "content_type": "text/plain",
  "cookies": {"sid": "1"},
  "body": "hi"
}
```

### 6.2 `Request` 常用属性与方法

| 成员 | 说明 |
|---|---|
| `request.method` | 请求方法，如 `"POST"` |
| `request.url` | 完整 URL 对象，有 `.path`、`.query`、`.scheme`、`.hostname` 等 |
| `request.base_url` | 应用根地址 |
| `request.headers` | 请求头（大小写不敏感的只读映射） |
| `request.query_params` | 查询参数（多值映射，`getlist("k")` 取多值） |
| `request.path_params` | 路径参数字典 |
| `request.cookies` | Cookie 字典 |
| `request.client` | 客户端 `(host, port)`，可能为 `None` |
| `request.state` | 请求级的"临时存储"，中间件和依赖常用来传递数据 |
| `request.app` | 当前 FastAPI 应用实例 |
| `await request.body()` | 原始请求体 `bytes` |
| `await request.json()` | 解析为 JSON |
| `await request.form()` | 解析为表单（需 `python-multipart`） |

```python
from fastapi import FastAPI, Request

app = FastAPI()


@app.post("/form-raw")
async def form_raw(request: Request):
    form = await request.form()
    return {"keys": list(form.keys())}
# curl -X POST http://127.0.0.1:8000/form-raw -d "a=1&b=2"
# {"keys":["a","b"]}
```

### 6.3 声明式参数 vs `Request`

| 对比 | 声明式参数（`Query`/`Body`/`Header`...） | `request: Request` |
|---|---|---|
| 类型转换与校验 | ✅ 自动 | ❌ 自己做 |
| 出现在 `/docs` | ✅ | ❌ 文档里看不到 |
| 灵活度 | 受限于声明 | 可读取任何东西 |
| 适用 | **默认选择** | 签名校验（需原始 body）、Webhook、动态字段、中间件/依赖内部 |

一个典型的必须用 `Request` 的场景是 **Webhook 签名校验**：第三方（如 GitHub、Stripe）会对**原始请求体**计算 HMAC 签名，你必须拿原始 bytes 来验签，一旦先解析成 JSON 再序列化，字节就可能变化，签名对不上。

> ⚠️ `Request` 和声明式参数可以混用：`async def f(item: Item, request: Request)`。但如果你在 `Request` 上读取了 body，又声明了 Body 参数，要清楚 body 已被 FastAPI 读取过一次（Starlette 会缓存，所以可以再次 `await request.body()`）。

## 7. 综合示例：带鉴权头的文件上传接口

把本节内容组合起来：通过请求头校验 API Key，接收"标题 + 多张图片"，并限制文件类型。

```python
# main.py
from pathlib import Path
from typing import Annotated
from uuid import uuid4

from fastapi import FastAPI, File, Form, Header, HTTPException, UploadFile, status

app = FastAPI()

UPLOAD_DIR = Path("uploads")
UPLOAD_DIR.mkdir(exist_ok=True)
ALLOWED_TYPES = {"image/png": ".png", "image/jpeg": ".jpg"}
API_KEY = "secret-key"


@app.post("/posts", status_code=status.HTTP_201_CREATED)
async def create_post(
    x_api_key: Annotated[str, Header()],
    title: Annotated[str, Form(min_length=1, max_length=50)],
    images: Annotated[list[UploadFile], File()],
    user_agent: Annotated[str | None, Header()] = None,
):
    if x_api_key != API_KEY:
        raise HTTPException(status.HTTP_401_UNAUTHORIZED, "API Key 无效")

    saved = []
    for image in images:
        suffix = ALLOWED_TYPES.get(image.content_type)
        if suffix is None:
            raise HTTPException(
                status.HTTP_415_UNSUPPORTED_MEDIA_TYPE,
                f"不支持的文件类型：{image.content_type}",
            )
        dest = UPLOAD_DIR / f"{uuid4().hex}{suffix}"
        dest.write_bytes(await image.read())
        saved.append({"original": image.filename, "stored": dest.name})

    return {"title": title, "images": saved, "client": user_agent}
```

```bash
curl -X POST http://127.0.0.1:8000/posts \
  -H "X-API-Key: secret-key" \
  -F "title=周末出游" \
  -F "images=@1.png;type=image/png" \
  -F "images=@2.jpg;type=image/jpeg"
```

```json
{
  "title": "周末出游",
  "images": [
    {"original": "1.png", "stored": "3f2a...e1.png"},
    {"original": "2.jpg", "stored": "9b7c...04.jpg"}
  ],
  "client": "curl/8.7.1"
}
```

> 💡 打开 `http://127.0.0.1:8000/docs`，可以看到 Swagger UI 自动为 `images` 生成了多文件选择框、为 `X-API-Key` 生成了 Header 输入框——声明式参数的好处在这里体现得很明显。

> ⚠️ `content_type` 由客户端声明，可以伪造。严肃场景需要读取文件头几个字节检查"魔数"（如 PNG 以 `\x89PNG` 开头），或使用 `python-magic`、`Pillow` 做真实校验。

## 常见坑

1. **忘了写 `Form()` / `Header()` / `Cookie()`**：参数会被当作查询参数，请求永远 422 或拿到 `None`。
2. **没装 `python-multipart`**：只要有 `Form`/`File` 参数，启动时就会报错。
3. **想同时接收表单和 JSON**：HTTP 请求只有一个 body，做不到，见 3.9 的替代方案。
4. **`bytes` 接大文件**：整个文件进内存，几个并发大文件就能把服务打挂，用 `UploadFile` + 分块。
5. **信任 `filename` / `content_type`**：前者可能含 `../` 造成路径穿越，后者可伪造，都要在服务端重新处理。
6. **读完文件再读得到空 bytes**：文件指针已在末尾，需要 `await file.seek(0)`。
7. **自定义 Header 用下划线**：会被很多代理丢弃，一律用连字符，如 `X-Request-ID`。
8. **Cookie 模型开启 `extra="forbid"`**：浏览器会带上各种无关 Cookie，容易误伤。
9. **滥用 `Request`**：手动解析的参数不会校验、不会出现在文档中，能声明就声明。

## 小结

- `Form`、`File`、`Header`、`Cookie` 与 `Query`、`Path` 用法一致，都通过 `Annotated[类型, XXX()]` 声明来源与校验规则。
- 表单和文件依赖 `python-multipart`；文件上传必须是 `multipart/form-data`。
- 文件优先用 `UploadFile`：内存友好、有元信息、支持异步读写；保存时分块写入并限制大小，不信任客户端文件名和类型。
- 一个请求只有一个 body，表单与 JSON 不能并存。
- `Header` 自动把下划线转成连字符、大小写不敏感，`list[str]` 可接收重复头；`Cookie` 不做转换。
- 表单、Header、Cookie 都支持用 Pydantic 模型批量声明，`extra="forbid"` 可禁止多余字段。
- `Request` 是"逃生舱"，适合需要原始数据的场景（如 Webhook 验签），日常优先使用声明式参数。
