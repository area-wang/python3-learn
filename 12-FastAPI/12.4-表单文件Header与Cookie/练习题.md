## 三、编程题

### 1. 注册表单（基础）

实现 `POST /register`，以表单方式接收：

- `username`：3~20 个字符，只允许字母、数字、下划线；
- `password`：至少 8 位；
- `agree`：布尔值，必须为 `true`，否则返回 400；
- 使用 **表单模型**（`Annotated[RegisterForm, Form()]`）实现，并禁止多余字段；
- 返回中**不要**包含密码。

### 2. 客户端信息接口（基础）

实现 `GET /client-info`，返回：

- `User-Agent`、`Accept-Language` 请求头（可选）；
- 所有 `X-Feature-Flag` 头的值（可能有多个，返回列表）；
- 名为 `theme` 的 Cookie，没有时默认为 `"light"`；
- 客户端 IP（提示：`request.client`）。

要求使用 Header 参数模型组织请求头。

### 3. 头像上传（进阶）

实现 `POST /users/{user_id}/avatar`：

- 只接收 `image/png`、`image/jpeg`，否则返回 415；
- 读取文件前 8 个字节校验魔数（PNG：`\x89PNG\r\n\x1a\n`，JPEG：以 `\xff\xd8\xff` 开头），与 `content_type` 不一致时返回 400；
- 文件大小上限 2 MB，**分块**读取过程中超限立即返回 413，且不留下残缺文件；
- 服务端文件名使用 `{user_id}_{uuid}.{ext}`，不使用客户端文件名；
- 返回保存后的文件名和字节数。

### 4. 批量上传与统计（进阶）

实现 `POST /batch`，接收：

- `files`：多个文件，最多 5 个，超出返回 400；
- `category`：表单字段，枚举值 `doc` / `image` / `other`；
- 返回每个文件的文件名、大小、`content_type`，以及总大小；
- 再实现一个 `def`（同步）版本 `/batch-sync`，用 `shutil.copyfileobj` 保存文件，思考两个版本在线程模型上的区别。

### 5. 带 JSON 元数据的上传（进阶）

实现 `POST /documents`，在一次 `multipart/form-data` 请求中同时接收：

- `file`：文档文件；
- `meta`：表单字段，内容是 JSON 字符串，如 `{"title": "周报", "tags": ["work"]}`；
- 在函数内用 Pydantic 模型 `DocumentMeta.model_validate_json()` 解析 `meta`，解析失败时返回 422，错误信息要能指出是哪个字段错了；
- 用 `curl -F` 写出调用命令。

### 6. Webhook 验签（挑战）

模拟一个第三方 Webhook 接收端 `POST /webhook`：

- 第三方在请求头 `X-Signature` 中携带 `sha256=<hex>`，值为 `HMAC-SHA256(secret, 原始请求体)`；
- 使用 `Request` 读取原始请求体并验签（使用 `hmac.compare_digest` 防止时序攻击）；
- 验签失败返回 401，成功后再把 body 解析为 JSON 并返回其中的 `event` 字段；
- 写一段 Python 脚本（使用 `httpx`）模拟第三方发送正确签名和错误签名的请求。
- 思考：如果把参数声明为 Pydantic 模型 `payload: Event`，再用 `payload.model_dump_json()` 重新计算签名，为什么可能验签失败？

## 四、综合实践：迷你网盘接口

实现一个内存 + 磁盘结合的迷你网盘服务：

1. `POST /files`：上传单个文件，需要请求头 `X-User`（用户名）；文件保存到 `storage/{用户名}/` 下，服务端生成文件 ID，元信息（ID、原始文件名、大小、类型、上传时间）存在内存字典中；
2. 上传限制：单文件最大 10 MB（分块校验），每个用户最多 20 个文件；
3. `GET /files`：根据 `X-User` 头列出该用户的文件元信息；
4. `POST /files/{file_id}/rename`：通过表单字段 `new_name` 修改展示名（不修改磁盘文件名）；
5. 用 Cookie `view_mode`（`list` / `grid`）决定 `GET /files` 返回结构：`list` 返回数组，`grid` 返回按文件类型分组的字典；
6. 所有错误使用合适的状态码：缺少 `X-User` → 422、超限 → 413、文件不存在 → 404、超出数量 → 400；
7. 打开 `/docs`，确认每个接口的 Header、Cookie、表单、文件参数都正确出现在文档中，并通过 Swagger UI 完成一次上传。
