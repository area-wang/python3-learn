# 12.9 数据库集成练习题

## 一、概念题

1. `Engine`、`sessionmaker`、`Session` 三者分别是什么？为什么 engine 全局只创建一个，而 Session 要每个请求创建一个？
2. 为什么推荐用带 `yield` 的依赖来提供 Session？`yield` 前后的代码分别负责什么？如果改成 `return SessionLocal()` 会有什么后果？
3. `Mapped[int]`、`Mapped[int | None]`、`Mapped[str] = mapped_column(String(50))` 分别会生成什么样的列？`default` 与 `server_default` 有什么区别？
4. 为什么要把 ORM 模型和 Pydantic Schema 分开定义？请说出 `UserCreate`、`UserUpdate`、`UserRead` 三者在字段上的典型差异。
5. `ConfigDict(from_attributes=True)` 的作用是什么？在什么情况下不配置它也能正常工作，什么情况下一定会报错？
6. `session.add()`、`session.flush()`、`session.commit()`、`session.refresh()`、`session.rollback()` 各自做了什么？什么时候需要 `flush()`？
7. 唯一约束冲突时为什么推荐「数据库约束 + 捕获 `IntegrityError`」而不是只靠「先查询是否存在再插入」？捕获后为什么必须 `rollback()`？
8. 什么是 N+1 问题？`selectinload` 和 `joinedload` 分别生成什么样的 SQL，各适合哪种关系？
9. 使用 `AsyncSession` 时为什么必须设置 `expire_on_commit=False`？为什么懒加载关系会报 `MissingGreenlet`？
10. `Base.metadata.create_all()` 和 Alembic 迁移各适用于什么阶段？`alembic revision --autogenerate` 有哪些检测不到或会误判的变更？

### 2. PATCH 把数据清空了

```python
class UserUpdate(BaseModel):
    name: str | None = None
    age: int | None = None


@app.patch("/users/{user_id}", response_model=UserRead)
def update_user(user_id: int, data: UserUpdate, session: SessionDep):
    user = session.get(User, user_id)
    for key, value in data.model_dump().items():
        setattr(user, key, value)
    session.commit()
    return user
```

## 三、编程题

### 1. 图书 CRUD（基础）

用 SQLAlchemy + SQLite 实现图书管理接口：

- 模型 `Book`：`id`、`title`（必填，最长 100）、`isbn`（唯一）、`price`（`Decimal`，≥ 0）、`stock`（默认 0）、`created_at`（数据库生成）；
- 定义 `BookCreate` / `BookUpdate` / `BookRead` 三个 Schema；
- 实现 `POST /books`、`GET /books/{id}`、`PATCH /books/{id}`、`DELETE /books/{id}`；
- 不存在返回 404，ISBN 重复返回 409。

### 2. 分页与过滤（基础）

为上题增加 `GET /books`：

- 支持 `offset`、`limit`（1~100）分页，返回 `{"total": ..., "items": [...]}`；
- 支持 `keyword`（标题模糊匹配）、`min_price`、`max_price` 可选过滤，`total` 要反映过滤后的数量；
- 支持 `sort` 参数，取值为 `price`、`-price`、`created_at`、`-created_at`（`-` 表示降序），用 `Enum` 限定取值。

### 3. 把「查不到就 404」写成依赖（进阶）

编写依赖 `get_book_or_404(book_id: int, session: SessionDep) -> Book`，并定义 `BookDep = Annotated[Book, Depends(get_book_or_404)]`，让读取、更新、删除接口都直接接收 `book: BookDep`。思考：依赖和路由中拿到的 `session` 是同一个吗？为什么？（提示：回顾 12.7 中依赖缓存 `use_cache`。）

### 4. 一对多：分类与图书（进阶）

- 新增 `Category` 模型，与 `Book` 建立一对多关系，删除分类时其下图书的 `category_id` 置空（提示：`ForeignKey(..., ondelete="SET NULL")` + `passive_deletes=True`，并思考 SQLite 需要开启外键支持）；
- `GET /categories` 返回每个分类及其图书列表；
- 用 `event.listens_for(engine, "before_cursor_execute")` 统计 SQL 条数，分别实现 N+1 版本和 `selectinload` 版本，记录对比结果。

### 5. 下单事务（进阶）

实现 `POST /orders`，请求体为 `{"book_id": 1, "quantity": 2}`：

- 在**同一个事务**中扣减库存并创建订单记录；
- 库存不足返回 400，且数据库中不能留下任何部分修改；
- 分别用「路由内显式 commit」和「`session.begin()` 事务依赖 + `scope="function"`」两种方式实现，并比较两者的优缺点。

### 6. 异步改造（挑战）

把第 1~4 题改造为 `create_async_engine` + `AsyncSession` 版本：

- 用 lifespan 建表、在关闭时 `engine.dispose()`；
- 所有关系字段的读取都要预加载，并在关系上设置 `lazy="raise"`，确认任何遗漏的懒加载都会立即报错而不是悄悄变慢。

## 四、综合实践：带迁移的博客后端

搭建一个博客后端的数据层与接口：

1. 模型：`User`（邮箱唯一）、`Post`（属于某个用户）、`Comment`（属于某篇文章和某个用户），用 `relationship` 建立双向关系；
2. 按 12.12 的思路拆分 `database.py`、`models.py`、`schemas.py`、`crud.py`、`routers/`；
3. 接口：用户注册、发文章、给文章评论、文章列表（分页，每篇带作者名和评论数）、文章详情（带全部评论及评论者）；
4. 文章列表的评论数用 SQL 聚合（`func.count` + `group_by` 或子查询）计算，而不是把评论全部查出来再 `len()`；
5. 使用 Alembic 管理表结构：先生成初始迁移，再给 `Post` 增加 `view_count` 字段生成第二个迁移，并演示 `upgrade head` / `downgrade -1`；
6. 打开 `echo=True` 检查每个接口执行的 SQL，确保列表接口没有 N+1。
