# 12.9 数据库集成

前面几节的数据都存在内存里的字典或列表中，进程一重启就全部丢失。真实的 Web 服务需要把数据持久化到数据库，并且要回答几个工程问题：**每个请求怎么拿到数据库会话、用完怎么关闭**；**ORM 模型和接口的输入输出模型是什么关系**；**唯一约束冲突、记录不存在这些错误怎么转成合适的 HTTP 状态码**；**关联查询如何避免 N+1**；**表结构变了怎么平滑升级**。本节以 SQLAlchemy 2.x 为主线回答这些问题，它把 12.7 学过的「yield 依赖」和 12.3 学过的 Pydantic 模型真正串了起来。

> 本节示例在 FastAPI 0.143 / SQLAlchemy 2.1 / Pydantic 2.14 / Python 3.14 下实测通过。为了方便运行，统一使用 SQLite（无需安装数据库服务），切换到 PostgreSQL/MySQL 时只需更换连接 URL 和驱动。

## 1. 技术选型

FastAPI 本身不绑定任何数据库，常见方案如下：

| 方案 | 特点 | 适用场景 |
|---|---|---|
| **SQLAlchemy 2.x**（本节主线） | Python 生态事实标准 ORM，功能最全，同时支持同步和异步 | 绝大多数项目，**首选** |
| SQLModel | FastAPI 作者开发，基于 SQLAlchemy + Pydantic，一个类同时充当表模型和数据模型 | 中小项目、想少写重复模型 |
| Tortoise ORM | 仿 Django ORM 的纯异步 ORM | 习惯 Django 风格的团队 |
| 原生驱动（asyncpg、psycopg） | 手写 SQL，性能最好、控制力最强 | 对性能极致敏感、SQL 复杂的场景 |

安装（`EmailStr` 需要 `email-validator`，`fastapi[standard]` 已自带）：

```bash
pip install "fastapi[standard]" sqlalchemy
# 异步版本还需要（注意 [asyncio]，它会装上 greenlet）：
pip install "sqlalchemy[asyncio]" aiosqlite
```

## 2. 连接数据库：Engine

`Engine` 是 SQLAlchemy 的入口，负责管理**连接池**。整个应用只创建**一个** engine，在模块级别定义即可。

```python
from sqlalchemy import create_engine

DATABASE_URL = "sqlite:///./app.db"

engine = create_engine(
    DATABASE_URL,
    connect_args={"check_same_thread": False},  # 仅 SQLite 需要
    echo=True,  # 打印执行的 SQL，调试时很有用，生产环境关掉
)
```

常见数据库的连接 URL 格式：`方言+驱动://用户名:密码@主机:端口/数据库名`

| 数据库 | 同步 URL 示例 | 异步 URL 示例 |
|---|---|---|
| SQLite | `sqlite:///./app.db`（三个斜杠 = 相对路径） | `sqlite+aiosqlite:///./app.db` |
| PostgreSQL | `postgresql+psycopg://user:pwd@localhost:5432/db` | `postgresql+asyncpg://user:pwd@localhost:5432/db` |
| MySQL | `mysql+pymysql://user:pwd@localhost:3306/db` | `mysql+aiomysql://user:pwd@localhost:3306/db` |

> 💡 **为什么 SQLite 要 `check_same_thread=False`？** Python 的 `sqlite3` 默认禁止在创建连接之外的线程使用该连接。而 FastAPI 会把普通 `def` 路由和 `def` 依赖放进**线程池**执行，连接池里的同一个连接会先后被不同线程使用，因此需要关闭这个检查。由于我们保证「一个请求一个 Session」，同一时刻一个连接只被一个线程使用，所以是安全的。
>
> 实际上 SQLAlchemy 2.0+ 在使用**文件型** SQLite 时已经**自动**把它设为 `False`（查看 `sqlalchemy/dialects/sqlite/pysqlite.py` 的文档可确认），显式写出来是为了表达意图并兼容旧版本 / 官方教程。但用 `sqlite://`（内存库）或直接使用 `sqlite3` 模块时仍必须自己处理。其他数据库不需要也不能传这个参数。

> ⚠️ 连接串里的密码不要硬编码，应从环境变量或配置读取（见 12.12 的 pydantic-settings）。

## 3. 声明 ORM 模型

SQLAlchemy 2.x 推荐使用**类型注解风格**的声明式模型：继承 `DeclarativeBase`，用 `Mapped[...]` 声明列类型，用 `mapped_column()` 补充约束。

```python
from datetime import datetime

from sqlalchemy import String, func
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column


class Base(DeclarativeBase):
    pass


class User(Base):
    __tablename__ = "users"

    id: Mapped[int] = mapped_column(primary_key=True)
    email: Mapped[str] = mapped_column(String(255), unique=True, index=True)
    name: Mapped[str] = mapped_column(String(50))
    age: Mapped[int | None]  # 可空列，没有额外约束时可以省略 mapped_column
    is_active: Mapped[bool] = mapped_column(default=True)
    created_at: Mapped[datetime] = mapped_column(server_default=func.now())


Base.metadata.create_all(engine)  # 按模型建表（表已存在则跳过）
```

`Mapped` 注解与数据库列的对应规则：

| 注解 | 生成的列 | 说明 |
|---|---|---|
| `Mapped[int]` | `INTEGER NOT NULL` | 非 Optional 类型自动 `NOT NULL` |
| `Mapped[int \| None]` | `INTEGER NULL` | `\| None` 自动允许为空 |
| `Mapped[str]` + `String(50)` | `VARCHAR(50) NOT NULL` | 字符串建议显式给长度（MySQL 必须） |
| `Mapped[bool]` | `BOOLEAN` | |
| `Mapped[datetime]` | `DATETIME` | |
| `Mapped[float]` / `Mapped[Decimal]` | `FLOAT` / `NUMERIC` | 金额用 `Decimal` |

`mapped_column()` 常用参数：

| 参数 | 作用 |
|---|---|
| `primary_key=True` | 主键；整数主键默认自增 |
| `unique=True` / `index=True` | 唯一约束 / 普通索引 |
| `default=...` | **Python 侧**默认值，INSERT 时由 SQLAlchemy 填充 |
| `server_default=...` | **数据库侧**默认值，写进建表语句（如 `func.now()`） |
| `nullable=False` | 显式指定是否可空（通常交给 `Mapped` 推断） |
| `ForeignKey("表名.列名")` | 外键（作为位置参数传入） |

> ⚠️ `create_all()` 只会**新建不存在的表**，不会给已有的表加列、改类型。学习阶段用它很方便，正式项目的表结构变更请交给 Alembic（见第 11 节）。

## 4. Session 与 yield 依赖

`Session` 是「一次数据库对话」：它追踪你加载和修改过的对象，在 `commit()` 时统一写回数据库。**Session 不是线程安全的**，正确的用法是**每个请求创建一个、请求结束关闭**——这正是 12.7 中 yield 依赖的典型场景。

```python
from typing import Annotated

from fastapi import Depends
from sqlalchemy.orm import Session, sessionmaker

SessionLocal = sessionmaker(bind=engine, autoflush=False, expire_on_commit=False)


def get_session():
    with SessionLocal() as session:  # with 结束时自动 close，连接归还连接池
        yield session


SessionDep = Annotated[Session, Depends(get_session)]
```

- `sessionmaker` 是 Session 的工厂，统一配置后每次调用 `SessionLocal()` 得到一个新 Session。
- `autoflush=False`：查询前不自动把未提交的修改 flush 到数据库，行为更可预测。
- `expire_on_commit=False`：`commit()` 后不让对象属性过期。默认 `True` 时，提交后再访问 `user.name` 会触发一次重新查询；设为 `False` 后可以直接把对象交给响应模型序列化（异步场景中**必须**设为 `False`，见第 9 节）。
- `SessionDep` 是用 `Annotated` 定义的依赖别名，路由里写 `session: SessionDep` 即可注入。

## 5. ORM 模型与 Pydantic Schema 分离

初学者常犯的错误是直接把 ORM 模型当作接口的输入输出。正确做法是 ORM 模型只负责「表结构」，接口另外定义 Pydantic Schema：

| 模型 | 用途 | 典型字段 |
|---|---|---|
| `User`（ORM） | 映射数据库表 | 全部列，包括 `hashed_password` 等内部字段 |
| `UserCreate` | 创建时的请求体 | 客户端可以提交的字段，**没有** `id` |
| `UserUpdate` | 部分更新的请求体 | 全部可选 |
| `UserRead` | 响应体 | 允许返回给客户端的字段，**有** `id`，**没有**密码 |

```python
from datetime import datetime

from pydantic import BaseModel, ConfigDict, EmailStr, Field


class UserCreate(BaseModel):
    email: EmailStr
    name: str = Field(min_length=1, max_length=50)
    age: int | None = Field(default=None, ge=0, le=150)


class UserUpdate(BaseModel):
    name: str | None = Field(default=None, min_length=1, max_length=50)
    age: int | None = Field(default=None, ge=0, le=150)
    is_active: bool | None = None


class UserRead(BaseModel):
    model_config = ConfigDict(from_attributes=True)  # 允许从 ORM 对象的属性读取数据

    id: int
    email: str
    name: str
    age: int | None
    is_active: bool
    created_at: datetime
```

`from_attributes=True`（Pydantic v1 中叫 `orm_mode`）让 Pydantic 可以通过 `obj.id`、`obj.name` 这样的**属性访问**来构造模型，而不仅仅是字典取值：

```python
user = session.get(User, 1)
UserRead.model_validate(user)  # ORM 对象 → Pydantic 模型；没配 from_attributes 会抛 ValidationError
```

在路由中声明 `response_model=UserRead` 后直接 `return user`，FastAPI 会自动完成这一步转换，并过滤掉 Schema 中没有的字段。

> 💡 实测细节：FastAPI 校验**响应**时内部总是以 `from_attributes=True` 调用（见 `fastapi/_compat/v2.py`），所以即使 Schema 没配置，`return orm_obj` 也能正常返回。但在 service 层、测试、后台任务中**手动**调用 `UserRead.model_validate(orm_obj)` 时就必须配置。建议所有「读」模型统一加上，行为一致、意图清晰。

> 💡 分离的好处：数据库加一个内部字段不会意外泄露到接口；接口字段改名不必动表结构；创建、更新、读取三种场景的校验规则可以各不相同。

## 6. 完整 CRUD 示例

把前面的内容组合起来，得到一个可运行的用户管理 API。保存为 `main.py`：

```python
from datetime import datetime
from typing import Annotated

from fastapi import Depends, FastAPI, HTTPException, Query, status
from pydantic import BaseModel, ConfigDict, EmailStr, Field
from sqlalchemy import String, create_engine, func, select
from sqlalchemy.exc import IntegrityError
from sqlalchemy.orm import DeclarativeBase, Mapped, Session, mapped_column, sessionmaker

# ---------- 数据库配置 ----------
DATABASE_URL = "sqlite:///./app.db"
engine = create_engine(DATABASE_URL, connect_args={"check_same_thread": False})
SessionLocal = sessionmaker(bind=engine, autoflush=False, expire_on_commit=False)


class Base(DeclarativeBase):
    pass


# ---------- ORM 模型 ----------
class User(Base):
    __tablename__ = "users"

    id: Mapped[int] = mapped_column(primary_key=True)
    email: Mapped[str] = mapped_column(String(255), unique=True, index=True)
    name: Mapped[str] = mapped_column(String(50))
    age: Mapped[int | None]
    is_active: Mapped[bool] = mapped_column(default=True)
    created_at: Mapped[datetime] = mapped_column(server_default=func.now())


Base.metadata.create_all(engine)


# ---------- Session 依赖 ----------
def get_session():
    with SessionLocal() as session:
        yield session


SessionDep = Annotated[Session, Depends(get_session)]


# ---------- Pydantic Schema ----------
class UserCreate(BaseModel):
    email: EmailStr
    name: str = Field(min_length=1, max_length=50)
    age: int | None = Field(default=None, ge=0, le=150)


class UserUpdate(BaseModel):
    name: str | None = Field(default=None, min_length=1, max_length=50)
    age: int | None = Field(default=None, ge=0, le=150)
    is_active: bool | None = None


class UserRead(BaseModel):
    model_config = ConfigDict(from_attributes=True)

    id: int
    email: str
    name: str
    age: int | None
    is_active: bool
    created_at: datetime


class UserPage(BaseModel):
    total: int
    items: list[UserRead]


app = FastAPI()


def get_user_or_404(session: Session, user_id: int) -> User:
    user = session.get(User, user_id)
    if user is None:
        raise HTTPException(status_code=404, detail=f"用户 {user_id} 不存在")
    return user


@app.post("/users", response_model=UserRead, status_code=status.HTTP_201_CREATED)
def create_user(data: UserCreate, session: SessionDep):
    user = User(**data.model_dump())
    session.add(user)
    try:
        session.commit()
    except IntegrityError:
        session.rollback()
        raise HTTPException(status_code=409, detail="邮箱已被注册")
    session.refresh(user)
    return user


@app.get("/users", response_model=UserPage)
def list_users(
    session: SessionDep,
    offset: Annotated[int, Query(ge=0)] = 0,
    limit: Annotated[int, Query(ge=1, le=100)] = 10,
):
    total = session.scalar(select(func.count()).select_from(User))
    users = session.scalars(
        select(User).order_by(User.id).offset(offset).limit(limit)
    ).all()
    return {"total": total, "items": users}


@app.get("/users/{user_id}", response_model=UserRead)
def read_user(user_id: int, session: SessionDep):
    return get_user_or_404(session, user_id)


@app.patch("/users/{user_id}", response_model=UserRead)
def update_user(user_id: int, data: UserUpdate, session: SessionDep):
    user = get_user_or_404(session, user_id)
    for key, value in data.model_dump(exclude_unset=True).items():
        setattr(user, key, value)
    session.commit()
    session.refresh(user)
    return user


@app.delete("/users/{user_id}", status_code=status.HTTP_204_NO_CONTENT)
def delete_user(user_id: int, session: SessionDep):
    user = get_user_or_404(session, user_id)
    session.delete(user)
    session.commit()
```

运行：

```bash
fastapi dev main.py
```

逐个解释关键点：

### 6.1 查询 API：`select()` + `scalars()` / `scalar()` / `get()`

SQLAlchemy 2.x 统一使用 `select()` 构造语句，再交给 Session 执行：

| 写法 | 返回 | 典型用途 |
|---|---|---|
| `session.get(User, 1)` | 对象或 `None` | 按主键取单条（会优先查 Session 缓存） |
| `session.scalars(stmt).all()` | 对象列表 | 查多条 |
| `session.scalars(stmt).first()` | 第一个对象或 `None` | 取第一条 |
| `session.scalar(stmt)` | 单个值或 `None` | `count()`、按条件取单条 |
| `session.execute(stmt).all()` | `Row` 元组列表 | 查多列，如 `select(User.id, User.name)` |

常用查询构造：

```python
select(User).where(User.age >= 18, User.is_active == True)  # 多个条件为 AND
select(User).where(User.name.like("%张%"))
select(User).where(User.id.in_([1, 2, 3]))
select(User).order_by(User.created_at.desc()).offset(20).limit(10)
select(func.count()).select_from(User)
```

> ⚠️ 旧教程里的 `session.query(User).filter(...)` 是 1.x 风格的 Legacy API，2.x 仍能用但不再推荐，新代码统一用 `select()`。

### 6.2 分页

分页参数用 `Query(ge=..., le=...)` 加上限，防止客户端一次拉取全表。响应里同时返回 `total` 方便前端计算页数。注意 **分页必须配合 `order_by`**，否则不同页之间的顺序不保证稳定。

### 6.3 404：先查再操作

`session.get()` 查不到返回 `None`，在公共函数 `get_user_or_404()` 里统一转成 404。读取、更新、删除三个接口都复用它。（也可以把它写成依赖，见本节练习题。）

### 6.4 唯一约束冲突 → 409

邮箱有 `unique=True` 约束，重复插入时 `commit()` 抛出 `sqlalchemy.exc.IntegrityError`。处理要点：

1. 捕获后**必须先 `session.rollback()`**，否则这个 Session 处于失败状态，后续任何操作都会报错；
2. 转换成 `409 Conflict`（资源冲突），而不是让它变成 500。

> 💡 也可以先 `select` 一下邮箱是否存在再插入，但「先查后插」在并发时仍可能冲突，**数据库约束 + 捕获异常**才是可靠的兜底。实际项目中两者常结合使用：先查用于给出友好提示，捕获异常用于兜底。

### 6.5 PATCH 部分更新：`exclude_unset=True`

`UserUpdate` 所有字段都是可选的。`model_dump(exclude_unset=True)` 只导出**客户端真正传了的字段**：

```python
UserUpdate(age=21).model_dump()                    # {'name': None, 'age': 21, 'is_active': None}
UserUpdate(age=21).model_dump(exclude_unset=True)  # {'age': 21}
```

如果不加 `exclude_unset`，只想改 `age` 时会把 `name` 也设为 `None`。同时它还能区分「没传」和「显式传了 null」：`{"age": null}` 会把 age 清空，而不传 age 则保持不变。

### 6.6 `refresh()` 的作用

`created_at` 使用 `server_default`，值由数据库生成，Python 对象里一开始并没有。`session.refresh(user)` 会重新从数据库读一次，把这类字段（以及自增 id）加载回对象。

## 7. 一对多关系与 N+1 问题

### 7.1 定义关系

用 `ForeignKey` 定义外键列，用 `relationship()` 定义对象之间的导航属性，`back_populates` 让两边保持同步：

```python
from sqlalchemy import ForeignKey, String
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, relationship


class Base(DeclarativeBase):
    pass


class Author(Base):
    __tablename__ = "authors"

    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(50))
    # 一对多：一个作者有多篇文章
    posts: Mapped[list["Post"]] = relationship(
        back_populates="author", cascade="all, delete-orphan"
    )


class Post(Base):
    __tablename__ = "posts"

    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(100))
    author_id: Mapped[int] = mapped_column(ForeignKey("authors.id"))
    # 多对一：每篇文章属于一个作者
    author: Mapped["Author"] = relationship(back_populates="posts")
```

- `Mapped[list["Post"]]` 表示「多」的一方，`Mapped["Author"]` 表示「一」的一方；字符串形式用于引用后面才定义的类。
- `cascade="all, delete-orphan"`：删除作者时级联删除其文章；从 `author.posts` 中移除的文章也会被删除。
- 建立关联时既可以给外键赋值 `Post(author_id=1)`，也可以给关系赋值 `Post(author=author)`，后者会自动填好 `author_id`。

### 7.2 嵌套响应模型

```python
from pydantic import BaseModel, ConfigDict


class PostRead(BaseModel):
    model_config = ConfigDict(from_attributes=True)
    id: int
    title: str


class AuthorRead(BaseModel):
    model_config = ConfigDict(from_attributes=True)
    id: int
    name: str


class AuthorWithPosts(AuthorRead):
    posts: list[PostRead]
```

Pydantic 在序列化 `AuthorWithPosts` 时会访问 `author.posts`，从而触发关系加载。

### 7.3 N+1 问题与 `selectinload`

关系默认是**懒加载**（lazy load）：查作者时不查文章，第一次访问 `author.posts` 时才单独发一条 SQL。如果一次返回 N 个作者，就会产生 **1 条查作者 + N 条查文章**，这就是著名的 **N+1 问题**。

下面的完整示例用 SQLAlchemy 事件统计每个请求执行的 SQL 条数：

```python
from typing import Annotated

from fastapi import Depends, FastAPI, HTTPException
from pydantic import BaseModel, ConfigDict
from sqlalchemy import ForeignKey, String, create_engine, event, select
from sqlalchemy.orm import (
    DeclarativeBase,
    Mapped,
    Session,
    mapped_column,
    relationship,
    selectinload,
    sessionmaker,
)

engine = create_engine("sqlite:///./blog.db", connect_args={"check_same_thread": False})
SessionLocal = sessionmaker(bind=engine, autoflush=False, expire_on_commit=False)

# 统计执行了多少条 SQL，用来观察 N+1 问题
query_count = 0


@event.listens_for(engine, "before_cursor_execute")
def count_queries(*args):
    global query_count
    query_count += 1


class Base(DeclarativeBase):
    pass


class Author(Base):
    __tablename__ = "authors"

    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(50))
    posts: Mapped[list["Post"]] = relationship(
        back_populates="author", cascade="all, delete-orphan"
    )

    __tablename__ = "posts"

Base.metadata.drop_all(engine)
Base.metadata.create_all(engine)


def get_session():

        yield session

    model_config = ConfigDict(from_attributes=True)

app = FastAPI()

    if author is None:
        raise HTTPException(404, "作者不存在")

@app.get("/authors-slow", response_model=list[AuthorWithPosts])

    return session.scalars(select(Author)).all()

/authors SQL 条数: 2

```

5 个作者时是 6 条 vs 2 条；1000 个作者时就是 1001 条 vs 2 条。几种加载策略对比：

| 策略 | SQL 形式 | 适用 |
|---|---|---|
| 懒加载（默认 `lazy="select"`） | 访问时每个对象一条 | 只偶尔访问关系；**列表接口要避免** |
| `selectinload()` | 主查询 + 一条 `WHERE ... IN (...)` | **一对多/多对多首选** |
| `joinedload()` | 一条 `LEFT JOIN` | 多对一（如查文章时带上作者） |
| `raiseload()` | 访问未加载的关系直接报错 | 强制团队显式声明加载策略 |

> 💡 经验法则：**响应模型里包含关系字段的接口，查询时一定要显式 `options(selectinload(...))` 或 `joinedload(...)`**。打开 `echo=True` 看 SQL 日志，是发现 N+1 最直接的办法。

## 8. 事务与 commit / rollback 策略

### 8.1 基本概念

- `session.add(obj)`：把对象放入 Session，此时还没写数据库。
- `session.flush()`：把待处理的修改发送给数据库（执行 INSERT/UPDATE），但**事务未提交**；常用于提前拿到自增 id。
- `session.commit()`：提交事务，修改永久生效。
- `session.rollback()`：回滚当前事务内所有未提交的修改。
- Session 被关闭时，未提交的事务会**自动回滚**。

### 8.2 两种常见策略

**策略 A：在路由（或 service 层）中显式 commit。** 第 6 节的 CRUD 就是这种写法，好处是直观，能在 commit 处就地捕获 `IntegrityError` 转换成 409。

**策略 B：请求级事务依赖。** 让依赖负责事务边界，路由里只管修改对象：

```python
from typing import Annotated

from fastapi import Depends, FastAPI, HTTPException
from sqlalchemy import CheckConstraint, String, create_engine, select
from sqlalchemy.orm import DeclarativeBase, Mapped, Session, mapped_column, sessionmaker

engine = create_engine("sqlite:///./bank.db", connect_args={"check_same_thread": False})
SessionLocal = sessionmaker(bind=engine, autoflush=False, expire_on_commit=False)


class Base(DeclarativeBase):
    pass


class Account(Base):
    __tablename__ = "accounts"
    __table_args__ = (CheckConstraint("balance >= 0", name="balance_non_negative"),)

    id: Mapped[int] = mapped_column(primary_key=True)
    owner: Mapped[str] = mapped_column(String(50))
    balance: Mapped[int]


Base.metadata.drop_all(engine)
Base.metadata.create_all(engine)
with SessionLocal() as s:
    s.add_all([Account(owner="A", balance=100), Account(owner="B", balance=0)])
    s.commit()


def get_tx_session():
    """请求级事务：正常结束自动 commit，抛异常自动 rollback"""
    with SessionLocal() as session:
        with session.begin():
            yield session


TxSessionDep = Annotated[Session, Depends(get_tx_session, scope="function")]
app = FastAPI()


@app.post("/transfer")
def transfer(from_id: int, to_id: int, amount: int, session: TxSessionDep):
    src = session.get(Account, from_id)
    dst = session.get(Account, to_id)
    if src is None or dst is None:
        raise HTTPException(404, "账户不存在")
    if src.balance < amount:
        raise HTTPException(400, "余额不足")
    src.balance -= amount
    dst.balance += amount
    # 不需要手动 commit：依赖退出时 session.begin() 会统一提交
    return {"msg": "转账成功"}


@app.get("/accounts")
def accounts(session: TxSessionDep):
    return [{"owner": a.owner, "balance": a.balance} for a in session.scalars(select(Account))]
```

实测：

```text
POST /transfer?from_id=1&to_id=2&amount=30   → 200 {"msg":"转账成功"}
GET  /accounts                               → [{"owner":"A","balance":70},{"owner":"B","balance":30}]
POST /transfer?from_id=1&to_id=2&amount=500  → 400 {"detail":"余额不足"}
GET  /accounts                               → 余额不变
```

`with session.begin():` 块正常退出时自动 commit；路由抛出任何异常（包括 `HTTPException`）时，异常会被抛进生成器，`begin()` 块捕获后自动 rollback。

> ⚠️ **注意 `scope="function"`！** 带 yield 的依赖默认在**响应发送之后**才执行 `yield` 后面的代码。如果把 commit 放在依赖退出时，又没有指定 `scope="function"`，那么即使 commit 失败（例如违反 `CHECK` 约束），客户端也**已经收到了 200**——实测如下：
>
> ```text
> # Depends(get_tx_session)                    → handler return → 200 {"msg":"ok?"} → 之后 commit 失败
> # Depends(get_tx_session, scope="function")  → handler return → commit 失败 → 500
> ```
>
> `scope="function"` 让依赖在路由函数结束后、**响应发送之前**退出，提交失败才能正确反映到响应里。只负责关闭 Session、不做 commit 的 `get_session()` 用默认值即可。

### 8.3 选择建议

| 场景 | 推荐 |
|---|---|
| 简单 CRUD、需要就地处理 `IntegrityError` | 策略 A，路由/service 中显式 commit |
| 一个请求内多步写操作必须原子完成（转账、下单扣库存） | 策略 B，或在 service 中用 `with session.begin():` 包住 |
| 需要部分回滚 | `session.begin_nested()`（SAVEPOINT） |

## 9. 异步版本：AsyncSession

如果路由用 `async def`，又在里面调用同步的 `session.scalars()`，会**阻塞事件循环**（参见 8.8 异步编程）。要么路由用普通 `def`（FastAPI 会放到线程池执行，第 6 节就是这样），要么整条链路都换成异步驱动 + `AsyncSession`。

```bash
pip install "sqlalchemy[asyncio]" aiosqlite
```

> ⚠️ 必须安装 `sqlalchemy[asyncio]`，它会带上 `greenlet`。只装 `sqlalchemy` 时导入 `sqlalchemy.ext.asyncio` 会直接报错：`ImportError: The SQLAlchemy asyncio module requires that the Python 'greenlet' library is installed.`

```python
from contextlib import asynccontextmanager
from typing import Annotated

from fastapi import Depends, FastAPI, HTTPException
from pydantic import BaseModel, ConfigDict
from sqlalchemy import ForeignKey, String, select
from sqlalchemy.ext.asyncio import AsyncSession, async_sessionmaker, create_async_engine
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column, relationship, selectinload

engine = create_async_engine("sqlite+aiosqlite:///./async.db")
AsyncSessionLocal = async_sessionmaker(engine, expire_on_commit=False)


class Base(DeclarativeBase):
    pass


class Author(Base):
    __tablename__ = "authors"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str] = mapped_column(String(50))
    posts: Mapped[list["Post"]] = relationship(back_populates="author")


class Post(Base):
    __tablename__ = "posts"
    id: Mapped[int] = mapped_column(primary_key=True)
    title: Mapped[str] = mapped_column(String(100))
    author_id: Mapped[int] = mapped_column(ForeignKey("authors.id"))
    author: Mapped[Author] = relationship(back_populates="posts")


@asynccontextmanager
async def lifespan(app: FastAPI):
    # create_all 是同步 API，需要通过 run_sync 在异步连接上执行
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.drop_all)
        await conn.run_sync(Base.metadata.create_all)
    yield
    await engine.dispose()  # 关闭连接池


async def get_session():
    async with AsyncSessionLocal() as session:
        yield session


SessionDep = Annotated[AsyncSession, Depends(get_session)]


class PostRead(BaseModel):
    model_config = ConfigDict(from_attributes=True)
    id: int
    title: str


class AuthorRead(BaseModel):
    model_config = ConfigDict(from_attributes=True)
    id: int
    name: str
    posts: list[PostRead] = []


app = FastAPI(lifespan=lifespan)


@app.post("/authors", response_model=AuthorRead, status_code=201)
async def create_author(name: str, session: SessionDep):
    author = Author(name=name, posts=[])  # 显式给空列表，序列化时就不会触发懒加载
    session.add(author)
    await session.commit()
    return author


@app.post("/authors/{author_id}/posts", response_model=PostRead, status_code=201)
async def create_post(author_id: int, title: str, session: SessionDep):
    if await session.get(Author, author_id) is None:
        raise HTTPException(404, "作者不存在")
    post = Post(title=title, author_id=author_id)
    session.add(post)
    await session.commit()
    return post


@app.get("/authors/{author_id}", response_model=AuthorRead)
async def read_author(author_id: int, session: SessionDep):
    stmt = (
        select(Author)
        .where(Author.id == author_id)
        .options(selectinload(Author.posts))  # 异步下必须显式预加载关系
    )
    author = await session.scalar(stmt)
    if author is None:
        raise HTTPException(404, "作者不存在")
    return author


@app.get("/authors-bad/{author_id}", response_model=AuthorRead)
async def read_author_bad(author_id: int, session: SessionDep):
    author = await session.get(Author, author_id)
    return author  # 序列化时访问 author.posts 触发懒加载 → MissingGreenlet
```

实测：

```text
POST /authors?name=张三            → {"id":1,"name":"张三","posts":[]}
POST /authors/1/posts?title=异步入门 → {"id":1,"title":"异步入门"}
GET  /authors/1                    → {"id":1,"name":"张三","posts":[{"id":1,"title":"异步入门"}]}
GET  /authors-bad/1                → 500，服务端日志：
  ResponseValidationError ... Error extracting attribute: StatementError:
  (sqlalchemy.exc.MissingGreenlet) greenlet_spawn has not been called ...
```

同步与异步写法对照：

| 同步 | 异步 |
|---|---|
| `create_engine("sqlite:///...")` | `create_async_engine("sqlite+aiosqlite:///...")` |
| `sessionmaker(...)` | `async_sessionmaker(...)` |
| `with SessionLocal() as s:` | `async with AsyncSessionLocal() as s:` |
| `s.get(...)` / `s.scalars(...)` / `s.commit()` | 前面都要加 `await` |
| `session.add(obj)` | `session.add(obj)`（**不需要** await，只是放入 Session） |
| `Base.metadata.create_all(engine)` | `await conn.run_sync(Base.metadata.create_all)` |
| 关系可以懒加载 | **懒加载会报 `MissingGreenlet`**，必须 `selectinload` 等预加载 |

异步场景两条铁律：

1. **`expire_on_commit=False` 必须设置**。否则 commit 后访问任何属性都会触发隐式 IO，在异步环境中直接报 `MissingGreenlet`。
2. **不要依赖懒加载**。所有要序列化的关系都在查询时预加载；也可以在关系上设置 `lazy="selectin"` 或 `lazy="raise"`。

> 💡 同步还是异步？如果数据库操作是主要耗时、且并发量大，异步更省资源；但同步 `def` 路由 + 线程池在多数业务里已经足够，而且心智负担更小。**不要混用**：在 `async def` 里调用同步 Session 是最糟糕的组合。

## 10. SQLModel 简介

SQLModel 由 FastAPI 作者开发，底层就是 SQLAlchemy + Pydantic。它最大的卖点是：**一个类加上 `table=True` 就既是表模型又是 Pydantic 模型**，通过继承减少重复定义。

```bash
pip install sqlmodel
```

```python
from typing import Annotated

from fastapi import Depends, FastAPI
from sqlmodel import Field, Session, SQLModel, create_engine, select


class HeroBase(SQLModel):
    name: str = Field(index=True)
    age: int | None = None


class Hero(HeroBase, table=True):  # table=True：既是 ORM 模型，也是 Pydantic 模型
    id: int | None = Field(default=None, primary_key=True)


class HeroCreate(HeroBase):
    pass


class HeroRead(HeroBase):
    id: int


engine = create_engine("sqlite:///./hero.db", connect_args={"check_same_thread": False})
SQLModel.metadata.create_all(engine)


def get_session():
    with Session(engine) as session:
        yield session


SessionDep = Annotated[Session, Depends(get_session)]
app = FastAPI()


@app.post("/heroes", response_model=HeroRead)
def create_hero(hero: HeroCreate, session: SessionDep):
    db_hero = Hero.model_validate(hero)
    session.add(db_hero)
    session.commit()
    session.refresh(db_hero)
    return db_hero


@app.get("/heroes", response_model=list[HeroRead])
def list_heroes(session: SessionDep):
    return session.exec(select(Hero)).all()
```

```text
POST /heroes {"name": "钢铁侠", "age": 45} → {"name":"钢铁侠","age":45,"id":1}
GET  /heroes                               → [{"name":"钢铁侠","age":45,"id":1}]
```

| 对比项 | SQLAlchemy + Pydantic | SQLModel |
|---|---|---|
| 模型定义 | ORM 模型、Schema 各写一套 | 通过继承共享字段，代码更少 |
| 查询 | `session.scalars(select(...))` | `session.exec(select(...))`，类型提示更友好 |
| 功能完整度 | 完整 | 复杂场景（高级关系、特殊类型）仍需回到 SQLAlchemy API |
| 文档与生态 | 极其丰富 | 较少，版本仍为 0.0.x |
| 推荐 | 中大型项目、团队协作 | 小项目、原型、学习 |

> 💡 学会 SQLAlchemy 后再看 SQLModel 几乎零成本，反过来则不然。因此本章以 SQLAlchemy 为主线。

## 11. Alembic 数据库迁移入门

`create_all()` 无法处理「给已有的表加一列」这类变更。生产环境使用 **Alembic**（SQLAlchemy 官方迁移工具）把每次表结构变化记录成一个版本化的迁移脚本，像 Git 管理代码一样管理数据库结构。

```bash
pip install alembic
alembic init migrations     # 生成 alembic.ini 和 migrations/ 目录
```

生成的目录结构：

```text
.
├── alembic.ini             # 配置文件：数据库 URL 等
├── migrations/
│   ├── env.py              # 迁移运行环境：告诉 Alembic 模型在哪里
│   ├── script.py.mako      # 迁移脚本模板
│   └── versions/           # 每次迁移生成一个 .py 文件
└── main.py
```

**第 1 步：配置数据库 URL**（`alembic.ini`）

```ini
sqlalchemy.url = sqlite:///./app.db
```

> 💡 实际项目通常在 `env.py` 中用 `config.set_main_option("sqlalchemy.url", settings.database_url)` 从配置读取，避免在 ini 里写密码。

**第 2 步：告诉 Alembic 模型的元数据**（`migrations/env.py`）

```python
# 把原来的 target_metadata = None 改为：
from main import Base  # 导入你的 DeclarativeBase，确保所有模型都已被导入
target_metadata = Base.metadata
```

**第 3 步：自动生成迁移并执行**

```bash
alembic revision --autogenerate -m "create users"
# INFO  [alembic.autogenerate.compare.tables] Detected added table 'users'
# INFO  [alembic.autogenerate.compare.constraints] Detected added index 'ix_users_email' on '('email',)'
# Generating .../migrations/versions/930a2e52cc97_create_users.py ...  done

alembic upgrade head
# INFO  [alembic.runtime.migration] Running upgrade  -> 930a2e52cc97, create users
```

此后不再在代码里调用 `Base.metadata.create_all()`。

**第 4 步：修改模型 → 再生成迁移**

给 `User` 加一个字段：

```python
phone: Mapped[str | None] = mapped_column(String(20))
```

```bash
alembic revision --autogenerate -m "add phone"
# INFO  [alembic.autogenerate.compare.tables] Detected added column 'users.phone'
alembic upgrade head
```

生成的迁移脚本（`versions/xxxx_add_phone.py`）：

```python
def upgrade() -> None:
    """Upgrade schema."""
    op.add_column('users', sa.Column('phone', sa.String(length=20), nullable=True))


def downgrade() -> None:
    """Downgrade schema."""
    op.drop_column('users', 'phone')
```

常用命令：

| 命令 | 作用 |
|---|---|
| `alembic revision --autogenerate -m "说明"` | 对比模型与数据库，生成迁移脚本 |
| `alembic revision -m "说明"` | 生成空白迁移脚本（手写数据迁移） |
| `alembic upgrade head` | 升级到最新版本 |
| `alembic downgrade -1` | 回退一个版本 |
| `alembic current` | 查看数据库当前版本 |
| `alembic history` | 查看迁移历史 |

> ⚠️ `--autogenerate` 不是万能的：**字段改名**会被识别成「删一列 + 加一列」（数据会丢！），某些类型变化、约束名变化也检测不到。**每次生成后都要人工检查迁移脚本**再执行。SQLite 对 `ALTER TABLE` 支持有限，复杂变更需在 `env.py` 的 `context.configure()` 中加 `render_as_batch=True`。

## 12. 项目中的代码组织

单文件示例便于学习，真实项目通常按职责拆分（详见 12.12）：

```text
app/
├── main.py           # 创建 FastAPI 实例、挂载路由
├── database.py       # engine、SessionLocal、Base、get_session、SessionDep
├── models.py         # ORM 模型
├── schemas.py        # Pydantic Schema（UserCreate / UserRead ...）
├── crud.py           # 数据访问函数：get_user、create_user ...（接收 session 参数）
└── routers/
    └── users.py      # 路由：只做参数接收、调用 crud、转换异常
```

把数据库操作抽到 `crud.py`（或 `repositories/`、`services/`）中，路由函数就只剩「接收参数 → 调用 → 返回」，测试时也可以单独测试 crud 函数。

## 常见坑

1. **把 Session 定义成全局变量**：多个请求共享同一个 Session 会导致数据错乱和线程安全问题。必须每个请求一个 Session，用 yield 依赖管理。
2. **`IntegrityError` 后没有 `rollback()`**：Session 停留在失败事务中，后续操作报 `PendingRollbackError`。
3. **Schema 没配 `from_attributes=True`**：`response_model` 场景 FastAPI 会帮你兜底，但手动 `UserRead.model_validate(orm_obj)` 时会抛 `ValidationError`，导致「接口正常、单元测试或后台任务却报错」的怪现象。
4. **把 ORM 模型当请求体或 `response_model`**：SQLAlchemy 模型不是合法的 Pydantic 类型，应用启动（注册路由）时就会抛 `FastAPIError: Invalid args for response field!`；即便能用，也会暴露所有字段。输入输出一律用 Pydantic Schema。
5. **PATCH 没用 `exclude_unset=True`**：没传的字段被覆盖成 `None`。
6. **列表接口 N+1**：响应模型带关系字段时忘了 `selectinload`，数据一多接口就慢。
7. **`async def` 路由里用同步 Session**：阻塞事件循环，所有请求一起变慢。要么用 `def`，要么全套异步。
8. **异步 Session 没设 `expire_on_commit=False`，或依赖懒加载**：报 `MissingGreenlet`。
9. **在依赖退出时 commit 却没指定 `scope="function"`**：commit 失败时客户端已经拿到 200。
10. **改了模型以为 `create_all()` 会同步表结构**：它只建新表；表结构变更要用 Alembic，且要人工检查自动生成的迁移。
11. **SQLite 内存库 / 原生 `sqlite3` 忘了 `check_same_thread=False`**：`def` 路由中报 `SQLite objects created in a thread can only be used in that same thread`（文件库 SQLAlchemy 2.x 会自动处理）。测试中用内存库时，还要配合 `poolclass=StaticPool` 让所有线程共享同一个连接（见 12.13）。

## 小结

- `Engine` 全局一个，管理连接池；`Session` 每请求一个，通过 **yield 依赖 + `Annotated` 别名（`SessionDep`）** 注入并自动关闭。
- SQLAlchemy 2.x 用 `DeclarativeBase` + `Mapped` + `mapped_column` 声明模型，用 `select()` + `scalars()/scalar()/get()` 查询。
- **ORM 模型与 Pydantic Schema 分离**：Create / Update / Read 各司其职，Read 模型开启 `from_attributes=True`。
- CRUD 中的错误转换：记录不存在 → 404，唯一约束冲突 `IntegrityError` → rollback + 409，参数越界 → 422；PATCH 用 `exclude_unset=True`。
- 关系用 `ForeignKey` + `relationship(back_populates=...)` 定义；列表接口用 `selectinload` / `joinedload` 避免 N+1。
- 事务可以在路由中显式 commit，也可以用 `session.begin()` 做请求级事务依赖（配合 `scope="function"`）。
- 异步版：`create_async_engine` + `async_sessionmaker(expire_on_commit=False)` + `AsyncSession`，关系必须预加载。
- SQLModel 能减少重复模型定义，适合小项目；表结构演进交给 Alembic，自动生成的迁移一定要人工审查。
