# 12.3 请求体与 Pydantic 模型

12.2 里的路径参数和查询参数适合传递「少量、扁平」的数据：ID、页码、过滤条件。但创建一个用户、提交一个订单时，客户端要发送的是一整块结构化数据，比如带嵌套地址、商品列表的 JSON——这部分数据放在 HTTP **请求体**（request body）中。FastAPI 用 **Pydantic 模型**来声明请求体：你用一个类描述「数据长什么样」，FastAPI 负责读取 JSON、转换类型、逐字段校验、在出错时返回精确的 422，并把模型结构写进接口文档。本节是整章最核心的内容之一，12.5 的响应模型、12.9 的数据库模型都建立在它之上。

> 本节聚焦 Pydantic 在 FastAPI 中的用法。如果你对 `dataclass`（10.2）比较熟悉，可以把 `BaseModel` 理解为「会自动校验和转换的 dataclass」。

## 1. 第一个请求体模型

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tax: float | None = None


@app.post("/items")
async def create_item(item: Item):
    data = item.model_dump()
    if item.tax is not None:
        data["price_with_tax"] = item.price + item.tax
    return data
```

```bash
curl -X POST http://127.0.0.1:8000/items \
  -H "Content-Type: application/json" \
  -d '{"name": "键盘", "price": 199, "tax": 19.9}'
# {"name":"键盘","description":null,"price":199.0,"tax":19.9,"price_with_tax":218.9}
```

FastAPI 在背后做了这些事：

1. 以 JSON 格式读取请求体；
2. 按 `Item` 的类型声明转换数据（`199` → `199.0`）；
3. 校验数据，失败时返回 422，指出具体哪个字段有问题；
4. 把结果作为 `Item` 实例传给参数 `item`，编辑器能对 `item.price` 做自动补全和类型检查；
5. 为模型生成 JSON Schema，显示在 `/docs` 中。

字段是否必填的规则与查询参数一致：**有默认值即可选**。上例中 `name`、`price` 必填，`description`、`tax` 可选。

### 1.1 校验失败的样子

```bash
curl -X POST http://127.0.0.1:8000/items \
  -H "Content-Type: application/json" \
  -d '{"name": "键盘", "price": "免费"}'
```

```json
{
  "detail": [
    {
      "type": "float_parsing",
      "loc": ["body", "price"],
      "msg": "Input should be a valid number, unable to parse string as a number",
      "input": "免费"
    }
  ]
}
```

`loc` 的第一项变成了 `body`，后面跟着字段名。几种特殊情况：

| 情况 | `type` | `loc` |
|---|---|---|
| 完全没有请求体 | `missing` | `["body"]` |
| 请求体不是合法 JSON | `json_invalid` | `["body", 0]` |
| 缺少某个必填字段 | `missing` | `["body", "price"]` |
| 嵌套字段出错 | 视情况 | `["body", "images", 0, "url"]` |

> ⚠️ 发送 JSON 请求体时，curl 必须带上 `-H "Content-Type: application/json"`。用 `/docs` 页面、httpx、requests 的 `json=` 参数发送时会自动设置。

### 1.2 模型实例的常用方法

`BaseModel` 实例提供了一组以 `model_` 开头的方法（Pydantic v2 命名）：

```python
from pydantic import BaseModel


class Item(BaseModel):
    name: str
    price: float
    tags: list[str] = []


item = Item(name="键盘", price="199")   # 字符串 "199" 被转换成 199.0
print(item)                              # name='键盘' price=199.0 tags=[]
print(item.model_dump())                 # {'name': '键盘', 'price': 199.0, 'tags': []}
print(item.model_dump_json())            # {"name":"键盘","price":199.0,"tags":[]}
print(item.model_dump(include={"name"})) # {'name': '键盘'}
print(item.model_dump(exclude={"tags"})) # {'name': '键盘', 'price': 199.0}

item2 = Item.model_validate({"name": "鼠标", "price": 59})  # 从 dict 构造并校验
item3 = Item.model_validate_json('{"name": "显示器", "price": 999}')  # 从 JSON 字符串构造
item4 = item2.model_copy(update={"price": 49})              # 复制并修改部分字段
print(item4)                             # name='鼠标' price=49 tags=[]
print(Item.model_json_schema())          # 模型的 JSON Schema（/docs 就用它）
```

| Pydantic v2 | Pydantic v1（旧教程常见） | 作用 |
|---|---|---|
| `model_dump()` | `dict()` | 转 dict |
| `model_dump_json()` | `json()` | 转 JSON 字符串 |
| `model_validate()` | `parse_obj()` | 从 dict 构造 |
| `model_validate_json()` | `parse_raw()` | 从 JSON 字符串构造 |
| `model_copy(update=...)` | `copy(update=...)` | 复制 |
| `model_config = ConfigDict(...)` | `class Config:` | 模型配置 |
| `@field_validator` | `@validator` | 字段校验器 |
| `@model_validator` | `@root_validator` | 模型校验器 |

> ⚠️ `model_copy(update=...)` **不会对 update 中的值做校验**（上例 `price=49` 保持为 `int`，没有转换成 `float`）。需要校验时，用 `Item.model_validate({**old.model_dump(), **update})`。

## 2. `Field`：字段级校验与元数据

`Field()` 之于模型字段，就像 `Query()` 之于查询参数，校验参数几乎一样：

```python
from decimal import Decimal

from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()


class Product(BaseModel):
    name: str = Field(min_length=1, max_length=50, description="商品名称")
    sku: str = Field(pattern=r"^[A-Z]{3}-\d{4}$", examples=["KBD-0001"])
    price: Decimal = Field(gt=0, max_digits=8, decimal_places=2)
    stock: int = Field(default=0, ge=0)
    discount: float = Field(default=1.0, gt=0, le=1, description="折扣，1 表示不打折")


@app.post("/products")
async def create_product(product: Product):
    return product
```

```bash
curl -X POST http://127.0.0.1:8000/products -H "Content-Type: application/json" \
  -d '{"name": "", "sku": "kbd-1", "price": -1}'
```

```json
{
  "detail": [
    {"type": "string_too_short", "loc": ["body", "name"], "msg": "String should have at least 1 character", "input": "", "ctx": {"min_length": 1}},
    {"type": "string_pattern_mismatch", "loc": ["body", "sku"], "msg": "String should match pattern '^[A-Z]{3}-\\d{4}$'", "input": "kbd-1", "ctx": {"pattern": "^[A-Z]{3}-\\d{4}$"}},
    {"type": "greater_than", "loc": ["body", "price"], "msg": "Input should be greater than 0", "input": -1, "ctx": {"gt": 0}}
  ]
}
```

所有字段的错误会**一次性全部**返回，客户端可以一次修正所有问题。

`Field` 常用参数：

| 参数 | 作用 |
|---|---|
| `default` / `default_factory` | 默认值 / 默认值工厂（如 `default_factory=list`、`default_factory=datetime.now`） |
| `min_length` / `max_length` / `pattern` | 字符串、列表约束 |
| `gt` / `ge` / `lt` / `le` / `multiple_of` | 数值约束 |
| `max_digits` / `decimal_places` | `Decimal` 的位数约束 |
| `alias` | JSON 中使用的字段名（如前端用 `userName`） |
| `title` / `description` / `examples` | 文档元数据 |
| `exclude=True` | 序列化时排除该字段 |
| `frozen=True` | 字段不可修改 |

> 💡 `Field` 同样可以用 `Annotated` 写法：`name: Annotated[str, Field(min_length=1)]`。两种写法在模型中都很常见，这里用更简短的 `= Field(...)` 写法；在函数参数中则统一用 `Annotated`。

## 3. 嵌套模型与容器类型

模型的字段可以是另一个模型，也可以是 `list`、`set`、`dict` 等容器，组合出任意深度的结构：

```python
from fastapi import FastAPI
from pydantic import BaseModel, HttpUrl

app = FastAPI()


class Image(BaseModel):
    url: HttpUrl
    name: str


class Item(BaseModel):
    name: str
    price: float
    tags: set[str] = set()
    images: list[Image] | None = None
    attributes: dict[str, str] = {}


class Order(BaseModel):
    order_no: str
    items: list[Item]
    remark: str | None = None


@app.post("/orders")
async def create_order(order: Order):
    total = sum(item.price for item in order.items)
    return {"order_no": order.order_no, "count": len(order.items), "total": total}
```

```bash
curl -X POST http://127.0.0.1:8000/orders -H "Content-Type: application/json" -d '{
  "order_no": "A001",
  "items": [
    {"name": "键盘", "price": 199, "tags": ["外设", "外设"],
     "images": [{"url": "https://example.com/kbd.png", "name": "正面"}],
     "attributes": {"颜色": "黑", "轴体": "红轴"}},
    {"name": "鼠标", "price": 59}
  ]
}'
# {"order_no":"A001","count":2,"total":258.0}
```

嵌套字段出错时，`loc` 会精确到具体位置：

```bash
curl -X POST http://127.0.0.1:8000/orders -H "Content-Type: application/json" \
  -d '{"order_no": "A002", "items": [{"name": "键盘", "price": 1, "images": [{"url": "nope", "name": "x"}]}]}'
# ... "type":"url_parsing","loc":["body","items",0,"images",0,"url"],
#     "msg":"Input should be a valid URL, relative URL without a base" ...
```

要点：

- `set[str]` 会自动去重（上例中重复的 `"外设"` 只保留一个），但集合**无序**，返回给客户端时的顺序不固定；
- `list[Image]` 中每个元素都会按 `Image` 校验；
- `dict[str, str]` 约束键和值的类型；
- 请求体的顶层也可以直接是列表：参数声明为 `items: list[Item]`，客户端就发送 `[{...}, {...}]`。

## 4. 常用特殊类型

Pydantic 内置了大量「带校验的类型」，直接用作字段类型即可：

```python
from datetime import date, datetime
from decimal import Decimal
from uuid import UUID, uuid4

from fastapi import FastAPI
from pydantic import BaseModel, EmailStr, Field, HttpUrl

app = FastAPI()


class Account(BaseModel):
    id: UUID = Field(default_factory=uuid4)
    email: EmailStr
    homepage: HttpUrl | None = None
    birthday: date | None = None
    balance: Decimal = Decimal("0.00")
    created_at: datetime = Field(default_factory=datetime.now)


@app.post("/accounts")
async def create_account(account: Account):
    return account
```

```bash
curl -X POST http://127.0.0.1:8000/accounts -H "Content-Type: application/json" \
  -d '{"email": "tom@example.com", "birthday": "2000-01-31", "balance": "100.50"}'
# {"id":"0f4c...（随机 UUID）","email":"tom@example.com","homepage":null,
#  "birthday":"2000-01-31","balance":"100.50","created_at":"2026-10-18T11:03:59.123456"}

curl -X POST http://127.0.0.1:8000/accounts -H "Content-Type: application/json" \
  -d '{"email": "not-an-email"}'
# ... "type":"value_error","loc":["body","email"],
#     "msg":"value is not a valid email address: An email address must have an @-sign." ...
```

| 类型 | 接受的 JSON 输入 | 输出到 JSON |
|---|---|---|
| `EmailStr` | 合法邮箱字符串（需要 `email-validator`，`fastapi[standard]` 已包含） | 字符串 |
| `HttpUrl` / `AnyUrl` | 合法 URL 字符串 | 字符串 |
| `UUID` | UUID 字符串 | 字符串 |
| `datetime` | ISO 8601 字符串（`2025-01-01T10:00:00`、`2025-01-01T10:00:00+08:00`）或时间戳数字 | ISO 字符串 |
| `date` | `2025-01-01` | `"2025-01-01"` |
| `Decimal` | 数字或数字字符串 | **字符串**（如 `"100.50"`，见下方提示） |
| `Enum` / `Literal[...]` | 枚举值 | 枚举值 |
| `SecretStr` | 字符串 | `"**********"`（打印和序列化时都被隐藏） |

> ⚠️ **金额用 `Decimal`，不要用 `float`**：`0.1 + 0.2 != 0.3` 的精度问题在金额计算中是不可接受的。Pydantic v2 把 `Decimal` 序列化为**字符串**以保证精度不丢失，这一点要和前端约定好。注意：如果你先 `model_dump()` 成普通 dict 再返回，FastAPI 会把 dict 中的 `Decimal` 转成 JSON 数字（`100.5`），结果和直接返回模型不一致——最好直接返回模型，或在 12.5 中用 `response_model` 统一控制输出。

## 5. 自定义校验器

### 5.1 `field_validator`：单个字段

```python
from fastapi import FastAPI
from pydantic import BaseModel, field_validator

app = FastAPI()


class UserCreate(BaseModel):
    username: str
    password: str
    tags: list[str] = []

    @field_validator("username")
    @classmethod
    def username_rules(cls, v: str) -> str:
        if " " in v:
            raise ValueError("用户名不能包含空格")
        return v.lower()  # 返回值会成为字段的最终值，可借此做规范化

    @field_validator("password")
    @classmethod
    def password_strength(cls, v: str) -> str:
        if len(v) < 8 or v.isdigit():
            raise ValueError("密码至少 8 位，且不能是纯数字")
        return v

    @field_validator("tags", mode="before")
    @classmethod
    def split_tags(cls, v):
        # mode="before"：在类型转换之前运行，可以接受原始输入
        if isinstance(v, str):
            return [t.strip() for t in v.split(",") if t.strip()]
        return v


@app.post("/users")
async def create_user(user: UserCreate):
    return {"username": user.username, "tags": user.tags}
```

```bash
curl -X POST http://127.0.0.1:8000/users -H "Content-Type: application/json" \
  -d '{"username": "Tom", "password": "abc12345", "tags": "python, web"}'
# {"username":"tom","tags":["python","web"]}

curl -X POST http://127.0.0.1:8000/users -H "Content-Type: application/json" \
  -d '{"username": "to m", "password": "123"}'
# {"detail":[
#   {"type":"value_error","loc":["body","username"],"msg":"Value error, 用户名不能包含空格","input":"to m","ctx":{"error":{}}},
#   {"type":"value_error","loc":["body","password"],"msg":"Value error, 密码至少 8 位，且不能是纯数字","input":"123","ctx":{"error":{}}}
# ]}
```

| `mode` | 运行时机 | 入参 | 典型用途 |
|---|---|---|---|
| `"after"`（默认） | 类型转换和内置校验**之后** | 已转换好的值 | 业务规则校验、规范化 |
| `"before"` | 类型转换**之前** | 客户端原始输入 | 兼容多种输入格式、预处理 |

校验器的写法要点：必须加 `@classmethod`（放在 `@field_validator` 下面）；校验失败抛出 `ValueError`（或 `AssertionError`），**不要**抛 `HTTPException`；**必须返回值**，忘记 `return` 会让字段变成 `None`。

### 5.2 `model_validator`：跨字段校验

当规则涉及多个字段（两次密码一致、开始时间早于结束时间），用 `model_validator`：

```python
from datetime import date

from fastapi import FastAPI
from pydantic import BaseModel, model_validator

app = FastAPI()


class Register(BaseModel):
    username: str
    password: str
    password2: str

    @model_validator(mode="after")
    def passwords_match(self):
        if self.password != self.password2:
            raise ValueError("两次密码不一致")
        return self


class DateRange(BaseModel):
    start: date
    end: date

    @model_validator(mode="after")
    def check_range(self):
        if self.start > self.end:
            raise ValueError("start 不能晚于 end")
        return self


@app.post("/register")
async def register(data: Register):
    return {"username": data.username}


@app.post("/reports")
async def report(period: DateRange):
    return {"days": (period.end - period.start).days}
```

```bash
curl -X POST http://127.0.0.1:8000/register -H "Content-Type: application/json" \
  -d '{"username": "tom", "password": "1", "password2": "2"}'
# {"detail":[{"type":"value_error","loc":["body"],"msg":"Value error, 两次密码不一致",
#   "input":{"username":"tom","password":"1","password2":"2"},"ctx":{"error":{}}}]}
```

注意 `loc` 只有 `["body"]`——模型级错误无法归属到某个字段。`mode="after"` 的校验器是**实例方法**，`self` 已是完整的模型实例，记得 `return self`。

> 💡 只有所有字段都校验通过后，`mode="after"` 的模型校验器才会执行。所以如果 `start` 本身格式就错了，客户端只会看到字段错误，不会看到「start 不能晚于 end」。

## 6. `ConfigDict`：模型级配置

```python
from fastapi import FastAPI
from pydantic import BaseModel, ConfigDict, Field

app = FastAPI()


class Profile(BaseModel):
    model_config = ConfigDict(
        str_strip_whitespace=True,  # 自动去掉字符串首尾空白
        extra="forbid",             # 禁止未声明的字段
        validate_by_name=True,      # 设置 alias 后，仍允许用字段名赋值
    )

    nick_name: str = Field(alias="nickName", min_length=1)
    bio: str = ""


@app.post("/profiles")
async def create_profile(profile: Profile):
    return profile.model_dump()
```

```bash
curl -X POST http://127.0.0.1:8000/profiles -H "Content-Type: application/json" \
  -d '{"nickName": "  小明  "}'
# {"nick_name":"小明","bio":""}

curl -X POST http://127.0.0.1:8000/profiles -H "Content-Type: application/json" \
  -d '{"nickName": "小明", "age": 18}'
# {"detail":[{"type":"extra_forbidden","loc":["body","age"],"msg":"Extra inputs are not permitted","input":18}]}
```

常用配置项：

| 配置 | 默认 | 作用 |
|---|---|---|
| `extra` | `"ignore"` | 多余字段的处理：`"ignore"` 忽略、`"forbid"` 报错、`"allow"` 保留 |
| `str_strip_whitespace` | `False` | 字符串去首尾空白 |
| `str_to_lower` | `False` | 字符串转小写 |
| `validate_by_name` | `False` | 设置了 alias 后，是否也接受原字段名（旧写法 `populate_by_name`，Pydantic 2.11 起不再推荐） |
| `frozen` | `False` | 实例不可变（且可哈希） |
| `from_attributes` | `False` | 允许从普通对象（如 ORM 对象）的属性读取数据，12.9 会用到 |
| `use_enum_values` | `False` | 存储枚举的值而不是枚举成员 |
| `json_schema_extra` | — | 向 JSON Schema 添加额外信息，如示例数据（见第 9 节） |

> ⚠️ `extra` 默认是 `"ignore"`：客户端拼错的字段名（如 `prcie`）会被**静默丢弃**，如果该字段可选，你甚至察觉不到。对外接口建议开启 `extra="forbid"`。
>
> 💡 `model_dump()` 默认输出字段名（`nick_name`）；需要输出别名时用 `model_dump(by_alias=True)`。

## 7. 多个请求体参数与 `Body`

### 7.1 多个模型参数

函数中有**多个** Pydantic 模型参数时，FastAPI 会把参数名作为 JSON 的键：

```python
from typing import Annotated

from fastapi import Body, FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    price: float


class User(BaseModel):
    username: str
    full_name: str | None = None


@app.put("/items/{item_id}")
async def update_item(
    item_id: int,
    item: Item,
    user: User,
    importance: Annotated[int, Body(gt=0)],
    q: str | None = None,
):
    return {"item_id": item_id, "item": item, "user": user, "importance": importance, "q": q}
```

此时客户端要发送的请求体是：

```json
{
  "item": {"name": "键盘", "price": 199},
  "user": {"username": "tom"},
  "importance": 5
}
```

```bash
curl -X PUT "http://127.0.0.1:8000/items/3?q=hi" -H "Content-Type: application/json" \
  -d '{"item": {"name": "键盘", "price": 199}, "user": {"username": "tom"}, "importance": 5}'
# {"item_id":3,"item":{"name":"键盘","price":199.0},"user":{"username":"tom","full_name":null},"importance":5,"q":"hi"}
```

注意 `importance: int` 是单值类型，默认会被当作查询参数；用 `Body()` 显式声明后，它才会从请求体中读取。

### 7.2 `Body(embed=True)`：单个模型也包一层

只有**一个**模型参数时，请求体就是模型本身：`{"name": ..., "price": ...}`。如果希望客户端发送 `{"item": {"name": ..., "price": ...}}`，用 `embed=True`：

```python
from typing import Annotated

from fastapi import Body, FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    price: float


@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Annotated[Item, Body(embed=True)]):
    return {"item_id": item_id, "item": item}
```

```bash
curl -X PUT http://127.0.0.1:8000/items/3 -H "Content-Type: application/json" \
  -d '{"item": {"name": "键盘", "price": 199}}'
# {"item_id":3,"item":{"name":"键盘","price":199.0}}

curl -X PUT http://127.0.0.1:8000/items/3 -H "Content-Type: application/json" \
  -d '{"name": "键盘", "price": 199}'
# {"detail":[{"type":"missing","loc":["body","item"],"msg":"Field required","input":null}]}
```

### 7.3 参数来源识别规则（完整版）

把 12.2 的规则补全：

| 函数参数 | 来源 |
|---|---|
| 名字出现在路径中 | 路径参数 |
| 单值类型（`int`、`str`、`float`、`bool`、`Enum`、`UUID`…） | 查询参数 |
| Pydantic 模型 | 请求体 |
| 显式 `Body()` 标注 | 请求体（单值类型也可以） |
| 只有一个请求体参数且未 `embed` | 请求体 = 该模型本身 |
| 多个请求体参数，或使用了 `embed=True` | 请求体 = `{参数名: 值, ...}` |

> 💡 请求体只能用于 POST、PUT、PATCH 等方法。规范上 GET 请求带请求体是「未定义行为」，很多代理和客户端会直接丢弃它，FastAPI 的 `/docs` 也不鼓励这么做。GET 接口的复杂过滤条件请用 12.2 的查询参数模型。

## 8. 输入模型与内部数据要分开

一个常见的需求是：创建用户时客户端传 `password`，但数据库存的是 `hashed_password`，返回给客户端时又不能包含任何密码。这时应该为不同场景定义不同的模型，并利用继承减少重复：

```python
from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

app = FastAPI()


class UserBase(BaseModel):
    username: str
    email: EmailStr


class UserCreate(UserBase):     # 客户端提交的数据
    password: str


class UserInDB(UserBase):       # 内部存储的数据
    id: int
    hashed_password: str


class UserPublic(UserBase):     # 返回给客户端的数据
    id: int


fake_db: list[UserInDB] = []


def fake_hash(password: str) -> str:
    return "hashed-" + password


@app.post("/users", status_code=201)
async def create_user(user_in: UserCreate) -> UserPublic:
    user = UserInDB(
        **user_in.model_dump(exclude={"password"}),
        id=len(fake_db) + 1,
        hashed_password=fake_hash(user_in.password),
    )
    fake_db.append(user)
    return UserPublic(**user.model_dump())
```

```bash
curl -X POST http://127.0.0.1:8000/users -H "Content-Type: application/json" \
  -d '{"username": "tom", "email": "tom@example.com", "password": "secret123"}'
# {"username":"tom","email":"tom@example.com","id":1}
```

函数返回类型标注为 `-> UserPublic`，FastAPI 会据此过滤输出、生成响应文档——这是 12.5「响应模型」的内容，这里先建立「输入、存储、输出三种模型分开」的意识。

## 9. 为文档提供示例数据

好的示例数据能让 `/docs` 的 “Try it out” 开箱即用。有三种方式：

```python
from typing import Annotated

from fastapi import Body, FastAPI
from pydantic import BaseModel, Field

app = FastAPI()


# 方式一：在模型上整体声明示例（json_schema_extra）
class Item(BaseModel):
    name: str
    price: float

    model_config = {
        "json_schema_extra": {
            "examples": [{"name": "机械键盘", "price": 399.0}],
        }
    }


# 方式二：在单个字段上声明（Field 的 examples）
class Book(BaseModel):
    title: str = Field(examples=["流畅的 Python"])
    isbn: str = Field(examples=["978-7-115-45415-1"])


# 方式三：在接口参数上声明（Body 的 openapi_examples，可以给多个命名示例）
@app.post("/items")
async def create_item(
    item: Annotated[
        Item,
        Body(
            openapi_examples={
                "normal": {
                    "summary": "正常数据",
                    "value": {"name": "机械键盘", "price": 399.0},
                },
                "invalid": {
                    "summary": "价格类型错误（会返回 422）",
                    "value": {"name": "机械键盘", "price": "很贵"},
                },
            }
        ),
    ],
):
    return item


@app.post("/books")
async def create_book(book: Book):
    return book
```

| 方式 | 写在哪里 | 适合 |
|---|---|---|
| `json_schema_extra` | 模型 `model_config` | 模型在多个接口复用，示例跟着模型走 |
| `Field(examples=[...])` | 字段 | 只想给个别字段示例 |
| `Body(openapi_examples={...})` | 接口参数 | 给同一接口提供多个可切换的示例（正常 / 异常 / 边界） |

> 💡 示例只影响文档，**不参与校验**。`openapi_examples` 在 Swagger UI 中会显示为一个下拉框，可以快速切换不同的请求体。

## 10. PATCH：部分更新

PUT 语义是「整体替换」，PATCH 是「只改传了的字段」。实现 PATCH 的关键是区分「客户端没传这个字段」和「客户端把这个字段设成了默认值 / null」——`model_dump(exclude_unset=True)` 正是为此设计的：

```python
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()


class Item(BaseModel):
    name: str
    description: str | None = None
    price: float
    tags: list[str] = []


class ItemUpdate(BaseModel):
    # 所有字段都可选，用于 PATCH
    name: str | None = None
    description: str | None = None
    price: float | None = None
    tags: list[str] | None = None


items: dict[int, Item] = {
    1: Item(name="键盘", description="机械键盘", price=399, tags=["外设"]),
}


@app.patch("/items/{item_id}")
async def patch_item(item_id: int, item_update: ItemUpdate) -> Item:
    stored = items[item_id]
    update_data = item_update.model_dump(exclude_unset=True)  # 只包含客户端显式传入的字段
    updated = stored.model_copy(update=update_data)
    items[item_id] = updated
    return updated
```

```bash
curl -X PATCH http://127.0.0.1:8000/items/1 -H "Content-Type: application/json" -d '{"price": 299}'
# {"name":"键盘","description":"机械键盘","price":299.0,"tags":["外设"]}
#  ↑ 只有 price 变了，description 和 tags 保持原样

curl -X PATCH http://127.0.0.1:8000/items/1 -H "Content-Type: application/json" -d '{"description": null}'
# {"name":"键盘","description":null,"price":299.0,"tags":["外设"]}
#  ↑ 显式传 null 也算「设置过」，description 被清空
```

对比三种导出方式（以 `ItemUpdate(price=299)` 为例）：

| 方法 | 结果 | 说明 |
|---|---|---|
| `model_dump()` | `{'name': None, 'description': None, 'price': 299.0, 'tags': None}` | 所有字段，PATCH 时会把没传的字段覆盖为 None ❌ |
| `model_dump(exclude_none=True)` | `{'price': 299.0}` | 去掉值为 None 的字段，但客户端**无法主动清空**某字段 |
| `model_dump(exclude_unset=True)` | `{'price': 299.0}` | 只保留显式设置过的字段，显式传 null 也会保留 ✅ |

> ⚠️ `model_copy(update=...)` 不会重新校验数据。更严谨的写法是 `Item.model_validate(stored.model_dump() | update_data)`，这样如果客户端传 `{"name": null}`，会因为 `Item.name` 不允许为 None 而得到 422，而不是把一个非法状态写进存储。

## 11. 不用模型时：直接读取原始请求

绝大多数场景都应该用模型。但如果要接收**结构完全不固定**的 JSON，可以用 `dict` 类型，或者直接拿到 Starlette 的 `Request` 对象：

```python
from typing import Any

from fastapi import FastAPI, Request

app = FastAPI()


@app.post("/webhook/any")
async def any_json(payload: dict[str, Any]):
    return {"keys": list(payload)}


@app.post("/webhook/raw")
async def raw_body(request: Request):
    body = await request.body()  # 原始字节，例如用于校验第三方回调的签名
    return {"length": len(body), "content_type": request.headers.get("content-type")}
```

代价是失去了校验和文档。`Request` 对象的更多用法见 12.4。

## 常见坑

1. **curl 忘记 `-H "Content-Type: application/json"`**：curl 的 `-d` 默认按表单类型发送，请求体不会被当作 JSON 解析，返回 422：`{"type":"model_attributes_type","loc":["body"],"msg":"Input should be a valid dictionary or object to extract fields from",...}`。
2. **GET 接口声明了模型参数**：模型默认是请求体，GET 请求体会被很多客户端丢弃；GET 的复杂参数请用 `Annotated[Model, Query()]`。
3. **单值参数想从请求体读取却没写 `Body()`**：`importance: int` 默认是查询参数。
4. **单模型参数与多模型参数的请求体格式不同**：从一个模型参数加到两个时，请求体会从 `{...}` 变为 `{"item": {...}, "user": {...}}`，这是**破坏性变更**，前端需要同步修改；为了稳定，可以一开始就用 `embed=True`。
5. **`extra` 默认忽略多余字段**：拼错的字段名会被静默丢弃，对外接口建议 `extra="forbid"`。
6. **校验器忘记 `return`**：字段值变成 `None`；`field_validator` 忘记 `@classmethod` 也会出错。
7. **在校验器里抛 `HTTPException`**：校验器属于数据层，应该抛 `ValueError`，由 FastAPI 统一转为 422。
8. **金额用 `float`**：精度问题；用 `Decimal`，并注意它被序列化为字符串。
9. **PATCH 用 `model_dump()` 而不是 `model_dump(exclude_unset=True)`**：没传的字段会被覆盖为 None。
10. **照抄 Pydantic v1 的代码**：`.dict()`、`@validator`、`class Config` 在 v2 中已废弃（部分仍能用但会告警），统一用 `model_dump()`、`@field_validator`、`model_config`。

## 小结

- 请求体用 Pydantic `BaseModel` 声明，FastAPI 自动完成 JSON 解析、类型转换、校验、文档生成；校验失败返回 422，`loc` 以 `body` 开头。
- `Field` 为字段声明约束和元数据；嵌套模型、`list`、`set`、`dict` 可以描述任意结构；`EmailStr`、`HttpUrl`、`UUID`、`datetime`、`Decimal` 等类型自带校验。
- `field_validator` 处理单字段规则（`mode="before"` 可预处理原始输入），`model_validator` 处理跨字段规则；校验器里抛 `ValueError` 并记得返回值。
- `ConfigDict` 控制模型行为，对外接口推荐 `extra="forbid"`。
- 多个请求体参数时以参数名为键；单值参数需 `Body()`；`Body(embed=True)` 让单个模型也包一层。
- 输入、存储、输出使用不同模型，用继承复用公共字段。
- 用 `json_schema_extra`、`Field(examples=...)`、`Body(openapi_examples=...)` 为文档提供示例。
- PATCH 用 `model_dump(exclude_unset=True)` 只更新客户端传入的字段。
