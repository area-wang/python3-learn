3. 多个中间件的执行顺序由什么决定？为什么说「后添加的在外层」？`@app.middleware("http")` 和 `app.add_middleware()` 混用时顺序规则是否一致？
4. 框架自带的 `ServerErrorMiddleware` 和 `ExceptionMiddleware` 分别位于中间件栈的什么位置？这个位置关系导致了什么现象？

6. 中间件如何把数据（如请求 ID、当前租户）传递给后面的依赖和路由？

## 二、判断代码输出 / 找错

### 1. 执行顺序

```python
from fastapi import FastAPI, Request

app = FastAPI()


@app.middleware("http")
async def first(request: Request, call_next):
    print("1-前")
    response = await call_next(request)
    print("1-后")
    return response


@app.middleware("http")
async def second(request: Request, call_next):
    print("2-前")
    response = await call_next(request)
    print("2-后")
    return response


@app.get("/")
async def index():
    print("路由")
    return {}
```

请求 `GET /` 时，按顺序写出控制台的全部输出。

### 2. 被吞掉的 401

```python
@app.middleware("http")
async def auth(request: Request, call_next):
    if "Authorization" not in request.headers:
        raise HTTPException(status_code=401, detail="未登录")
    return await call_next(request)


@app.exception_handler(HTTPException)
async def http_exc_handler(request: Request, exc: HTTPException):
    return JSONResponse({"error": exc.detail}, status_code=exc.status_code)
```

不带 `Authorization` 头请求任意接口，客户端收到的状态码和响应体是什么？为什么已经注册了异常处理器还是不行？请给出两种修复方案。

### 3. 前端看到的 CORS error

### 4. 跨域配置找错

```python

    CORSMiddleware,
    allow_origins=["http://localhost:5173/"],

```

前端（运行在 `http://localhost:5173`）用 `fetch` 发送 `POST /items`，`Content-Type: application/json`，带 Cookie，并想读取响应头 `X-Total-Count`。请找出这段配置中所有会导致失败的问题。

### 5. 星号与凭证

### 6. ContextVar 去哪了

```python
current_user = contextvars.ContextVar("current_user", default=None)

    async def dispatch(self, request, call_next):
        response = await call_next(request)
        print("审计：", current_user.get())
        return response


@app.get("/orders")
async def orders():

    return []
```

## 三、编程题

### 1. 访问日志中间件（基础）

用 `@app.middleware("http")` 实现访问日志：输出 `方法 路径 状态码 耗时ms 客户端IP`，并在响应头加入 `X-Process-Time`。要求 404 和 422 的请求同样被记录。

### 2. 请求 ID 全链路（基础）

- 中间件读取请求头 `X-Request-ID`，没有则生成 UUID，写入 `request.state` 和响应头；
- 编写一个依赖 `get_request_id(request: Request) -> str`，在路由中返回当前请求 ID；
- 进阶：把请求 ID 存入 `contextvars`，再写一个 `logging.Filter`，让业务代码中任何 `logger.info()` 输出都自动带上请求 ID。

### 3. 可配置的 IP 黑名单（基础）

用 `BaseHTTPMiddleware` 子类实现 `IPBlacklistMiddleware(app, blocked: set[str])`，被拉黑的 IP 返回 403 JSON。用 TestClient 测试（提示：TestClient 的客户端地址是 `testclient`）。

### 4. 纯 ASGI 实现响应大小统计（进阶）

写一个纯 ASGI 中间件，通过包装 `send`：

- 先思考：能否把响应体大小放进响应头 `X-Response-Size`？（提示：响应头随 `http.response.start` 在 body 之前发送。）如果不能，改为在响应结束后把「路径 + 字节数」打印到日志；
- 用一个返回 `StreamingResponse` 的接口验证它能正确统计流式响应的总字节数。

### 5. 简易限流中间件（进阶）

实现基于内存的固定窗口限流：每个 IP 每 10 秒最多 5 次请求，超过返回 429 并带 `Retry-After` 头。要求：

- 白名单路径（如 `/health`）不限流；
- 与 `CORSMiddleware` 配合时顺序正确，前端能读到 429；
- 思考：多进程（多个 worker）部署时这个实现有什么问题？应该改用什么存储？

### 6. CORS 实验（进阶）

- 用 `python -m http.server 5173` 启动一个静态页面，页面中用 `fetch` 分别发起 GET 和 `Content-Type: application/json` 的 POST 请求到 `http://localhost:8000`；
- 在浏览器开发者工具「网络」面板中观察：哪个请求触发了 OPTIONS 预检？预检的请求头和响应头分别是什么？
- 依次修改 `allow_origins`、`allow_methods`、`expose_headers`、`allow_credentials`，记录每种错误配置下浏览器控制台的报错信息。

## 四、综合实践：API 网关风格的中间件栈

为一个 FastAPI 应用组装完整的中间件栈，并写测试验证：

1. `CORSMiddleware`：只允许配置中的前端域名，允许凭证，暴露 `X-Request-ID`、`X-Total-Count`；
2. `TrustedHostMiddleware`：只接受 `api.example.com` 和 `localhost`；
3. 请求 ID 中间件 + 访问日志中间件（纯 ASGI 实现）；
4. 维护模式中间件：通过环境变量开启，开启后除 `/health` 外全部返回 503；
5. `GZipMiddleware`：大于 1KB 的响应压缩；
6. 画出最终的洋葱结构图，说明你选择的添加顺序及理由；
7. 用 TestClient 编写测试，覆盖：预检请求、非法 Host、维护模式、请求 ID 透传与生成、大响应被压缩。
