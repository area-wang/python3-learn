# 12.14 WebSocket与流式响应

前面所有章节的接口都遵循同一个模式：客户端发一个请求，服务端处理完后**一次性**返回完整响应，然后这次交互就结束了。但很多真实需求并不是这样：聊天室需要服务端随时把别人的消息推给你；ChatGPT 式的问答需要一个字一个字地"流"出来；导出一个几 GB 的文件不能先全部读进内存再返回；股票行情、任务进度需要持续推送。本节介绍 FastAPI 处理这类"实时 / 持续"通信的三种工具：**WebSocket**（双向长连接）、**StreamingResponse**（分块流式响应）和 **SSE**（Server-Sent Events，服务端单向推送）。

> 本节示例基于 FastAPI 0.143 / Starlette 1.8 实际运行验证。WebSocket 依赖 `websockets` 库，`pip install "fastapi[standard]"` 已自带。

## 1. WebSocket 与 HTTP 的区别

| | HTTP（普通请求） | WebSocket |
|---|---|---|
| 通信方向 | 客户端发起，服务端响应（一问一答） | **双向**，任何一方随时可以发消息 |
| 连接生命周期 | 一次请求结束即完成（keep-alive 只是复用 TCP） | 握手后**长期保持**，直到一方主动关闭 |
| 服务端主动推送 | 做不到，只能靠客户端轮询 | 天然支持 |
| 消息开销 | 每次都带完整请求头 | 握手后每帧只有 2~14 字节帧头 |
| URL 协议 | `http://` / `https://` | `ws://` / `wss://` |
| 典型场景 | CRUD 接口 | 聊天、协同编辑、在线游戏、实时通知 |

WebSocket 的连接建立过程本身就是一个 HTTP 请求：客户端发送带 `Upgrade: websocket` 头的 GET 请求，服务端回 `101 Switching Protocols`，之后这条 TCP 连接就"升级"为 WebSocket，不再遵循 HTTP 的一问一答。

```text
客户端                                         服务端
  │  GET /ws  Upgrade: websocket  ────────────▶ │
  │  ◀──────────── 101 Switching Protocols      │   ← 握手（websocket.accept()）
  │  ═══════════ 双向消息帧 ══════════════════  │
  │  "hello" ─────────────────────────────────▶ │
  │  ◀───────────────────────────── "echo: hi"  │
  │  ◀───────────────────── "有新消息"(主动推送) │
  │  Close(1000) ─────────────────────────────▶ │   ← 任意一方关闭
```

## 2. 第一个 WebSocket 端点

用 `@app.websocket()` 声明 WebSocket 路由，参数里声明一个 `WebSocket` 类型的对象，通过它完成握手、收发消息：

```python
# ws_basic.py
from fastapi import FastAPI, WebSocket, WebSocketDisconnect

app = FastAPI()


@app.websocket("/ws/echo")
async def echo(websocket: WebSocket):
    await websocket.accept()                      # 1. 完成握手
    try:
        while True:
            text = await websocket.receive_text()  # 2. 等待客户端消息
            await websocket.send_text(f"echo: {text}")  # 3. 回复
    except WebSocketDisconnect as e:
        print(f"客户端断开，code={e.code}")


@app.websocket("/ws/calc")
async def calc(websocket: WebSocket):
    await websocket.accept()
    try:
        async for data in websocket.iter_json():   # 自动处理断开，循环结束即断开
            result = data["a"] + data["b"]
            await websocket.send_json({"op": "add", "result": result})
    finally:
        print("calc 连接结束")
```

几个要点：

- WebSocket 端点**必须是 `async def`**，因为收发消息都是 `await` 操作。
- `accept()` 之前不能收发消息；不调用 `accept()` 直接返回，等于拒绝握手。
- `while True` + `receive_*()` 是最常见的"消息循环"写法；客户端断开时 `receive_*()` 会抛出 `WebSocketDisconnect`。
- `iter_text()` / `iter_json()` 是对消息循环的封装，内部已经捕获了 `WebSocketDisconnect`，客户端断开时循环自然结束。

### 2.1 收发 API 一览

| 方法 | 说明 |
|---|---|
| `await websocket.accept(subprotocol=None, headers=None)` | 接受握手，可指定子协议、附加响应头 |
| `await websocket.receive_text()` | 接收一条文本消息，返回 `str` |
| `await websocket.receive_bytes()` | 接收一条二进制消息，返回 `bytes` |
| `await websocket.receive_json()` | 接收文本消息并 `json.loads` |
| `await websocket.send_text(data)` | 发送文本 |
| `await websocket.send_bytes(data)` | 发送二进制（图片、音频帧、protobuf 等） |
| `await websocket.send_json(data)` | `json.dumps` 后作为文本发送 |
| `websocket.iter_text()` / `iter_bytes()` / `iter_json()` | 异步迭代器形式的消息循环 |
| `await websocket.close(code=1000, reason=None)` | 服务端主动关闭连接 |
| `websocket.client` / `headers` / `query_params` / `cookies` | 与 `Request` 类似的连接信息 |

## 3. 处理断开与关闭码

WebSocket 是长连接，"对方随时可能消失"是常态：用户关掉页面、手机切到后台、网络抖动。务必处理好断开，否则会出现异常日志刷屏、连接对象泄漏等问题。

两类断开：

1. **客户端断开**：服务端在 `receive_*()` 时收到 `WebSocketDisconnect` 异常，`e.code` 是关闭码。
2. **服务端主动关闭**：调用 `await websocket.close(code=..., reason=...)`，之后不能再收发。

常用关闭码（`fastapi.status` 中都有对应常量）：

| 关闭码 | 常量 | 含义 |
|---|---|---|
| 1000 | `WS_1000_NORMAL_CLOSURE` | 正常关闭 |
| 1001 | `WS_1001_GOING_AWAY` | 一方离开（页面关闭、服务器重启） |
| 1003 | `WS_1003_UNSUPPORTED_DATA` | 收到无法处理的数据类型 |
| 1008 | `WS_1008_POLICY_VIOLATION` | 违反策略，**最常用于鉴权失败** |
| 1009 | `WS_1009_MESSAGE_TOO_BIG` | 消息过大 |
| 1011 | `WS_1011_INTERNAL_ERROR` | 服务端内部错误 |
| 4000-4999 | — | 留给应用自定义（如 4001 表示 token 过期） |

> ⚠️ 在**已经断开**的连接上调用 `send_*()` 会抛异常（通常是 `WebSocketDisconnect` 或 `RuntimeError`）。广播给多个客户端时尤其要注意，见第 5 节。

## 4. 路径参数、查询参数、依赖与鉴权

WebSocket 路由同样支持路径参数、查询参数、`Header`、`Cookie` 和 `Depends`，写法与 HTTP 路由几乎一样。区别在于**出错方式**：WebSocket 中不能抛 `HTTPException`（已经没有 HTTP 响应可返回了），而要抛 `WebSocketException`，它会让握手以指定关闭码失败。

浏览器原生的 `WebSocket` API **不支持自定义请求头**，所以无法像 HTTP 接口那样用 `Authorization: Bearer xxx` 传 token。常用的两种鉴权方式：

| 方式 | 做法 | 优缺点 |
|---|---|---|
| 查询参数 token | `ws://host/ws?token=xxx` | 简单；但 token 会出现在访问日志和代理日志中，应使用短期 token |
| 首条消息认证 | 先 `accept()`，要求客户端第一条消息发送 token | token 不进 URL；但未认证连接也会占用资源，需加超时 |
| Cookie | 同域时浏览器自动携带 Cookie | 适合已有 Session 登录体系的网站，需防 CSWSH（校验 `Origin`） |

```python
# ws_auth.py
import asyncio
from typing import Annotated

from fastapi import (
    Depends,
    FastAPI,
    Query,
    WebSocket,
    WebSocketDisconnect,
    WebSocketException,
    status,
)

app = FastAPI()

FAKE_TOKENS = {"token-alice": "alice", "token-bob": "bob"}


async def get_ws_user(token: Annotated[str | None, Query()] = None) -> str:
    """WebSocket 版本的"当前用户"依赖：token 放在查询参数里。"""
    if token is None or token not in FAKE_TOKENS:
        # 在 WebSocket 中不能抛 HTTPException，要抛 WebSocketException
        raise WebSocketException(
            code=status.WS_1008_POLICY_VIOLATION, reason="token 无效"
        )
    return FAKE_TOKENS[token]


@app.websocket("/ws/rooms/{room_id}")
async def room(
    websocket: WebSocket,
    room_id: int,                                   # 路径参数，同样会做类型转换
    user: Annotated[str, Depends(get_ws_user)],     # 依赖注入照常可用
    lang: Annotated[str, Query()] = "zh",
):
    await websocket.accept()
    await websocket.send_json({"room": room_id, "user": user, "lang": lang})
    try:
        while True:
            msg = await websocket.receive_text()
            await websocket.send_text(f"[{room_id}] {user}: {msg}")
    except WebSocketDisconnect:
        pass


@app.websocket("/ws/secure")
async def secure(websocket: WebSocket):
    """首条消息认证：先 accept，再要求客户端在 5 秒内发送 token。"""
    await websocket.accept()
    try:
        auth = await asyncio.wait_for(websocket.receive_json(), timeout=5)
    except (TimeoutError, WebSocketDisconnect):
        await websocket.close(code=status.WS_1008_POLICY_VIOLATION, reason="认证超时")
        return

    user = FAKE_TOKENS.get(auth.get("token", ""))
    if user is None:
        await websocket.close(code=status.WS_1008_POLICY_VIOLATION, reason="token 无效")
        return

    await websocket.send_json({"type": "auth_ok", "user": user})
    async for text in websocket.iter_text():
        await websocket.send_text(f"{user} 说：{text}")
```

## 5. 聊天室：用 ConnectionManager 广播

一个 WebSocket 端点函数只"看得到"自己这一条连接。要实现群聊，需要一个全局对象记录所有在线连接，收到消息时遍历发送——这就是常说的 `ConnectionManager`：

```python
# chat.py
from collections import defaultdict

from fastapi import FastAPI, WebSocket, WebSocketDisconnect


class ConnectionManager:
    """管理"房间 -> 连接集合"，负责加入、离开、广播。"""

    def __init__(self) -> None:
        self.rooms: dict[str, set[WebSocket]] = defaultdict(set)

    async def connect(self, room: str, websocket: WebSocket) -> None:
        await websocket.accept()
        self.rooms[room].add(websocket)

    def disconnect(self, room: str, websocket: WebSocket) -> None:
        self.rooms[room].discard(websocket)
        if not self.rooms[room]:
            del self.rooms[room]           # 房间空了就清理，避免内存泄漏

    async def send_personal(self, websocket: WebSocket, message: dict) -> None:
        await websocket.send_json(message)

    async def broadcast(self, room: str, message: dict, exclude: WebSocket | None = None) -> None:
        dead: list[WebSocket] = []
        for ws in list(self.rooms.get(room, ())):   # 拷贝一份，防止遍历时集合被修改
            if ws is exclude:
                continue
            try:
                await ws.send_json(message)
            except Exception:               # 对方已断开但还没来得及清理
                dead.append(ws)
        for ws in dead:
            self.disconnect(room, ws)

    def online(self, room: str) -> int:
        return len(self.rooms.get(room, ()))


manager = ConnectionManager()
app = FastAPI()


@app.websocket("/ws/chat/{room}/{nickname}")
async def chat(websocket: WebSocket, room: str, nickname: str):
    await manager.connect(room, websocket)
    await manager.broadcast(room, {"type": "system", "text": f"{nickname} 进入房间，在线 {manager.online(room)} 人"})
    try:
        while True:
            text = await websocket.receive_text()
            await manager.broadcast(room, {"type": "chat", "from": nickname, "text": text})
    except WebSocketDisconnect:
        manager.disconnect(room, websocket)
        await manager.broadcast(room, {"type": "system", "text": f"{nickname} 离开了房间"})
```

设计要点：

- **遍历前拷贝**：`for ws in list(...)`。广播过程中 `await` 会让出控制权，其他协程可能正在增删连接，直接遍历集合可能抛 `RuntimeError: Set changed size during iteration`。
- **单个连接发送失败不能影响其他人**：用 `try/except` 包住每一次 `send`，失败的连接收集起来统一清理。
- **广播是串行的**：某个客户端网络很慢时，`await ws.send_json()` 会拖慢后面所有人。连接很多时可以用 `asyncio.gather(..., return_exceptions=True)` 并发发送，或者为每个连接配一个 `asyncio.Queue` + 独立发送协程。

## 6. 多实例部署：广播需要 Redis Pub/Sub

上面的 `manager` 是**进程内的全局变量**。一旦用 `--workers 4` 启动多个进程，或者部署多个容器，就会出现问题：

```text
             ┌──────────── 负载均衡 ────────────┐
             ▼                                  ▼
   worker A (manager: {alice})        worker B (manager: {bob})
   alice 发消息 → 只广播给 A 里的连接 → bob 永远收不到！
```

解决办法是引入一个所有实例都能访问的**消息中间件**，最常用的是 Redis Pub/Sub：每个实例都订阅同一个频道；收到客户端消息时**发布到 Redis**，而不是直接广播；每个实例的订阅协程收到消息后，再推给"连在自己身上"的客户端。

```python
# chat_redis.py
import asyncio
import json
from contextlib import asynccontextmanager

import redis.asyncio as redis
from fastapi import FastAPI, WebSocket

CHANNEL = "chat:broadcast"


def create_app(redis_client: redis.Redis) -> FastAPI:
    local_conns: set[WebSocket] = set()        # 只保存"连到本实例"的客户端

    async def listen_redis() -> None:
        """后台任务：订阅 Redis 频道，把任何实例发布的消息推给本实例的客户端。"""
        pubsub = redis_client.pubsub()
        await pubsub.subscribe(CHANNEL)
        try:
            async for msg in pubsub.listen():
                if msg["type"] != "message":
                    continue
                for ws in list(local_conns):
                    try:
                        await ws.send_text(msg["data"])
                    except Exception:
                        local_conns.discard(ws)
        finally:
            await pubsub.aclose()

    @asynccontextmanager
    async def lifespan(app: FastAPI):
        task = asyncio.create_task(listen_redis())
        yield
        task.cancel()

    app = FastAPI(lifespan=lifespan)

    @app.websocket("/ws/{nickname}")
    async def chat(websocket: WebSocket, nickname: str):
        await websocket.accept()
        local_conns.add(websocket)
        try:
            async for text in websocket.iter_text():
                # 不直接广播给本地连接，而是发布到 Redis，由所有实例的订阅者统一下发
                payload = json.dumps({"from": nickname, "text": text}, ensure_ascii=False)
                await redis_client.publish(CHANNEL, payload)
        finally:
            local_conns.discard(websocket)

    return app


# 生产中：app = create_app(redis.from_url("redis://redis:6379/0", decode_responses=True))
```

本地没有 Redis 也能验证：`fakeredis` 可以在内存中模拟 Redis（`pip install redis fakeredis`）。下面用两个 app 模拟两个实例，共享同一个"Redis 服务"：

> 💡 Redis Pub/Sub 是"发后即忘"的：订阅者不在线时消息就丢了。需要离线消息、消息历史时，应把消息先写入数据库或 Redis Stream，再推送通知。另外，多实例下负载均衡器要支持 WebSocket（Nginx 需配置 `Upgrade` 头，见 12.15 节）。

## 7. StreamingResponse：分块流式响应

WebSocket 是一套独立协议，而很多场景其实只需要**普通 HTTP 请求 + 服务端分批返回**：大文件下载、导出 CSV、LLM 逐字输出。`StreamingResponse` 接收一个**生成器**（同步或异步均可），每 `yield` 一块就立即发给客户端，而不是等全部生成完：

```python
# stream_demo.py
import asyncio
import time
from collections.abc import AsyncIterator, Iterator
from pathlib import Path

from fastapi import FastAPI
from fastapi.responses import StreamingResponse
from pydantic import BaseModel

# ① 同步生成器：FastAPI 会放到线程池里迭代，不会阻塞事件循环
def count_sync(n: int) -> Iterator[str]:
    for i in range(1, n + 1):
        time.sleep(0.1)          # 模拟阻塞 IO
        yield f"line {i}\n"


@app.get("/stream/sync")
def stream_sync():
    return StreamingResponse(count_sync(3), media_type="text/plain; charset=utf-8")


# ② 异步生成器：适合内部本身就是 await 的场景（异步 HTTP、异步数据库游标）
async def count_async(n: int) -> AsyncIterator[str]:
    for i in range(1, n + 1):
        await asyncio.sleep(0.1)
        yield f"chunk {i}\n"


@app.get("/stream/async")
async def stream_async():
    return StreamingResponse(count_async(3), media_type="text/plain; charset=utf-8")


# ③ 大文件分块下载：每次只读 64KB 进内存
def iter_file(path: Path, chunk_size: int = 64 * 1024) -> Iterator[bytes]:
    with path.open("rb") as f:
        while chunk := f.read(chunk_size):
            yield chunk

    return StreamingResponse(
        iter_file(path),
        media_type="application/octet-stream",
```

### 7.1 三种流式写法对比

较新版本的 FastAPI 允许**路径操作函数本身就是生成器**，根据 `response_class` 决定输出格式：

| 写法 | 输出格式 | 说明 |
|---|---|---|
| `return StreamingResponse(gen(), media_type=...)` | 原样输出每个块 | 经典写法，所有版本通用，最灵活 |
| 函数内 `yield` + `response_class=StreamingResponse`（或其子类） | 原样输出每个块 | 省去包一层；Content-Type 需通过子类的 `media_type` 指定 |
| 函数内 `yield` + **不指定** `response_class` | **JSON Lines**（`application/jsonl`），每个元素一行 JSON | 配合返回类型 `AsyncIterator[Model]` 会按模型校验和序列化，适合进度、批量结果 |
| 函数内 `yield` + `response_class=EventSourceResponse` | SSE | 见第 8 节 |

> ⚠️ `StreamingResponse` 一旦开始发送，**状态码和响应头就已经发出去了**。如果生成器在中途抛异常，客户端只会看到连接突然断开或数据不完整，而不会收到 500。需要在生成器内部捕获异常，并约定一种"错误块"格式告诉客户端。

> 💡 对于磁盘上**已存在**的文件，优先用 `FileResponse`（12.5 节）：它自动设置 `Content-Length`、支持 `Range` 断点续传，比手写 `iter_file` 更好。`StreamingResponse` 适合"边生成边发送"的内容，例如从数据库游标逐行导出 CSV、从对象存储转发、实时压缩打包。

## 8. Server-Sent Events（SSE）

SSE 是浏览器原生支持的**服务端单向推送**协议：它就是一个普通的 HTTP 长响应，`Content-Type: text/event-stream`，内容按固定的文本格式一条条写出：

```text
event: notice          ← 事件类型（可选，默认是 message）
id: 6                  ← 事件 ID（可选，断线重连时浏览器会通过 Last-Event-ID 带回来）
retry: 3000            ← 建议的重连间隔毫秒数（可选）
data: {"msg": "hi"}    ← 数据，可以有多行 data
                       ← 空行：表示一个事件结束
: 这是注释             ← 冒号开头是注释，常用作心跳
```

相比 WebSocket，SSE 的优点是：基于普通 HTTP（无需协议升级，代理、鉴权、HTTP/2 全部照常工作）、浏览器 `EventSource` **自动断线重连**、协议简单。ChatGPT、各种大模型 API 的流式输出几乎都使用 SSE。

### 8.1 使用 `fastapi.sse.EventSourceResponse`

FastAPI 内置了 SSE 支持：把 `response_class` 设为 `EventSourceResponse`，路径操作函数里直接 `yield` 即可。

```python
# sse_demo.py
import asyncio
import json
from collections.abc import AsyncIterator
from typing import Annotated

from fastapi import FastAPI, Header
from fastapi.responses import StreamingResponse
from fastapi.sse import EventSourceResponse, ServerSentEvent
from pydantic import BaseModel

app = FastAPI()


class Price(BaseModel):
    symbol: str
    price: float


# ① 最简单：yield 普通对象 -> 自动 JSON 编码后放进 data 字段
@app.get("/sse/prices", response_class=EventSourceResponse)
async def prices() -> AsyncIterator[Price]:
    for i in range(3):
        await asyncio.sleep(0.1)
        yield Price(symbol="AAPL", price=200 + i)


# ② 需要 event / id / retry 时，yield ServerSentEvent
@app.get("/sse/notifications", response_class=EventSourceResponse)
async def notifications(
    last_event_id: Annotated[int | None, Header()] = None,   # 浏览器重连时自动带上 Last-Event-ID
) -> AsyncIterator[ServerSentEvent]:
    start = (last_event_id or 0) + 1
    yield ServerSentEvent(comment="连接已建立", retry=3000)
    for i in range(start, start + 3):
        await asyncio.sleep(0.1)
        yield ServerSentEvent(data={"msg": f"第 {i} 条通知"}, event="notice", id=str(i))
    yield ServerSentEvent(raw_data="bye", event="done")      # raw_data：不做 JSON 编码


# ③ LLM 流式输出常见格式：POST + SSE（SSE 并不要求必须 GET）
class ChatRequest(BaseModel):
    prompt: str


@app.post("/sse/chat", response_class=EventSourceResponse)
async def chat(req: ChatRequest) -> AsyncIterator[ServerSentEvent]:
    for token in ["你好", "，", "我是", "AI", "。"]:
        await asyncio.sleep(0.05)
        yield ServerSentEvent(data={"delta": token}, event="token")
    yield ServerSentEvent(raw_data="[DONE]", event="end")
```

`ServerSentEvent` 的字段：

| 字段 | 对应 SSE 行 | 说明 |
|---|---|---|
| `data` | `data:` | 任意可 JSON 序列化的对象，**总是**做 JSON 编码（字符串 `"hi"` 会变成 `data: "hi"`，带引号） |
| `raw_data` | `data:` | 原样输出的字符串，不做 JSON 编码；与 `data` 二选一 |
| `event` | `event:` | 事件类型，前端用 `addEventListener("类型", ...)` 监听 |
| `id` | `id:` | 事件 ID，用于断线续传 |
| `retry` | `retry:` | 建议的重连间隔（毫秒） |
| `comment` | `: ...` | 注释行，客户端会忽略，可用作心跳 |

`EventSourceResponse` 还自动帮你做了几件事：设置 `Cache-Control: no-cache` 和 `X-Accel-Buffering: no`（告诉 Nginx 不要缓冲），并在生成器**空闲超过 15 秒**时自动发送 `: ping` 心跳注释，防止代理或负载均衡把"长时间没数据"的连接掐掉。

```python
# t_sse.py

from sse_demo import app

client = TestClient(app)

with client.stream("GET", "/sse/prices") as r:
    print(r.headers["content-type"], r.headers["cache-control"], r.headers["x-accel-buffering"])
    print(repr(r.read().decode()))

with client.stream("GET", "/sse/notifications", headers={"Last-Event-ID": "5"}) as r:
    print(r.read().decode())

with client.stream("POST", "/sse/chat", json={"prompt": "hi"}) as r:
    print(r.read().decode())
```

### 8.2 对照：用 StreamingResponse 手写 SSE

理解了协议格式，不借助 `fastapi.sse` 也能实现 SSE——本质上就是一个 `text/event-stream` 的流式响应。老版本 FastAPI 或者需要完全控制输出格式时可以这样写：

```python
# 接上面的 sse_demo.py
async def manual_events() -> AsyncIterator[str]:
    for i in range(1, 4):
        await asyncio.sleep(0.1)
        payload = json.dumps({"n": i}, ensure_ascii=False)
        yield f"id: {i}\nevent: tick\ndata: {payload}\n\n"   # 每个事件以空行结束


@app.get("/sse/manual")
async def manual():
    return StreamingResponse(
        manual_events(),
        media_type="text/event-stream",
        headers={"Cache-Control": "no-cache", "X-Accel-Buffering": "no"},
    )
```

```text
$ curl -N http://127.0.0.1:8000/sse/manual
id: 1
event: tick
data: {"n": 1}

id: 2
event: tick
data: {"n": 2}

id: 3
event: tick
data: {"n": 3}
```

| | `EventSourceResponse` + `yield` | 手写 `StreamingResponse` |
|---|---|---|
| 协议格式 | 自动拼装，自动处理多行 data、校验 event/id 不能换行 | 自己拼字符串，容易漏掉结尾空行 |
| 数据序列化 | 自动 JSON 编码，支持按返回类型校验 | 自己 `json.dumps` |
| 心跳 | 空闲 15 秒自动发 `: ping` | 需要自己实现 |
| 防缓冲响应头 | 自动设置 | 自己设置 |
| 适用 | 新项目首选 | 老版本兼容、特殊格式 |

> 💡 社区还有一个常用第三方库 `sse-starlette`，在 FastAPI 内置 SSE 之前被广泛使用，看到老项目里的 `from sse_starlette.sse import EventSourceResponse` 不要和 `fastapi.sse` 混淆。

## 9. 前端如何接收

下面的 `realtime.py` 把一个 HTML 页面、一个 WebSocket 端点、一个 SSE 端点放在一起，启动后用浏览器打开即可体验：

```python
# realtime.py
import asyncio
from collections.abc import AsyncIterator
from datetime import datetime

from fastapi import FastAPI, WebSocket, WebSocketDisconnect
from fastapi.responses import HTMLResponse
from fastapi.sse import EventSourceResponse, ServerSentEvent

app = FastAPI()

HTML = """
<!doctype html>
<html>
<body>
  <h3>WebSocket 回声</h3>
  <input id="msg" placeholder="输入消息后回车">
  <ul id="ws-log"></ul>

  <h3>SSE 服务器时钟</h3>
  <ul id="sse-log"></ul>

  <script>
    // ---------- WebSocket ----------
    const proto = location.protocol === "https:" ? "wss" : "ws";
    const ws = new WebSocket(`${proto}://${location.host}/ws`);
    ws.onopen = () => console.log("WebSocket 已连接");
    ws.onmessage = (e) => {
      const li = document.createElement("li");
      li.textContent = e.data;
      document.getElementById("ws-log").appendChild(li);
    };
    ws.onclose = (e) => console.log("WebSocket 关闭", e.code, e.reason);
    document.getElementById("msg").addEventListener("keydown", (e) => {
      if (e.key === "Enter") { ws.send(e.target.value); e.target.value = ""; }
    });

    // ---------- SSE ----------
    const es = new EventSource("/sse/clock");
    es.addEventListener("tick", (e) => {          // 对应服务端 event="tick"
      const li = document.createElement("li");
      li.textContent = JSON.parse(e.data).now + "  (id=" + e.lastEventId + ")";
      document.getElementById("sse-log").appendChild(li);
    });
    es.onerror = () => console.log("SSE 断开，浏览器会自动重连");
  </script>
</body>
</html>
"""


@app.get("/")
async def index():
    return HTMLResponse(HTML)


@app.websocket("/ws")
async def ws_echo(websocket: WebSocket):
    await websocket.accept()
    try:
        while True:
            text = await websocket.receive_text()
            await websocket.send_text(f"服务端收到：{text}")
    except WebSocketDisconnect:
        pass


@app.get("/sse/clock", response_class=EventSourceResponse)
async def clock() -> AsyncIterator[ServerSentEvent]:
    n = 0
    while True:                                   # 无限推送，客户端断开时 FastAPI 会取消该生成器
        n += 1
        yield ServerSentEvent(data={"now": datetime.now().strftime("%H:%M:%S")}, event="tick", id=str(n))
        await asyncio.sleep(1)
```

```bash
fastapi dev realtime.py      # 浏览器打开 http://127.0.0.1:8000
curl -N http://127.0.0.1:8000/sse/clock
```

```text
event: tick
data: {"now": "11:06:29"}
id: 1

event: tick
data: {"now": "11:06:30"}
id: 2
...
```

前端要点：

- 页面是 `https` 时，WebSocket 必须用 `wss://`，否则浏览器会以"混合内容"为由拦截。
- `EventSource` **只能发 GET 请求、不能自定义请求头**。像第 8 节 `/sse/chat` 那样的 POST + SSE 接口，前端要用 `fetch()` 读取 `response.body` 流并自行按空行切分事件（或使用 `@microsoft/fetch-event-source` 之类的库）。
- 没有指定 `event` 的事件用 `es.onmessage` 接收；指定了 `event: tick` 的事件**只能**用 `addEventListener("tick", ...)` 接收。

## 10. 客户端断开与资源清理

流式响应和 SSE 中，用户随时可能关掉页面。对于 `yield` 写法，客户端断开时 FastAPI 会**取消生成器**，因此把清理逻辑写在 `try/finally` 里即可：

```python
# disc.py
import asyncio
from collections.abc import AsyncIterator

from fastapi import FastAPI
from fastapi.responses import StreamingResponse
from fastapi.sse import EventSourceResponse

app = FastAPI()


async def ticker() -> AsyncIterator[str]:
    try:
        i = 0
        while True:
            i += 1
            yield f"tick {i}\n"
            await asyncio.sleep(0.5)
    finally:
        print("streaming 客户端断开，生成器清理完成", flush=True)


@app.get("/stream")
async def stream():
    return StreamingResponse(ticker(), media_type="text/plain")


@app.get("/sse", response_class=EventSourceResponse)
async def sse() -> AsyncIterator[dict]:
    try:
        i = 0
        while True:
            i += 1
            yield {"i": i}
            await asyncio.sleep(0.5)
    finally:
        print("SSE 客户端断开，生成器清理完成", flush=True)
```

```bash
uvicorn disc:app
curl -sN -m 1.2 http://127.0.0.1:8000/stream    # -m 1.2：1.2 秒后 curl 主动断开
curl -sN -m 1.2 http://127.0.0.1:8000/sse
```

服务端输出：

```text
streaming 客户端断开，生成器清理完成
SSE 客户端断开，生成器清理完成
```

> ⚠️ 不要在 `finally` 里执行耗时的 `await`：此时协程正处于取消状态，再次 `await` 可能立刻被取消。需要异步清理时可以用 `asyncio.shield()` 或交给后台任务。另外，**同步生成器**运行在线程池里，取消信号无法打断正在执行的 `time.sleep()` 等阻塞调用，清理会有延迟。

## 11. 如何选型：轮询 vs SSE vs WebSocket

| | 短轮询 | 长轮询 | SSE | WebSocket |
|---|---|---|---|---|
| 原理 | 客户端每隔 N 秒发一次请求 | 请求挂起直到有数据或超时，再立即发下一次 | 一个长 HTTP 响应持续推送 | 协议升级后的双向长连接 |
| 方向 | 客户端拉 | 客户端拉（近似推） | 服务端 → 客户端 | 双向 |
| 实时性 | 差（取决于间隔） | 较好 | 好 | 最好 |
| 服务器开销 | 大量无效请求 | 中等 | 每客户端一条连接 | 每客户端一条连接 |
| 断线重连 | 天然 | 天然 | 浏览器**自动**重连 + `Last-Event-ID` | 需自己实现 |
| 二进制数据 | 支持 | 支持 | 仅文本（二进制需 base64） | 原生支持 |
| 与代理/HTTP 生态兼容 | 完全兼容 | 完全兼容 | 完全兼容（注意关闭缓冲） | 需代理显式支持 Upgrade |
| FastAPI 写法 | 普通接口 | 普通接口 + `await` 等待事件 | `EventSourceResponse` | `@app.websocket` |
| 典型场景 | 低频状态查询（订单是否支付） | 兼容老环境的消息通知 | LLM 输出、通知、进度、行情 | 聊天、协同编辑、游戏、音视频信令 |

经验法则：**只需要服务端推送，就用 SSE；需要客户端也频繁发消息，才用 WebSocket；更新频率很低（分钟级），轮询最省事。**

## 常见坑

1. **WebSocket 里抛 `HTTPException`**：握手阶段应抛 `WebSocketException(code=1008)`；`accept()` 之后则应 `await websocket.close(code=...)`。
2. **忘记 `await websocket.accept()`**：没有接受握手就收发消息会报 `RuntimeError`。
3. **不处理 `WebSocketDisconnect`**：客户端一断开就是一条异常堆栈，且连接对象留在 `ConnectionManager` 里造成泄漏。
4. **遍历连接集合时修改它**：广播时用 `list(...)` 拷贝后再遍历；发送失败的连接延后统一移除。
5. **多 worker / 多实例下用进程内 `ConnectionManager` 广播**：消息只能到达同一进程的连接，需要 Redis Pub/Sub 等中间件。
6. **在 async 生成器里调用阻塞函数**：`time.sleep()`、同步数据库驱动会卡住事件循环，导致所有连接一起"卡顿"；改用异步库，或使用同步生成器（会被放到线程池执行）。
7. **SSE 被 Nginx 缓冲**：表现为数据"攒一大批才一起出来"。需要 `X-Accel-Buffering: no` 响应头（`EventSourceResponse` 已自动设置）或在 Nginx 中 `proxy_buffering off;`。另外，`GZipMiddleware` 默认已排除 `text/event-stream`，但对 `text/plain` 等普通流式响应仍会压缩，压缩器会攒够数据才输出，"逐字输出"的效果就没了。
8. **流式响应中途出错**：状态码已经是 200 发出去了，无法再变成 500；需要在生成器内捕获异常并发送约定好的错误事件。
9. **`data="hello"` 变成了 `data: "hello"`**：`ServerSentEvent.data` 总是 JSON 编码，要发送纯文本请用 `raw_data`。
10. **URL 里的 token 泄漏**：查询参数会被写进访问日志，WebSocket 鉴权应使用短期 token 或首条消息认证。

## 小结

- **WebSocket**：`@app.websocket` + `accept()` + `receive_*`/`send_*` 消息循环；用 `WebSocketDisconnect` 处理断开、`WebSocketException`/`close(code)` 拒绝连接；依赖注入、路径和查询参数照常可用。
- **广播**：进程内用 `ConnectionManager` 维护连接集合；多实例必须借助 Redis Pub/Sub 等共享通道。
- **StreamingResponse**：传入同步/异步生成器即可边生成边发送，适合大文件导出、LLM 逐字输出；路径函数直接 `yield` 时，默认输出 JSON Lines。
- **SSE**：`response_class=EventSourceResponse` + `yield`，用 `ServerSentEvent` 控制 `event`/`id`/`retry`；浏览器 `EventSource` 自动重连，是"服务端单向推送"的首选方案。
- **清理**：在生成器的 `try/finally` 中释放资源；在 WebSocket 消息循环外层处理断开。
- **选型**：单向推送用 SSE，双向高频交互用 WebSocket，低频状态查询用轮询。
