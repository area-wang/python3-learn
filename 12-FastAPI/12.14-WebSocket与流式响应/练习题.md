## 三、编程题

### 1. 带时间戳的回声服务（基础）

实现 `/ws/echo`：

- 客户端发送文本，服务端回复 JSON：`{"echo": 原文, "length": 字符数, "at": ISO 时间}`；
- 客户端发送 `"bye"` 时，服务端回复 `{"echo": "bye"}` 后以 1000 主动关闭；
- 用 `TestClient` 编写测试，覆盖正常回声和 `bye` 两种情况。

### 2. 带鉴权的私聊（基础）

在第 5 节聊天室基础上实现私聊：

- 通过查询参数 `token` 鉴权（准备一个假的 token → 用户名字典），失败以 1008 拒绝握手；
- 客户端发送 `{"to": "bob", "text": "hi"}` 时只发给 bob；`to` 为空时广播；
- 目标用户不在线时，回复发送者 `{"type": "error", "text": "bob 不在线"}`；
- 同一用户重复登录时，踢掉旧连接（以自定义关闭码 4001 关闭）。

### 3. CSV 流式导出（进阶）

- 用 SQLite（或一个生成 10 万行假数据的生成器）模拟数据源；
- 实现 `GET /export/users.csv`，用 `StreamingResponse` 逐行输出 CSV，内存占用不随行数增长；
- 设置 `Content-Disposition` 让浏览器下载为 `users.csv`；
- 用 `csv.writer` 配合 `io.StringIO` 正确处理逗号、引号等特殊字符；
- 对比"一次性拼接完整字符串再返回"的写法，用 `tracemalloc` 测量两者的峰值内存。

### 4. 模拟 LLM 流式问答（进阶）

实现 `POST /v1/chat`，请求体为 `{"prompt": str, "stream": bool}`：

- `stream=false` 时返回完整 JSON `{"answer": "..."}`；
- `stream=true` 时返回 SSE：每个 token 一个 `event: delta` 事件，最后发送 `event: done`，`data` 中包含总 token 数和耗时；
- 生成过程中模拟 10% 概率出错，出错时发送 `event: error` 事件后结束流；
- 用 `httpx` 编写一个 Python 客户端，逐行解析 SSE 并把 token 实时打印到终端。

### 5. 任务进度推送（进阶）

- `POST /tasks` 创建一个耗时任务（用 `asyncio.create_task` 模拟，耗时 5 秒，每秒进度 +20%），返回 `task_id`；
- `GET /tasks/{task_id}/events` 通过 SSE 推送该任务的进度，任务完成后发送 `event: finished` 并结束；
- 支持 `Last-Event-ID`：客户端断线重连时，不重复推送已收到的进度；
- 任务不存在时返回 404（注意：这时还没开始流式输出，可以正常抛 `HTTPException`）。

### 6. 心跳与超时踢出（挑战）

为 WebSocket 聊天室加上应用层心跳：

- 客户端每 10 秒发送 `{"type": "ping"}`，服务端回复 `{"type": "pong"}`；
- 服务端如果 30 秒内没有收到某连接的任何消息，主动以 1001 关闭它；
- 提示：用 `asyncio.wait_for(websocket.receive_json(), timeout=30)`，或为每个连接启动一个独立的看门狗任务；
- 思考：uvicorn 的 `--ws-ping-interval` / `--ws-ping-timeout` 是协议层心跳，它与应用层心跳分别能解决什么问题？

## 四、综合实践：实时协作看板

实现一个多人实时协作的任务看板后端：

1. 数据模型：看板（board）下有若干卡片（card），卡片有 `id`、`title`、`column`（todo/doing/done）；数据可以先存在内存字典中。
2. REST 接口：`GET /boards/{board_id}` 获取看板完整状态。
3. WebSocket 接口 `/ws/boards/{board_id}?token=...`：
   - 鉴权失败以 1008 拒绝；
   - 连接成功后先推送一次看板完整快照；
   - 客户端可发送 `{"action": "create" | "move" | "delete", ...}`，服务端校验（用 Pydantic 模型 + 判别联合 `discriminator`）后更新数据，并把变更事件广播给同一看板的所有在线用户；
   - 非法消息只回复给发送者 `{"type": "error", ...}`，不能导致连接断开；
   - 广播在线用户列表的变化（加入 / 离开）。
4. 额外提供 `GET /boards/{board_id}/activity` SSE 接口，供"只看不改"的大屏展示页面订阅变更事件。
5. 编写一个 HTML 页面，用原生 JS 实现三列看板的展示和拖动（拖动发送 `move`）。
6. 用 `TestClient` 编写至少 5 个测试：鉴权失败、快照推送、两个客户端之间的广播、非法消息处理、断开后在线列表更新。
7. 思考并写在 README 中：如果要部署 3 个实例，需要做哪些改造？消息顺序如何保证？
