# 12.12 大型项目结构

前面的小节为了讲清楚单个知识点，所有代码都写在一个 `main.py` 里。真实项目会有几十上百个接口、多套数据模型、配置、数据库、鉴权……全塞在一个文件里很快就无法维护。本节解决「代码该怎么拆」的问题：用 `APIRouter` 把路由拆到多个模块，用分层架构把「HTTP 处理 / 业务规则 / 数据访问」分开，用 `pydantic-settings` 统一管理配置，再加上 API 版本化、子应用挂载和 OpenAPI 文档定制。学完本节，你应当能独立搭出一个可以长期演进的 FastAPI 项目骨架，下一节（12.13 测试）也会直接基于这种结构编写测试。

> 本节代码在 FastAPI 0.143 / Pydantic 2.14 / pydantic-settings 2.16 / Python 3.14 下实际跑通。

## 1. 为什么要拆分：单文件的极限

一个典型的「长大了的」单文件应用大概长这样：

```python
# main.py —— 反面示例
app = FastAPI()

SECRET_KEY = "xxx"            # 配置散落在代码里
fake_db = {}                  # 数据存储

class Item(BaseModel): ...    # 模型
class User(BaseModel): ...

@app.get("/items/")           # 路由 + 业务 + 数据访问全混在一起
def list_items(): ...

@app.post("/users/")
def create_user(): ...
# ……再写 2000 行
```

问题很明显：

| 问题 | 后果 |
|---|---|
| 一个文件几千行 | 难以阅读和定位，多人协作频繁冲突 |
| 路由函数里直接写业务和 SQL | 业务逻辑无法复用（比如命令行脚本也要创建用户），也很难单独测试 |
| 配置硬编码 | 开发/测试/生产环境切换要改代码，密钥会被提交进 Git |
| 接口没有分组 | `/docs` 里所有接口挤在 `default` 下面 |

拆分的目标：**每个文件只做一类事，依赖方向清晰（上层依赖下层，下层不知道上层）**。

## 2. `APIRouter`：把路由拆到多个模块

`APIRouter` 可以理解为「迷你版的 FastAPI 应用」：它支持和 `app` 完全一样的 `@router.get/post/...` 装饰器，最后再统一 `include_router` 到主应用上。

### 2.1 基本用法

```python
# app/routers/users.py
from fastapi import APIRouter

router = APIRouter()


@router.get("/users/")
def list_users():
    return [{"username": "alice"}, {"username": "bob"}]


@router.get("/users/{username}")
def get_user(username: str):
    return {"username": username}
```

```python
# app/main.py
from fastapi import FastAPI

from app.routers import users

app = FastAPI()
app.include_router(users.router)
```

### 2.2 `APIRouter` 的常用参数

同一个模块里的接口通常有相同的路径前缀、相同的分组标签、相同的鉴权要求，这些都可以在 `APIRouter(...)` 上一次性声明：

| 参数 | 作用 |
|---|---|
| `prefix` | 路径前缀，如 `"/items"`，不能以 `/` 结尾 |
| `tags` | OpenAPI 分组标签，决定接口在 `/docs` 中显示在哪一组 |
| `dependencies` | 依赖列表，对该 router 下**所有**接口生效（常用于鉴权） |
| `responses` | 额外的响应说明，会合并到每个接口的文档里 |
| `deprecated` | 把整组接口标记为弃用 |
| `include_in_schema` | 设为 `False` 则整组接口不出现在文档中 |

```python
# app/api/v1/items.py
from typing import Annotated

from fastapi import APIRouter, HTTPException, Query, status

router = APIRouter(
    prefix="/items",
    tags=["items"],
    responses={404: {"description": "商品不存在"}},
)


@router.get("/")              # 实际路径：/items/
def list_items(limit: Annotated[int, Query(ge=1, le=100)] = 10): ...


@router.get("/{item_id}")     # 实际路径：/items/{item_id}
def get_item(item_id: int): ...
```

### 2.3 在 `include_router` 时再补充参数

`include_router` 也接受 `prefix`、`tags`、`dependencies`、`responses`。这在接入**无法修改源码**的 router（比如第三方包或公司公共库提供的）时很有用：

```python
from typing import Annotated

from fastapi import APIRouter, Depends, FastAPI, Header, HTTPException


async def verify_key(x_api_key: Annotated[str, Header()]) -> None:
    if x_api_key != "abc":
        raise HTTPException(status_code=403, detail="Forbidden")


# 假设这是一个"第三方"router：自身没有 prefix/tags
legacy_router = APIRouter()


@legacy_router.get("/ping")
def ping():
    return "pong"


app = FastAPI()
app.include_router(
    legacy_router,
    prefix="/legacy",
    tags=["legacy"],
    dependencies=[Depends(verify_key)],
    responses={403: {"description": "API Key 错误"}},
)
# 结果：GET /legacy/ping，需要 X-Api-Key: abc 请求头
```

参数是**叠加**的：router 自身的 `prefix="/items"` + `include_router(prefix="/api/v1")` = `/api/v1/items`；`tags`、`dependencies` 也是合并而不是覆盖。

### 2.4 嵌套 router

router 可以再 `include_router` 另一个 router，形成层级结构。下例中评论接口挂在文章接口下：

```python
from fastapi import APIRouter, FastAPI

comments_router = APIRouter(prefix="/{post_id}/comments", tags=["comments"])


@comments_router.get("/")
def list_comments(post_id: int):
    return {"post_id": post_id, "comments": []}


posts_router = APIRouter(prefix="/posts", tags=["posts"])


@posts_router.get("/")
def list_posts():
    return []


posts_router.include_router(comments_router)   # 嵌套

app = FastAPI()
app.include_router(posts_router, prefix="/api/v1")
```

最终路径为 `/api/v1/posts/` 和 `/api/v1/posts/{post_id}/comments/`，`post_id` 作为路径参数正常注入。

> 💡 想查看最终注册了哪些路径，最可靠的方式是看 OpenAPI：`print(list(app.openapi()["paths"]))`。新版 FastAPI（0.14x）中 `include_router` 不再把子路由逐条复制到 `app.routes`，而是登记一个"被包含的 router"整体，所以遍历 `app.routes` 只能看到这些整体对象，看不到每条 `APIRoute`。
>
> ⚠️ 也因为这个实现变化，新版里「先 `include_router`，再往 router 上添加路由」同样能生效；但在老版本中这样添加的路由会**丢失**。为了兼容和可读性，始终保持「先定义完路由，再 include」的顺序。

## 3. 目录结构：按层组织 vs 按领域组织

社区里有两种主流组织方式。

### 3.1 按层组织（Layer-based）

把同一"技术角色"的代码放在一起，FastAPI 官方全栈模板就采用这种思路：

```text
shop/
├── .env                      # 本地环境变量（不提交 Git）
├── .env.example              # 环境变量示例（提交 Git）
├── pyproject.toml
├── static/                   # 静态文件
├── templates/                # Jinja2 模板
├── tests/
└── app/
    ├── __init__.py
    ├── main.py               # 创建 FastAPI 实例、注册 router/中间件/异常处理
    ├── core/
    │   ├── config.py         # Settings 配置
    │   └── security.py       # 密码哈希、JWT 等
    ├── api/
    │   ├── deps.py           # 公共依赖：get_db、get_current_user、get_xxx_service
    │   └── v1/
    │       ├── __init__.py   # 汇总 v1 下所有 router -> api_router
    │       ├── items.py      # 商品接口（只做 HTTP 适配）
    │       ├── users.py
    │       └── admin.py
    ├── schemas/              # Pydantic 模型：请求体、响应体
    │   └── item.py
    ├── models/               # ORM 模型（数据库表）
    │   └── item.py
    ├── repositories/         # 数据访问层（也有人叫 crud/）
    │   └── item_repo.py
    └── services/             # 业务逻辑层
        └── item_service.py
```

### 3.2 按领域/功能模块组织（Domain-based）

把同一"业务领域"的所有代码放在一起，每个领域是一个相对独立的小包：

```text
shop/
└── app/
    ├── main.py
    ├── config.py
    ├── database.py
    ├── exceptions.py           # 全局异常基类
    ├── items/                  # 商品领域
    │   ├── router.py
    │   ├── schemas.py
    │   ├── models.py
    │   ├── service.py
    │   ├── dependencies.py
    │   └── exceptions.py
    ├── users/                  # 用户领域
    │   ├── router.py
    │   ├── schemas.py
    │   ├── models.py
    │   └── service.py
    └── orders/                 # 订单领域
        └── ...
```

### 3.3 如何选择

| | 按层组织 | 按领域组织 |
|---|---|---|
| 新增一个功能 | 要在 4~5 个目录里各加一个文件 | 只在一个目录里加文件 |
| 查找某层的所有代码 | 方便（比如所有 schemas） | 分散在各领域目录 |
| 领域间边界 | 不明显，容易互相 import | 清晰，方便以后拆成微服务 |
| 适合 | 中小型项目、接口数 < 50、领域少 | 领域多、团队多人并行开发、长期演进 |

> 💡 没有绝对正确的结构。小项目从按层组织起步，等某个领域明显变大时，再把它整体抽成领域包。关键是团队内统一，并保持**依赖方向单向**：`router → service → repository → model`，下层绝不 import 上层。

## 4. 分层架构：router 薄、service 管业务、repository 管数据

下面用按层组织的结构实现一个完整的「商品」模块。为了不依赖数据库，repository 用内存字典模拟（12.9 已讲过如何换成 SQLAlchemy，换的时候只需改 repository 这一层）。

各层职责：

| 层 | 文件 | 知道 HTTP 吗 | 职责 |
|---|---|---|---|
| Router | `api/v1/items.py` | 知道 | 解析请求参数、调用 service、把业务异常转成 HTTP 状态码 |
| Service | `services/item_service.py` | **不知道** | 业务规则（如"商品名不能重复"），组合多个仓储操作 |
| Repository | `repositories/item_repo.py` | **不知道** | 只做增删改查，不含业务判断 |
| Schema | `schemas/item.py` | — | 数据的形状和校验 |

### 4.1 Schema 层

```python
# app/schemas/item.py
from pydantic import BaseModel, Field


class ItemCreate(BaseModel):
    name: str = Field(min_length=1, max_length=50)
    price: float = Field(gt=0)


class ItemOut(BaseModel):
    id: int
    name: str
    price: float
```

### 4.2 Repository 层

```python
# app/repositories/item_repo.py
from app.schemas.item import ItemCreate, ItemOut


class ItemRepository:
    """数据访问层：只负责存取，不含业务规则。这里用内存字典模拟数据库。"""

    def __init__(self) -> None:
        self._data: dict[int, ItemOut] = {}
        self._next_id = 1

    def get(self, item_id: int) -> ItemOut | None:
        return self._data.get(item_id)

    def get_by_name(self, name: str) -> ItemOut | None:
        return next((i for i in self._data.values() if i.name == name), None)

    def list(self, skip: int = 0, limit: int = 10) -> list[ItemOut]:
        return list(self._data.values())[skip : skip + limit]

    def add(self, data: ItemCreate) -> ItemOut:
        item = ItemOut(id=self._next_id, **data.model_dump())
        self._data[item.id] = item
        self._next_id += 1
        return item


# 模块级单例，模拟一个共享的数据库
item_repository = ItemRepository()
```

### 4.3 Service 层

```python
# app/services/item_service.py
from app.repositories.item_repo import ItemRepository
from app.schemas.item import ItemCreate, ItemOut


class ItemNotFoundError(Exception):
    pass


class DuplicateItemError(Exception):
    pass


class ItemService:
    """业务层：组合仓储操作，实现业务规则，不关心 HTTP。"""

    def __init__(self, repo: ItemRepository) -> None:
        self.repo = repo

    def get_item(self, item_id: int) -> ItemOut:
        item = self.repo.get(item_id)
        if item is None:
            raise ItemNotFoundError(item_id)
        return item

    def list_items(self, skip: int, limit: int) -> list[ItemOut]:
        return self.repo.list(skip, limit)

    def create_item(self, data: ItemCreate) -> ItemOut:
        if self.repo.get_by_name(data.name):
            raise DuplicateItemError(data.name)
        return self.repo.add(data)
```

注意 service 抛的是**业务异常**（`ItemNotFoundError`），而不是 `HTTPException`。这样同一个 service 可以被命令行脚本、定时任务、消息消费者复用，它们根本没有 HTTP 状态码的概念。

### 4.4 用依赖注入把各层串起来

```python
# app/api/deps.py
from typing import Annotated

from fastapi import Depends, Header, HTTPException

from app.core.config import Settings, get_settings
from app.repositories.item_repo import ItemRepository, item_repository
from app.services.item_service import ItemService

SettingsDep = Annotated[Settings, Depends(get_settings)]


def get_item_repo() -> ItemRepository:
    return item_repository


def get_item_service(
    repo: Annotated[ItemRepository, Depends(get_item_repo)],
) -> ItemService:
    return ItemService(repo)


ItemServiceDep = Annotated[ItemService, Depends(get_item_service)]


async def verify_token(x_token: Annotated[str, Header()]) -> None:
    if x_token != "secret-token":
        raise HTTPException(status_code=401, detail="X-Token 无效")
```

`get_item_service` 依赖 `get_item_repo`，形成一条依赖链。好处是测试时只要 `app.dependency_overrides[get_item_repo] = ...` 就能把数据层整个换掉（见 12.13）。

### 4.5 Router 层：越薄越好

```python
# app/api/v1/items.py
from typing import Annotated

from fastapi import APIRouter, HTTPException, Query, status

from app.api.deps import ItemServiceDep
from app.schemas.item import ItemCreate, ItemOut
from app.services.item_service import DuplicateItemError, ItemNotFoundError

router = APIRouter(
    prefix="/items",
    tags=["items"],
    responses={404: {"description": "商品不存在"}},
)


@router.get("/", response_model=list[ItemOut])
def list_items(
    service: ItemServiceDep,
    skip: Annotated[int, Query(ge=0)] = 0,
    limit: Annotated[int, Query(ge=1, le=100)] = 10,
):
    return service.list_items(skip, limit)


@router.get("/{item_id}", response_model=ItemOut)
def get_item(item_id: int, service: ItemServiceDep):
    try:
        return service.get_item(item_id)
    except ItemNotFoundError:
        raise HTTPException(status_code=404, detail="商品不存在")


@router.post("/", response_model=ItemOut, status_code=status.HTTP_201_CREATED)
def create_item(data: ItemCreate, service: ItemServiceDep):
    try:
        return service.create_item(data)
    except DuplicateItemError:
        raise HTTPException(status_code=409, detail="商品名已存在")
```

> 💡 如果每个接口都写 `try/except` 转换异常显得啰嗦，可以用 12.6 讲过的 `@app.exception_handler(ItemNotFoundError)` 做全局转换，router 里就只剩一行 `return service.get_item(item_id)`。

另外两个 router：

```python
# app/api/v1/users.py
from fastapi import APIRouter

router = APIRouter(prefix="/users", tags=["users"])


@router.get("/me")
def read_me():
    return {"username": "alice"}
```

```python
# app/api/v1/admin.py
from fastapi import APIRouter, Depends

from app.api.deps import SettingsDep, verify_token

router = APIRouter(
    prefix="/admin",
    tags=["admin"],
    dependencies=[Depends(verify_token)],  # 该 router 下所有接口都要校验 X-Token
)


@router.get("/settings")
def show_settings(settings: SettingsDep):
    return {"app_name": settings.app_name, "debug": settings.debug, "db_url": settings.db.url}
```

汇总 v1 的所有 router：

```python
# app/api/v1/__init__.py
from fastapi import APIRouter

from app.api.v1 import admin, items, users

api_router = APIRouter()
api_router.include_router(items.router)
api_router.include_router(users.router)
api_router.include_router(admin.router)
```

### 4.6 分层带来的可测试性

service 不依赖 FastAPI，可以像普通 Python 类一样直接测试，不需要启动任何 HTTP 客户端：

```python
from app.repositories.item_repo import ItemRepository
from app.schemas.item import ItemCreate
from app.services.item_service import DuplicateItemError, ItemService

service = ItemService(ItemRepository())   # 每次传一个全新的仓储，互不干扰
service.create_item(ItemCreate(name="苹果", price=5))
try:
    service.create_item(ItemCreate(name="苹果", price=6))
except DuplicateItemError as e:
    print("重复：", e)    # 重复： 苹果
```

## 5. 配置管理：`pydantic-settings`

配置（数据库地址、密钥、调试开关……）应当来自**环境变量**，而不是写死在代码里——这是 [12-Factor App](https://12factor.net/zh_cn/config) 的基本原则。`pydantic-settings` 让你用 Pydantic 模型的方式声明配置，自动从环境变量和 `.env` 文件读取并做类型校验。

```bash
pip install pydantic-settings     # fastapi[standard] 已自带
```

### 5.1 定义配置类

```python
# app/core/config.py
from functools import lru_cache

from pydantic import BaseModel
from pydantic_settings import BaseSettings, SettingsConfigDict


class DatabaseSettings(BaseModel):
    url: str = "sqlite:///./app.db"
    echo: bool = False


class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_file=".env",              # 从 .env 读取
        env_file_encoding="utf-8",
        env_prefix="SHOP_",           # 只认 SHOP_ 开头的环境变量
        env_nested_delimiter="__",    # SHOP_DB__URL -> settings.db.url
        extra="ignore",               # .env 中多余的变量忽略，不报错
    )

    app_name: str = "Shop API"
    debug: bool = False
    api_v1_prefix: str = "/api/v1"
    secret_key: str = "change-me"
    allowed_hosts: list[str] = ["*"]
    db: DatabaseSettings = DatabaseSettings()


@lru_cache
def get_settings() -> Settings:
    return Settings()
```

`.env` 文件（放在启动目录下）：

```bash
# .env
SHOP_APP_NAME="My Shop"
SHOP_DEBUG=true
SHOP_DB__URL=postgresql://user:pass@localhost/shop
```

### 5.2 读取规则

| 规则 | 说明 |
|---|---|
| 字段名 → 变量名 | `app_name` 对应 `SHOP_APP_NAME`，**默认不区分大小写** |
| 优先级 | 构造函数传参 > 系统环境变量 > `.env` 文件 > 字段默认值 |
| 类型转换 | `"true"/"1"/"yes"` → `True`；`list`/`dict` 等复杂类型要写成 JSON：`SHOP_ALLOWED_HOSTS='["a.com","b.com"]'` |
| 嵌套 | 设置 `env_nested_delimiter="__"` 后，`SHOP_DB__ECHO=1` → `settings.db.echo = True` |
| 校验失败 | 启动时直接抛 `ValidationError`，而不是运行到一半才出错 |

验证一下：

```bash
SHOP_DEBUG=false SHOP_ALLOWED_HOSTS='["a.com","b.com"]' SHOP_DB__ECHO=1 \
  python -c "from app.core.config import Settings; print(Settings().model_dump())"
```

```text
{'app_name': 'My Shop', 'debug': False, 'api_v1_prefix': '/api/v1', 'secret_key': 'change-me',
 'allowed_hosts': ['a.com', 'b.com'], 'db': {'url': 'postgresql://user:pass@localhost/shop', 'echo': True}}
```

可以看到：`app_name` 和 `db.url` 来自 `.env`；`debug` 被系统环境变量覆盖成 `False`；`db.echo` 通过嵌套分隔符设置。

如果把 `SHOP_DEBUG` 设成 `abc`，启动即报错：

```text
pydantic_core._pydantic_core.ValidationError: 1 validation error for Settings
debug
  Input should be a valid boolean, unable to interpret input [type=bool_parsing, input_value='abc', input_type=str]
```

### 5.3 为什么用 `@lru_cache` + 依赖注入

- `@lru_cache` 让 `get_settings()` 只在第一次调用时读取环境变量和 `.env`，之后直接返回同一个对象，避免每个请求都读文件。
- 通过 `Depends(get_settings)` 注入（而不是在各模块里 `from config import settings`），测试时就可以用 `dependency_overrides` 换一套配置：

```python
def get_settings_override() -> Settings:
    return Settings(debug=True, db=DatabaseSettings(url="sqlite://"))

app.dependency_overrides[get_settings] = get_settings_override
```

> ⚠️ `main.py` 中创建 app 时也需要配置（比如决定 docs 是否开启），这里只能直接调用 `get_settings()`，`dependency_overrides` 对它无效。所以"模块导入时就要用的配置"测试时只能靠设置环境变量来改变。
>
> ⚠️ 敏感信息（密码、密钥）可以声明为 `SecretStr` 类型，打印或 `repr` 时会显示为 `'**********'`，取值用 `.get_secret_value()`。`.env` 要加进 `.gitignore`，只提交一份不含真实密钥的 `.env.example`。

## 6. API 版本化

当接口需要做不兼容的修改（删字段、改字段含义）时，为了不影响老客户端，通常保留旧版本、新增新版本。最常用的是 **URL 路径版本化**：

```python
from fastapi import APIRouter, FastAPI

v1 = APIRouter(prefix="/api/v1")
v2 = APIRouter(prefix="/api/v2")


@v1.get("/users/{user_id}")
def get_user_v1(user_id: int):
    return {"id": user_id, "name": "Alice Smith"}


@v2.get("/users/{user_id}")
def get_user_v2(user_id: int):
    # v2 把 name 拆成 first_name / last_name，属于不兼容变更
    return {"id": user_id, "first_name": "Alice", "last_name": "Smith"}


app = FastAPI()
app.include_router(v1)
app.include_router(v2)
```

在真实项目中，每个版本是一个包（`app/api/v1/`、`app/api/v2/`），各自有 `api_router`，`main.py` 中：

```python
app.include_router(v1_router, prefix="/api/v1")
app.include_router(v2_router, prefix="/api/v2")
```

| 方式 | 示例 | 优点 | 缺点 |
|---|---|---|---|
| URL 路径 | `/api/v1/users` | 直观、易调试、文档清晰，**最常用** | URL 变化 |
| 请求头 | `Accept: application/vnd.shop.v2+json` | URL 稳定 | 难以在浏览器调试，FastAPI 需自己写依赖分发 |
| 查询参数 | `/users?version=2` | 简单 | 容易和业务参数混淆 |

> 💡 版本号只在**不兼容**变更时升级。新增字段、新增接口属于兼容变更，不需要升版本。

## 7. 挂载子应用、静态文件与模板

### 7.1 `app.mount`：挂载独立的 ASGI 应用

`include_router` 是把路由**合并**到主应用；`mount` 则是把一个**完全独立**的应用挂在某个路径下。子应用有自己的中间件、异常处理器和 OpenAPI 文档。

```python
from fastapi import FastAPI, Request
from fastapi.responses import HTMLResponse
from fastapi.staticfiles import StaticFiles
from fastapi.templating import Jinja2Templates

app = FastAPI(title="主应用")
admin_app = FastAPI(title="后台子应用")
templates = Jinja2Templates(directory="templates")


@app.get("/")
def root():
    return {"message": "主应用"}


@admin_app.get("/")
def admin_root():
    return {"message": "子应用"}


@app.get("/hello/{name}", response_class=HTMLResponse)
def hello(request: Request, name: str):
    return templates.TemplateResponse(request, "hello.html", {"name": name})


app.mount("/admin", admin_app)
app.mount("/static", StaticFiles(directory="static"), name="static")
```

```html
<!-- templates/hello.html -->
<!doctype html>
<html>
  <body>
    <h1>你好，{{ name }}！</h1>
  </body>
</html>
```

运行后：

| 请求 | 结果 |
|---|---|
| `GET /` | `{"message": "主应用"}` |
| `GET /admin/` | `{"message": "子应用"}` |
| `GET /admin/docs` | 子应用自己的文档页，标题「后台子应用」 |
| `GET /docs` | 主应用文档，**不包含**子应用的接口 |
| `GET /static/logo.png` | 返回 `static/logo.png` 文件 |
| `GET /hello/小明` | 渲染后的 HTML：`<h1>你好，小明！</h1>` |

| | `include_router` | `mount` |
|---|---|---|
| 被挂载对象 | `APIRouter` | 任何 ASGI 应用（FastAPI、StaticFiles、Starlette、Flask 经 WSGI 适配……） |
| 中间件/异常处理器 | 共用主应用的 | 子应用自己的 |
| OpenAPI 文档 | 合并进主文档 | 独立文档 |
| 典型用途 | 拆分业务模块 | 静态文件、独立后台、整合遗留应用 |

> ⚠️ `StaticFiles(directory="static")` 和 `Jinja2Templates(directory="templates")` 中的相对路径是相对于**启动命令所在目录**的。静态目录不存在时启动直接报 `RuntimeError: Directory 'static' does not exist`；模板目录不存在则不会立刻报错，要等到渲染时才抛 `TemplateNotFound`。更稳妥的写法是基于源码位置计算：`BASE_DIR = Path(__file__).resolve().parent`，再用 `BASE_DIR / "static"`。
>
> 💡 新版 Starlette 的 `TemplateResponse` 第一个参数是 `request`，然后才是模板名；老教程里的 `TemplateResponse("hello.html", {"request": request, ...})` 写法已弃用。

### 7.2 前后端分离时的选择

FastAPI 主要用来写 JSON API。如果有独立的前端（Vue/React），模板基本用不上，静态文件一般也交给 Nginx 或 CDN。`Jinja2Templates` 适合管理后台、邮件模板、简单的服务端渲染页面。

## 8. 定制 OpenAPI 文档

### 8.1 应用元数据与标签说明

```python
from fastapi import FastAPI

tags_metadata = [
    {"name": "items", "description": "商品的增删改查"},
    {"name": "users", "description": "用户相关操作"},
    {
        "name": "admin",
        "description": "管理接口，需要 **X-Token** 请求头",   # 支持 Markdown
        "externalDocs": {"description": "管理手册", "url": "https://example.com/admin-docs"},
    },
]

app = FastAPI(
    title="Shop API",
    version="1.0.0",
    summary="商城后端接口",
    description="一个演示**大型项目结构**的商城 API",
    openapi_tags=tags_metadata,       # 列表顺序 = 文档中分组的显示顺序
    servers=[
        {"url": "http://localhost:8000", "description": "本地开发"},
        {"url": "https://api.example.com", "description": "生产环境"},
    ],
    contact={"name": "后端组", "email": "backend@example.com"},
    license_info={"name": "MIT"},
)
```

设置 `servers` 后，`/docs` 页面左上角会出现服务器下拉框，"Try it out" 会把请求发到选中的服务器。

### 8.2 隐藏接口与关闭文档

```python
@app.get("/health", include_in_schema=False)   # 健康检查不需要出现在文档里
def health():
    return {"status": "ok"}
```

生产环境常常不对外暴露文档：

```python
settings = get_settings()

app = FastAPI(
    docs_url="/docs" if settings.debug else None,     # Swagger UI
    redoc_url="/redoc" if settings.debug else None,   # ReDoc
    # openapi_url=None 会连 /openapi.json 一起关闭，docs 和 redoc 也就无法工作
)
```

| 参数 | 默认 | 设为 `None` 的效果 |
|---|---|---|
| `docs_url` | `/docs` | 关闭 Swagger UI |
| `redoc_url` | `/redoc` | 关闭 ReDoc |
| `openapi_url` | `/openapi.json` | 关闭 OpenAPI schema，上面两个也随之失效 |

### 8.3 `generate_unique_id_function`：定制 operationId

每个接口在 OpenAPI 中都有一个 `operationId`，前端用 `openapi-ts`、`openapi-generator` 等工具生成 SDK 时，它会成为函数名。默认值形如 `list_items_api_v1_items__get`，又长又丑。可以自定义：

```python
from fastapi import FastAPI
from fastapi.routing import APIRoute


def custom_generate_unique_id(route: APIRoute) -> str:
    # 生成形如 items-list_items 的 operationId
    return f"{route.tags[0]}-{route.name}" if route.tags else route.name


app = FastAPI(generate_unique_id_function=custom_generate_unique_id)
```

> ⚠️ 用了这种方案后，同一个 tag 下的接口函数名必须唯一，否则 operationId 冲突，生成的 SDK 会出问题。

## 9. 组装主应用并运行

```python
# app/main.py
from fastapi import FastAPI
from fastapi.routing import APIRoute
from fastapi.staticfiles import StaticFiles

from app.api.v1 import api_router
from app.core.config import get_settings

settings = get_settings()


def custom_generate_unique_id(route: APIRoute) -> str:
    return f"{route.tags[0]}-{route.name}" if route.tags else route.name


tags_metadata = [
    {"name": "items", "description": "商品的增删改查"},
    {"name": "users", "description": "用户相关操作"},
    {"name": "admin", "description": "管理接口，需要 **X-Token** 请求头"},
]

app = FastAPI(
    title=settings.app_name,
    version="1.0.0",
    description="一个演示**大型项目结构**的商城 API",
    openapi_tags=tags_metadata,
    generate_unique_id_function=custom_generate_unique_id,
    docs_url=None if not settings.debug else "/docs",
)

app.include_router(api_router, prefix=settings.api_v1_prefix)
app.mount("/static", StaticFiles(directory="static"), name="static")


@app.get("/health", include_in_schema=False)
def health():
    return {"status": "ok"}
```

> 💡 `main.py` 只负责「组装」：创建应用、注册 router、中间件、异常处理器、lifespan。不要在这里写任何业务接口（健康检查这种基础设施接口除外）。当组装逻辑变多时，可以进一步抽成 `create_app()` 工厂函数，方便测试时用不同配置创建多个实例。

在**项目根目录**（`shop/`，即 `.env` 和 `static/` 所在目录）运行：


## 常见坑

1. **循环导入**：`main.py` import `routers`，`routers` 又 import `main` 里的 `app` 或配置 → `ImportError`。router 模块永远不要 import `main.py`；公共对象放到 `core/`、`api/deps.py` 这类底层模块中。
2. **prefix 以 `/` 结尾**：`APIRouter(prefix="/items/")` 会直接报 `AssertionError: A path prefix must not end with '/', as the routes will start with '/'`。
3. **路径斜杠不一致**：`@router.get("/")` 加上 `prefix="/items"` 得到 `/items/`；请求 `/items` 会被 307 重定向到 `/items/`。团队要统一风格（要么都带尾斜杠，要么 `@router.get("")`）。
4. **相对路径依赖启动目录**：`.env`、`static/`、`templates/` 都是相对于运行命令时的当前目录查找，在别的目录启动就会找不到 `.env`（静默使用默认值！）或报目录不存在。
5. **`get_settings` 忘记 `@lru_cache`**：每次请求都重新读取 `.env`，性能变差；反过来，加了缓存之后在测试里修改环境变量不会生效，需要 `get_settings.cache_clear()`。
6. **service 里抛 `HTTPException`**：业务层和 HTTP 耦合，脚本/定时任务里复用时语义混乱。业务层抛业务异常，由 router 或全局异常处理器翻译成 HTTP 响应。
7. **以为 `mount` 的子应用会继承主应用的中间件/异常处理器/依赖**：不会，子应用是完全独立的；同样，主应用的 `/docs` 也不会显示子应用的接口。
8. **把 `.env` 提交到 Git**：密钥泄露。只提交 `.env.example`。

## 小结

- `APIRouter` 是拆分路由的基本单位，`prefix`、`tags`、`dependencies`、`responses` 既可以在创建时声明，也可以在 `include_router` 时补充，且会叠加；router 可以嵌套。
- 目录结构有**按层**和**按领域**两种主流方案：小项目按层起步，领域变多后再按领域拆分；无论哪种都要保证依赖方向单向。
- 分层架构：**router 只做 HTTP 适配，service 承载业务规则，repository 负责数据访问**，用依赖注入把它们串起来，测试时可以逐层替换。
- `pydantic-settings` 的 `BaseSettings` 从环境变量和 `.env` 读取并校验配置；配合 `@lru_cache` 的 `get_settings()` 作为依赖注入，方便测试覆盖。
- 用 `/api/v1` 这样的路径前缀做版本化；`app.mount` 用于挂载独立应用、静态文件；`Jinja2Templates` 用于服务端渲染。
- 通过 `title`/`description`/`openapi_tags`/`servers`/`include_in_schema`/`generate_unique_id_function` 定制 OpenAPI 文档，生产环境可通过 `docs_url=None` 关闭文档。
