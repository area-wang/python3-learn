# 12.2 路径参数与查询参数练习题

## 一、概念题

1. FastAPI 根据什么规则判断一个函数参数是路径参数、查询参数还是请求体？请分别举例说明。
2. 为什么说路径参数「总是必填」？查询参数是否必填由什么决定？`x: int | None` 与 `x: int | None = None` 有什么区别？
3. 路由是如何匹配的？为什么 `/users/me` 必须声明在 `/users/{user_id}` 之前？如果 `user_id` 是 `int` 类型，访问 `/users/me` 会得到什么结果？
4. 用 `Enum` 声明路径参数有哪些好处？为什么示例中的枚举要同时继承 `str` 和 `Enum`？`Literal` 与 `Enum` 应如何取舍？
5. `{file_path:path}` 解决了什么问题？使用它时有什么安全隐患，应如何防范？
6. `Annotated[int, Query(ge=1)] = 1` 与旧写法 `page: int = Query(default=1, ge=1)` 相比有哪些优势？
7. `Query()` 中哪些参数用于**校验**，哪些只影响**文档或参数名**？`deprecated=True` 和 `include_in_schema=False` 会让参数失效吗？
8. 为什么 `tags: list[str] = []` 不会被识别为查询参数？应该怎么写？
9. 查询参数模型（`Annotated[FilterParams, Query()]`）适合什么场景？`extra="forbid"` 解决了什么实际问题？
10. 422 错误响应中 `detail`、`type`、`loc`、`msg`、`input`、`ctx` 各表示什么？为什么来自查询参数的 `input` 总是字符串？

## 二、判断代码输出 / 找错

### 1. 路由顺序

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/files/{name}")
async def get_file(name: str):
    return {"file": name}


@app.get("/files/latest")
async def latest():
    return {"file": "latest.txt"}


@app.get("/reports/{year}")
async def report(year: int):
    return {"year": year}


@app.get("/reports/summary")
async def summary():
    return {"summary": True}
```

分别写出 `GET /files/latest` 和 `GET /reports/summary` 的状态码与响应，并修改代码使两个固定路径都能正确访问。

### 2. 可选还是必填

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/search")
async def search(q: str | None, page: int = 1, size: int | None = 10):
    return {"q": q, "page": page, "size": size}
```

以下请求分别返回什么？

- `GET /search`
- `GET /search?q=python`
- `GET /search?q=python&size=`（`size` 传空字符串）

### 3. 列表参数为什么收不到

```python
from fastapi import FastAPI

app = FastAPI()


@app.get("/posts")
async def list_posts(tag: list[str] | None = None):
    return {"tag": tag}
```

请求 `GET /posts?tag=a&tag=b` 返回 `{"tag": null}`。请解释原因，说明在 `/docs` 中能观察到什么异常现象，并修复。

### 4. alias 的陷阱

```python
from typing import Annotated

from fastapi import FastAPI, Query

app = FastAPI()


@app.get("/items")
async def read_items(page_size: Annotated[int, Query(alias="page-size", le=50)] = 10):
    return {"page_size": page_size}
```

写出下列请求的结果：

- `GET /items?page-size=20`
- `GET /items?page_size=20`
- `GET /items?page-size=100`

### 5. 读错误体

某接口返回如下响应，请推断接口的参数声明（参数名、来源、类型、约束），并写出一个能复现该响应的请求。

  "detail": [

## 三、编程题

### 1. 用户与订单

实现以下接口：

- `GET /users/me` 返回 `{"user": "current"}`；
- `GET /users/{user_id}`，`user_id` 为大于 0 的整数；
- `GET /users/{user_id}/orders/{order_no}`，`order_no` 必须匹配 `^ORD\d{8}$`；
- 支持可选查询参数 `with_items: bool = False`，为真时在响应中附带一个假数据列表 `items`。

分别构造请求，触发 `greater_than`、`string_pattern_mismatch`、`bool_parsing` 三种错误。

### 2. 枚举排序

定义枚举 `SortField`（`price`、`sales`、`created_at`）和 `SortOrder`（`asc`、`desc`），实现 `GET /products?sort_by=...&order=...`，按指定字段和方向对一个内存中的商品列表排序后返回。要求：

- 两个参数都有默认值；
- 在 `/docs` 中确认它们显示为下拉框；
- 函数内部分别用 `is` 和 `.value` 两种方式判断枚举值。

### 3. 带校验的搜索

实现 `GET /search`：

| 参数 | 规则 |
|---|---|
| `q` | 必填，2~20 个字符 |
| `page` | 默认 1，`>= 1` |
| `size` | 默认 10，`1 ~ 100` |
| `lang` | 可选，只能是 `zh` 或 `en`（用 `pattern` 实现，再用 `Literal` 实现一次并比较两者的错误信息） |
| `sort_by` | 可选字符串；URL 中的参数名为 `sort-by` |

另外，把 `page` 和 `size` 的约束抽成 `Annotated` 别名，在另一个接口 `GET /articles` 中复用。

### 4. 文件路径接口

实现 `GET /static/{file_path:path}`：

- 允许访问的根目录为项目下的 `public/` 目录；
- 文件存在则返回 `{"path": 相对路径, "size": 字节数}`；
- 请求 `../` 越界路径时返回 `{"error": "非法路径"}`（状态码暂时不做要求，12.6 会学习 `HTTPException`）；
- 用 `pathlib.Path.resolve()` 和 `is_relative_to()` 实现越界判断。

### 5. 标签过滤与自定义校验

实现 `GET /notes`：

- 支持多值参数 `tag`（`?tag=a&tag=b`），最多 5 个（提示：`Query(max_length=5)` 对列表同样生效）；
- 支持 `date_from`、`date_to` 两个 `date` 类型的可选参数；
- 用 `AfterValidator` 实现：`tag` 中每个元素只能包含小写字母和数字，否则返回 `value_error`；
- 思考：「`date_from` 必须早于 `date_to`」这种**跨参数**校验，用单个参数的 `AfterValidator` 能实现吗？用查询参数模型 + `model_validator` 如何实现？（`model_validator` 将在 12.3 学习）

## 四、综合实践：商品列表查询接口

为一个商品服务实现完整的列表查询接口 `GET /categories/{category}/products`：

1. `category` 是枚举：`phone`、`laptop`、`tablet`；
2. 所有查询参数收拢到 `ProductQuery` 查询参数模型中：
   - `keyword`：可选，1~30 个字符；
   - `min_price` / `max_price`：可选，`>= 0`；
   - `brands`：多值参数；
   - `in_stock`：可选 bool；
   - `sort_by`：`Literal["price", "sales"]`，默认 `"sales"`；
   - `page` / `size`：分页，`size` 不超过 50；
3. 模型开启 `extra="forbid"`，验证拼错参数名会得到 422；
4. 用内存中至少 20 条假数据实现真正的过滤、排序和分页，响应格式为：
   ```json
   {"total": 23, "page": 1, "size": 10, "items": [...]}
   ```
5. 在 `/docs` 中检查每个参数的说明、默认值和约束是否正确展示；
6. 列出你为这个接口设计的 5 个以上「错误请求」，预测每个请求的 422 响应中的 `type` 和 `loc`，再实际请求验证。

## 五、参考检查点

- 能否准确说出参数来源的判断规则，尤其是「复杂类型默认是请求体」这一条；
- 能否正确处理路由声明顺序，理解路由匹配不看类型；
- 能否用 `Enum` / `Literal` 限定取值，用 `:path` 接收多级路径并防范路径穿越；
- 能否熟练使用 `Annotated` + `Query` / `Path` 声明长度、范围、正则约束和 alias、描述、废弃等元数据；
- 能否用 `AfterValidator` 实现自定义校验，用 `Annotated` 别名复用约束；
- 能否正确声明列表查询参数，并用查询参数模型 + `extra="forbid"` 组织复杂查询；
- 能否根据 422 响应快速定位是哪个参数、什么原因校验失败。
