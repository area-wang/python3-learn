# 12.7 依赖注入练习题

## 一、概念题

1. 什么是依赖注入？与"在接口函数里自己调用工具函数"相比，FastAPI 的依赖注入多做了哪些事情（至少说出 4 点）？
2. `Depends(get_db)` 和 `Depends(get_db())` 有什么区别？为什么后者是错误写法？
3. 为什么官方推荐用 `Annotated[T, Depends(f)]` 而不是 `x: T = Depends(f)`？用 `SessionDep = Annotated[Session, Depends(get_session)]` 这种别名有什么好处？
4. 类作为依赖时，FastAPI 根据哪个方法的参数来解析请求？带 `__call__` 的类**实例**作为依赖时呢？`Annotated[CommonQueryParams, Depends()]` 中省略参数的前提是什么？
5. 同一个请求中，同一个依赖被声明了 3 次，它会被调用几次？如何让它每次都重新调用？这个缓存会跨请求生效吗？如果想跨请求复用一个对象（如配置），应该怎么做？
6. `def` 依赖和 `async def` 依赖分别在哪里执行？为什么说"拿不准就用 `def`"？
7. 在 yield 依赖中，接口函数抛出的异常会出现在什么位置？如果 `except` 之后没有 `raise`，会发生什么？只需要做清理工作时应该用什么语法？
8. 解释 `Depends(..., scope="request")` 与 `scope="function"` 的区别。为什么默认 scope 下在 `yield` 之后抛 `HTTPException` 无法改变客户端收到的响应？
9. 写在 `@app.get(..., dependencies=[...])`、`APIRouter(dependencies=[...])`、`FastAPI(dependencies=[...])` 中的依赖和写在函数参数中的依赖有什么区别？多个层级同时存在时执行顺序是怎样的？
10. 实现"可参数化依赖"有哪两种方式？各有什么优缺点？为什么工厂函数生成的依赖不方便用 `dependency_overrides` 覆盖？

### 2. yield 依赖的执行顺序

    print("outer end")

### 3. 找错：吞掉的异常

### 6. 找错：参数同名

## 三、编程题

### 1. 排序参数依赖

编写一个依赖类 `SortParams`（用 `dataclass` 实现）：

- 查询参数 `sort_by`（默认 `"id"`）和 `order`（只能是 `"asc"` 或 `"desc"`，默认 `"asc"`）；
- 提供方法 `apply(items: list[dict]) -> list[dict]` 返回排序后的列表；
- 在 `/products` 接口中使用 `Annotated[SortParams, Depends()]`，对内存中的产品列表排序后返回；
- `sort_by` 不是产品的字段时返回 400。

### 2. 资源加载依赖

内存中有 `USERS = {1: {...}, 2: {...}}`：

- 编写依赖 `get_user_or_404(user_id: int)`，不存在时返回 404；
- 定义别名 `UserDep`；
- 用它实现 `GET /users/{user_id}`、`GET /users/{user_id}/profile`、`DELETE /users/{user_id}` 三个接口，接口函数体中不允许再出现 404 判断。

### 3. 计时与请求 ID

编写一个 `async def` + `yield` 的依赖 `request_context`：

- 进入时生成一个 UUID 作为请求 ID，并记录开始时间；
- 通过 `Response` 参数把请求 ID 写入响应头 `X-Request-ID`；
- 退出时打印 `"[<request_id>] <method> <path> 耗时 xx ms"`；
- 作为**全局依赖**注册，让所有接口自动生效；
- 用 `TestClient` 验证响应头存在，并观察打印输出。

### 4. 可参数化限流依赖

实现一个带 `__call__` 的类 `RateLimiter(times: int, seconds: int)`：

- 按客户端 IP（`request.client.host`）计数，`seconds` 秒内最多 `times` 次；
- 超限时返回 `429 Too Many Requests`，并带上 `Retry-After` 响应头；
- 分别用 `RateLimiter(3, 10)` 和 `RateLimiter(100, 60)` 保护两个不同的接口；
- 思考：多进程部署（多个 worker）时这个实现会有什么问题？

### 5. 事务依赖

模拟一个事务对象（记录 `begin/commit/rollback/close` 调用）：

- 编写 `get_tx` yield 依赖：正常结束时 `commit`，有异常时 `rollback` 并重新抛出，最后总是 `close`；
- 编写 `POST /accounts/{id}/withdraw?amount=` 接口，余额不足时抛 `HTTPException(400)`；
- 用 `TestClient` 分别验证成功和失败两种情况下事务对象的调用记录。

### 6. 依赖覆盖

在第 5 题的基础上：

- 用 `app.dependency_overrides` 把 `get_tx` 替换为一个总是记录到列表 `fake_calls` 的假事务；
- 写一个 pytest 测试函数，验证接口确实调用了 `commit`；

## 四、综合实践：多租户笔记 API

用纯内存数据实现一个多租户笔记服务，要求全部公共逻辑都用依赖实现，接口函数里只有业务代码：

1. **配置**：`get_settings()` 用 `lru_cache` 缓存，包含 `max_page_size`、`valid_tenants`。
2. **租户识别**：依赖 `get_tenant` 从请求头 `X-Tenant` 读取租户 ID，不在 `valid_tenants` 中返回 400；作为 `APIRouter` 级依赖挂在 `/notes` 路由器上。
3. **用户识别**：依赖 `get_current_user` 从 `X-User` 头读取用户名，同时依赖 `get_tenant`，确保用户属于该租户，否则 401。
4. **会话**：yield 依赖 `get_store` 返回当前租户的数据字典，并在请求结束时打印"写回存储"。
5. **分页**：类依赖，`size` 不能超过配置中的 `max_page_size`。
6. **权限**：`RoleChecker("admin")` 保护 `DELETE /notes/{id}`；普通用户只能修改自己的笔记（用"加载资源 + 权限检查"的依赖实现）。
7. 接口：`GET /notes`、`POST /notes`、`GET /notes/{id}`、`PUT /notes/{id}`、`DELETE /notes/{id}`。
8. 画出 `PUT /notes/{id}` 的完整依赖树，标出哪些依赖在同一请求中被缓存复用。
9. 编写至少 6 个 `TestClient` 测试，覆盖：租户无效、未登录、跨租户访问、修改他人笔记、管理员删除、分页上限。

- 能否识别"`Depends(f())`""吞掉异常""async 依赖中调用阻塞函数""参数同名冲突"等常见错误。
