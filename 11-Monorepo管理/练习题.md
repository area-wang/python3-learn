# 11-Monorepo管理 · 练习题

## 一、概念题

1. 用自己的话说明 monorepo 相比 polyrepo 的两个优势和两个代价。
2. `[project] dependencies` 与 `[tool.uv.sources]` 的区别是什么？哪一个会随包发布？
3. 为什么根目录要做成 virtual workspace root？它带来什么影响（提示：`uv sync`）？
4. 一个仓库只有一个 `uv.lock`，当两个成员要求同一个库的版本互斥时会发生什么？这是好事还是坏事？
5. 为什么 `mono-utils` 发布到 PyPI 之前，要把 `"mono-core"` 改成 `"mono-core>=0.1.0"`？

## 二、动手题

6. **搭骨架**：不看文档，从空目录搭出 `core / utils / api` 三个成员的工作区，并让 `uv run --package mono-api mono-api` 输出内容。
7. **新增成员**：新建 `packages/config`（`mono-config`），提供 `load(name: str) -> dict`，让 `mono-api` 依赖它，不要手改 `pyproject.toml`，全部用 `uv add --package`。
8. **测试**：给 `mono-config` 写 2 个测试，并让两个不同成员各有一个叫 `test_basic.py` 的文件。在去掉 `--import-mode=importlib` 的情况下运行，观察报错，再还原。
9. **依赖冲突**：给 `mono-core` 添加 `pydantic>=2`，再给 `mono-utils` 添加 `pydantic<2`，运行 `uv lock` 观察错误信息，然后修复。
10. **依赖树**：用 `uv tree` 画出当前依赖图；再尝试让 `core` 依赖 `utils`，观察 uv 如何处理循环依赖。

## 三、实战题

11. **迁移**：把仓库里已有的 `my-project`（独立 uv 项目）迁入一个新工作区的 `packages/` 目录，使其成为成员。需要处理哪些问题？（提示：包名、`requires-python`、各自的 `uv.lock`、`[project.scripts]`。）
12. **Makefile**：写一个 `make check`，依次执行 lint、格式检查、类型检查、测试，任意一步失败就终止。
13. **CI**：写出一份 GitHub Actions 配置：PR 触发，先 `uv lock --check`，再跑全部检查。
14. **发布演练**：用 `uv build --all-packages` 构建全部包，然后在一个干净的临时虚拟环境里只安装 `mono_api-*.whl` 和它依赖的另外两个 wheel（`uv pip install --find-links dist mono-api`），确认能运行。
15. **选型思考**：假设仓库增长到 40 个包、CI 要 30 分钟，你会怎么优化？列出至少 3 个手段，并说明何时值得引入 Pants。

## 参考答案要点

1. 优势：原子跨项目改动、统一依赖和工具链、复用方便；代价：仓库变大、CI 需做增量、权限难细分。
2. `dependencies` 是标准声明，随包发布；`[tool.uv.sources]` 只是 uv 的本地来源映射，不随包发布。
3. 根不是包，只做声明。`uv sync` 不会把根当包安装，需用 `--all-packages` 或 `--package` 指定要装的成员。
4. `uv lock` 报错，无法生成锁文件。好事：问题在提交前暴露，而不是在运行时。
5. `sources` 不随包发布，PyPI 上的依赖元数据只有 `dependencies`；不写下限就可能装到不兼容的旧版本。
6–10. 对照文档 Step 1–8 自查；第 8 题报错原因是同名测试模块冲突；第 9 题 uv 会指出具体冲突的两个成员和版本范围；第 10 题循环依赖应通过抽取公共层解决。
11. 注意 `my-project` 的 `[project.scripts]` 指向的模块名要与 `src/` 下的实际包名一致，迁入后删掉它自己的 `uv.lock`，让根统一解析。
12. 用 `check: lint typecheck test`；Make 会在某个目标失败时停止。
13. 参考文档 12.2 节。
14. 用 `--find-links dist` 让 uv 从本地 `dist/` 找内部依赖，其余走 PyPI。
15. 手段：按路径过滤 CI、并行拆分 job、缓存 uv 与 `.venv`、变更检测只测受影响包及下游、pytest-xdist 并行；当包间依赖复杂、需要依赖图级别的增量缓存时再引入 Pants / Bazel。
