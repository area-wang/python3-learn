## 一、概念题

1. 描述符协议包含哪些方法？各自在什么时机、由谁自动调用？

4. `__set_name__` 解决了描述符实现中的什么痛点？如果没有它，早期的描述符要怎样才能知道自己绑定的属性名？
5. `@property` 与自己动手实现的数据描述符类有什么关系？说说 `fget`/`fset`/`fdel` 与 `__get__`/`__set__`/`__delete__` 的对应关系。
6. 为什么函数对象也是一种描述符？这与 `obj.method()` 能自动传入 `self` 有什么关系？如果把一个函数赋值给**实例**属性而不是类属性，还会自动绑定 `self` 吗？
7. `staticmethod` 与 `classmethod` 的 `__get__` 分别做了什么？为什么通过子类访问 `classmethod` 时，`cls` 会自动变成子类而不是定义它的父类？
8. 只定义 `__get__` 而不定义 `__set__` 的描述符，能否阻止用户对该属性赋值？请说明原因；如果想做出真正「只读」的属性，应该怎么写？
9. 结合懒加载/缓存属性的实现，说说它为什么必须是非数据描述符而不是数据描述符。如果写成数据描述符，还能不能复用「写入实例字典即可命中缓存」这个技巧？

### 1. 数据描述符能否被实例字典绕过

```python
class Locked:
    def __set_name__(self, owner, name):
        self.name = "_" + name

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return getattr(obj, self.name, None)

    def __set__(self, obj, value):
        print(f"设置 {self.name} = {value}")
        setattr(obj, self.name, value)


class Config:
    debug = Locked()


c = Config()
c.__dict__["debug"] = "sneaky"
c.debug = True
print(c.debug)
print(c.__dict__)
```

### 2. 非数据描述符与缓存命中

```python
class Cache:
    def __init__(self, func):
        self.func = func

    def __set_name__(self, owner, name):
        self.name = name

    def __get__(self, obj, objtype=None):
        print("__get__ 调用")
        if obj is None:
            return self
        value = self.func(obj)
        obj.__dict__[self.name] = value
        return value


class Circle:
    def __init__(self, r):
        self.r = r

    @Cache
    def area(self):
        return 3.14 * self.r ** 2


c = Circle(2)
print(c.area)
print(c.area)
c.area = 100
print(c.area)
```

写出三次 `print` 的输出，说明第二次访问为什么没有打印 `"__get__ 调用"`，以及 `c.area = 100` 之后为什么读到的是 `100` 而不是重新计算的面积。

### 3. classmethod 描述符与子类

```python
class MyClassMethod:
    def __init__(self, func):
        self.func = func

    def __get__(self, obj, objtype=None):
        cls = objtype if objtype is not None else type(obj)
        def bound(*args, **kwargs):
            return self.func(cls, *args, **kwargs)
        return bound


class Animal:
    @MyClassMethod
    def make(cls):
        return f"一只 {cls.__name__}"


class Dog(Animal):
    pass


print(Animal.make())
print(Dog.make())
print(Dog().make())
```

写出三行输出，并解释 `Dog.make()` 中 `cls` 为什么是 `Dog` 而不是 `Animal`（提示：`__get__` 的 `objtype` 参数在什么时候传入什么值）。

### 4. 「只定义 `__get__`」是否真的只读

```python
class ReadOnly:
    def __set_name__(self, owner, name):
        self.name = "_" + name

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return getattr(obj, self.name)


class Point:
    x = ReadOnly()

    def __init__(self, x):
        self._x = x


p = Point(5)
print(p.x)
p.x = 10
print(p.x)
print(p.__dict__)
```

## 三、编程题

### 1. 取值范围校验描述符

实现描述符类 `Ranged(min_value=None, max_value=None)`：

- 用 `__set_name__` 自动记录属性名，把真实值存储在 `obj.__dict__` 的私有键（如 `_属性名`）中；
- 赋值超出 `[min_value, max_value]` 范围时抛出 `ValueError`，消息中包含属性名与合法范围；
- `min_value`/`max_value` 任意一个为 `None` 表示该方向不做限制；
- 在两个不同的类中各用一次 `Ranged`，证明同一个描述符类可以复用，且不同实例、不同属性之间的存储互不干扰。

### 2. 手写 `cached_property` 与失效

- 实现 `CachedProperty` 描述符，行为与本节 `LazyProperty` 一致（首次访问计算并缓存，之后直接命中）；
- 额外提供一个模块级函数 `invalidate(obj, name)`，能清除已缓存的值，使下次访问重新计算；
- 用一个内部计数器证明：未失效前多次访问只触发一次计算，调用 `invalidate` 后再访问会重新计算一次；
- 结合概念题 9 的答案，在代码注释中说明为什么 `CachedProperty` 必须是非数据描述符才能配合 `invalidate` 工作。

### 3. 真正只读的属性

实现 `StrictReadOnly` 描述符：

- 只允许在对象生命周期内第一次写入（通常发生在 `__init__` 里），此后任何赋值都要抛出 `AttributeError`，消息包含属性名；
- 提示：可以在 `__set__` 里检查私有存储键是否已经存在于 `obj.__dict__`；
- 用代码验证：正常赋值一次可以成功，第二次赋值会报错；
- 额外思考并写出结论：如果用户绕过属性访问，直接执行 `obj.__dict__["_x"] = 999`，`StrictReadOnly` 还能不能拦住？为什么？

### 4. 迷你 ORM 字段增强

在本节 `Field` 描述符的基础上进行增强：

- 增加 `choices` 参数，赋值时只允许集合内的取值，否则抛出 `ValueError`；
- 增加 `default` 参数：构造对象时未传该字段值，使用默认值而不是触发必填校验失败；
- 给 `BaseModel` 实现 `__repr__`，自动列出所有 `Field` 字段及当前取值，格式类似 `User(name='Alice', role='admin')`；
- 写一个 `User(BaseModel)` 例子，包含一个 `role` 字段（`choices=("admin", "member")`），演示传入非法取值时抛出 `ValueError`。

## 四、综合实践：字段系统与简易 ORM

在前面练习的基础上，设计一个更完整的迷你 ORM 风格字段系统，要求：

1. 至少提供三种字段描述符：`StringField`、`IntField`、`ChoiceField`，都继承自统一的 `Field` 基类，公共校验逻辑（必填、默认值）写在基类里，类型相关校验在子类里覆盖；
2. `Field` 支持可选的 `validator` 参数，接收一个自定义校验函数 `validator(value) -> bool`，校验失败时抛出 `ValueError`；
3. `Model` 基类自动收集类上声明的所有字段（通过 `__set_name__` 或遍历 `__dict__`），提供：
   - `validate()`：一次性收集**所有**字段的校验错误（而不是遇到第一个错误就抛异常中断），最后汇总抛出一个包含全部错误信息的异常；
   - `to_dict()` / `from_dict(data)`：模型与普通字典之间的双向转换；
   - `save()`：模拟写入数据库，调用前自动执行一次 `validate()`，校验不通过就拒绝保存；这里"写入数据库"可以只是把 `to_dict()` 的结果追加到一个模块级列表里；
4. 验证字段描述符本身在多个 `Model` 子类之间复用时，不同实例的数据互不干扰（呼应 4.2 节讲到的「可变类属性陷阱」——字段描述符是类属性，但它管理的数据必须落在每个实例自己的 `__dict__` 里）；
5. 写至少两个 `Model` 子类（例如 `User`、`Article`），分别构造若干实例，覆盖「校验失败」「默认值生效」「跨实例数据不串扰」三种场景并打印验证结果。
