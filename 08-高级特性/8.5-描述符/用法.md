# 8.5 描述符

在 4.2 节中我们学习了 `@property`：把方法包装成属性一样访问，支持读取时计算、写入时校验。但 `property` 本身只是语法糖，它底层依赖的是一套更通用的机制——**描述符协议（Descriptor Protocol）**。理解描述符，才能明白 `property`、实例方法、`staticmethod`、`classmethod` 为什么都能用「点号访问」的方式工作，也才能写出自己的校验属性、懒加载属性、甚至一个简化版的 ORM 字段系统。

## 1. 什么是描述符

只要一个类定义了 `__get__`、`__set__`、`__delete__` 中的任意一个，这个类的实例就是一个**描述符**。描述符本身通常不直接使用，而是作为**另一个类的类属性**存在，由 Python 的属性查找机制自动调用。

```python
class Descriptor:
    def __get__(self, obj, objtype=None):
        print("__get__ 被调用")
        return 42

class Demo:
    attr = Descriptor()   # attr 是类属性，也是一个描述符

d = Demo()
print(d.attr)   # 触发 Descriptor.__get__，输出 "__get__ 被调用" 再输出 42
```

关键点：`d.attr` 并没有直接返回 `Descriptor` 实例，而是自动调用了它的 `__get__` 方法。这一步转换发生在 `object.__getattribute__` 内部，对使用者是透明的。

## 2. 描述符协议的四个方法

| 方法 | 触发时机 | 典型签名 |
|---|---|---|
| `__get__(self, obj, objtype=None)` | 读取 `obj.attr` 或 `Class.attr` | 返回计算出的值 |
| `__set__(self, obj, value)` | 执行 `obj.attr = value` | 通常不返回值，负责保存 |
| `__delete__(self, obj)` | 执行 `del obj.attr` | 负责清理 |
| `__set_name__(self, owner, name)` | 描述符所在的类被创建时，由解释器自动调用一次 | 用于让描述符知道自己绑定的属性名 |

`__get__` 的 `obj` 参数在**通过类访问**（如 `Demo.attr`）时会是 `None`，`objtype` 则是所属类，这也是很多描述符要写 `if obj is None: return self` 分支的原因（`property` 内部就是这样处理的，使得 `Demo.attr` 能拿到 `property` 对象本身，而不是触发 getter）。

```python
class Verbose:
    def __get__(self, obj, objtype=None):
        if obj is None:
            return self           # 通过类访问，返回描述符自身
        return obj.__dict__.get("_value")

    def __set__(self, obj, value):
        obj.__dict__["_value"] = value

    def __set_name__(self, owner, name):
        self.name = name          # 记录属性名，供调试或报错使用
        print(f"{name} 绑定到 {owner.__name__}")

class Box:
    value = Verbose()   # 类创建时自动调用一次 __set_name__("Box", "value")

b = Box()
b.value = 10
print(b.value)          # 10
print(Box.value)        # <__main__.Verbose object ...>，因为 obj is None
```

`__set_name__` 是 Python 3.6 才引入的，解决了早期描述符必须手工传入属性名字符串的麻烦（如 `Verbose("value")`），现在描述符可以「自己知道自己叫什么」。

## 3. 数据描述符 vs 非数据描述符

描述符按定义的方法分两类：

| 类型 | 判定条件 | 优先级 |
|---|---|---|
| 数据描述符（data descriptor） | 定义了 `__set__` 或 `__delete__`（可以同时有 `__get__`） | 高于实例 `__dict__` |
| 非数据描述符（non-data descriptor） | 只定义了 `__get__` | 低于实例 `__dict__` |

```python
class DataDesc:
    def __get__(self, obj, objtype=None):
        return "data"
    def __set__(self, obj, value):
        pass

class NonDataDesc:
    def __get__(self, obj, objtype=None):
        return "non-data"

class Sample:
    d = DataDesc()
    n = NonDataDesc()

s = Sample()
s.__dict__["d"] = "instance-d"   # 直接写实例字典，绕开 __set__
s.__dict__["n"] = "instance-n"

print(s.d)   # "data"       —— 数据描述符优先于实例字典
print(s.n)   # "instance-n" —— 实例字典优先于非数据描述符
```

这个区分不是文字游戏，而是直接决定了下一节的查找算法结果。

## 4. 属性查找的真实算法

`obj.attr` 的查找由 `type.__getattribute__`（准确地说是 `object.__getattribute__`）实现，大致等价于下面这个过程（伪代码，简化自 CPython 实现）：

```python
def object_getattribute(obj, name):
    cls = type(obj)
    meta_attr = _lookup_in_mro(cls, name)   # 按 MRO 在类及父类的 __dict__ 中查找

    if meta_attr is not None and _is_data_descriptor(meta_attr):
        return meta_attr.__get__(obj, cls)          # ① 数据描述符最优先

    if name in obj.__dict__:
        return obj.__dict__[name]                    # ② 实例字典其次

    if meta_attr is not None:
        if _is_non_data_descriptor(meta_attr):
            return meta_attr.__get__(obj, cls)        # ③ 非数据描述符
        return meta_attr                              # ④ 普通类属性

    raise AttributeError(name)                        # ⑤ 都找不到
```

`_lookup_in_mro` 会沿着 `type(obj).__mro__` 依次在每个类的 `__dict__` 里找同名属性，找到第一个即停止——这就是为什么子类能覆盖父类的描述符或普通属性。

完整优先级顺序：

1. **数据描述符**（类或父类中定义了 `__set__`/`__delete__`）
2. **实例 `__dict__`**
3. **非数据描述符**（类或父类中只定义了 `__get__`，含普通函数）
4. **类 `__dict__`（含父类）中的普通属性**
5. 都没有则触发 `__getattr__`（如果定义了），否则 `AttributeError`

```python
class Base:
    class_attr = "base class attr"

class Child(Base):
    pass

c = Child()
print(c.class_attr)      # "base class attr"，MRO 沿 Child -> Base 查找
c.class_attr = "instance attr"
print(c.class_attr)      # "instance attr"，普通类属性没有 __set__，实例字典可以遮蔽它
```

这也解释了 4.2 节提到的「实例属性优先于类属性」，其本质是「实例字典优先于非数据描述符/普通属性」，而 `@property` 之所以能拦截赋值（不被实例字典覆盖），正是因为它是数据描述符。

## 5. `property` 就是一个数据描述符

`@property` 不是关键字，而是一个内置类，其行为完全可以用纯 Python 复刻：

```python
class MyProperty:
    def __init__(self, fget=None, fset=None, fdel=None, doc=None):
        self.fget = fget
        self.fset = fset
        self.fdel = fdel
        self.__doc__ = doc or (fget.__doc__ if fget else None)

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        if self.fget is None:
            raise AttributeError("属性不可读")
        return self.fget(obj)

    def __set__(self, obj, value):
        if self.fset is None:
            raise AttributeError("属性不可写")
        self.fset(obj, value)

    def __delete__(self, obj):
        if self.fdel is None:
            raise AttributeError("属性不可删")
        self.fdel(obj)

    def setter(self, fset):
        return MyProperty(self.fget, fset, self.fdel, self.__doc__)

    def deleter(self, fdel):
        return MyProperty(self.fget, self.fset, fdel, self.__doc__)


class Product:
    def __init__(self, price):
        self._price = price

    @MyProperty
    def price(self):
        return self._price

    @price.setter
    def price(self, value):
        if value < 0:
            raise ValueError("价格不能为负")
        self._price = value


p = Product(10)
print(p.price)     # 10
p.price = 20
print(p.price)      # 20
```

因为 `MyProperty` 定义了 `__set__`，它是数据描述符——这就是为什么 `p.price = -1` 会执行校验逻辑而不是简单地往 `p.__dict__` 里塞一个 `price` 键。

## 6. 函数是非数据描述符：绑定方法的秘密

普通函数对象本身就实现了 `__get__`（但没有 `__set__`），所以它也是一个描述符，只不过是非数据描述符。这正是 `obj.method()` 能自动传入 `self` 的原因：

```python
def greet(self):
    return f"hello, {self.name}"

class Person:
    name = "Alice"

p = Person()
bound = greet.__get__(p, Person)   # 函数对象天生具备 __get__
print(bound)             # <bound method greet of <...Person object...>>
print(bound())            # "hello, Alice"，self 已被自动绑定
```

真实场景中 `p.greet()` 的执行过程是：`type(p).__mro__` 中找到函数对象 `greet` → 它是非数据描述符 → 调用 `greet.__get__(p, Person)` 生成一个绑定方法（`bound method`）→ 再对绑定方法执行 `()` 调用。由于函数是非数据描述符，实例可以用同名的实例属性遮蔽它（例如 `p.greet = lambda: "hi"` 之后 `p.greet()` 会调用这个新函数，而不是类方法）。

## 7. `staticmethod` 与 `classmethod` 也是描述符

```python
class MyStaticMethod:
    def __init__(self, func):
        self.func = func

    def __get__(self, obj, objtype=None):
        return self.func          # 不绑定任何对象，原样返回

class MyClassMethod:
    def __init__(self, func):
        self.func = func

    def __get__(self, obj, objtype=None):
        cls = objtype if objtype is not None else type(obj)
        def bound(*args, **kwargs):
            return self.func(cls, *args, **kwargs)
        return bound


class Util:
    @MyStaticMethod
    def add(a, b):
        return a + b

    @MyClassMethod
    def create(cls):
        return cls()

print(Util.add(1, 2))     # 3，没有隐式的 self/cls
print(Util().add(1, 2))   # 3，实例调用也一样
print(Util.create())      # <__main__.Util object ...>，cls 自动绑定为 Util
```

内置 `staticmethod`/`classmethod` 的实现思路与此完全一致：`staticmethod.__get__` 直接返回原函数，`classmethod.__get__` 返回一个把类作为第一个参数预绑定的可调用对象。

## 8. 实战一：类型校验描述符

利用 `__set_name__` 可以写出通用的「自描述」校验描述符，不需要每个字段单独传属性名：

```python
class Typed:
    def __init__(self, expected_type, default=None):
        self.expected_type = expected_type
        self.default = default

    def __set_name__(self, owner, name):
        self.name = "_" + name           # 实际存储用的私有名

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return getattr(obj, self.name, self.default)

    def __set__(self, obj, value):
        if not isinstance(value, self.expected_type):
            raise TypeError(f"{self.name[1:]} 必须是 {self.expected_type.__name__} 类型")
        setattr(obj, self.name, value)


class Employee:
    name = Typed(str)
    age = Typed(int, default=0)

    def __init__(self, name, age):
        self.name = name
        self.age = age


e = Employee("Alice", 30)
print(e.name, e.age)     # Alice 30
e.age = 31
try:
    e.age = "old"
except TypeError as err:
    print(err)            # age 必须是 int 类型
```

同一个 `Typed` 描述符类可以复用到任意字段，每个字段各自维护独立的存储位置（`_name`、`_age`），互不干扰。

## 9. 实战二：惰性求值 / 缓存属性

非数据描述符可以用来实现「第一次访问才计算，之后直接命中实例字典」的懒加载属性——因为实例字典优先于非数据描述符：

```python
class LazyProperty:
    def __init__(self, func):
        self.func = func
        self.__doc__ = func.__doc__

    def __set_name__(self, owner, name):
        self.name = name

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        value = self.func(obj)
        obj.__dict__[self.name] = value   # 写入实例字典，覆盖后续查找
        return value


class Report:
    def __init__(self, rows):
        self.rows = rows

    @LazyProperty
    def total(self):
        print("正在计算 total ...")
        return sum(self.rows)


r = Report([1, 2, 3, 4])
print(r.total)   # 打印 "正在计算 total ..." 然后 10
print(r.total)   # 直接 10，不再打印计算过程
```

关键在于 `LazyProperty` 只有 `__get__`，属于非数据描述符；一旦把结果塞进 `obj.__dict__`，之后的属性查找按第 4 节的算法会优先命中实例字典，描述符不会再被触发。这与 `functools.cached_property` 的实现思路一致。

## 10. 实战三：迷你 ORM 字段系统

结合 `Typed` 的思路，可以做一个类似 ORM 模型字段的小系统，用元类之外的普通方式实现字段收集与校验：

```python
class Field:
    def __init__(self, type_, required=True):
        self.type_ = type_
        self.required = required

    def __set_name__(self, owner, name):
        self.name = name

    def __get__(self, obj, objtype=None):
        if obj is None:
            return self
        return obj.__dict__.get(self.name)

    def __set__(self, obj, value):
        if value is None and self.required:
            raise ValueError(f"字段 {self.name} 是必填的")
        if value is not None and not isinstance(value, self.type_):
            raise TypeError(f"字段 {self.name} 期望 {self.type_.__name__}")
        obj.__dict__[self.name] = value


class Model:
    def __init__(self, **kwargs):
        # 按类上声明的 Field 顺序赋值，未传的字段用 None 触发必填校验
        for name, field in self.__class__.__dict__.items():
            if isinstance(field, Field):
                setattr(self, name, kwargs.get(name))

    def to_dict(self):
        return {
            name: getattr(self, name)
            for name, field in self.__class__.__dict__.items()
            if isinstance(field, Field)
        }


class User(Model):
    name = Field(str)
    age = Field(int, required=False)


u = User(name="Alice", age=30)
print(u.to_dict())   # {'name': 'Alice', 'age': 30}

try:
    User(age=20)      # 缺少必填的 name
except ValueError as err:
    print(err)         # 字段 name 是必填的
```

这里的 `Field` 与真实 ORM（如 Django 的 `Field`、SQLAlchemy 的 `Column`）思路一致：字段本身是数据描述符，负责校验和存储；模型类只是描述符的容器，真正的数据仍然保存在每个实例的 `__dict__` 里（键名与描述符同名，只是通过描述符的 `__set__`/`__get__` 加上了一层校验）。

## 11. 本节小结

1. 只要类实现了 `__get__`、`__set__`、`__delete__` 之一，其实例就是描述符，作为另一个类的类属性使用时会被自动触发；
2. `__set_name__(self, owner, name)` 在类创建时自动调用一次，让描述符知道自己绑定的属性名，避免手写字符串；
3. 定义了 `__set__` 或 `__delete__` 的是数据描述符，优先级高于实例 `__dict__`；只定义 `__get__` 的是非数据描述符，优先级低于实例 `__dict__`；
4. 完整查找顺序：数据描述符 → 实例 `__dict__` → 非数据描述符/普通类属性 → `__getattr__` → `AttributeError`；
5. `@property` 本质是一个数据描述符类，`fget`/`fset`/`fdel` 分别对应 `__get__`/`__set__`/`__delete__` 的实现；
6. 函数对象自带 `__get__`，是非数据描述符，这正是 `obj.method()` 能自动绑定 `self` 生成 bound method 的底层机制；
7. `staticmethod` 通过 `__get__` 直接返回原函数，`classmethod` 通过 `__get__` 返回预绑定了类的可调用对象，二者都是描述符；
8. 描述符的实用场景包括：类型校验属性、惰性求值/缓存属性（非数据描述符 + 写入实例字典）、类似 ORM 的字段系统（数据描述符统一处理存储和校验）；
9. 编写描述符时注意 `obj is None` 分支（通过类访问）、存储键要避免与描述符自身重名（否则会无限递归），并优先复用 `__set_name__` 而不是硬编码属性名。
