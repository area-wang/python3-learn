# 8.8 异步编程

8.7 已经介绍了 `async def`/`await` 语法和协程对象本身。但仅有协程语法还不足以写出实际的并发程序——真正的异步程序需要能够「同时调度多个协程」「获取它们的结果或异常」「设置超时和取消」「在并发访问共享资源时加锁或限流」。这些能力由 `asyncio` 提供的一整套工具组成，是本节的重点。

## 1. 从协程到并发任务：`asyncio.create_task()`

单纯 `await` 一个协程是**顺序**执行，不会带来并发。要让多个协程真正同时运行，需要用 `asyncio.create_task()` 把协程包装成 `Task`，并提交给事件循环调度：

```python
import asyncio
import time


async def fetch(name, delay):
    print(f"{name} 开始")
    await asyncio.sleep(delay)
    print(f"{name} 完成")
    return f"{name} 的结果"


async def main():
    start = time.perf_counter()

    # 直接 await：顺序执行，总耗时约为两者之和
    # await fetch("A", 1)
    # await fetch("B", 1)

    # create_task：提交后立即返回，两个任务并发运行
    task_a = asyncio.create_task(fetch("A", 1))
    task_b = asyncio.create_task(fetch("B", 1))

    result_a = await task_a
    result_b = await task_b
    print(result_a, result_b)
    print(f"耗时：{time.perf_counter() - start:.2f}s")  # 约 1s，而非 2s


asyncio.run(main())
```

`create_task()` 调用后任务立即被**调度**（下一次事件循环轮转时开始执行），不需要等到 `await` 才启动。这是它与直接 `await` 协程的本质区别。

## 2. `Task` 对象与生命周期

`Task` 是对协程的一层封装，代表「已提交给事件循环的一次执行」。它有以下几种状态和常用方法：

| 方法/属性 | 说明 |
|---|---|
| `done()` | 任务是否已结束（正常完成、抛异常或被取消） |
| `result()` | 获取返回值；未完成时抛 `InvalidStateError`；异常结束时重新抛出该异常 |
| `exception()` | 获取任务内抛出的异常对象；未完成时抛 `InvalidStateError`；正常完成返回 `None` |
| `cancel()` | 请求取消任务 |
| `cancelled()` | 任务是否已被取消 |
| `add_done_callback(fn)` | 任务结束时调用回调函数，参数为该 `Task` 本身 |
| `get_name()` / `set_name()` | 获取/设置任务名称，便于调试 |

```python
import asyncio


async def risky():
    await asyncio.sleep(0.5)
    raise ValueError("出错了")


async def main():
    task = asyncio.create_task(risky(), name="risky-task")

    await asyncio.sleep(0.1)
    print(task.done())  # False，还未执行完

    try:
        await task
    except ValueError as e:
        print("捕获异常：", e)

    print(task.done())        # True
    print(task.exception())   # ValueError('出错了')


asyncio.run(main())
```

如果一个 `Task` 抛出了异常但从未被 `await` 或检查过 `exception()`，Python 会在该 `Task` 被垃圾回收时打印一条 `Task exception was never retrieved` 警告——这是异步代码里异常被「吞掉」的常见信号，务必留意。

## 3. `Future`：`Task` 的父类

`Future` 是比 `Task`更底层的对象，表示「一个尚未完成、将来会有结果的值」。`Task` 就是一个内部驱动协程执行的 `Future` 子类：

```python
isinstance(asyncio.create_task(some_coro()), asyncio.Future)  # True
```

普通业务代码几乎不需要手动创建 `Future`，但理解它有助于弄清 `Task` 的原理，也是对接回调式 API（如某些网络库）时的常用桥梁：

```python
import asyncio


async def main():
    loop = asyncio.get_running_loop()
    fut = loop.create_future()

    def set_result_later():
        fut.set_result("手动设置的结果")

    loop.call_later(1, set_result_later)  # 1 秒后回调
    result = await fut  # 在 set_result 被调用前一直挂起
    print(result)


asyncio.run(main())
```

`Future` 的核心方法：`set_result(value)` 设置结果、`set_exception(exc)` 设置异常、`await future` 等价于「阻塞直到结果或异常被设置」。`Task` 之所以能被 `await`，正是因为它实现了同样的 `Future` 接口，只是结果由协程的执行驱动，而不是手动设置。

## 4. `asyncio.gather()`：并发运行并收集结果

`gather()` 是最常用的「批量并发」工具：传入多个协程或 `Task`，等待全部完成，按传入顺序返回结果列表。

```python
import asyncio


async def fetch(name, delay):
    await asyncio.sleep(delay)
    return f"{name}:{delay}"


async def main():
    results = await asyncio.gather(
        fetch("A", 1),
        fetch("B", 2),
        fetch("C", 0.5),
    )
    print(results)  # ['A:1', 'B:2', 'C:0.5']，顺序与传入一致，耗时约 2s（最长的那个）


asyncio.run(main())
```

默认情况下，只要有一个协程抛出异常，`gather()` 会立即把异常向上抛出（其他未完成的任务不会被自动取消，仍在后台运行）。传入 `return_exceptions=True` 可以让异常也作为结果收集，不中断整体流程：

```python
async def main():
    results = await asyncio.gather(
        fetch("A", 1),
        boom(),                 # 假设内部抛出 ValueError
        fetch("C", 0.5),
        return_exceptions=True,
    )
    for r in results:
        if isinstance(r, Exception):
            print("失败：", r)
        else:
            print("成功：", r)
```

## 5. `asyncio.wait()` 与 `gather()` 的选择

`wait()` 提供更细粒度的控制：它只接受 `Task`/`Future`（协程需先用 `create_task()` 包装），返回 `(done, pending)` 两个集合，且支持 `return_when` 控制何时返回。

| 对比项 | `gather()` | `wait()` |
|---|---|---|
| 入参 | 协程或 `Task` 均可 | 必须是 `Task`/`Future` |
| 返回值 | 结果列表（保持传入顺序） | `(done, pending)` 两个集合（无序） |
| 异常传播 | 默认立即抛出 | 不抛出，需自行检查每个 `Task.exception()` |
| 部分完成 | 不直接支持 | `return_when=FIRST_COMPLETED` 等可控制提前返回 |

```python
import asyncio


async def fetch(name, delay):
    await asyncio.sleep(delay)
    return name


async def main():
    tasks = [
        asyncio.create_task(fetch("A", 1)),
        asyncio.create_task(fetch("B", 3)),
    ]
    done, pending = await asyncio.wait(tasks, timeout=2)
    print("已完成：", [t.result() for t in done])
    print("未完成：", len(pending))
    for t in pending:
        t.cancel()  # 不再需要的任务应显式取消，避免它继续占用资源


asyncio.run(main())
```

简单场景优先用 `gather()`；需要「谁先完成就先处理」「部分超时后仍保留其余任务继续跑」这类精细控制时用 `wait()`。

## 6. 超时控制：`wait_for` 与 `timeout`

`asyncio.wait_for(coro, timeout)` 给单个协程/任务设置超时，超时后自动取消并抛出 `asyncio.TimeoutError`（Python 3.11 起是 `TimeoutError` 的别名）：

```python
import asyncio


async def slow_task():
    await asyncio.sleep(5)
    return "完成"


async def main():
    try:
        result = await asyncio.wait_for(slow_task(), timeout=1)
    except asyncio.TimeoutError:
        print("超时了，任务已被自动取消")


asyncio.run(main())
```

Python 3.11 引入了 `asyncio.timeout()` 异步上下文管理器，可以给**一段代码块**（而不仅是单个协程）设置统一超时，写法更贴近同步代码里的 `with`：

```python
import asyncio


async def main():
    try:
        async with asyncio.timeout(1):
            await asyncio.sleep(0.5)
            await asyncio.sleep(0.5)
            await asyncio.sleep(0.5)  # 累计超过 1 秒，整个代码块被取消
    except TimeoutError:
        print("代码块整体超时")

# 需要 Python 3.11+；3.11 以前只能用 wait_for 逐个包装，或组合 wait() + timeout 参数
```

## 7. 取消任务与 `CancelledError`

调用 `task.cancel()` 会向任务当前挂起的 `await` 点注入 `asyncio.CancelledError`。协程可以捕获它做清理，但**通常应该重新抛出**，否则任务会被视为「正常完成」而不是「已取消」：

```python
import asyncio


async def worker():
    try:
        while True:
            print("工作中...")
            await asyncio.sleep(0.5)
    except asyncio.CancelledError:
        print("收到取消信号，清理资源")
        raise  # 强烈建议重新抛出，让取消状态正确传播


async def main():
    task = asyncio.create_task(worker())
    await asyncio.sleep(1.2)
    task.cancel()
    try:
        await task
    except asyncio.CancelledError:
        print("确认任务已取消")


asyncio.run(main())
```

要点：`cancel()` 只是**请求**取消，真正的取消发生在协程下一次执行到 `await` 点时；如果协程在两次 `await` 之间的同步代码里跑了很久，取消会被延迟。

## 8. 并发控制原语：`Lock` 与 `Semaphore`

多个协程并发访问共享资源（如同一个文件、同一个计数器）时，需要与线程编程类似的同步原语。`asyncio.Lock` 保证同一时刻只有一个协程进入临界区：

```python
import asyncio

counter = 0
lock = asyncio.Lock()


async def increment():
    global counter
    async with lock:
        current = counter
        await asyncio.sleep(0)  # 模拟让出控制权
        counter = current + 1


async def main():
    await asyncio.gather(*(increment() for _ in range(100)))
    print(counter)  # 稳定输出 100，没有 Lock 会因为并发读改写而错乱


asyncio.run(main())
```

`asyncio.Semaphore(n)` 限制同时进入某段代码的协程数量，常用于限制并发请求数（如爬虫限流）：

```python
import asyncio

semaphore = asyncio.Semaphore(3)  # 最多 3 个并发


async def download(name):
    async with semaphore:
        print(f"{name} 开始下载")
        await asyncio.sleep(1)
        print(f"{name} 下载完成")


async def main():
    await asyncio.gather(*(download(f"文件{i}") for i in range(10)))


asyncio.run(main())
```

## 9. `Event`：事件通知

`asyncio.Event` 用于「一个或多个协程等待某个条件被触发」，类似线程里的 `threading.Event`：

```python
import asyncio


async def waiter(event, name):
    print(f"{name} 等待事件")
    await event.wait()
    print(f"{name} 收到事件，继续执行")


async def setter(event):
    await asyncio.sleep(1)
    print("设置事件")
    event.set()


async def main():
    event = asyncio.Event()
    await asyncio.gather(
        waiter(event, "A"),
        waiter(event, "B"),
        setter(event),
    )


asyncio.run(main())
```

`event.set()` 之后所有正在 `wait()` 的协程都会被唤醒；`event.clear()` 可以重置状态供下一轮使用。

## 10. `Queue`：生产者/消费者模式

`asyncio.Queue` 是协程间安全传递数据的先进先出队列，天然适合「生产者—消费者」结构：

```python
import asyncio


async def producer(queue, n):
    for i in range(n):
        await asyncio.sleep(0.1)
        await queue.put(i)
        print(f"生产：{i}")
    await queue.put(None)  # 用 None 作为结束哨兵


async def consumer(queue):
    while True:
        item = await queue.get()
        if item is None:
            queue.task_done()
            break
        print(f"消费：{item}")
        queue.task_done()


async def main():
    queue = asyncio.Queue(maxsize=5)  # 队列满时 put() 会挂起，形成背压
    await asyncio.gather(producer(queue, 5), consumer(queue))


asyncio.run(main())
```

`maxsize` 提供了简单的背压（backpressure）机制：生产过快时 `put()` 会阻塞协程，避免内存无限堆积。`join()` + `task_done()` 组合可以用来等待队列中所有任务被处理完毕。

## 11. 异步上下文管理器

普通 `with` 对应 `__enter__`/`__exit__`，异步版本 `async with` 对应 `__aenter__`/`__aexit__`，二者都是协程方法，可以在进入/退出时执行 `await` 操作（如异步获取连接、异步释放锁）：

```python
import asyncio


class AsyncResource:
    async def __aenter__(self):
        print("异步获取资源")
        await asyncio.sleep(0.2)
        return self

    async def __aexit__(self, exc_type, exc, tb):
        print("异步释放资源")
        await asyncio.sleep(0.2)
        return False  # 不吞掉异常


async def main():
    async with AsyncResource() as res:
        print("使用资源", res)


asyncio.run(main())
```

`asyncio.Lock`、`asyncio.Semaphore` 本身就实现了这个协议，这也是它们能配合 `async with` 使用的原因。`contextlib.asynccontextmanager` 装饰器可以用生成器函数写出等价效果，用法与同步版 `@contextmanager` 一致（见 8.4）。

## 12. 异步迭代器与异步生成器

`async for` 对应 `__aiter__`/`__anext__` 协议：`__aiter__` 返回自身（或另一个异步迭代器），`__anext__` 是一个协程，遍历结束时抛出 `StopAsyncIteration`。

```python
import asyncio


class Countdown:
    def __init__(self, start):
        self.current = start

    def __aiter__(self):
        return self

    async def __anext__(self):
        if self.current <= 0:
            raise StopAsyncIteration
        await asyncio.sleep(0.3)
        self.current -= 1
        return self.current + 1


async def main():
    async for n in Countdown(3):
        print(n)


asyncio.run(main())
```

更方便的写法是**异步生成器**：在 `async def` 函数体内使用 `yield`，Python 自动为其生成 `__aiter__`/`__anext__`：

```python
import asyncio


async def countdown(start):
    while start > 0:
        await asyncio.sleep(0.3)
        yield start
        start -= 1


async def main():
    async for n in countdown(3):
        print(n)


asyncio.run(main())
```

异步生成器特别适合「边等待 IO 边产出数据」的场景，例如逐条读取一个异步数据库游标、或分页拉取远程接口。

## 13. 常见陷阱

- **在协程里误调用阻塞的同步函数**：如 `time.sleep()`、同步的 `requests.get()`、未加 `await` 的磁盘大文件读写。这类调用会独占事件循环所在线程，导致所有其他协程一起卡住，而不仅仅是当前任务变慢。应使用异步版本（`asyncio.sleep()`、`aiohttp` 等），或用下条方法丢给线程池。
- **忘记 `await` 协程**：直接调用 `some_coro()` 只会创建一个协程对象，不会执行其中的代码，还会触发 `RuntimeWarning: coroutine '...' was never awaited`。看到这个警告基本可以断定漏写了 `await` 或 `create_task()`。
- **CPU 密集型任务拖慢事件循环**：`asyncio` 的并发依赖协程在 `await` 处主动让出控制权，纯 CPU 计算（如大循环、复杂加密运算）没有让出点，会同样阻塞整个事件循环。逃生舱是把这类任务丢到线程池或进程池：

```python
import asyncio


def cpu_heavy(n):
    return sum(i * i for i in range(n))


async def main():
    loop = asyncio.get_running_loop()
    # 丢给默认线程池执行，不阻塞事件循环
    result = await loop.run_in_executor(None, cpu_heavy, 10_000_000)
    print(result)

    # Python 3.9+ 的简化写法，效果等价于 run_in_executor(None, ...)
    result2 = await asyncio.to_thread(cpu_heavy, 10_000_000)
    print(result2)


asyncio.run(main())
```

  注意 `run_in_executor`/`to_thread` 用的是**线程池**，只能缓解阻塞型 IO 或释放了 GIL 的计算；真正 CPU 密集且受 GIL 限制的任务，仍需 `concurrent.futures.ProcessPoolExecutor` 或多进程方案才能利用多核。

## 14. 本节小结

1. `asyncio.create_task()` 把协程包装成 `Task` 并立即提交调度，是实现并发（而非顺序 `await`）的关键一步；
2. `Task` 是 `Future` 的子类，`result()`/`exception()` 用于取回结果或异常，未被检查的任务异常会在垃圾回收时发出警告；
3. `gather()` 适合「等待一批协程全部完成并按序取回结果」，`wait()` 适合需要 `(done, pending)` 精细控制或提前返回的场景；
4. `wait_for()` 给单个协程加超时，`asyncio.timeout()`（3.11+）可以给一段代码块整体加超时；`cancel()` 只是发出请求，真正取消发生在协程下一次 `await` 时，且应重新抛出 `CancelledError`；
5. `Lock`/`Semaphore`/`Event`/`Queue` 是协程间同步与通信的标准工具，分别对应互斥、限流、事件通知、生产者-消费者场景；
6. 异步上下文管理器（`__aenter__`/`__aexit__`）和异步迭代器/生成器（`__aiter__`/`__anext__`，或直接在 `async def` 中 `yield`）让资源管理和惰性数据流在异步代码里保持同样简洁的写法；
7. 最容易踩的坑是在协程里调用了阻塞的同步函数——这会拖垮整个事件循环，而不只是当前协程；忘记 `await` 会导致协程根本不执行；CPU 密集型任务应通过 `run_in_executor`/`asyncio.to_thread` 移出事件循环。
