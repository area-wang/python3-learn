# 8.8 异步编程练习题

## 一、概念题

1. 直接 `await` 一个协程和用 `asyncio.create_task()` 包装后再 `await` 有什么本质区别？为什么后者才能实现并发？
2. `Task` 与 `Future` 是什么关系？`result()` 和 `exception()` 在任务未完成、正常完成、异常结束三种情况下分别有什么行为？
3. `asyncio.gather()` 默认遇到异常会怎样处理？`return_exceptions=True` 改变了什么？
4. `asyncio.wait()` 和 `gather()` 的返回值有什么区别？什么场景下必须用 `wait()` 而不是 `gather()`？
5. `task.cancel()` 之后协程是立即停止还是延后停止？为什么协程捕获 `CancelledError` 后通常要重新抛出？
6. `asyncio.Lock`、`asyncio.Semaphore`、`asyncio.Event`、`asyncio.Queue` 各自解决什么问题？请各举一个恰当的使用场景。
7. 异步上下文管理器需要实现哪两个方法？它们与同步版本 `__enter__`/`__exit__` 相比多了什么能力？
8. 异步生成器（`async def` 函数体内使用 `yield`）与实现 `__aiter__`/`__anext__` 的类相比，各有什么优劣？
9. 为什么在协程里调用同步阻塞函数（如 `time.sleep()`）会让"所有"并发任务一起变慢，而不只是当前协程？
10. `run_in_executor`/`asyncio.to_thread` 分别适合处理哪些类型的任务？它们能否解决 CPU 密集型且受 GIL 限制的性能问题？为什么？

## 二、判断代码输出

### 1. 顺序 await 还是并发

```python
import asyncio
import time


async def task(name, delay):
    await asyncio.sleep(delay)
    return name


async def main():
    start = time.perf_counter()
    a = await task("A", 1)
    b = await task("B", 1)
    print(a, b, f"{time.perf_counter() - start:.1f}")


asyncio.run(main())
```

写出大致耗时，并说明如果把这两行改成先 `create_task()` 再统一 `await`，耗时会如何变化。

### 2. gather 的异常传播

```python
import asyncio


async def ok():
    await asyncio.sleep(0.1)
    return "ok"


async def bad():
    await asyncio.sleep(0.05)
    raise ValueError("坏了")


async def main():
    try:
        results = await asyncio.gather(ok(), bad())
        print(results)
    except ValueError as e:
        print("捕获：", e)


asyncio.run(main())
```

写出输出。如果把 `gather` 换成 `gather(ok(), bad(), return_exceptions=True)`，输出会变成什么？

### 3. 取消的时机

```python
import asyncio


async def worker():
    try:
        for i in range(5):
            print("步骤", i)
            await asyncio.sleep(0.3)
    except asyncio.CancelledError:
        print("被取消")
        raise


async def main():
    task = asyncio.create_task(worker())
    await asyncio.sleep(0.7)
    task.cancel()
    try:
        await task
    except asyncio.CancelledError:
        print("main 确认取消")


asyncio.run(main())
```

写出大致的打印顺序和步骤编号，解释为什么 `task.cancel()` 之后不是立刻停止打印。

### 4. Semaphore 限流

```python
import asyncio


async def job(sem, name):
    async with sem:
        print(f"{name} 进入")
        await asyncio.sleep(0.5)
        print(f"{name} 离开")


async def main():
    sem = asyncio.Semaphore(2)
    await asyncio.gather(*(job(sem, f"job{i}") for i in range(4)))


asyncio.run(main())
```

分析同一时刻最多有几个 `job` 处于"进入"和"离开"之间，并说明总耗时大致是多少个 0.5 秒。

## 三、编程题

### 1. 并发抓取器

编写 `fetch_all(urls, concurrency=5)`（用 `asyncio.sleep(random.uniform(0.1, 0.5))` 模拟网络请求，不需要真实联网）：

- 使用 `asyncio.Semaphore` 把同时"请求"的数量限制为 `concurrency`；
- 使用 `asyncio.gather(..., return_exceptions=True)` 收集所有结果，某个地址失败不影响其余；
- 返回一个字典 `{url: 结果或异常对象}`；
- 记录并打印整体耗时。

### 2. 带超时的任务执行器

实现 `run_with_timeout(coro, timeout, default=None)`：

- 使用 `asyncio.wait_for` 执行传入的协程；
- 超时后返回 `default`，并打印一条超时提示，不让异常向外传播；
- 正常完成则返回协程结果；
- 编写至少一个会超时和一个不会超时的测试协程验证行为。

### 3. 生产者/消费者流水线

用 `asyncio.Queue` 实现一个两阶段流水线：

- 一个生产者协程持续产出 0~99 的整数（模拟到达速率不均匀，用随机 `sleep`）；
- 两个消费者协程并发地从队列取出数字并"处理"（打印 `消费者X 处理了 n`）；
- 使用哨兵值或 `queue.join()` 保证所有数字都被处理后程序才退出；
- 统计每个消费者各处理了多少个数字。

### 4. 异步限速迭代器

实现一个类 `RateLimitedRange`，支持 `async for`：

- 构造参数 `(start, stop, interval)`，每隔 `interval` 秒才产出下一个数字；
- 通过实现 `__aiter__`/`__anext__` 完成（不允许直接用 `async def` 生成器函数糊弄过去）；
- 遍历到 `stop` 时正确抛出 `StopAsyncIteration`；
- 额外实现一个基于 `async def` + `yield` 的等价版本，对比两种写法的代码量。

### 5. 异步资源池

实现异步上下文管理器 `AsyncConnectionPool`：

- 构造时传入池大小 `size`；
- `async with pool.acquire() as conn:` 获取一个"连接"（可以只是一个整数 ID），池满时协程应挂起等待，而不是抛异常；
- 退出 `with` 块时自动归还连接到池中；
- 提示：内部可以用 `asyncio.Queue` 存放可用连接，用它天然的 `get`/`put` 实现等待与归还。

## 四、综合实践：并发任务调度中心

设计一个模拟的"任务调度中心"，要求：

1. 维护一个待执行任务队列（`asyncio.Queue`），任务是形如 `(task_id, duration, fail_rate)` 的元组，`duration` 模拟执行耗时，`fail_rate` 是随机失败概率；
2. 启动固定数量（如 4 个）的"工作协程"并发地从队列取任务执行，同时用 `asyncio.Semaphore` 额外限制"同时占用外部资源"的任务数不超过 2；
3. 每个任务执行时用 `asyncio.wait_for` 施加超时，超时或失败的任务要记录到一个失败列表，成功的记录到成功列表，两个列表的写入都要用 `asyncio.Lock` 保护；
4. 提供一个"取消开关"：调度中心运行 3 秒后，如果还有未完成任务，主动 `cancel()` 所有工作协程，并正确处理它们抛出的 `CancelledError`，保证清理逻辑（如打印"工作协程 N 已停止"）总会执行；
5. 全部任务结束或被取消后，打印成功数量、失败数量、被取消时仍在队列中的任务数量；
6. 思考：如果某个工作协程在 `except asyncio.CancelledError` 块里又 `await` 了一个耗时协程，会发生什么？应该如何正确处理"取消期间的清理"？
