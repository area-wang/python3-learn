# 8.6 元类

在 Python 中「一切皆对象」，类本身也是对象——而对象都由某个类创建，创建类的类就叫**元类（metaclass）**。理解元类的关键是想清楚一件事：`class` 语句本质上只是一段语法糖，它在背后调用了某个「创建类的函数」，这个函数默认是内置的 `type`。掌握元类能让你看懂 ORM、序列化框架、插件系统等库的底层实现，但也要清楚：绝大多数业务代码用不到自定义元类，本节最后会专门讨论何时应该收手。

## 1. `type` 的两幅面孔

`type` 既是「查看对象类型」的内置函数，又是创建所有类的默认元类，这是理解元类的第一个断点。

```python
print(type(42))          # <class 'int'>
print(type("hi"))        # <class 'str'>
print(type([]))          # <class 'list'>

class Dog:
    pass

d = Dog()
print(type(d))           # <class '__main__.Dog'>   实例的类型是它的类
print(type(Dog))         # <class 'type'>            类的类型是 type
print(type(type))        # <class 'type'>            type 的类型是它自己
```

每个对象都有类型：`d` 的类型是 `Dog`，而 `Dog` 的类型是 `type`。一路追问「这是什么类型」，最终都会停在 `type` 自身——它是自己的元类，是整个类型体系的终点。

```python
print(isinstance(d, Dog))      # True
print(isinstance(Dog, type))   # True，Dog 本身就是 type 的一个实例
print(issubclass(Dog, object)) # True，所有类最终继承自 object
```

## 2. 用 `type(name, bases, namespace)` 动态创建类

`type` 除了单参数用法（查看类型），还有三参数用法：直接创建一个新类，这正是 `class` 语句的运行时等价形式。

```python
def greet(self):
    return f"hello, I'm {self.name}"

Person = type(
    "Person",                      # 类名
    (object,),                     # 基类元组
    {                              # 命名空间（类体内定义的属性/方法）
        "species": "human",
        "greet": greet,
        "__init__": lambda self, name: setattr(self, "name", name),
    },
)

p = Person("Alice")
print(p.greet())        # hello, I'm Alice
print(p.species)        # human
print(type(p))          # <class '__main__.Person'>
print(type(Person))     # <class 'type'>
```

三个参数分别对应 `class` 语句的三个组成部分：

| `type()` 参数 | 对应 `class` 语句 |
|---|---|
| `name` | `class Person:` 中的类名 `Person` |
| `bases` | 括号里的基类列表 `(Base1, Base2)` |
| `namespace` | 缩进类体中定义的所有属性和方法，打包成一个字典 |

这说明 `class Person(object): ...` 与上面 `type(...)` 调用在语义上是等价的——动态生成类在写框架时很常见，比如根据配置批量生成模型类。

## 3. `class` 语句执行时到底发生了什么

写下 `class Foo(Base, metaclass=Meta): ...` 时，Python 解释器按以下顺序动作：

1. **确定元类**：如果显式指定了 `metaclass`，用它；否则取第一个基类的元类；都没有则用内置 `type`。
2. **调用 `metaclass.__prepare__(name, bases, **kwds)`**：返回一个映射对象（默认是普通 `dict`），作为类体执行期间收集属性用的命名空间。自定义 `__prepare__` 可以返回有序字典之外的特殊映射，从而在类体执行阶段就拦截属性写入。
3. **在这个命名空间里执行类体**：类体内的赋值语句、方法定义都写进这个命名空间，而不是当前作用域。
4. **调用 `metaclass(name, bases, namespace, **kwds)`**：即元类的 `__call__`，它会依次触发元类的 `__new__`（创建类对象）和 `__init__`（初始化类对象），返回最终的类。

```python
class Meta(type):
    @classmethod
    def __prepare__(mcs, name, bases, **kwargs):
        print(f"1. __prepare__ 被调用，准备 {name} 的命名空间")
        return {}

    def __new__(mcs, name, bases, namespace, **kwargs):
        print(f"2. __new__ 被调用，创建类 {name}")
        return super().__new__(mcs, name, bases, namespace)

    def __init__(cls, name, bases, namespace, **kwargs):
        print(f"3. __init__ 被调用，初始化类 {name}")
        super().__init__(name, bases, namespace)


class Foo(metaclass=Meta):
    x = 1

# 输出：
# 1. __prepare__ 被调用，准备 Foo 的命名空间
# 2. __new__ 被调用，创建类 Foo
# 3. __init__ 被调用，初始化类 Foo
```

注意：这一整套流程发生在**类定义时**（模块加载、`class` 语句执行的那一刻），而不是每次创建实例时。实例化 `Foo()` 触发的是 `Foo.__call__`（默认由 `type.__call__` 提供），继而调用 `Foo.__new__` 和 `Foo.__init__`——层级不同，容易混淆。

## 4. 编写自定义元类

自定义元类就是继承 `type` 并重写 `__new__`/`__init__`（有时还有 `__prepare__`、`__call__`）。

```python
class UpperAttrMeta(type):
    """把类体中所有非双下划线开头的属性名转为大写"""

    def __new__(mcs, name, bases, namespace, **kwargs):
        upper_namespace = {
            (key.upper() if not key.startswith("__") else key): value
            for key, value in namespace.items()
        }
        return super().__new__(mcs, name, bases, upper_namespace, **kwargs)


class Config(metaclass=UpperAttrMeta):
    debug = True
    host = "localhost"

print(Config.DEBUG, Config.HOST)   # True localhost
print(hasattr(Config, "debug"))    # False，属性名已被改写
```

元类继承是链式的：一个类如果没有显式指定 `metaclass`，会沿用其基类的元类；子类可以进一步继承并扩展某个自定义元类。

## 5. `__new__` 与 `__init__` 在元类中的区别

和普通类一样，元类里的 `__new__` 负责**创建**类对象，`__init__` 负责**初始化**已创建的类对象，但要注意这里操作的对象层级更高一层——是「类」本身，而不是类的实例。

| 方法 | 接收的 `cls`/`mcs` | 时机 | 典型用途 |
|---|---|---|---|
| `__new__(mcs, name, bases, namespace)` | 元类本身 | 类对象**创建之前** | 修改 `namespace`、替换基类、决定是否真的创建这个类（甚至返回一个完全不同的对象） |
| `__init__(cls, name, bases, namespace)` | 刚创建出的类对象 | 类对象**创建之后** | 基于已存在的类对象做附加设置，如注册到全局表、校验类属性 |

```python
class ValidatingMeta(type):
    def __new__(mcs, name, bases, namespace):
        # 此时类对象还不存在，只能操作即将传给 super().__new__ 的原始材料
        if "required_field" not in namespace and bases:
            raise TypeError(f"{name} 必须定义 required_field")
        return super().__new__(mcs, name, bases, namespace)

    def __init__(cls, name, bases, namespace):
        # 此时 cls 已经是创建好的类对象，可以用 cls.xxx 访问
        super().__init__(name, bases, namespace)
        cls.created_by = "ValidatingMeta"


class Item(metaclass=ValidatingMeta):
    required_field = "sku"

print(Item.created_by)   # ValidatingMeta
```

需要**修改类创建过程本身**（如动态增删属性、替换基类）时用 `__new__`；只需要在类创建**之后**追加逻辑（如注册、打日志）时用 `__init__` 即可，逻辑更简单。

## 6. `__init_subclass__`：更轻量的替代方案

多数「在子类定义时做点什么」的需求，不需要写元类。Python 3.6 引入的 `__init_subclass__` 是一个隐式的类方法钩子，每当有子类被创建时自动调用，写法更简单、无需处理元类冲突。

```python
class Plugin:
    registry = []

    def __init_subclass__(cls, **kwargs):
        super().__init_subclass__(**kwargs)
        Plugin.registry.append(cls)
        print(f"注册插件: {cls.__name__}")


class TextPlugin(Plugin):
    pass


class ImagePlugin(Plugin):
    pass

print(Plugin.registry)   # [<class '...TextPlugin'>, <class '...ImagePlugin'>]
```

`__init_subclass__` 甚至可以接收关键字参数，配合 `class Foo(Base, key=value)` 语法：

```python
class Base:
    def __init_subclass__(cls, kind=None, **kwargs):
        super().__init_subclass__(**kwargs)
        cls.kind = kind


class Circle(Base, kind="shape"):
    pass

print(Circle.kind)   # shape
```

### 元类 vs `__init_subclass__` 如何选择

| 场景 | 推荐方案 |
|---|---|
| 只需要在子类创建后做校验、注册、打标记 | `__init_subclass__` |
| 需要修改类体命名空间本身（如批量改写属性名、注入方法） | 元类的 `__new__` |
| 需要自定义类体收集属性的过程（`__prepare__`，如保留定义顺序早期版本、限制可用名字） | 元类 |
| 需要多个不相关的类共享同一套"类创建逻辑"，且这些类已有各自不同的基类体系 | 元类（可独立于继承链附加） |
| 团队协作，代码需要尽量好懂、少踩坑 | 优先 `__init_subclass__`，能不用元类就不用 |

`__init_subclass__` 依赖继承关系传播，而元类可以脱离继承体系、通过 `metaclass=` 参数横向应用到任意类上，这是两者本质的区别。

## 7. `abc.ABCMeta`：标准库中的元类实践

Python 的抽象基类机制（`abc` 模块）就是用元类实现的真实范例。`ABCMeta` 是 `type` 的子类，它让类可以声明抽象方法，并在**实例化时**而非运行时才检查是否所有抽象方法都被实现。

```python
from abc import ABC, ABCMeta, abstractmethod

class Shape(ABC):          # ABC 是 metaclass=ABCMeta 的便捷写法
    @abstractmethod
    def area(self):
        ...

    @abstractmethod
    def perimeter(self):
        ...


class Rectangle(Shape):
    def __init__(self, w, h):
        self.w, self.h = w, h

    def area(self):
        return self.w * self.h

    def perimeter(self):
        return 2 * (self.w + self.h)


try:
    Shape()                 # TypeError：抽象类不能直接实例化
except TypeError as e:
    print(e)

r = Rectangle(3, 4)
print(r.area(), r.perimeter())    # 12 14

print(type(Shape))          # <class 'abc.ABCMeta'>
print(isinstance(Shape, ABCMeta))  # True
```

`class Shape(ABC):` 等价于 `class Shape(metaclass=ABCMeta):`，`ABC` 只是一个已经指定好元类的空基类，方便书写。`ABCMeta` 还支持 `register()` 实现「虚拟子类」（无需实际继承即可让 `isinstance` 判定为真），以及配合 `@abstractmethod` 检查属性、`classmethod`、`staticmethod`。这是元类在标准库中最重要、最经典的落地场景。

## 8. 实战应用一：类创建时的约束校验

元类可以在类刚定义完时就发现问题，把错误提前到「导入模块」阶段，而不是等到运行时才暴露。

```python
class EnforceInterfaceMeta(type):
    required_methods = ("save", "load")

    def __new__(mcs, name, bases, namespace):
        cls = super().__new__(mcs, name, bases, namespace)
        if bases:  # 跳过基类本身的检查
            missing = [m for m in mcs.required_methods if not callable(namespace.get(m))]
            if missing:
                raise TypeError(f"{name} 缺少必须实现的方法: {missing}")
        return cls


class Repository(metaclass=EnforceInterfaceMeta):
    pass


class UserRepository(Repository):
    def save(self):
        pass

    def load(self):
        pass


try:
    class BrokenRepository(Repository):
        def save(self):
            pass
        # 缺少 load
except TypeError as e:
    print(e)   # BrokenRepository 缺少必须实现的方法: ['load']
```

## 9. 实战应用二：子类自动注册

框架、插件系统常用元类把所有子类自动收集到一张注册表里，调用方无需手动维护映射关系。

```python
class SerializerMeta(type):
    registry = {}

    def __new__(mcs, name, bases, namespace):
        cls = super().__new__(mcs, name, bases, namespace)
        if bases:  # 跳过基类
            key = namespace.get("format_name", name.lower())
            mcs.registry[key] = cls
        return cls


class Serializer(metaclass=SerializerMeta):
    format_name = None


class JsonSerializer(Serializer):
    format_name = "json"


class YamlSerializer(Serializer):
    format_name = "yaml"


print(SerializerMeta.registry)
# {'json': <class '...JsonSerializer'>, 'yaml': <class '...YamlSerializer'>}

serializer_cls = SerializerMeta.registry["json"]
print(serializer_cls())
```

## 10. 实战应用三：单例模式

利用元类拦截 `()` 调用（即重写 `__call__`），可以让「实例化」这件事本身返回同一个对象，实现单例。

```python
class SingletonMeta(type):
    _instances = {}

    def __call__(cls, *args, **kwargs):
        if cls not in cls._instances:
            cls._instances[cls] = super().__call__(*args, **kwargs)
        return cls._instances[cls]


class Database(metaclass=SingletonMeta):
    def __init__(self, dsn):
        self.dsn = dsn
        print(f"建立连接: {dsn}")


db1 = Database("postgres://localhost/app")
db2 = Database("postgres://other/ignored")   # 不会重新执行 __init__
print(db1 is db2)     # True
print(db1.dsn)        # postgres://localhost/app
```

这里的关键是 `SingletonMeta.__call__` 覆盖了默认的 `type.__call__`，所以 `Database(...)` 这个调用不再直接触发 `__new__`/`__init__`，而是先经过元类的判断逻辑。

## 11. 实战应用四：校验属性声明

元类可以在类定义阶段检查类属性是否符合约定的「声明式」格式，常见于 ORM 字段定义。

```python
class Field:
    def __init__(self, field_type):
        self.field_type = field_type


class ModelMeta(type):
    def __new__(mcs, name, bases, namespace):
        fields = {}
        for key, value in namespace.items():
            if isinstance(value, Field):
                fields[key] = value
        namespace["_fields"] = fields
        return super().__new__(mcs, name, bases, namespace)


class Model(metaclass=ModelMeta):
    def __init__(self, **kwargs):
        for key, field in self._fields.items():
            value = kwargs.get(key)
            if value is not None and not isinstance(value, field.field_type):
                raise TypeError(f"{key} 应为 {field.field_type.__name__} 类型")
            setattr(self, key, value)


class User(Model):
    name = Field(str)
    age = Field(int)


u = User(name="Alice", age=30)
print(u.name, u.age)     # Alice 30

try:
    User(name="Bob", age="thirty")
except TypeError as e:
    print(e)   # age 应为 int 类型
```

## 12. 什么时候不该用元类

元类是 Python 里最容易被误用的机制之一，社区中流传的经验是：*「元类是深层魔法，99% 的用户永远不需要用到它；如果你在纠结要不要用元类，答案就是不需要。」* 原因有三：

- **可读性代价高**：元类改变了「类」本身的创建方式，阅读代码的人必须先理解元类逻辑才能知道类里发生了什么，调试栈也更深。
- **组合困难**：一个类只能有一个元类；如果两个基类分别绑定了不相干的元类，多重继承会直接抛 `TypeError: metaclass conflict`，需要手写第三个元类去调和，维护成本陡增。
- **多数场景有更简单的替代方案**：

| 需求 | 更简单的替代方案 |
|---|---|
| 子类创建时自动注册、校验 | `__init_subclass__`（见第 6 节） |
| 给已有类批量添加方法/属性、包一层行为 | 类装饰器：`def register(cls): ...; return cls` |
| 限制属性赋值、类型检查 | 描述符（见 8.5 节）或 `@property` |
| 运行时动态生成相似的类 | 工厂函数返回 `type(...)` 创建的类，无需自定义元类 |
| 单例、缓存实例 | 模块级变量、`functools.lru_cache` 装饰构造函数，甚至简单的类装饰器 |

一个实用的判断标准：如果需求可以用「类装饰器」或 `__init_subclass__` 表达清楚，就不要引入元类；只有当你确实需要**介入类对象本身的创建过程**（例如修改 `namespace`、控制 `__prepare__`、让类的实例化行为本身可插拔）时，元类才是不可替代的工具——`abc.ABCMeta` 正是这种「不可替代」的典型例子。

## 13. 本节小结

1. `type` 既是查看类型的内置函数，也是所有类默认的元类，`Dog` 的类型是 `type`，`type` 的类型是它自己；
2. `type(name, bases, namespace)` 可以在运行时动态创建类，这与 `class` 语句在语义上等价；
3. `class` 语句执行时依次经历「确定元类 → `__prepare__` 准备命名空间 → 执行类体 → 元类 `__call__` 触发 `__new__`/`__init__`」；
4. 自定义元类需继承 `type`，重写 `__new__` 修改类创建过程、重写 `__init__` 在类创建后追加逻辑；
5. 元类的 `__new__` 操作「尚未创建」的类材料，`__init__` 操作「已创建」的类对象，二者层级不同于普通类里的同名方法；
6. `__init_subclass__` 是更轻量的钩子，能覆盖元类的大多数常见用途（注册、校验），且不涉及元类冲突问题；
7. `abc.ABCMeta` 是元类在标准库中的经典应用，通过它可以定义抽象方法并在实例化时强制子类实现；
8. 元类的实战场景包括：类创建时校验约束、子类自动注册、通过重写元类 `__call__` 实现单例、校验声明式属性（ORM 风格）；
9. 元类是「深层魔法」，多数需求可以用类装饰器或 `__init_subclass__` 替代，只有需要真正介入类创建过程时才应该使用元类。
