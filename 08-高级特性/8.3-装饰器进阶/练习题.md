# 8.3 装饰器进阶练习题

## 一、概念题

1. 多个装饰器叠加时，应用顺序和执行顺序分别是什么？请用嵌套函数调用的形式展开 `@a @b @c def f(): ...`。
2. 为什么把 `lru_cache` 放在日志类装饰器的内层和外层，观察到的日志行为会不一样？
3. 用类实现装饰器时，`__init__` 和 `__call__` 各自承担什么职责？相比闭包实现，类装饰器的优势是什么？
4. `functools.wraps` 具体复制了哪些属性（`WRAPPER_ASSIGNMENTS`）？又用什么方式合并 `__dict__`（`WRAPPER_UPDATES`）？
5. 为什么加了 `@wraps` 之后，`inspect.signature()` 能看到原函数的签名，而不是 `wrapper(*args, **kwargs)`？
6. `functools.singledispatch` 的分派依据是什么？如果调用参数类型没有被注册过，会发生什么？
7. `lru_cache` 的 `maxsize` 和 `typed` 参数分别控制什么？`cache_info()` 返回哪四个字段？
8. 为什么 `lru_cache` 装饰的函数不能传入 `list`、`dict` 这类参数？
9. 装饰 `staticmethod`/`classmethod` 时为什么要求自定义装饰器写在更外层？如果写反会发生什么？
10. 用类装饰器批量装饰一个类的所有方法时，通常需要遍历类的哪个属性？如何避免误把魔术方法也装饰进去？

## 二、判断代码输出

### 1. 装饰器链的顺序

```python
from functools import wraps

def deco(tag):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            print(f"-> {tag}")
            r = func(*args, **kwargs)
            print(f"<- {tag}")
            return r
        return wrapper
    return decorator

@deco("X")
@deco("Y")
def task():
    print("run")

task()
```

写出完整输出，并说明哪个装饰器最先包裹 `task`。

### 2. 缓存装饰器的位置

```python
from functools import lru_cache

calls = []

def record(func):
    def wrapper(*args, **kwargs):
        calls.append(args)
        return func(*args, **kwargs)
    return wrapper

@record
@lru_cache(maxsize=None)
def square(n):
    return n * n

square(3)
square(3)
square(3)
print(len(calls))
```

写出 `len(calls)` 的值，并解释为什么缓存没有减少 `record` 记录的调用次数。

### 3. 类装饰器的状态

```python
class Counter:
    def __init__(self, func):
        self.func = func
        self.n = 0

    def __call__(self, *args, **kwargs):
        self.n += 1
        return self.func(*args, **kwargs)

@Counter
def ping():
    return "pong"

a = ping
b = ping
a()
b()
print(ping.n)
```

写出 `ping.n` 的值，并解释 `a`、`b` 是否是两个独立的计数器。

### 4. `wraps` 缺失导致的签名丢失

```python
import inspect

def deco(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper

@deco
def greet(name, *, loud=False):
    """打招呼"""
    return name

print(greet.__name__)
print(greet.__doc__)
print(inspect.signature(greet))
```

写出三行输出，并说明如果给 `wrapper` 加上 `@wraps(func)` 之后，三行输出会分别变成什么。

### 5. `singledispatch` 的默认分支

```python
from functools import singledispatch

@singledispatch
def describe(x):
    return f"未知类型:{type(x).__name__}"

@describe.register(int)
def _(x):
    return f"整数:{x}"

print(describe(5))
print(describe(5.0))
print(describe("5"))
```

写出三行输出，并说明第二行为什么没有走 `int` 的分支。

## 三、编程题

### 1. 装饰器工厂：限速器

实现 `rate_limited(max_calls, period)`：

- 三层结构（参数装饰 → decorator → wrapper）；
- 在 `period` 秒内最多允许调用 `max_calls` 次，超过则抛出 `RuntimeError`；
- 用 `functools.wraps` 保留原函数的元信息；
- 编写一个被装饰的函数并验证超限时确实抛出异常。

### 2. 类装饰器：调用统计与缓存二合一

实现类 `StatsCache`：

- `__init__(self, func)` 保存函数、初始化缓存字典、命中/未命中计数；
- `__call__` 优先查缓存，未命中时调用原函数并存入缓存；
- 提供 `stats` 属性或方法返回 `{"hits": ..., "misses": ...}`；
- 提供 `clear()` 方法清空缓存和计数；
- 用 `wraps(func)(self)` 保留 `__name__` 等元信息。

### 3. 保留签名的类型校验装饰器

实现 `enforce_types`：

- 根据函数的类型注解（用 `inspect.signature` 获取参数与注解）在调用时校验实参类型；
- 类型不匹配时抛出 `TypeError`，错误信息中包含参数名、期望类型、实际类型；
- 用 `functools.wraps` 保证装饰后 `inspect.signature()` 仍能看到原始注解和默认值；
- 编写至少两个用例：一个类型正确通过，一个类型错误触发异常。

### 4. `singledispatch` 实现统一的序列化函数

实现 `to_json_like(value)`：

- 默认实现处理 `object`，直接 `str()`；
- 为 `int`、`float`、`bool`、`str`、`type(None)` 注册专门实现，返回 Python 内置对应类型能直接序列化的值；
- 为 `list`、`tuple` 注册实现，把每个元素递归调用 `to_json_like`；
- 为 `dict` 注册实现，对每个 value 递归调用 `to_json_like`，key 转为字符串；
- 编写测试用例覆盖嵌套结构，如 `{"a": [1, 2.5, None, {"b": True}]}`。

### 5. 类装饰器：批量为类方法加日志并可关闭

实现类装饰器 `auto_log(cls=None, *, exclude=())`：

- 支持 `@auto_log` 直接使用，也支持 `@auto_log(exclude=("save",))` 排除指定方法名；
- 遍历类的所有普通方法（排除以 `_` 开头的），逐一包装日志装饰器；
- 日志格式为 `"[类名.方法名] args=... kwargs=..."`；
- 用 `functools.wraps` 保证每个方法被包装后 `__name__` 不变；
- 验证 `exclude` 中的方法确实没有被包装。

## 四、综合实践：构建一个"计算任务"装饰器工具箱

设计一组配合使用的装饰器，模拟对昂贵计算任务的工程化封装，要求：

1. `@timed`：记录每次调用耗时，把耗时累加到函数对象的 `total_time` 属性上；
2. `@retry(times=3, exceptions=(ValueError,))`：失败自动重试，重试次数用尽后把最后一次异常原样抛出；
3. `@cache_with_ttl(ttl_seconds)`：自定义带过期时间的缓存装饰器（不能直接用 `lru_cache`，因为需要时间维度失效），要求提供 `cache_info()` 方法返回 `hits`/`misses`/`size`；
4. 把三者按下面顺序叠加到同一个函数上，并说明为什么是这个顺序而不是别的顺序：

   ```python
   @timed
   @retry(times=3, exceptions=(ValueError,))
   @cache_with_ttl(ttl_seconds=5)
   def fetch_price(symbol):
       ...
   ```

5. 用一个类装饰器 `@expose_stats` 把上面所有装饰器附加的统计信息（`total_time`、`cache_info()` 等）汇总成 `fetch_price.stats()` 一个统一入口；
6. 编写至少三个测试场景：正常命中缓存、缓存过期后重新计算、模拟异常触发重试并最终抛出。
7. 思考并写下结论：如果把 `@cache_with_ttl` 放在最外层、`@timed` 放在最内层，统计出来的耗时和缓存命中率会有什么变化？
