# 8.4 上下文管理器练习题

## 一、概念题

1. 上下文管理器协议由哪两个方法组成？`with` 语句在正常结束和异常结束两种情况下分别如何调用它们？
2. `__exit__(self, exc_type, exc_val, exc_tb)` 的三个参数分别表示什么？什么情况下它们同时为 `None`？
3. `__exit__` 返回 `True` 和返回 `False`/`None` 有什么区别？为什么大多数场景不建议无条件返回 `True`？
4. 用 `@contextmanager` 装饰生成器函数时，`yield` 前后的代码分别对应协议中的哪个方法？为什么必须用 `try/finally` 包裹 `yield`？
5. `contextlib.suppress` 的作用是什么？它和普通的 `try/except: pass` 相比有什么优势？
6. `redirect_stdout`/`redirect_stderr` 通常用在什么场景？它们在 `with` 块结束后会做什么？
7. `ExitStack` 解决了普通 `with` 语句的什么局限？`enter_context`、`push`、`callback` 三个方法分别用来做什么？
8. 一行 `with` 语句管理多个上下文管理器时，进入和退出的顺序分别是什么？
9. 「可重入」和「可重用」这两个概念有什么区别？`@contextmanager` 装饰出的对象在这两方面各自的表现如何？
10. `async with` 对应哪两个协议方法？它与本节讲的同步协议在语义上有什么对应关系（不需要展开异步细节）？

## 二、判断代码输出

### 1. `__exit__` 的返回值

```python
class Demo:
    def __enter__(self):
        print("enter")
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        print(f"exit: {exc_type}")
        return True

with Demo():
    print("body")
    raise ValueError("boom")

print("after")
```

写出输出，并说明为什么最后一行 `print("after")` 会被执行到。

### 2. 生成器版上下文管理器缺少 `try/finally`

```python
from contextlib import contextmanager

@contextmanager
def cm():
    print("start")
    yield
    print("end")   # 注意：没有用 try/finally 包裹

with cm():
    print("body")
    raise RuntimeError("oops")
```

预测这段代码的实际行为（是否抛出异常、`"end"` 是否会被打印），并说明原因。

### 3. 多次使用同一个 `@contextmanager` 实例

```python
from contextlib import contextmanager

@contextmanager
def once():
    print("enter")
    yield
    print("exit")

cm = once()
with cm:
    print("first use")
with cm:
    print("second use")
```

写出运行到第二个 `with cm:` 时会发生什么，并解释原因。

### 4. `ExitStack` 的清理顺序

```python
from contextlib import ExitStack

class Res:
    def __init__(self, name):
        self.name = name
    def __enter__(self):
        print(f"open {self.name}")
        return self
    def __exit__(self, *exc_info):
        print(f"close {self.name}")
        return False

with ExitStack() as stack:
    for name in ["a", "b", "c"]:
        stack.enter_context(Res(name))
    print("body")
```

写出完整输出顺序，说明资源关闭顺序与打开顺序的关系。

## 三、编程题

### 1. 计时上下文管理器

用类实现 `Timer`：

- `__enter__` 记录开始时间并返回自身；
- `__exit__` 计算耗时，打印形如 `耗时: 0.0032s`；
- 无论 `with` 块内是否抛出异常都要打印耗时，且不吞掉异常；
- 额外提供一个只读属性 `elapsed`，在 `with` 块结束后仍可访问。

### 2. `@contextmanager` 版本的临时目录切换

用 `contextlib.contextmanager` 实现 `chdir(path)`：

- 进入时用 `os.chdir` 切换到目标目录，记录原目录；
- 无论 `with` 块内代码是否抛出异常，退出时都必须切回原目录；
- 目标目录不存在时抛出清晰的异常，且不切换目录。

### 3. 可控的异常抑制器

实现一个类 `SuppressAndLog`，接收若干异常类型：

- 作为上下文管理器使用，捕获到列表中的异常类型时打印日志并抑制该异常；
- 遇到列表之外的异常类型正常向外传播；
- 提供一个属性（如 `caught`），记录最近一次是否真的抑制了异常，供调用方在 `with` 块外检查。

### 4. 用 `ExitStack` 批量管理动态数量的资源

实现函数 `open_many(paths)`：

- 接收一个路径列表，数量不固定；
- 使用 `ExitStack` 依次打开所有文件并返回一个「组合上下文管理器」，可以用 `with open_many(paths) as files:` 的形式使用，`files` 是文件对象列表；
- 如果中途某个文件打开失败，已经打开的文件必须全部正确关闭，不能泄漏；
- 额外用 `stack.callback` 注册一条日志，记录本次一共打开了多少个文件。

### 5. 验证可重入行为

编写一小段测试代码：

- 分别用普通类实现的上下文管理器和 `@contextmanager` 实现的上下文管理器，尝试嵌套 `with` 同一个实例；
- 观察并记录哪种写法会出错、错误信息是什么；
- 修改类实现，使用一个计数器让它支持可重入（嵌套使用时只在最外层真正执行 `__enter__`/`__exit__` 的核心逻辑）。

## 四、综合实践：批量任务执行框架

设计一个「批量任务执行」小框架，要求综合运用本节内容：

1. 用 `@contextmanager` 实现 `task_context(name)`：进入时打印 `[开始] name`，正常退出打印 `[完成] name`，异常退出打印 `[失败] name: 具体异常信息` 并抑制异常（让批量执行不会因为单个任务失败而中断整体流程）；
2. 用 `ExitStack` 管理一批任务共享的资源（如统一打开的日志文件、统一获取的锁），保证无论任务成功还是失败，这些共享资源都会被正确释放；
3. 用 `contextlib.redirect_stdout` 捕获每个任务内部的 `print` 输出，分别归档到以任务名命名的字符串缓冲区中，执行结束后统一打印一份「任务输出汇总」；
4. 用 `contextlib.suppress` 处理任务清理阶段可能出现的「资源已被外部提前释放」（如 `FileNotFoundError`）等可忽略错误；
5. 统计并打印本次批量执行的总任务数、成功数、失败数（失败任务名单列出来）；
6. 思考并写下你的结论：本框架中哪些上下文管理器是「可重用」的，哪些实例每次任务只能使用一次？为什么批量循环中不能对同一个 `@contextmanager` 实例重复 `with`？
