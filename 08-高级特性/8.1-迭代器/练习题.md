### 2. 迭代器与可迭代对象的区别

```python
class Repeater:
    def __init__(self, value, times):
        self.value = value
        self.times = times

    def __iter__(self):
        return RepeaterIterator(self.value, self.times)


class RepeaterIterator:
    def __init__(self, value, times):
        self.value = value
        self.remaining = times

    def __iter__(self):
        return self

    def __next__(self):
        if self.remaining <= 0:
            raise StopIteration
        self.remaining -= 1
        return self.value


r = Repeater("x", 2)
print(list(r))
print(list(r))
```

两次 `list(r)` 的结果是否相同？说明原因，并对比如果 `Repeater.__iter__` 直接 `return self`（把两个类合并成一个）会有什么不同的行为。

## 三、编程题

### 1. 区间迭代器 `RangeLike`

实现一个类 `RangeLike(start, stop, step=1)`，模拟内置 `range` 的部分行为：

- 支持 `for x in RangeLike(...)` 遍历；
- `step` 可以为负数（倒序）；
- `step` 为 `0` 时在构造函数中抛出 `ValueError`；
- 要求可以对同一个 `RangeLike` 实例发起多次独立的 `for` 遍历，互不影响（提示：拆分容器类与迭代器类）。

### 2. 循环缓冲区迭代器 `RingBuffer`

实现类 `RingBuffer(items, laps)`：

- 内部保存一份序列 `items`；
- 迭代时按顺序循环遍历 `items` 共 `laps` 圈后停止（`laps` 为整数，允许为 0，此时立即 `StopIteration`）；
- 例如 `list(RingBuffer([1, 2, 3], 2))` 应得到 `[1, 2, 3, 1, 2, 3]`；
- 不允许直接把结果一次性用列表乘法拼出来再返回，必须逐步 `__next__` 产出。

### 3. 用 `iter()` 哨兵形式实现「读取直到遇到指定值」

编写函数 `read_until(source, sentinel)`：

- `source` 是一个不接受参数、每次调用返回下一个值的可调用对象（模拟从设备/队列取数据）；
- 使用 `iter(source, sentinel)` 构造迭代器；
- 返回一个列表，包含从 `source` 中依次取出的值，直到（但不包含）取到 `sentinel` 为止；
- 编写至少一个使用 `functools.partial` 包装 `next(iterator, default)` 来构造 `source` 的示例进行验证。

### 4. 惰性分页器 `paginate`

利用 `itertools.islice` 实现函数 `paginate(iterable, page_size)`：

- 返回一个生成分页的迭代器，每次产出一个长度不超过 `page_size` 的列表；
- 输入的 `iterable` 只能被消费一次（不要求支持重复分页）；
- 最后一页可以小于 `page_size`，输入为空时不产出任何分页；
- 例如 `list(paginate(range(7), 3))` 应得到 `[[0, 1, 2], [3, 4, 5], [6]]`。

## 四、综合实践：多源日志合并浏览器

有三个日志来源（可以用列表模拟），每条记录形如 `(timestamp, source_name, message)`，且**各来源内部已按 `timestamp` 升序排列**，但来源之间未必对齐：

```python
source_a = [(1, "A", "start"), (3, "A", "tick"), (8, "A", "stop")]
source_b = [(2, "B", "start"), (4, "B", "tick"), (5, "B", "tick")]
source_c = [(6, "C", "warn"), (7, "C", "error")]
```

要求实现一个类 `LogMerger(*sources)`，满足：

1. `LogMerger` 本身是可迭代对象，支持多次独立的 `for` 遍历（每次都从头开始）；
2. 迭代时按 `timestamp` 全局升序输出所有来源的记录，且不能把三个来源全部提前合并排序成一个大列表——同一时刻只允许在内存中保留每个来源「当前待比较的一条」记录（提示：为每个来源单独持有一个迭代器，配合手动维护的「当前元素缓存」比较取最小值，类似于归并排序里的归并阶段）；
3. 使用 `itertools.chain` 提供一个辅助方法 `flatten_debug()`，按来源顺序（不按时间）依次输出所有记录，用于对比调试；
4. 使用 `itertools.groupby` 实现另一个辅助方法 `count_by_source()`，统计每个来源产出的记录条数（提示：先用 `flatten_debug()` 或重新遍历一次，按 `source_name` 排序后再分组）；
5. 为整个 `LogMerger` 编写至少三个测试用例：来源为空、只有一个来源、时间戳有重复的跨来源记录如何排序（约定同一时间戳按来源出现的顺序决定先后）。
