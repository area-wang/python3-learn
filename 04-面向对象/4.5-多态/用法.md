## 多态的概念

多态指“同一接口，不同对象有不同实现”。调用者只关心对象能做什么，不关心对象具体是什么类。

```python
class Dog:
    def speak(self):
        return "汪"

class Cat:
    def speak(self):
        return "喵"

def make_sound(animal):
    print(animal.speak())

make_sound(Dog())
make_sound(Cat())
```

`make_sound` 不需要判断是狗还是猫，只要求对象有 `speak()` 方法。

## 继承中的多态

继承体系中，父类定义统一接口，子类提供具体实现。

```python
class Shape:
    def area(self):
        raise NotImplementedError

class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height

    def area(self):
        return self.width * self.height

class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

    def area(self):
        return 3.14159 * self.radius ** 2

def total_area(shapes):
    return sum(shape.area() for shape in shapes)

print(total_area([Rectangle(3, 4), Circle(2)]))
```

这里 `total_area` 对所有 `Shape` 子类都能工作。

## 鸭子类型

Python 更强调鸭子类型：如果一个对象走起来像鸭子，叫起来像鸭子，就可以当作鸭子使用。

```python
class FileLogger:
    def write(self, text):
        print(f"写入文件: {text}")

class ConsoleLogger:
    def write(self, text):
        print(f"控制台: {text}")

def save_log(writer, message):
    writer.write(message)

save_log(FileLogger(), "hello")
save_log(ConsoleLogger(), "hello")
```

两个类没有共同父类，但只要都有 `write` 方法，就能被同一函数使用。

### 内置协议也是鸭子类型

```python
def show_all(items):
    for item in items:
        print(item)

show_all([1, 2, 3])
show_all(("a", "b"))
show_all({"x": 1, "y": 2})
```

`show_all` 只要求 `items` 可迭代。

## 统一接口设计

多态的前提是接口稳定。多个类应提供相同的方法名、参数含义和返回值约定。

```python
class EmailSender:
    def send(self, to, content):
        return f"Email to {to}: {content}"

class SMSSender:
    def send(self, to, content):
        return f"SMS to {to}: {content}"

def notify(sender, user, message):
    return sender.send(user, message)
```

如果接口不一致，调用者就会被迫写大量判断。

```python
# 不好：不同类的方法名不同
class Email:
    def send_email(self, to, content): ...

class SMS:
    def send_sms(self, phone, text): ...
```

## 抽象基类 ABC

抽象基类可以强制子类实现某些方法。

```python
from abc import ABC, abstractmethod

class Payment(ABC):
    @abstractmethod
    def pay(self, amount):
        pass

class AliPay(Payment):
    def pay(self, amount):
        return f"支付宝支付 {amount}"

# Payment()  # TypeError，抽象类不能实例化
print(AliPay().pay(100))
```

如果子类没有实现抽象方法，也不能实例化。

```python
class BadPayment(Payment):
    pass

# BadPayment()  # TypeError
```

适合使用 ABC 的场景：

- 框架要求插件实现固定接口
- 团队协作中需要明确约束
- 子类很多，漏实现会造成运行时 bug

## 协议式编程

Python 3.8+ 的 `typing.Protocol` 可以表达“只要结构匹配即可”的类型约束，常用于类型检查。

```python
from typing import Protocol

class Writable(Protocol):
    def write(self, text: str) -> None:
        ...

def save(writer: Writable, text: str) -> None:
    writer.write(text)

class Console:
    def write(self, text: str) -> None:
        print(text)

save(Console(), "hello")
```

`Console` 不需要继承 `Writable`，只要拥有兼容的 `write` 方法，静态类型检查器就认可。

## 多态与类型判断

多态通常减少 `isinstance` 分支。

```python
# 不推荐：每来一个新类型都要改函数
def area(shape):
    if isinstance(shape, Rectangle):
        return shape.width * shape.height
    if isinstance(shape, Circle):
        return 3.14159 * shape.radius ** 2
    raise TypeError("未知形状")

# 推荐：对象自己负责自己的 area
def area(shape):
    return shape.area()
```

`isinstance` 不是不能用，适合边界校验、兼容旧接口、处理外部输入。但业务扩展点应优先使用多态。

## 常见错误与最佳实践

### 1. 接口名字相同但含义不同

不同类都叫 `run()`，但一个表示启动任务，一个表示跑步，这不是好的多态接口。

### 2. 返回值约定不一致

```python
class A:
    def parse(self):
        return {"ok": True}

class B:
    def parse(self):
        return True  # 调用者会困惑
```

### 3. 父类写太多空方法

如果父类只是堆满 `pass`，可能说明你需要 ABC、Protocol，或重新设计职责。

### 4. 用类型判断代替对象行为

多态的核心是“把变化放到对象内部”，而不是让调用者识别所有类型。

---

## 小结

- 多态让同一调用适配不同对象。
- Python 更常用鸭子类型：关注对象有没有所需行为。
- 继承、ABC、Protocol 都可以表达多态接口。
- 好的多态要求方法名、参数、返回值语义一致。
- 少写类型分支，多让对象自己完成行为。
